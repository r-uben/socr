# 2026-08-30 — TICKET-D1b: table judge ladder resume skip policy (GH-353)

## What changed

`src/socr/pipeline/orchestrator.py` (`_load_terminal_page`):

- Added one deliberate, positive exception to the otherwise
  "doubt-reprocesses" gate: after the fingerprint and input-checksum checks
  (both unchanged), the sidecar's `table_ladder_disposition` is read. When
  it equals `FailureMode.TABLE_REJECTED.value`, the page skips the two
  checks that follow (`status == SUCCESS`, `audit_passed is True`) and is
  still skip-and-kept. Every other condition in the method (missing
  sidecar/fragment, corrupt JSON, non-`True` `terminal`, fingerprint
  mismatch, checksum mismatch, missing/unrebuildable `winning_output`,
  empty/failure-marker body) is untouched and applies identically whether
  or not the page is REJECTED.
- `FailureMode.TABLE_UNVERIFIED` gets no exception — an UNVERIFIED page's
  finalized `winning_output` is demoted by C3's
  `_apply_ladder_disposition_guard` exactly like a REJECTED one
  (`status=WARNING`, `audit_passed=False`), so it falls straight through
  the existing SUCCESS/audit_passed checks and is reprocessed, unchanged
  from before this ticket.
- Docstring updated to name the exception explicitly (which condition it
  bypasses and why), rather than leaving the "skip iff ALL hold" list
  silently wrong for the one disposition it no longer literally covers.

No change was needed to make "changed rung identity reprocesses a REJECTED
page" true — B1's `_run_fingerprint` extension already binds
`table_judge_ladder`, `table_judge_rung1_model`, `table_judge_rung2_binary`,
`table_judge_timeout_sec`, and the prompt digest into the run fingerprint,
and the fingerprint check runs BEFORE the new disposition branch is ever
consulted. This ticket only pins that behaviour in a test (below); the
mechanism already existed.

## Why the branch sits where it does

The contract asked for the positive early-return "after fingerprint + input
checksum validation but before the SUCCESS/audit checks." Rather than
duplicating the winning-output-presence / body-read / rebuild logic in a
separate early-return block, the disposition is captured as a boolean
(`is_ladder_rejected`) right after the checksum check, and the two
downstream checks it exempts are wrapped in `if not is_ladder_rejected:` —
one linear path, no duplicated reconstruction logic, and every other
invariant (winning-output must exist and rebuild, body must exist and not
be a failure marker) still applies unconditionally to a REJECTED page. A
REJECTED page's body is real, judge-distrusted TABLE content on an
otherwise-shipped page — not a failure marker — so gating it on
`is_page_failed_marker` alongside every other page is correct, not an
oversight.

## Tests

New: `tests/test_ladder_resume.py` — 5 tests, hermetic (drives
`_flush_page_fragment` / `_flush_page_sidecar` / `_load_terminal_page` /
`_restore_terminal_page_state` directly, mirroring
`tests/test_gh161_resume_ledger_audit_gate.py`'s pattern; no rung/witness
machinery reachable, no provider ladder, no `_available_engines_for_agentic`
patch needed).

- `TestRejectedSkipsAndKeeps` (3): REJECTED + matching fingerprint skips
  (with a precondition assertion that C3's guard really did demote the
  sidecar's `winning_output` to WARNING/audit_passed=False first, so the
  test isn't vacuously passing through the pre-existing checks); a resumed
  run's re-flush of a skipped REJECTED page reproduces byte-identical
  sidecar bytes; a changed `table_judge_rung2_binary` (fingerprint mismatch)
  reprocesses a REJECTED page instead of reusing the stale ledger entry.
- `TestUnverifiedAlwaysReprocesses` (1): UNVERIFIED + matching fingerprint
  is still reprocessed (`_load_terminal_page` returns `None`), same
  demoted-sidecar shape as REJECTED, proving the exception is disposition-
  specific and not a blanket "any ladder terminal skips."
- `TestBaselineUntouched` (1): a page with no ladder disposition at all
  (flag off / no tables / ACCEPTED) keeps `status=SUCCESS,
  audit_passed=True` and still skips through the ORIGINAL, unmodified
  checks — the non-ladder majority case is provably undisturbed.
