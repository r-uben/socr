# PP-6 (GH-54): Lane-cooccupancy routing gate + content-type vector on PageState

**Date:** 2026-06-16
**Ticket:** PP-6 / GitHub #54
**Branch:** fix/54-routing-overroute

## What changed

### 1. `src/socr/core/born_digital.py` — Replace loose single-token heuristic

`BornDigitalDetector._detect_tables` previously had two passes:
1. `page.find_tables()` (bordered/ruled tables) — kept as-is.
2. `_detect_columnar_numbers` (single-token line ratio >= 15 lines, > 50% single-token)
   — **replaced** with `has_numeric_columns` from `socr.tables.reconstruct`.

The old `_detect_columnar_numbers` false-fired on chart-axis tick values (y-axis labels
stacked vertically at a single x-position). Each tick is a single token, so 20 tick
marks (common in CE chart figures) produced 20 single-token lines, well above the floor.

`has_numeric_columns` requires numeric tokens to co-occupy `_MIN_LANES_PER_ROW` (= 3)
distinct x-lanes *within the same data row*. Chart tick labels share one x-lane and
never satisfy this; a genuine regression table co-occupies 4–6 lanes per row.

`_detect_columnar_numbers` is removed entirely (dead code with the new fallback).

### 2. `src/socr/core/state.py` — Content-type vector on PageState

Added `has_figures: bool = False` and `has_equations: bool = False` to `PageState`.

`apply_born_digital` now propagates the full content-type vector
(has_tables, has_figures, has_equations) from `PageAssessment` to `PageState`, so
downstream routing phases can read directly from `PageState` without re-consulting
`_last_assessment`.

### 3. `src/socr/pipeline/orchestrator.py` — Remove ad hoc re-reads

- **`_phase_tiered` page_hints block (~line 703):** Replaced the inline
  `bd_assessment = next(…_last_assessment.pages…)` loop with direct reads of
  `ps.has_tables` / `ps.has_equations` from `PageState`. This is the primary
  change the ticket called out as the routing over-fire root cause.

- **`_phase_judge_hard_pages` hard_pages set (~line 1344):** Primary source is now
  `PageState.has_tables / has_equations`; falls back to `_last_assessment` for
  partial pipeline runs and unit tests that bypass `apply_born_digital`.

- **`_phase_dual_pass_tables` table_pages set (~line 1442):** Same pattern — PageState
  first, `_last_assessment` fallback. This preserves existing unit tests that inject
  the assessment directly.

## Test fixtures — limitation note

No real CE PDF is checked in. The chart-axis acceptance test (`test_chart_axis_labels_not_flagged_as_table`) uses a synthetic born-digital page with 20 single-token y-axis tick values at a single x-position. This is representative of the failure mode (all tokens in one x-lane, no multi-lane row co-occupation) but is not the exact CE document that triggered issue #54. Any real CE page that contains an actual data table alongside chart axes would need separate verification to confirm narrowing is correct. Annotated on the test.

Native reconstruction path is unchanged: `has_numeric_columns` is the existing gate
in `reconstruct_table_regions` — we now reuse it for routing, not in addition to it.
A page that was already passing `has_numeric_columns` in reconstruction continues to do
so; narrowing only removes the false-positive single-lane cases.
