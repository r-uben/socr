## Defect confirmed on main

`stale_pages` (`manifest.py`) checked only text blobs in the `BlobStore`. Replay reassembles markdown
containing relative image links (figures, chart crops, equation crops) written to `<doc_dir>/figures/`
by `figures/extractor.py`, `figures/chart_regions.py`, and the orchestrator's chart-page/table-failure
PNG renderers, and never verified those files exist, are unmodified, or are reachable from wherever
`socr replay -o` writes the reconstructed document. `socr replay` exits 0 and prints "0 model calls"
on a document whose figure links silently resolve to nothing — the silent-loss shape this repo's
cardinal rule forbids, and exactly what the issue names.

## Back-compat decision (stated before implementing, per the team lead's gate)

**Question:** does replay of an OLD manifest (no asset records) fail, warn, or proceed?

**Answer: proceed, with NO asset-integrity issues reported — not "verified intact", but "nothing was
ever recorded to check".** Justification, with file:line evidence:

- `MANIFEST_SCHEMA_VERSION` (`manifest.py:82`, comment block above it) exists but is **never branched
  on anywhere in the file** — confirmed via `grep -rn schema_version src/socr | grep -v manifest.py`
  (no hits). Every prior optional addition to `Manifest`/`ManifestEntry` (`timings_s`,
  `agentic_ladder`) is instead detected by **presence** — `to_dict` omits the key when falsy, `from_dict`
  reads it with `d.get(key, default)`. There is no version-branching migration mechanism to reuse; the
  established mechanism IS duck-typed presence detection, so I followed it rather than inventing a new
  one.
- I therefore did **not** bump `MANIFEST_SCHEMA_VERSION`. A first draft did (to "2", documenting the
  new field), but that turned out to be purely cosmetic (nothing reads it) while creating a spurious
  top-level `('manifest', 0, 'schema_version')` diff in `tests/test_p6_stage_c_difference.py`'s
  exact-surface oracle (`TestStageCCompleteExactDelta`, an unrelated golden fixture asserting the ONLY
  diffs between a captured "prechange" and "current" corpus run are its own enumerated set). Reverted.
- `ManifestEntry.assets` (`manifest.py`, new field) defaults to `[]` and `to_dict()` omits the `"assets"`
  key entirely when empty — same convention as `timings_s`/`agentic_ladder` on `Manifest`. A document
  with no images (or a manifest built without `doc_dir`, see below) produces byte-identical JSON to
  before this ticket. This is what let the existing P6 golden-fixture and byte-identity tests pass
  unmodified once the version bump was reverted (see Verification).
- Failing closed on old manifests (raising on `entries[n].assets == []`) would refuse replay for
  **every existing cache in the wild** with no way for the operator to fix it short of a full re-OCR —
  defeating the entire point of a "0 model calls" replay path, for a class of document (images this
  ticket never had provenance for) that was never promised protection in the first place. The
  acceptance criteria protect documents processed **from now on**; they do not retroactively guarantee
  ones already on disk. `stale_assets` (`manifest.py`) makes this explicit in its own docstring:
  > "nothing was ever recorded to check" is a distinct state from "checked and found intact"

## Implementation

**`build_manifest`** gained an optional `doc_dir: Path | None = None` parameter. When given, each
page's frozen text (`record.output.text` — the exact bytes that also become the blob and, when
`saved_body` is given, the on-disk `.md`) is scanned by a new `_local_page_asset_refs` helper for LIVE
local image links, and each becomes an `AssetRef(logical_path, content_hash)` on `ManifestEntry.assets`.
`_local_page_asset_refs` reuses `figures/chart_regions.py`'s own markdown scanner
(`markdown_literal_context` + `live_image_tokens`) rather than a second regex — that module already
solved fence/inline-code/HTML-comment literal-context correctly for this exact "is this `![...]` a real
reference or just shown text" question; a second hand-rolled scanner here risked exactly the
fence/comment drift this repo already learned to avoid once (see the module's own docstring). Omitted
when the destination is a URL/`data:`/anchor (nothing local to hash), when the resolved path would
escape `doc_dir` (not a real asset this run wrote), or when the file doesn't exist at build time (logged
— there is nothing to record provenance for).

`orchestrator.py::_write_manifest` now passes `doc_dir=doc_dir` (it already computed it via
`doc_dir_for`/`relative_key` for the `BlobStore`/`manifest.json` paths, one line above).

**`stale_assets(manifest, doc_dir) -> list[AssetIntegrityIssue]`** — new, `stale_pages`'s counterpart
for visual assets. For each recorded `AssetRef`, re-resolves `doc_dir / logical_path` and:
- reports `kind="missing"` if the file doesn't exist (or is unreadable — same bucket, same operator
  action: restore/regenerate),
- reports `kind="modified"` if it exists but its sha256 no longer matches the recorded hash
  (corrupted/overwritten — different operator action: investigate what wrote over it).

Distinguishing the two is what the acceptance criteria asked for ("missing" vs "modified" vs
"relocated" need different operator actions).

**"Relocated"** is handled as acceptance #3 describes: copying, not a third `stale_assets` kind. `socr
replay -o <path>` now (a) runs `stale_assets` against `manifest_path.parent` (where the manifest and
its `figures/` actually live) **before** reassembling anything, refusing explicitly on any issue, then
(b) if `-o` points outside that directory, copies every recorded asset to the new location via the new
`copy_page_assets(manifest, source_dir, dest_dir)`, preserving each asset's `logical_path` (e.g.
`figures/figure_1_page3.png`) relative to the new output directory, so the replayed document's relative
image links keep resolving. No-op when source and dest are the same directory (the common case — no
copy of anything that didn't move).

**CLI surfacing** (`cli.py::replay`): the missing/modified report reaches `click.ClickException` (exit
code != 0, message on stderr via Click) grouped by kind with page number, logical path, and detail per
asset — not a log line. A successful relocated replay reports `"N asset(s) copied"` in the same
success line that already reports page count and "0 model calls".
