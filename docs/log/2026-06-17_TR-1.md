## Critical investigation: find_tables() separate-vs-merged

The TR-1 ticket requires recording whether `find_tables()` (default "lines" strategy)
returns the two CE-like tables as SEPARATE regions or ONE merged region.

**Finding for the TR-0 fixture (`ce_like_p4.pdf`):**
`find_tables()` with the default "lines" strategy returns **ZERO tables**. The fixture
has no ruling lines (whitespace-gutter layout, exactly CE p.4 style), so the lines
strategy has nothing to latch on to. The separate-vs-merged question is moot for this
fixture: both tables are invisible to the lines strategy.

`find_tables(vertical_strategy="text", horizontal_strategy="text")` — the text strategy
used by `reconstruct_table_regions` — returns **ONE merged region** spanning the entire
page (y=48..424), covering main table, chart tick labels, chart year labels, historical
table, and prose. This merged region fails `_looks_tabular` because the chart-tick rows
(5 rows at y=205-269 with only one numeric token each) dilute the data_row_frac to 0.45
(< 0.5 threshold). So `reconstruct_table_regions` correctly rejects it, and
`extract_structured` was falling back to flat `get_text("text")` output.

**Implication for TR-2:** The two-table split is NOT the issue for this fixture.
The issue is that:
1. The lines strategy finds nothing (no ruling lines).
2. The text strategy over-merges the whole page.
3. The word-geometry rowizer (TR-1) uses vertical y-gap segmentation to find the main
   table cleanly, but the chart region's y=205-335 segment merges with the historical
   table and still fails `_looks_tabular` (data_row_frac = 0.45).

For TR-2, the historical table extraction will require using `has_chart_marks` bboxes
to clip the chart sub-region from the merged segment, so the historical table can be
rowized independently.

## What changed

### `src/socr/tables/reconstruct.py`

Added two new public functions and one private helper:

- `rowize_from_words(page)` — public entry point; calls `rowize_from_word_list` on
  `page.get_text("words")`.
- `rowize_from_word_list(words)` — the core rowizer. Groups words by y-coordinate
  (rounded), derives the inter-region split threshold as 1.5 × median inter-row gap
  (from the page's own layout — no magic pixel constant), splits into y-segments, then
  calls `_rowize_segment` on each. Returns `(fitz.Rect, markdown)` pairs, same shape as
  `reconstruct_table_regions`.
- `_rowize_segment(seg_words, seg_ys, rows_by_y)` — builds a raw grid for one
  y-segment. Identifies numeric x-lanes, determines the label boundary as
  `data_start_x - LANE_SNAP_MULT × LANE_X_TOL_PT`, assigns each word to the nearest
  lane (or concatenates into the label cell), and produces a blank `""` for any lane
  with no token in a given row. The label is ALWAYS emitted as column 0 (even if empty)
  so all rows share the same column layout. Uses actual word bounding boxes (not rounded
  y-group values) for the returned rect, so the `extract_structured` overlap check
  correctly suppresses corresponding prose blocks.

Added two module-level constants (documented as structural, not magic thresholds):
- `_SPLIT_GAP_MULT = 1.5` — multiplier for the gap threshold (1.5 × median gap).
- `_SPLIT_GAP_MIN_PT = 10.0` — minimum absolute gap to avoid splitting sub-pixel jitter.
- `_LANE_SNAP_MULT = 3` — snap radius multiplier for word-to-lane assignment.

Added imports: `statistics`, `defaultdict`.

### `src/socr/core/born_digital.py`

Added `_is_lane_stacked(table)` module-level function:
- Returns True if any cell in `table.extract()` contains an embedded newline (the CE
  whitespace-gutter collapse symptom).
- Used in `extract_structured` to detect when a `find_tables()` result should be routed
  to the rowizer instead of `_table_to_markdown`.

Updated `extract_structured` method:
1. For each table from `find_tables()`: if `_is_lane_stacked(table)` → clip words to
   the table's bbox and call `rowize_from_word_list` (for the CE case where find_tables
   DOES return something but it's lane-stacked). Otherwise → `_table_to_markdown` as
   before.
2. After `reconstruct_table_regions` returns nothing (text-strategy fails): try
   `rowize_from_words(page)` as a final fallback (for the fixture case where both
   find_tables strategies fail).

## Magic threshold avoidance

All constants in the rowizer are derived from the data or are documented structural constants:
- `_SPLIT_GAP_MULT = 1.5`: multiplier on the median inter-row gap. The gap threshold adapts
  to each document's row spacing — a table with 13 pt rows gets a ~19.5 pt split threshold;
  a table with 22 pt rows gets ~33 pt. No fixed pixel value.
- `_SPLIT_GAP_MIN_PT = 10.0`: absolute floor to prevent sub-pixel y-jitter from creating
  spurious segment splits. 10 pt is below any typographically meaningful row separation.
- `_LANE_SNAP_MULT = 3`: snap radius = 3 × lane tolerance (18 pt). Documents the structural
  intent: a word within 3× the lane tolerance of a data-column center is assigned there.

The existing `_LANE_X_TOL_PT = 6.0`, `_MIN_LANES_PER_ROW = 3`, `_MIN_TABLE_ROWS = 3`,
`_MIN_DATA_ROW_FRAC = 0.5` constants are reused unchanged from the existing reconstruct.py
logic (already documented there).
