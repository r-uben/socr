# 2026-09-16 — GH-789 / GH-790: two leftovers from PR #788's desk review

## GH-789 — dark `orphan_drops` path in `reconstruct_table_regions`

Of the five `rowize_from_word_list` call sites, `reconstruct.py:386`
(`_reconstruct_table_regions_for_words`'s destroyed-token fallback, reached
when the GH-144 boundary-split check rejects a text-strategy grid) was the
only one that never received `orphan_drops`. Its output feeds
`out.extend(rowized)` — i.e. shipped table regions — so an orphan word
dropped on this path was an unmeasured table loss, undermining the residual-
loss contract GH-418 step 1 exists to guarantee everywhere else.

Fix: threaded `orphan_drops: list[dict] | None = None` through
`reconstruct_table_regions` → `_reconstruct_table_regions_for_words` → the
`rowize_from_word_list` call at the destroyed-token fallback, and wired the
new keyword at `born_digital.py`'s one call site (`extract_structured`,
~3611), extending `self._last_extraction_orphan_drops` when the fallback
reports drops — the same pattern the other four call sites already follow.

### Reachability proof

Verified every other `rowize_from_word_list` call site in the repo
(`reconstruct.py:1769`, `:1834`, `born_digital.py:3596`,
`benchmark/binding_coverage.py:285`) already passes `orphan_drops` — no
third dark path exists.

Built a fully-controlled fixture (`tests/test_gh789_790_dark_drop_paths.py`,
`_destroyed_grid_with_sparse_orphan_row`) with a fake PyMuPDF
`Table`/`TableFinder`: a 4-column (3-numeric-lane) grid whose text-strategy
extraction boundary-splits `"0.67"` into `"0"` (triggering
`_destroyed_numeric_tokens` rejection → the fallback), plus a sparse "Memo"
row populating only one of the three lanes and carrying an orphan word
(`"n.a."`) past the snap radius of every lane. The row is deliberately kept
below the GH-418-step-2 `>= 2` populated-lanes "data row" gate, or the
fallback CAPTURES the stray word into a trailing column instead of dropping
it, and the test would exercise the wrong branch.

`test_destroyed_token_fallback_reports_its_own_orphan_drop` asserts:
rejection fired, a region shipped, AND the drop event for `"n.a."` is
present. `test_no_spurious_orphan_events_on_a_clean_page` is the negative
control (no rejection path reached → no manufactured events).

## GH-790 — `_last_extraction_grid_rejections` missing from `__init__`

Same class of gap as `_last_extraction_orphan_drops` (GH-418), which was
already given a fix in `BornDigitalDetector.__init__` for the standalone-
harness case. `_last_extraction_grid_rejections` (GH-195) was reset only in
`_assess_page`, so a harness calling `extract_structured` directly (the same
shape `test_born_digital_aligned_runs.py` already exercises for other
assertions) raised `AttributeError` the first time a text-strategy grid was
rejected without any drops — the attribute only comes into existence via the
conditional `if _rejections: self._last_extraction_grid_rejections = ...`
assignment inside `extract_structured` itself.

Fix: initialise `self._last_extraction_grid_rejections: list[dict] = []` in
`__init__`, alongside the existing `_last_extraction_orphan_drops` init.

### Reachability proof

The naive "positive" test (standalone `extract_structured` call on a page
that DOES trigger a rejection) turned out to be an insufficient guard on its
own: `extract_structured`'s own `if _rejections: self.… = list(_rejections)`
assignment creates the attribute for the first time when the list is
non-empty, so that test passes even with the `__init__` fix reverted.
`test_extract_structured_standalone_no_drops_on_clean_page` (a standalone
call on a page with NO rejection) is the guard that actually needs the
`__init__` line — confirmed by mutation (below).
