# TR-4 — Token-equality value-guard (GH-56)

Date: 2026-06-17
Ticket: TR-4 (table-repair initiative, GH-56). NEEDS-DESIGN → DONE.
Depends on: TR-4a (DONE).

## What changed

Replaced the `geometry_impossible_collapse` Tier-1 hard-fail predicate in
`native_verifier.py:_verify_from_words` with a two-part **value-guard**:

### Part 1: Number-completeness (row-aware multiset equality)

Uses the existing `_pair_output_to_native_rows` overlap-based pairing to
match output data rows to native numeric rows (handles header rows in the
native that appear above the separator in the output — they have no output
counterpart and are correctly skipped). For each paired row, computes the
**N2-normalized numeric-token Counter** (both native and output side) and
hard-fails if they differ.

N2 normalization (deterministic string equality, no float parsing):
- Strip thousands-separator commas: `1,204` → `1204`
- Strip parenthesis wrappers (econ-table negative-sign): `(0.014)` → `0.014`
- Strip trailing `%`: `45%` → `45`
- Stated decimal precision preserved: `2.10` ≠ `2.1` (NO float cast)

### Part 2: Label-binding (interleaved-pattern detection)

Detects the TR-4a name/value-offset failure mode: the interleaved pattern
produces BOTH numeric rows with empty labels (values without names) AND
label-only rows (names without values). Both conditions must coexist to
hard-fail — this avoids over-firing on regression tables with SE rows (which
have empty-label numeric rows but NO label-only companion rows).

## Revision (2026-06-17): coordinator review BLOCKING 1 + BLOCKING 2

Two blocking issues were identified by the coordinator review:

### BLOCKING 1 (false-negative): row-count mismatch passes silently

Original `_value_guard` only compared PAIRED rows via overlap-based matching.
If output had FEWER numeric rows than native (dropped forecaster), the pairing
simply found fewer pairs — the unmatched native rows were silently ignored.

**Fix:** Added row-count predicate (`predicate: "row_count_mismatch"`). Count
OUTPUT numeric rows (from `_parse_all_data_rows`) vs NATIVE numeric rows
(from `_rows_by_y_from_words`). On the native side, LEADING header-like rows
(y < first data-like row y) whose N2-normalized tokens ALL appear in the output
markdown column header are excluded — these were absorbed into the output header
row, not output data rows. Examples: spec-number `(1)(2)(3)` headers,
year-label `2020 2021 2022` headers. A POSITIONAL CONSTRAINT ensures only rows
above the first data-like row are excluded (prevents year-annotation footers
like `2024` at the bottom of a page from being incorrectly excluded).

New tests: `TestTR4RowCount` class with:
- `test_dropped_forecaster_row_fails` (3 native → 2 output → row_count_mismatch)
- `test_invented_row_fails` (2 native → 3 output → row_count_mismatch)
- `test_two_native_merged_into_one_labeled_output_row_fails` (2 → 1 → row_count_mismatch)
- `test_legitimate_structural_rows_do_not_trip_row_count` (5 clean + structural rows → PASS)

### BLOCKING 2 (false-positive): label-binding over-fires on legitimate structure

Original label-binding: "if ANY unlabeled-numeric rows AND ANY label-only rows
coexist → hard-fail." On real CE correct 47-row table, structural rows triggered:
- `Comparison Forecasts` (section header = label-only)
- `2020 2021 2022 2023` (year sub-header = unlabeled-numeric)
- `Auto & Light Truck`, `Federal Budget Balance` (multi-line labels = label-only)

These are LEGITIMATE structure, NOT the TR-4a interleaved failure pattern.

**Fix:** Replaced coexistence check with ADJACENCY-DOMINANCE check:
count consecutive-row ADJACENT pairs of (unlabeled-numeric, label-only) in
either order. Fire only when `adjacent_pairs > 0 AND adjacent_pairs >= clean_labeled`.
- CE real table (47 clean + few structural rows): 1-2 adjacent pairs vs 47 clean → 1 < 47 → does NOT fire
- TR-4a dense fixture (28 alternating rows): 14 adjacent pairs vs 0 clean → 14 >= 0 → FIRES

## Revision 3 (2026-06-17): Option B — demote row-count to soft warning (codex+gemini panel)

### Decision

The panel (codex + gemini, unanimous) chose **Option B**: demote the row-count check
from a HARD-FAIL to a SOFT WARNING because row-count gaps are confounded by
non-table page numerals (chart tick labels, bar values, prose annotations on CE p.4).
Silently discarding correct tables is worse than shipping them with a WARNING flag.

### Changes

**`src/socr/tables/native_verifier.py`**

- `VerifierResult`: Added `row_count_warn: bool = False` and
  `row_count_warn_reason: str = ""` fields.
- `_value_guard`: Signature changed from `-> tuple[bool, str, list[dict]]` to
  `-> tuple[bool, str, list[dict], dict | None]`. When row-count mismatch is
  detected, the function now:
  - Populates `row_count_warn_info` dict (predicate, counts, detail)
  - Does NOT return early with `hard_fail=True`
  - Continues to label-binding and multiset checks
  - Returns `row_count_warn_info` as the 4th element
- `_verify_from_words`: Unpacks 4-tuple; sets `result.row_count_warn = True` and
  `result.row_count_warn_reason` when `vg_row_count_warn is not None`.

**`src/socr/pipeline/agentic.py`**

- `NativeTableVerifierJudge.assess`: Before hard-fail / warn blocks, if
  `vr.row_count_warn`, emits `value_guard_row_count_warning` audit event.
  Table still delegates to inner judge (ships). The audit event carries
  `native_lane_count`, `output_col_count`, and the warn reason.

### Tests updated

`TestTR4RowCount` class: all three row-count tests changed from asserting
`hard_fail=True` to asserting `hard_fail=False, row_count_warn=True`:
- `test_dropped_forecaster_row_warns_not_hard_fails` (was `test_dropped_forecaster_row_fails`)
- `test_invented_row_warns_not_hard_fails` (was `test_invented_row_fails`)
- `test_two_native_merged_into_one_labeled_output_row_warns` (was `...fails`)

New test: `test_row_count_gap_emits_audit_event_and_ships` — verifies that when
row-count gap fires, `value_guard_row_count_warning` audit event is emitted and
`NativeTableVerifierJudge` returns `accept=True`.

`TestFalseFailGuard`: `test_footnote_row_with_distinct_tokens_warns_not_hard_fails`
(was `test_footnote_row_with_distinct_tokens_trips_row_count`) — now expects
`hard_fail=False, row_count_warn=True`.

`TestTR4ValueGuard`: `test_merged_rows_fails` and
`test_full_collapse_via_interleaved_pattern_fails` — updated assertions:
`hard_fail=True` via `label_binding` (not `row_count_mismatch`), and
`row_count_warn=True` for both (row gap also detected as soft warning).

### CE p.4 status (Option B)

Page 4 of 202401.pdf has 63 native rows. The previous `row_count_mismatch: output
