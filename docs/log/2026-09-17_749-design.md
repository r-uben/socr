# GH-749 design — the fail-closed floor discards a page that has no table

Read-only design note. No source changed. Measured against `main@e271346` in a throwaway
worktree; every number below was produced by running the repo's own predicates on the
reproducer, not inferred.

Reproducer: Federal Reserve MPR March 2011, PDF page 32 (public). Kept in `/tmp`, never
committed; no corpus text is quoted here.

---

## 1. What exists today, and what is actually true

### 1.1 The measured page

Running `BornDigitalDetector` on the single extracted page:

| signal | value |
| --- | --- |
| `is_born_digital` | `True` |
| `native_text` | 2,797 chars (2,807 bytes) |
| `has_tables` | **`True`** |
| `has_figures` | `False` |
| `detected_table_count` | **1** |
| `detected_table_bboxes` | 1 box, ~(77, 133)–(282, 235) |
| `native_table_region_count` | **0** |
| `has_chart_marks` | **`False`** (1,935 vector drawings on the page) |

The one "detected table" is `page.find_tables()` latching onto a line chart's plot frame.
Its extraction is a **single row of two cells**, the first holding three maturity legend
labels, the second empty. Zero numerals. That object is the entire reason the page dies.

`native_rows_from_page` parses 7 rows — chart axis tick years, a NOTE line, an index-base
line — and `rows_establish_grid` returns **`False`**. That is the pipeline saying, with its
own predicate, *there is no grid in this page's native geometry*.

### 1.2 Where the prose stops being shipped — the exact site

```
_winning_page_output                      manifest.py:3378  →  if _reaches_structure_class_branch(p)
  _reaches_structure_class_branch         manifest.py:914   →  True (see 1.3)
  structure_class_grid_winner             manifest.py:1687  →  None  (no attempt authored a grid)
  floor_text = structure_class_floor_text manifest.py:3546  ←  THE SITE
    structure_class_floor_text            manifest.py:2109
      table_floor_text_for_source         manifest.py:2253
        native_table_region_count (0) != detected_table_count (1)
        →  manifest.py:2346  `return whole_page`          ←  THE LINE
```

`manifest.py:2346` returns the bare marker. Reproduced deterministically, no model, no
network — a `PageState` carrying the six measured fields above yields:

```
floor text: 102 bytes   ("[page N failed: unverifiable table — see image]" + PNG ref)
native text: 2,807 bytes
```

Exactly the 102 bytes the issue reports. The page's prose never reaches assemble: the
`PageOutput` returned at `manifest.py:3547` carries the marker as its `text`.

The document-level consequence is downstream and coherent: `_canonical_body`
(`orchestrator.py:12318`) calls `is_page_failed_marker` on each page text and sets
`has_content = False` when every page is a marker, so `has_text` is `False`,
`output_path` is written as `""` (`orchestrator.py:14335`) and the document status is
`ERROR`/`FAILED` (`orchestrator.py:13129`). Nothing here is a second bug; it is the
faithful propagation of one deleted page.

### 1.3 Why the entry gate opens

`_reaches_structure_class_branch` requires `p.is_structure_class()`, which is
`bool(self.has_tables)` and nothing else (`state.py:380–402`). `has_tables` is the
**lane-cooccupancy heuristic**. The repo already records that this heuristic false-fires on
prose, in its own words at `orchestrator.py:2181`:

> `has_tables` is the lane-cooccupancy heuristic, which the census measured false-firing on
> prose (every page of a transcript flagged 3/3, 400 events across 68 Fed documents)

and at `orchestrator.py:5490`:

> `PageState.has_tables` does NOT discriminate here — it is True on those pages too

So the floor's entry gate is keyed on the one table signal the codebase has already
measured to be unreliable, while a narrower structural signal (`detected_table_count`,
`_page_has_scorable_table_evidence`, `rows_establish_grid`) exists and is trusted
elsewhere for exactly that reason.

### 1.4 Why the splice cannot rescue this page

GH-520's splice needs four agreements. Two hold here (`detected_count == 1 > 0`,
`len(bboxes) == count`). Two cannot:

* `native_table_region_count (0) != detected_table_count (1)` — reconstruction produced no
  region, because there is no table to reconstruct;
* `len(find_table_blocks(native_text)) == 0 != 1` — **the page's native text contains no
  markdown table block at all.**

The splice architecture assumes the page's text *contains* the table it is stamping over.
When the detected "table" is a chart frame, there is nothing in the text to stamp, and the
guard's only remaining move is to delete everything.

### 1.5 Does the floor consult `table_not_scorable`? No.

`structure_class_floor_applies` (`manifest.py:2081`) reads exactly two things:
`_reaches_structure_class_branch(p)` and `structure_class_grid_winner(p) is None`. It never
looks at the classification. The `table_not_scorable` event is emitted far upstream, at
`orchestrator.py:5538`, by `_score_per_page`, and flows only to `tables_trust` /
document-level distrust.

`manifest.py:1738` excludes `table_not_scorable` from `CREDENTIAL_BLOCKING_EVENT_KINDS`
with the reasoning "it says socr could not SCORE the page, not that anything contradicts
it. Inability to measure is not a positive rejection." That reasoning is correct there and
**cuts both ways**: it is equally not a positive assertion that a table exists. So the event
kind itself is the wrong thing for the floor to read.

The *structural fact underneath* the event is the right thing: `rows_establish_grid` over
the page's own native rows. That is a positive statement about geometry, and on a
**born-digital** page (where every word carries an x-coordinate) it is a meaningful one.

### 1.6 Blast radius on this document

Across all 61 pages of the source document:

* 25 pages have `has_tables == True`;
* **6** of those establish a native grid (page 37, the Fed balance-sheet table, is one);
* **19** are in page 32's state: table-judged by `has_tables`, no native grid.

Spot-checking four of the 19 (pages 19, 25, 32, 41): all are chart pages whose parsed
"rows" are axis tick labels and caption fragments. None of the 19 has two rows sharing a
value-column width. Caveat, stated plainly: "floor-exposed" here means *satisfies the
structure-class precondition while carrying no native grid*. Whether each of the 19 would
actually reach the floor depends on the ladder refusing every rung, which I did not run
(that needs the full provider path, ~10 min/page).

### 1.7 A secondary finding, not this ticket

`has_chart_marks` returns `False` on a page with four line charts and 1,935 vector
drawings, so the PP-7 chart-asset lane never intercepts this page either. Worth its own
issue; it does not change the fix below.

## 2. Options

None of the three puts a model anywhere in the routing or verify path. All gates below are
deterministic geometry over the page's own native words.

### Option A — reuse the #649 band-level recovery at the S1 floor

`native_prose_floor_text` (`manifest.py:2556`) already does exactly "ship the prose,
withhold the numeric bands, mark each elision". It is wired only to the *scanned*
`UNVERIFIABLE_TABLE_SCANNED` branch (`manifest.py:3151`), not to the born-digital S1 floor.

**Measured on this page** (fed the real `native_words`):

| | |
| --- | --- |
| output | **2,136 bytes** (vs 102 today, vs 2,748 for `--no-table-judge-ladder`) |
| bands | 71 total, 26 prose, **45 withheld** |
| markers | 9 repeated marker+PNG blocks interleaved through the text |
| readability | **two columns interleaved line-by-line** |

The chart axis labels make most bands "numeric", so the majority of the page is still
withheld, and because the banding is y-only it splices left-column and right-column
sentences together — **this is #700, inherited verbatim.** Chart caption/unit/SOURCE lines
survive; the running prose is shredded into alternating-column fragments.

* Re-admits an unverified grid? **No** — every band carrying numerals is withheld.
* Changes existing tests? The #649/#700 suites are untouched; the GH-317 suite would
  change (see below).
* Cost: delivers a page a human cannot read, and makes #700 a blocker for #749.

### Option B — don't enter the structure-class branch when the page carries no native grid

Gate `_reaches_structure_class_branch` (`manifest.py:914`) on a persisted
"native rows establish a grid" verdict, so a chart page never becomes structure-class.

* Ships the full native text (2,807 B), correctly column-ordered.
* Re-admits an unverified grid? **Potentially yes**, and this is the real objection: the
  gate changes *routing and selection*, not just the floor. A page whose table is real but
  whose native geometry is broken enough that `rows_establish_grid` fails would now bypass
  S1 entirely and could ship as a clean native `SUCCESS` — silently. That is the cardinal
  rule re-opened.
* Also flips ~19/61 pages of this one document out of structure-class. Large, hard to bound.
* Changes existing tests: yes — anything pinning the branch entry.

### Option C — keep the floor's verdict; stop it deleting a body that contains no grid

Leave `structure_class_floor_applies`, the page status, the failure mode, the buckets and
the CLI wording **exactly as they are**. Change only `table_floor_text_for_source`: when
the splice guard fails, release the source text unspliced **iff both** hold —

1. `len(find_table_blocks(source_text)) == 0` — the bytes about to ship contain no
   markdown table syntax, so there is literally no grid in them to be trusted; and
2. a **persisted** verdict that the page's own native rows establish no grid
   (`rows_establish_grid` over `native_rows_from_page`), recorded at extraction time while
   `native_words` still exists, restored on resume, **failing closed when absent** —
   the same contract `table_bbox_sane` operates under after #652 P2a
   (`manifest.py:2263`, `state.py:200–202`).

Everything else is unchanged: `PageStatus.ERROR`, `audit_passed=False`,
`STRUCTURE_CLASS_LADDER_EXHAUSTED`, `structure_class_floor_pages` still flips `pages_ok`
(`orchestrator.py:13012`). The only downstream change is that `has_text` becomes `True`, so
the document lands on `AUDIT_FAILED` rather than `ERROR` — which is the shape
`orchestrator.py:13114` already documents as intended for a partial withhold:

> a regional withhold that kept its prose still has text (AUDIT_FAILED), while a page
> withheld whole ships only the marker

* Re-admits an unverified grid? **No.** Condition 1 is a direct check on the shipped bytes;
  condition 2 is a direct check on the page's geometry. Where either is unprovable, the
  floor behaves exactly as today.
* Changes existing tests? **Measured: no.** Every floor fixture's `native_text` contains at
  least one markdown table block — `NATIVE_TEXT_WITH_PROSE` 1, `MIXED_VALIDITY_NATIVE_TEXT`
  1, `TWO_PARSEABLE_TABLES` 2 — so condition 1 alone already holds the floor closed on all
  of `test_gh317_structure_class_floor.py` and `test_gh520_regional_floor_splice.py`,
  including `test_no_grid_page_ships_no_native_byte_at_all` and
  `test_no_detected_table_is_no_evidence`. Those tests keep their present meaning without
  being rewritten.
* Residual risk, stated honestly: a **flattened** table — real rows printed as columnar
  runs with no pipes — has zero table blocks too. Condition 2 is what excludes it, and its
  strength rests on the claim that on a born-digital page a real table's x-coordinates make
  `rows_establish_grid` true. Measured support: on this document the predicate separates the
  balance-sheet table page from the chart pages cleanly. That is one document. It is the
  weakest link in the option and the panel should be told so.

## 3. Recommendation

**Option C.**

The floor is right about what it distrusts and wrong about what it deletes. C is the
minimum change that fixes the deletion without touching the distrust: same status, same
failure mode, same document-level demotion, same behaviour on every existing fixture —
only the body survives. It is the same move #649 already made for scanned pages, executed
with the gate appropriate to born-digital geometry instead of y-banding.

A is measurably worse than doing nothing well: 2,136 bytes of column-interleaved fragments
is not a readable page, and it makes #700 a prerequisite. B is the only option that reopens
the cardinal rule, and it does so on the routing path where it is hardest to bound.

Cost of C: one new persisted `PageState` field plus its sidecar round-trip and resume
contract (the #652 P2a pattern, which is where this kind of change has previously gone
wrong), and a documented residual on flattened tables.

## 4. The sibling question — #697, #700, #749

**They do not unify. #700 and #749 share a principle; #697 is a different shape.**

* **#697 is surfacing, not loss.** The recovered prose *ships*; what fails to ship is its
  provenance note at the document-metadata and CLI levels. Its own issue text places it in
  the `#658`/`#659`/`#625` lineage — "a signal that reached one level and no other". No
  content is withheld. Nothing in #749's fix touches it, and nothing in #697's fix would
  have saved page 32's prose.

* **#700 and #749 share one principle: withhold at the granularity of the evidence, not at
  the granularity of the container.** #700 withholds a full-page-width y-band because its
  right half carries a table row; #749 withholds a whole page because one chart frame was
  called a table. Both discard content the distrust never had a claim on.

  But they are not one fix and not one code path. #700 is in the band partition
  (`partition_prose_bands` / `row_corroboration`) on the scanned recovery path; #749 is in
  the born-digital selection floor (`table_floor_text_for_source`). **Evidence they are
  distinct:** under Option C the page-32 defect is fixed while #700's banding code is never
  executed at all (C ships `native_text`, which PyMuPDF already orders by column). Under
  Option A the two collide — the measurement in §2 shows #749's page inheriting #700's
  column interleaving directly. So the choice of #749's fix determines whether they touch;
  they do not share a fix by nature.

* Practical consequence: fixing #700 is **not** a prerequisite for #749 under Option C, and
  **is** a prerequisite under Option A.

## 5. The decision question for the panel

> socr's fail-closed structure-class floor currently discards an entire born-digital page —
> 2,777 characters of prose reduced to a 102-byte "unverifiable table" marker — because
> PyMuPDF's `find_tables()` classified a line chart's plot frame as a table, even though the
> page's own native-row parser reports that no grid exists on the page (`rows_establish_grid
> == False`, `native_table_region_count == 0`, zero markdown table blocks in the text).
> The floor exists so an unverified native grid is never shipped as trusted, and it must
> keep that guarantee. **Should the floor be allowed to ship the page's unspliced native
> text — while keeping the page at ERROR / `audit_passed=False` / ladder-exhausted and the
> document at AUDIT_FAILED — when, and only when, the text about to ship contains zero
> markdown table blocks AND a persisted extraction-time verdict says the page's native rows
> establish no grid (failing closed whenever either check is unavailable)?**
>
> The three candidate designs, in full:
>
> **(A)** Reuse the existing #649 band-level recovery (`native_prose_floor_text`) at this
> floor: ship prose bands, withhold every band carrying numerals, mark each elision in
> place. Measured on the reproducer: 2,136 bytes, 45 of 71 bands withheld, nine repeated
> markers, and the page's two columns interleaved line-by-line because the banding is
> y-only (this is the known limitation tracked as issue #700). Re-admits no grid.
>
> **(B)** Prevent the page from entering the structure-class branch at all when it carries
> no native grid, by gating the branch's entry predicate. Ships the full native text
> correctly ordered, but changes routing and selection rather than only the floor: a page
> whose table is real yet whose native geometry is too broken for the grid predicate would
> bypass the floor entirely and could ship as a clean SUCCESS.
>
> **(C)** Leave the floor's verdict, status, failure mode and document-level demotion
> untouched, and change only the body it emits: release the source text unspliced when the
> two conditions above hold. Measured: every existing fixture for this floor has at least
> one markdown table block in its native text, so all current tests keep their meaning
> unchanged. Residual risk: a *flattened* table — real rows printed as columnar runs with no
> pipe characters — also has zero markdown table blocks, so the whole guarantee rests on the
> grid predicate correctly detecting it from the page's x-coordinates. That claim is
> supported by one document (the predicate separates that document's real balance-sheet
> table page from its chart pages), not by a corpus-wide measurement.

Secondary question, only if the panel picks (C):

> Should the "no native grid" verdict be a new persisted `PageState` field recorded at
> extraction time (mirroring `table_bbox_sane` after #652 P2a, so a resumed run replays the
> decision rather than retaking it with the words gone), or should the floor instead read
> the upstream `table_not_scorable` audit event that already records the same fact?

## 6. Acceptance-criteria readiness

GH-749 carries no `### Acceptance Criteria` section — the issue is a measurement plus a
reproducer. Once an option is chosen, the criteria that need writing are:

1. **The difference, not the value** (CLAUDE.md's CI trap): run the same page state twice in
   one process with the new gate enabled and disabled, and assert the bodies differ exactly
   as intended. Do not pin an absolute `(status, audit_passed, failure_mode, doc_status)`
   tuple — the reproducer's own tuple is provider-dependent and will differ in CI.
2. **The credential is unchanged**: page stays `ERROR` / `audit_passed=False` /
   `STRUCTURE_CLASS_LADDER_EXHAUSTED`, `structure_class_floor_pages` still contains the
   page, the CLI still names it. Only the body changes.
3. **The guard is load-bearing**: a fixture whose native text *does* contain a table block
   must still floor to the bare marker; a fixture whose persisted grid verdict is absent
   must still floor. Both must be shown to FAIL if the gate is deleted (mutant copy).
4. **Resume determinism**: a page floored under the new gate, flushed and resumed, must
   reach the identical body — the verdict is replayed from the sidecar, not recomputed from
   `native_words` that no longer exist.
5. **Hermeticity**: any test driving `_phase_agentic` must patch
   `_available_engines_for_agentic`; the floor tests here run `_winning_page_output`
   directly and need no provider.

Criterion 3 is the one most likely to be written tautologically and should be called out in
the ticket explicitly.

## Orchestrator verification + panel amendments (2026-09-17)

### Reproduced independently, hermetically

`table_floor_text_for_source(PageState(detected_table_count=1, detected_table_bboxes=[...],
native_table_region_count=0), 1, <3000 chars of prose>)` returns **47 bytes** —
`[page 1 failed: unverifiable table — see image]`. No model, no PDF. The note's mechanism holds.

### CORRECTION to this note, from the panel and verified

The note says option C's guarantee rests on "the grid predicate correctly detecting [a flattened
table] from the page's x-coordinates." **That overstates the predicate.** `rows_establish_grid`
(`core/table_grid.py:120`) consumes ALREADY-PARSED rows and tests shape only:

    modal_width, rows_at_modal = widths.most_common(1)[0]
    return modal_width >= 2 and rows_at_modal >= 2

Coordinate interpretation happens upstream. Measured, the residual class is precise:

    2x2 grid        -> True
    one-row table   -> False      <- released under plain C
    key/value pairs -> False      <- released under plain C

So plain C releases genuine one-row and key/value tables that carry no pipe characters. That is
exactly the class the floor exists to catch.

### Amendment: C+, not plain C (GPT seat, accepted pending the other two)

1. **Inline warning in the body.** Preservation is permissible only because the page stays failed at
   every machine-readable surface AND the emitted text itself labels the content unverified, so a
   Markdown-only consumer sees it too. If the body is raw text with no inline warning, C is rejected.
2. **Tri-state persisted verdict** (`true` / `false` / unavailable). A boolean defaulting to `False`
   conflates "measured: no grid" with "no evidence available"; the second must fail closed.
3. **"Every existing fixture has a markdown block" proves COMPATIBILITY, not SAFETY** — the dangerous
   class is absent from those fixtures. This note offered it as evidence of safety; it is not.
4. Option **B is disqualified outright**: a real table with broken geometry would bypass the floor and
   ship as clean SUCCESS — silent acceptance of unverified structured content.
5. Do FIRST: try to FALSIFY the proposed gate against adversarial real flattened tables (one-row,
   key/value, irregular widths, merged headers, damaged geometry) before implementing it.

### Second seat (kimi) — converges on C + banner, adds the consumer question

Independently reached C-plus-inline-banner. New points, with my verification where I could get it:

1. **Do a corpus CENSUS first, not code.** C's residual rests on ONE document. Run the
   already-persisted extraction-time fields over the whole corpus, classify every page in the
   failing state (has_tables, grid==False, zero markdown blocks) as prose/chart vs flattened table.
   Cheap, and it decides whether C ships as-is, gains a third condition, or dies.
2. **Census the PARSER, not the boolean.** The failure mode to measure is bands not splitting a
   flattened table into multi-value rows — `rows_establish_grid` only counts values per parsed row.
   Instrument the parser's row shapes.
3. **The precise reading of the cardinal rule:** it is "never ship unverified content AS TRUSTED",
   not "never emit unverified bytes". A flattened table the predicate misses would ship its numbers
   in native reading order under a loud failure — strictly better than today, where the prose is
   destroyed AND the table is still lost, and it is not silent.
4. **B repeats the original error one level up** — it gates entry on a heuristic of the same kind
   that false-fired 400 times.
5. **The artifact-level hole** (converges with seat 1): page/doc/metadata/CLI surface the failure,
   but the stitched final `.md` — the thing a human reads — would get prose indistinguishable from
   trusted text. The banner is a requirement, not an option.

### VERIFIED BY ME: the banner is load-bearing for a downstream consumer, not just for humans

`benchmark/replay_binding.py:257`:

    def _is_fail_closed_marker(text: str, page_num: int) -> bool:
        return f"[page {page_num} failed: unverifiable table" in text

It detects a failed page by SUBSTRING. Under C+ a body carrying the banner plus prose STILL matches,
so this consumer keeps working — **provided the banner preserves that exact string**. Reword the
banner and this silently starts treating a failed page as a real reading.

**Requirement:** the inline banner must contain the existing marker substring verbatim, and a test
must pin `_is_fail_closed_marker` True on a released-prose body. Enumerate the other body consumers
the same way — today a failed page's body is a 102-byte marker; after C it contains real numerals.

### VERIFIED BY ME: the tri-state requirement is necessary, against the repo's real pattern

Both seats warned that a naive `bool = False` would be lethal here. Confirmed in `core/state.py`:

    native_table_region_count: int = 0                                    # :178
    ps.native_table_region_count = getattr(pa, "native_table_region_count", 0)   # :688

The default cannot distinguish **measured zero** from **field absent**. A grid verdict persisted the
same way would read every pre-existing sidecar as "no grid" and release text on resume — silently,
on exactly the pages that predate the fix. The verdict must be tri-state and absence must fail closed.

### Quorum so far (2 of 3 seats, independent)

Both rule **C**, both reject A and B, both require the inline banner, both require tri-state.
Neither saw the other's answer. Third seat outstanding; no implementation and no census until it lands.

**Sequencing, if the third seat concurs:** census FIRST (instrumenting the parser's row shapes, not
the boolean), then implement only if the census shows the predicate catches the flattened tables the
corpus actually contains. If it does not, C gains a third condition or dies.

### Third seat (grok) FALSIFIED a measured claim in this note — verified by me

The note argued option C is safe for existing tests because "every existing fixture for this floor
has at least one markdown table block in its native text, so all current tests keep their meaning."

**That is false, and I measured it:**

    GH-317 NATIVE_TEXT_WITH_PROSE          -> 1 block
    the unparseable fixture                -> 0 blocks

`tests/test_gh317_structure_class_floor.py:338`,
`test_no_grid_page_with_unparseable_native_text_falls_back_to_whole_page_marker`, uses

    "revenue costs were up\nno pipe characters or GFM separators here\n"

and its docstring states its whole purpose: *"never ship the raw unparseable text as if it were
safe prose."* Zero markdown blocks. **Condition 1 alone would release exactly the text an existing
test exists to withhold.**

The note measured the named GFM fixtures and generalised to "every fixture". The seat that
disagreed went and measured the one that mattered.

**Consequence: condition 2 is not a refinement, it is load-bearing.** The absent/False verdict
fail-closed is what keeps that test passing. Anyone implementing C who treats condition 2 as
optional polish will silently invert a deliberate guard.

### Two more from this seat, source-traced (NOT re-executed by me — treat as unverified)

- `rows_establish_grid` returning False does NOT mean "no table": `native_rows_from_page` is scoped
  to `locate_tables` boxes, so **no boxes -> [] -> False** for "no region found" as well as "no
  grid". A 2-column table can also miss `has_numeric_columns` (`_MIN_LANES_PER_ROW = 3`).
- B's fallthrough after the S1 branch is `NATIVE_CLEAN` / `SUCCESS` — which is why B is
  disqualified on the SUCCESS path alone, independent of blast radius.

### RULING: C, unanimous 3/3. Sequencing is now fixed.

All three seats: **C**; A rejected (measured unreadable, inherits #700); **B disqualified outright**
(real table + broken geometry -> clean SUCCESS = unverified content as trusted).

Required, with the agreement of every seat:
1. **Both conditions, condition 2 load-bearing** — zero markdown blocks AND a persisted tri-state
   verdict that is exactly False; absent/unavailable/malformed -> today's marker.
2. **Inline banner in the released body**, preserving the existing marker substring verbatim —
   `benchmark/replay_binding.py:257` detects a failed page by that substring, so this is functional,
   not cosmetic.
3. **Persist like `table_bbox_sane` (#652 P2a)**, at extraction while `native_words` exist. Do NOT
   read `table_not_scorable` — it is an assemble-time event with no resume contract.
4. **Census FIRST**, instrumenting the parser's row shapes rather than the boolean. If flattened
   tables escape at any real rate, C gains a third condition or dies.
5. Mutation-prove each condition separately; pin a DIFFERENCE not a tuple; fixtures for
   absent-verdict, grid-True, and any-markdown-block all -> marker.
