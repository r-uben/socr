# #1124 / #1125: promotion gate for marked scanned tables

## What + why

#1123 lifted the scanned-table floor on any later `decision.accepted`. A later
rung that accepts prose (no table) un-floored the page to SUCCESS and the
disputed table disappeared unmarked — the outcome the owner ruling forbids.

`settle_scanned_table_decision` now un-accepts a winner that does not carry a
table the source-evidence check passed, **only when some attempt already
carries a marked table** (ordinary prose accepts are left alone), then walks
marked candidates last to first. A candidate ships only when the inner page-judge chain accepts it
(heuristic / VLM, not a re-entry of `SourceEvidenceTableJudge` and not native
geometry on a scan). None accepts → the old fail-closed floor.

Chosen over "just keep the floor on a prose winner": a disputed / uncheckable
table must ship with a visible mark and the page image. Silent SUCCESS table
loss is worse than a marked table.

## Round 2 (Astra: do not merge)

Four findings, all reproduced through `process()` (deadline at the promotion helper + real `_TimeoutJudge`, because a short deadline on the whole judge also aborts the source-evidence check).

1. **P0 maths-only winner — fixed.** `accepted_winner_has_passed_table` used `find_table_blocks`, which counts the maths pipes `#1098` excludes. Both the "has a table" predicate and the count now use `evidence_readable_table_count` (the same blocks `collect_table_tokens` / `verify_scanned_table` read). Difference: later maths vs later verified table. Mutant: `find_table_blocks` instead → maths test fails (equations ship SUCCESS, table gone).

2. **P0 dropped table — fixed.** Rule: promote when the winner has fewer evidence-readable tables than any marked attempt, or either side cannot be counted (unparsed HTML). No overlap threshold. A later HTML retry of one verified grid (same count) may lift the floor; A+B then B may not. When in doubt, promote. Difference: first rung A+B vs B-only, later text B either way. Mutant: `winner_accounts_for_marked_tables` always True → drop-A test fails.

3. **P1 deadline — fixed.** `_promotion_inner_judge` peels only `SourceEvidenceTableJudge` and rebuilds every `_TimeoutJudge` around the peeled inner (the orchestrator adds its own timeout wrapper outside `_build_page_judge`). Native + circuit breaker stay. Difference: same slow inner under the peeled deadline vs no deadline. Mutant: return the peeled inner without rebuilding timeouts → test fails.

4. **P1 journal — fixed.** Source-evidence reject sets `AcceptDecision.judge_outcome = JUDGE_OUTCOME_SOURCE_EVIDENCE` (`source_evidence_table`), a missing verdict so `route_page` does not stamp `page_judge_completed`. Difference: one disputed rung vs two; only the promoted attempt (inner ran) is `page_judge_completed`. Mutant: leave `judge_outcome=""` → both rungs stamp completed.

Measurement after r2: **72 / 96 / 5 / 8**, 72/72 verified have a table block (unchanged). `verify_scanned_table` behaviour was not edited.

## Round 4 (Astra r3: one P2; fixed by the orchestrator)

Astra r3 confirmed the round-1 and round-2 scenarios fixed through `process()` (92 targeted tests, six mutants caught) and found one more P2: a fence opener inside an HTML comment (`<!--` / ```` ``` ```` / `-->`) put the following disputed table "inside a fence", so it shipped with no mark. Every fence parser tried here misread model output somewhere (a shorter inner fence in r2, a fence in a comment in r3; an unclosed fence would hide every later table).

Decision: `_table_start_lines` no longer skips fenced code at all; `fenced_line_mask` is removed. A table inside a code block now gets a mark too. That is harmless; a hidden dispute is not. The #1125 soft about marks inside fenced code is therefore declined, not fixed.

Tests: `test_table_start_lines_counts_tables_inside_a_fence_too` (replaces the skip pin) and `test_a_stray_fence_before_the_table_does_not_hide_its_mark` (difference: with vs without a comment-wrapped fence, and an unclosed fence). Mutant: restore a fence toggle in `_table_start_lines` → 3 tests fail (`exec/1124/mutant-r4/`, `socr.__file__` asserted inside the copy).
