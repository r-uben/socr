# #1267: rows shipped under the wrong label (row-binding check)

## Defect
Rotated born-digital Greenbook tables read by qwen shipped SUCCESS with each labelled row carrying the values
printed one row above (the group header empty, the group's last row unlabelled). Values were correct; the
label-value binding was wrong. Fed run (socr aebc444c): 16 of the 171 SUCCESS table pages had a binding
defect (10 whole-group shifts, 6 local), 179 image-confirmed defect rows.

## Why nothing caught it
- The per-cell native binder (`tables/binding.py` via `native_cell_check`) received raw, unrotated words
  (`orchestrator.py` `page.get_text("words")`), so on a rotated page no row bound (0 of 59 rotated pages), and
  it is advisory by default (`native_cell_gating=False`).
- Every other check compares values without labels: row corroboration (value tuples), #1185 agreement (a page
  multiset), header attribution (column headers), the page judge ("faithful").
- qwen makes the error (it empties parent rows and shifts values down a label); rotation is why no check saw it.

## Fix
A focused check, `tables/row_binding_check.py`, separate from `bind()`: words in the reading frame
(`upright_words_for_page`), shipped data rows assigned to text-layer lines by value sequence with a one-to-one,
order-preserving assignment; per row BOUND / DISPLACED / LABEL_LOST / EMPTIED / UNVERIFIABLE (convictions only
on positive geometry). It runs once in the agentic flush on the finalized record, after every step that can
change a table (reread, crop patch, escalation, ladder, withhold gates).
Owner ruling 2026-11-05: CONTRADICTED -> the table is WITHHELD (failure marker + page picture, page ERROR,
`table_ladder_withheld` reason `row_binding_contradiction`, model table kept unshipped in the sidecar);
UNVERIFIABLE -> page WARNING with a "row binding not verified" mark on the unverifiable tables only (a
table the check bound carries no mark when nothing else made the page unverified). Both kinds are distrust
kinds that a later ladder acceptance cannot clear (the ladder reads values, not labels).

- Merge gate round 4 (both reviewers; top-orchestrator decision under the overnight policy): the
  burden of proof is inverted. BOUND (no mark) needs exact positive evidence: the shipped label equals
  the words printed before the row's values on the SAME text-layer line, under NFC + casefold +
  collapsed whitespace + markup removed (`**`, `*`, backticks, `<br>`, HTML entities), one trailing
  period/colon dropped, and a trailing footnote mark dropped only from the side that has one when the
  other has none. Every letter, digit and symbol is kept (`Rate (%)` != `Rate ($)`, `2003` !=

  wrapped-label pooling and header-year skips can now only convict (unchanged) or leave a row
  UNVERIFIABLE. Valueless group rows bind only on an exact valueless line; header-position rows with
  numbers-only cells are always judged and bind only exactly.

  Found on the way: a wrapped label shipped on an empty row above an UNLABELLED value row was convicted

## Proof
Unit tests at rotation 0/90/270 (shift, duplicates, all-zero rows, wrapped/split labels, valueless headers,
categorical rows, numeric labels, footer on a data baseline); pipeline A/B tests that run `process()` twice
changing only whether the check runs (clean -> identical bytes; shifted -> withheld; unverifiable -> marked;
resume/re-finalize byte-identical; ladder replacement and crop patch). Mutation: 17 of 18 mutants killed after
two gaps were closed; the survivor is equivalent. Merge-gate guards: round 1 8/8 and round 2 9/9 mutants
killed, each by its own new test; the round-1 head fails 32 of the round-2 tests. Suite: 1 failed + 8 teardown errors,
all also failing on origin/main 4e170962.
Merge-gate P2s (Fable), closed: a row-binding withhold counts as layer-caused at resume (re-read, not replayed,
when the layer turns suspect); stale row-binding state is cleared before the check's early returns; when the
row-binding check alone made the page unverified, a table it BOUND carries no table mark
(`row_binding_mark_only`, persisted); the check-error test is a two-arm difference.
Tests whose scope was narrowed (the row check patched out, each with a comment, because they pin other
behaviour on fixtures whose text layer does not print the model's values, or whose table is genuinely shifted):
`test_gh993_readable_tables.py`, `test_gh851_escalation_latch_evidence.py`, `test_chart_lane.py` (gh318),
`test_gh259_flagged_model_table_wins.py`, `test_ladder_e2e.py`, `test_gh974_review_pins.py`,
`test_resf_native_cell_pipeline.py`.
