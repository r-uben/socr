# TICKET-C1 — surface unexplained lanes as content loss (socr #123)

Branch `feat/123-metric-blind-spots`, on top of B5's `18b3b64`-descendant HEAD.

## What changed

**Two content-loss facts that used to reach no surface now both go through the
same `tables_trust`/`TABLE_DISTRUST_KINDS` machinery — a second input to one
mechanism, not a second mechanism, per the ticket and the B1 review finding it
folds in.**

1. **Unexplained lanes** (`src/socr/benchmark/table_exactness.py`). Added
   `ExactnessReport.unexplained_lanes`: the mirror image of the existing
   diagnostics-only `unmapped_nonempty_columns` — ground-truth lanes that carry a
   value in a matched row but that the best lane→column map never gave a column.
   Computed once, additively, right next to `unmapped_nonempty_columns`; does not
   touch `cells`/`exact`/`pct` (pinned by the corpus gate, see below).

2. **Not-scorable pages** (`src/socr/pipeline/orchestrator.py`,
   `_table_page_needs_escalation`). This is `score_page`'s other production
   consumer and, per the B1 review, the one place every table-page candidate for
   escalation is scored against its own native layer regardless of whether
   escalation ends up firing. Changed its signature to accept `state, page_num`
   and emit a literal `kind="table_not_scorable"` `AuditEvent` whenever
   `rows_establish_grid` fails (B1's grid gate) or `report.ceiling_note` is set
   (the second, no-label-matched ceiling in `score_rows`) — both existing
   not-scorable contracts route through the one new kind, no third contract
   introduced. A `kind="table_unexplained_lanes"` event fires when the incumbent
   text has `unexplained_lanes > 0` and the page IS scorable (the two are
   mutually exclusive — a not-scorable page doesn't get a lane opinion).

   Both new kinds resolve automatically via the existing
   `RESOLVING_KINDS = {"table_escalation_accepted"}` machinery: they're emitted
   for the incumbent text before the accept/reject decision, so a page that goes
   on to be escalated-and-accepted has its stale flag cleared the same way
   `dualpass_flagged` already does — no new resolution logic needed.

3. **`escalation_decision.decide_escalation`** — the accept rule is now
   lexicographic, not a bare `exact` compare:

   ```
   fewer unexplained lanes  -> accept
   more unexplained lanes   -> reject, regardless of exactness
   equal unexplained lanes  -> exactness is the tiebreak (the old rule)
   ```

   This closes the exact exploit the B2 design note warned about and TICKET-C1
   names explicitly: a wider candidate can raise `exact` while dropping a whole
   ground-truth lane the narrower incumbent covered. `EscalationDecision` gained
   `incumbent_unexplained_lanes` / `candidate_unexplained_lanes` /
   `incumbent_ceiling_note` / `candidate_ceiling_note` fields so a caller can
   surface this without re-scoring.

4. **`tables_trust.TABLE_DISTRUST_KINDS`** — added `"table_unexplained_lanes"`
   and `"table_not_scorable"`, both literal `kind="..."` strings in
   `orchestrator.py` (required by
   `tests/test_gh95_tables_trust.py::test_watched_kinds_are_real_emitted_kinds`,
   which fails on any watched kind that is never actually emitted as a literal).

## A not-scorable page at the document level (was: silently absent)

`tests/test_gh95_tables_trust.py::test_a_not_scorable_page_is_visible_at_the_document_level`
feeds one `table_not_scorable` event (page 54, the OBR chart page named in the B1
review) through `build_tables_trust` and asserts:

```python
trust.untrusted_pages == [54]
payload["counts_by_kind"] == {"table_not_scorable": 1}
"table_not_scorable" in payload["pages"]["54"]["reasons"]
```

i.e. it now appears in `tables_trust.json`'s `untrusted_pages`,
`counts_by_kind`, and per-page `reasons` — the same three places any other
distrust kind appears, rather than `pct=None` with zero trace anywhere
(`grep -rn "ceiling_note" src/` outside `table_exactness.py` was zero hits
before this ticket).

## No third not-scorable contract

Confirmed both existing contracts are handled, not replaced:
- B1's grid gate (`rows_establish_grid` fails before `score_page` even runs;
  `gt_rows=0`, `pct=None`) — handled at the `_table_page_needs_escalation` call
  site before `score_page` is invoked.
- `score_rows`'s no-label-matched ceiling (`ceiling_note` set,
  `scorable=False`, but `pct` is a REAL number, not `None`, because `cells` is
  still counted) — handled via `if report.ceiling_note:` after `score_page`
  returns. Deliberately does **not** change the return value: `decide_escalation`
  still compares this case on measurement rather than deferring to the canary
  (existing behaviour, `test_an_incumbent_with_no_matching_labels_is_still_compared`),
  and `_table_page_needs_escalation` still returns `True` when `pct < 100.0` for
  this ceiling, unchanged from before this ticket.

## Deviation from the ticket text

None load-bearing. The ticket's example log line
(`native_lanes=14, output_cols=6, gap=8`) is `native_verifier.py`'s existing,
separate, already-thresholded (`col_gap >= 2`) mechanism
(`ambiguous_lane_count_mismatch`, already in `TABLE_DISTRUST_KINDS` via
`native_table_verifier_warn`) — not touched by this ticket. TICKET-C1's own
threshold-free fact is built from B2's `lane_to_column`/`lane_count` diagnostics
on `ExactnessReport`, a different (newer) mechanism the ticket text conflates
with the log line as motivating context. STATUS.md's ticket table still says
`depends-on: B4`; B4 was merged into B2 (see TICKETS.md), so the live dependency
is B2, already satisfied.
