# GH-913: a minus read as "2" re-routes the page off trusted-native

Branch `fix/913-minus2-reroute`, from origin/main d8dc9b13.

## Problem
The trusted-native lane ships the repaired text layer verbatim, bypassing every model and
judge. #217 repairs fonts whose CMap it can rebuild; a font it cannot repair still hands back
the raw byte, so a minus extracts as `2` and `-0.12` ships as `20.12` under SUCCESS
(measured: Gofman p38/p45, Baqaee p35, Orphanides p14; see
`~/.local/state/socr-housekeeping/gh913/report.md`).

## Change
- `core/glyph_recovery.py`: `count_minus_as_digit_hits(page)` and the named constant
  `MINUS_AS_DIGIT_SIZE_TOLERANCE_PT = 0.5` (no existing size tolerance to reuse).
  Hit: a one-character span `2`, followed on the same line by a span starting with a digit or
  `.digit`, in a different font, same size within the tolerance. Runs on the page as it looks
  after #217's repair (`open_pdf` already repaired the document the detector reads).
- `core/born_digital.py`: `_assess_page_signals` calls it (only when the page text contains a
  `2`), stores `PageAssessment.minus_as_digit_hits`, and sets `needs_ocr_enhancement`. That
  flag already makes `_is_native_eligible_without_ocr` false, so both the `ocr_pages` build
  and the per-page loop in `_phase_agentic` take the page off the free lane. No content is
  dropped; a model reads the page.
- `pipeline/orchestrator.py`: `_phase_analyze` emits `minus_extracted_as_digit`
  (page, `data.hits`).
- Resume: the event is derived in `_phase_analyze`, which runs on every run before the
  per-page resume gate, from the PDF alone. It is recomputed deterministically each run, so it
  is deliberately NOT in `_RESUME_REPLAYED` (replaying would double-count; same contract as
  `landscape_page_refused` / `orphan_word_dropped`). `test_resume_restore_kinds` is unchanged.
- Not touched: `ship_gate.py` (#936 owns it). The report found a ship-gate predicate inert.

## Cost
`get_text("dict")` with default flags decodes every image: 78 ms/page on a 411-page book,
more than half of `_assess_page`. The detector drops only `TEXT_PRESERVE_IMAGES`:
3.8 ms/page mean (max 9 ms) against 108 ms for `_assess_page` on the same pages (~3.5%).
Dropping the other flags is NOT free: without `TEXT_CID_FOR_UNKNOWN_UNICODE` the Orphanides
p14 hit disappears (caught by the routing comparison below, not by the unit tests).

## Tests

`_resolve_judge_model` patched, engines pinned; the routing pin is a difference, detector
neutralised vs live in the same process):
hits = a "2" in a symbol font, a lone "2" in another font; controls = superscript 2 (smaller
size), ordinary `2.5`, same-font lone 2 (colour split), "2" then a letter, lone "3".

Mutations (external copy of src + tests + pyproject, uncapped `count(anchor) == 1` asserted,
baseline 17 passed, source canary in the suite): route flag not set, size check removed, font
check removed, digit check removed, lone-"2" check weakened, event not emitted: 6 of 6 killed.
