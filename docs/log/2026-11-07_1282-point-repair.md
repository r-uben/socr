# #1282: restore a dropped decimal point from the page's own text layer

## Defect
qwen reads `-.7` as `-7` on rotated born-digital Greenbook tables. The shipped row then equals no text-layer line,
so the row-binding check (#1267) calls it UNVERIFIABLE, and `text_layer_numbers` (#1185) names the pair
(`text layer says -.7, reading says -7`) without binding it to a cell. Measured on 308 pages: 36 pages show the
pattern, 175 cells on 29 pages are repairable.

## Rule (`tables/row_binding_check.propose_point_repairs`)
A data row is repaired only when ALL hold; condition numbers are quoted by the tests and the mutation record.

0. The table is not CONTRADICTED.
1. No text-layer line ANYWHERE ON THE PAGE (not just in the table's box) carries the row's values exactly: a number the page prints is never changed, and a box that misses the row's own line cannot make a right number look wrong (review, case B).
2. Exactly one line/panel has the same number of values, prints the row's label EXACTLY (the BOUND gate's strict
   rule) and every differing pair is a point drop (`-7`/`-.7`, `4`/`.4`, `12`/`1.2`, `-2.`/`-.2`; never a digit
   dropped, a sign changed, or a point on both sides).
3. At least `MIN_AGREEING_VALUES = 2` other values agree by position (measured minimum on the corpus: 3, so no measured repair is lost; with 1 a two-value row was repaired on a single agreeing value, review case A).
4. The line is not an exact option of another row and lies in reading order between the BOUND rows around it.
5. The data cells carry no markdown decoration, and the shipped and native tokens have the same prefix and suffix (`-7` is not repaired to `-.7%`, review case E).
6. The production check then binds the repaired row, no BOUND row loses it, the table does not turn CONTRADICTED.
7. No OTHER line anywhere on the page prints the row's exact label with the same number of values and is within
   `MAX_RIVAL_MISMATCHES = 2` values of the row, or is itself a point-only hit (review fix N, below).

The page helper adds a refusal before any of these (review fix B, below): with more than one table block and no box
per block, no block of the page is repaired.

The cell becomes the PDF's own string (`-.7`, not `-0.7`).

The page keeps its row-binding mark, status and disposition; the record carries `rows: []` and the repair evidence.

## Pipeline (`UnifiedPipeline._repair_dropped_points`)
One step in the agentic page loop, on the winning output, BEFORE `finalized_page_record`: transform once, from
source, before marks. The verdict (`text_layer_numbers`, `text_layer_drops`), the marks and the row-binding check
then all see the repaired bytes.

- One predicate, `row_binding_check.layer_can_judge_tables`, called through `_row_binding_applies` by BOTH the check
  and the repair (two stages: cheap guards, then the born-digital / refused-for-spacing-and-admitted test with the
  fitz page). The repair cannot touch a page the check would not judge (old OCR layer, native engine,
  chart asset, failed candidate, `native_only`).
- Evidence attaches to a table by its block index inside the shipped text (matched by content within that block), so another table of the page cannot vouch for it; tested with an earlier table withheld.
- Event `table_point_repaired` (data: table id, rows of old/new/label/column/native line/agreeing values), replayed
  on resume (`_RESUME_REPLAYED`), not a distrust kind, not in `ROW_BINDING_EVENT_KINDS` (the check's rollback must
  not drop it). Evidence also in the sidecar: `row_binding[table]["repairs"]`, attached only if the shipped table
  still carries the repaired row.
- A failure of the step leaves the page as the model wrote it (the check then marks it, as before) and is logged.
- Resume: a repaired page is marked (WARNING), and the per-page ledger never skip-and-keeps a TABLE_UNVERIFIED page, so
  a resume reads it again and repairs it again, deterministically: same bytes, one event (tested with the root index
  removed so the page loop and `_load_terminal_page` really run, spy count > 0). The page-level restore
  (`_restore_terminal_page_state`) is tested directly: it replays the event once and restores the evidence.

## Offline tool (`socr-refinalize-point-drops <out_dir> --pdf-dir <dir> [--apply]`)
Dry run by default. Same rule and predicate, no model. For each terminal model-read page: repaired text; the two
text-layer clauses RECOMPUTED (unlike `refinalize_own_text`, which leaves a page that has one) and the stale marks
removed; `apply_verdict_marks`; `row_binding` record and events rewritten from the check on the new text;
fragment, document `.md`, manifest blob and cache, document `audit_log.json`, document notes, table counts, and
`refinalized_point_drops.json` (every old and new cell). Idempotent. Tested against a live run with the step: the
fragment, document, verdict, `row_binding`, events, notes and counts are equal.

The tool records exactly what the live step records (the same `effective_outcome`, payload and event builders), so
its bytes are the live run's bytes: fragment, document, sidecar, events (tested on three fixtures, including a
two-table page with a label slip on the second table, at rotation 0 and 90). The only page it still declines is one
where applying the repair would leave the page with no clause at all; that page is NAMED (document and page) in the
output and under `left_alone` in `refinalized_point_drops.json`. The document `status` is never moved back
(`partial` stays): a document can be `partial` for reasons the tool cannot see.

## Review fixes (carbon review 3, 2026-11-10)
The review showed the repair could write a WRONG number on some layouts (verified in
`scratch/army/fed-e2e/LAND-1282/CARBON-VERIFY.md`). Three refusals were added. Each is a refusal only: no new way to
write a number.
- **B** `region_shared_with_another_block` (`propose_page_point_repairs`). With more than one table block and no
  box per block (no boxes, or a different count), every block would scan one shared region. Another table's line with
  the same label could then be the only hit, and its value was written into this table (finding 1: panel B's
  `- 7` became panel A's `-.7`). The check may still judge against the union, because a superset only adds ambiguity.
  The repair writes a number, so it refuses.
- **Z** (`point_dropped`). The digit strings must be equal apart from the point and the one `0` a canonical form puts
  before a leading point. `7` for `.07` and `70` for `.070` lose a zero as well as the point, so they are refused
  (finding 2b). `70`/`7.0` and `125`/`1.25` are still point drops by design.
- **N** `another_line_prints_the_label_close_to_the_row` (condition 7). `MAX_RIVAL_MISMATCHES = 2` is a named
  judgement, not a derived value. When the row's own line is not the hit, it failed condition 1 because of at least
  one slip that is not a point drop (a detached minus `- 7`, a misread `-7.1`). One such slip plus the dropped point
  being repaired makes two differences. A same-label line that close could be the row's own line, so the hit could
  be another section's `Previous` (findings 2a, 3). The same tolerance already named a labelled line "near" in the
  refusal reasons, and that literal is now the constant. A line that is itself a point-only hit is a rival at any
  distance (finding 3 with several dropped points). A sign printed as its own word before the first value is read as
  part of the value. Without that, `Previous - 7` prints the label `Previous -`, and the strict label rule would
  never see the row's own line. This reading goes beyond the brief's wording. It only adds refusals. The blunter rule
  "the label must be unique on the page" was not used: it loses 74 of 152 repairs.

**A repair is recorded only when it ships (2026-11-13, review of 0af33c04).** The first fix (608dab62: `_table_reading_that_ships`, re-listing the selector's D3-keep and structure-class branches) was removed. It was wrong both ways: it missed the branches it did not list (native fallback, the D3 and S1 floors, `_apply_table_emission_guard`, and the page-wide row-binding withhold, which happens after the repair) and it could skip a repair whose `bo` does ship (the D3 predicate returns an older attempt while `_select_page_output_tagged` ships `bo`). The selector is not re-listed, because any copy of it drifts.

The rule now: `_repair_dropped_points` still repairs `bo.text` where it did, so the verdict and the row-binding check see the repaired bytes, but it only BUFFERS the `table_point_repaired` events (`ps.point_repair_events`). `_commit_point_repairs` runs once per page after the row-binding policy and the last `finalized_page_record`, before the fragment flush, on the FINAL shipped text: a repair is kept only when every `row_after` of its table is a line of the same-index table block there. Kept: the event is appended to `state.events` and `ps.point_repairs` keeps it. Dropped: no event, and `row_binding[table]["repairs"]` is removed. A withheld page, a floor, a native fallback or an older attempt ships none of the repaired rows, so it records nothing. The events are written once (the sidecar's `audit_events`), a resumed page replays them from there, and `_rewrite_all_fragments` rewrites bytes only. The event now follows the page's row-binding events in `audit_log.json` (the offline tool places its events the same way). Pinned at `process()` in `tests/test_gh1282_point_repair_pipeline.py` (two tables, one CONTRADICTED) and `tests/test_gh1282_point_repair_winner.py` (older attempt wins; native-fallback branch), each against a control arm where the repair ships.

A repaired row is re-serialised, not edited in place (review nit): spacing in every cell and the closing pipe normalise to `| a | b |`; values change only in the repaired cell, and `row_after` records the normalised form.

The printed value's trailing `,` or `.` (`-.7,`) is an affix, not part of the number, so the repair is refused (`token_affix_differs`); the shipped trailing-point form (`-2.` for `-.2`) is still the dropped point.
