# GH-940: the resume gate probes engines without side effects

`_escalation_retry_blocks_resume` called `_available_engines_for_agentic()`, which resets
`_qwen_cloud_pin_unavailable`, emits the once-per-pipeline unservable report and runs the
per-engine CLI checks. The side effects are the defect.

## Change (`pipeline/orchestrator.py`)
- New `_probe_engines_for_agentic()` returns `(available, unservable, pin_reason)` and touches
  no pipeline state (the old loop body, with the two writes turned into return values).
- `_available_engines_for_agentic()` is `probe + apply effects` (unchanged behaviour).
- The gate calls the pure probe directly. No pin reset, no report.

## Why there is no hold-and-reuse (first attempt, 67d875ba, withdrawn)
The first version held the gate's probe on the pipeline and let `_phase_agentic` consume it
so a refused skip probed once. Review found the hold unsound: it is unkeyed and pipeline-wide
(in batch preflight a later document consumes an earlier document's probe), early failures and
dry-run leave stale holds, nothing re-checks config before reuse, it is unsynchronized, and the
equivalence test consumed the hold itself. The saving was one cheap probe (~15 ms HTTP), while
the issue's complaint was the side effects. A refused skip now probes twice (gate + phase);
accepted.

## Tests
`tests/test_gh940_resume_probe.py`: spy tests (gate emits no unservable report, leaves the pin
flag alone); gate adds exactly one side-effect-free probe and the phase then records the
effects; a 32-case difference test (ladder x agentic x escalate x strict_local) on two
independent pipelines, new gate vs a verbatim copy of the origin/main gate body (which uses the
side-effecting wrapper, stubbed on its own instance). `_run` in the gh851 test additionally
stubs the pure probe, since the gate no longer goes through the wrapper it stubbed; no gh851
test body changed.
