# GH-940: the resume gate probes engines without side effects, once

`_escalation_retry_blocks_resume` called `_available_engines_for_agentic()`, which resets
`_qwen_cloud_pin_unavailable`, emits the once-per-pipeline unservable report and runs the
per-engine CLI checks. A refused skip then probed again in `_phase_agentic`.

## Change (`pipeline/orchestrator.py`)
- New `_probe_engines_for_agentic()` returns `(available, unservable, pin_reason)` and touches
  no pipeline state (the old loop body, with the two writes turned into return values).
- `_available_engines_for_agentic(decision_only=False)` applies the effects. `decision_only=True`
  (the gate) probes, holds the tuple in `_gate_engine_probe`, applies nothing.
- The gate drops the held probe when it lets the skip through; when it refuses, the next
  non-decision call consumes the held probe (one probe, effects applied there).
- The gate keeps going through `_available_engines_for_agentic`, so existing tests that stub
  that method stay hermetic and unchanged.

## Tests
`tests/test_gh940_resume_probe.py`: spy on report / pin flag at the gate; refused skip probes
once and the phase gets the effects; non-refusing gate holds nothing; 32-case difference test
(ladder x agentic x escalate x strict_local) of gate outcome vs the old body; end-to-end
wedge-then-resume counts exactly one probe. `_run` in the gh851 test gained an optional
`stub_available=True` (default behaviour unchanged).

## Mutations (external copies, `socr.__file__` canary)
gate back to side-effecting wrapper: 3 fail; no reuse (double probe): 2 fail; effects dropped
in wrapper: 1 fail; stale hold kept after a non-refusing gate: 1 fail.

Caveat: a held probe from a refusing gate is consumed by the next non-decision call; if a
refusal were ever not followed by `_phase_agentic`, that call would use a slightly older probe.
