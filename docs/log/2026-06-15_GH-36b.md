## What was built

### 1. `src/socr/math/validate_latex.py` (new)

Deterministic, offline, pylatexenc-backed 1A structural validation gate.

`validate_latex_structure(latex: str) -> (ok: bool, reason: str)`:

- Check 1 (non-empty): `latex.strip()` must not be empty → fails with
  `"empty or whitespace-only LaTeX"`.
- Check 2 (structural parse): `LatexWalker(stripped, tolerant_parsing=False)
  .get_latex_nodes(pos=0)` must not raise `LatexWalkerError` → catches
  unmatched braces, unclosed environments, etc. Failure reason is the first
  line of the parse error (truncated to 200 chars for audit compactness).
- On any unexpected error (defensive): returns `(False, "unexpected validation
  error: ...")` — never raises.
- Unknown environments: pass (1A is structural/syntax, not macro-completeness).
  `\begin{myenv} x \end{myenv}` is well-formed and passes.

Also contains `EQUATION_LATEX_PROMPT` — the named prompt constant for the
clean-equation VLM call (no anonymous magic strings per repo rule).

### 2. `src/socr/math/equation_latex.py` (new)

Full GH-36b pipeline per detected equation region:

- `latex_for_crop(crop_path, *, ocr=None, model, host, ...)` — reads the
  saved crop PNG bytes, calls the Ollama endpoint with `EQUATION_LATEX_PROMPT`
  (NOT the corrupt-math `_PROMPT` from recover.py — separate prompt for the
  clean case). Injectable `ocr` parameter for tests (no real network call).
  Returns `""` on failure (never raises).

- `build_equation_sidecar(crop_path, native_text, raw_latex, validation_ok,
  validation_reason) -> (sidecar_block, latex_attached)` — implements 1C:
  - Crop PNG is ALWAYS inlined as `![equation crop](path)`.
  - If `validation_ok` and LaTeX non-empty: attach in a fenced ```latex block
    beneath the image, preceded by `EQUATION_SIDECAR_HEADER` (HTML comment
    marking it as structurally-validated, non-authoritative).
  - If `validation_ok=False`: emit `EQUATION_SIDECAR_FAILED_HEADER` comment +
    the native linearised text (fallback; never omitted).
  - If `crop_path=None`: emit `<!-- socr-equation: crop PNG unavailable -->`.
  Neither the crop nor the native text is ever silently replaced.

- `process_equation_region(region_index, page_num, crop_path, native_text,
  *, ocr=None, model, host, ...) -> EquationLatexResult` — top-level
  orchestration: engine call → 1A gate → 1C sidecar. Returns an
  `EquationLatexResult` dataclass with all provenance fields:
  `raw_latex`, `validation_ok`, `validation_reason`, `latex_attached`,
  `model_id`, `sidecar_block`.

Named constants:
- `EQUATION_SIDECAR_HEADER` — HTML comment marking 1A-validated LaTeX as
  non-authoritative.
- `EQUATION_SIDECAR_FAILED_HEADER` — comment emitted when 1A fails.

## 1A validator function — key design points

```python
def validate_latex_structure(latex: str) -> tuple[bool, str]:
    stripped = latex.strip()
    if not stripped:
        return False, "empty or whitespace-only LaTeX"
    try:
        walker = LatexWalker(stripped, tolerant_parsing=False)
        nodelist, _pos, _len = walker.get_latex_nodes(pos=0)
    except LatexWalkerError as exc:
        reason = str(exc).split("\n")[0][:200]
        return False, f"parse error: {reason}"
    return True, "ok"
```

`tolerant_parsing=False` is critical: it raises on structural errors rather
than silently ignoring them. The 1A gate must be strict to be safe.

## 1C attach mechanism chosen

Fenced ```latex block with an HTML comment header, appended ADJACENTLY after
the crop image reference. Format of the sidecar block:

```
![equation crop](/path/to/equation_1_page3.png)
<!-- socr-equation: structurally-validated LaTeX candidate
     (1A syntax gate, non-authoritative — see crop for ground truth) -->
```latex
x^2 + y^2 = z^2
```
```

On 1A failure:
```
![equation crop](/path/to/equation_1_page3.png)
<!-- socr-equation: LaTeX NOT attached (parse error: ...) —
     native text is the authoritative content -->
native linearised equation text
```

The `EQUATION_SIDECAR_HEADER` constant makes the non-authoritative marker
assertable in tests and consistent across future changes.

## Provenance events

Two new audit event kinds:
- `equation_latex_accepted`: 1A passed; LaTeX attached. `data` contains:
  `region_index`, `crop_path`, `raw_latex`, `validation_ok=True`,
  `validation_reason="ok"`, `latex_attached=True`, `model_id`.
- `equation_latex_rejected_kept_crop`: 1A failed; native text kept. Same
  fields but `validation_ok=False`, `latex_attached=False`, failure reason.

Both are machine-readable and deterministic; `socr replay` is unaffected.

## Default-off — deliberate decision

`recover_clean_equations` defaults to `False` and is NOT flipped in this
ticket. Per consilium 20260615T210537Z-6621 and the GH-36b AC:

> The default-on decision awaits real-corpus throughput measurement
> (GH-36a AC5 numbers are synthetic geometry-only; per-region VLM latency
> with qwen3-vl:30b-a3b-instruct on real equation crops is unknown).

Enabling this flag without per-region latency data risks an operator silently
adding O(equation_count * ~10–60 s/region) to every batch run. The operator
must explicitly pass `--recover-clean-equations --detect-equations` to opt in.

## Residual risk / notes for default-on decision

- **No GPU / no real model test**: the VLM engine path (Ollama HTTP call) is
  tested with a mock stub only. Real-GPU validation of qwen3-vl:30b-a3b-
  instruct on representative display-equation crops is required before
  default-on can be considered.
- **Throughput unknown**: per-region VLM latency on real crops must be
  measured (keep_alive=30m mitigates cold-reload cost, but first-call latency
  on a 30B MoE model is significant).
- **1A is syntax, not fidelity**: even valid LaTeX passes 1A if it is
  structurally correct but semantically wrong (swapped subscripts, dropped
  factor). The crop PNG as visual ground truth is the only fidelity check.
  Operators should treat attached LaTeX as a candidate, not a trusted
  transcription, until real-corpus accuracy is measured.
- **Interaction with math_model config**: the orchestrator uses
  `config.math_model` as the model for both corrupt-math recovery and
  clean-equation recovery. `math_model` defaults to `"qwen3.5:cloud"`
  (Ollama Cloud). For offline runs pass `--math-model qwen3-vl:30b-a3b-
  instruct` to force local model use.
