Date: 2026-06-15

## What changed

`src/socr/prompts/table_extract.md` — added a "Column-lane anchoring" bullet to the
table extraction prompt. The new instruction explicitly tells the model to:

- Place every value under the header column it visually aligns with.
- Count positions from the header row; do not left-pack or right-pack values.
- Fill all other lane positions with blank cells when a sparse row has only a few
  populated cells (e.g. institutional comparison rows like CBO, IMF, OECD).
- Never slide a value sideways to close a gap left by blank cells.

No code was changed — this is a prompt-only fix, which is the cheapest correct
approach for a column-lane anchoring problem.

## Why prompt-only is sufficient here

The bug is column-lane anchoring during VLM transcription, not a parsing or
reconciliation defect. The existing prompt already says "Empty cells stay empty" and
has a paired-column rule for summary rows, but lacked an explicit instruction about
anchoring values to header lanes in sparse rows. The new bullet makes this structural
expectation unambiguous. A deterministic header-lane reconciliation path (GH-49A)
would catch drift post-hoc, but is not needed to express the rule to the model.
