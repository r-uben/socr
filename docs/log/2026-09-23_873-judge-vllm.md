# GH-873 — a VLM judge reachable where there is no Ollama (2026-09-23)

Branch `fix/873-judge-vllm-backend`, PR #874.

## Why

The only VLM judge was `OllamaVisionJudge`, resolved from an Ollama-only candidate
ladder. On the Bocconi cluster Ollama is absent everywhere (not on PATH, no module, not in
`so-hpc`, no `~/.ollama` on a shared home — checked 2026-09-22), so every HPC run degraded
to the heuristic judge while vLLM was already serving a vision model in the same job.

## What

`VLLMVisionJudge` (OpenAI-compatible twin of the Ollama judge), `--judge-vllm-url` /
`--judge-vllm-model`, and wiring in `_resolve_judge_model` and `_build_page_judge`.

## Decisions

- **The named server is probed, once per run.** The first version returned the named model
  without probing, reasoning that `_build_page_judge` probes anyway. The adversarial review
  showed why that is wrong: `_resolve_judge_model` also feeds `_run_fingerprint`'s
  `judge_model`, which is availability-dependent by design. Naming the model while the
  server is down lets heuristic-judged pages fingerprint as VLM-judged, and the resume gate
  would later skip them as current — the resume half of #133. Fixed by probing and caching
  in `_judge_model_cache`; pinned by
  `test_an_unreachable_named_server_fingerprints_as_heuristic`, seen to fail with the probe
  removed.
- **No fall-through to Ollama when the named server is down.** `_build_page_judge` builds the
  vLLM judge whenever the pair is set, so resolving an Ollama model instead would record a
  judge that never ran.
- **Honoured under `--strict-local`.** A named endpoint is an operator instruction, as
  `--qwen-vllm-url` already is. Same known gap as that flag: pointing it at a metered
  remote server sends page images out under `--max-cost-per-page 0` with no warning.
- **Exact served-id match**, never a prefix (#133).

## Out of scope, stated so nobody assumes otherwise

- The **table judge ladder** (GH-353: `table_rung_ollama.py`, the `OllamaVisionJudge`
  construction in `cli.py`) is a separate system and is still Ollama-only. On the cluster it
  still cannot run. These flags do not cover it.
- Recording in `metadata.json` when the judge degrades to heuristics — the other half of
  #873 — is not done here.
- Neither judge backend takes a config-driven timeout; both default to 120 s. Pre-existing.
