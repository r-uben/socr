# GH-151 TICKET-B1 — design: what the page-level structural gate keys on

Ticket: `docs/plans/gh151-structural-gate/TICKETS.md:33-39` · Wave 3 (`docs/plans/extraction-defects/STATUS.md:83-86`)

## 0. TL;DR

- **Gate on A1's `GridStructureReport` plus one new absolute row-pair predicate** ("detached
  label"), not on `GridStructureReport.defective` as it stands. Measured on four real papers,
  `defective` fires on **27 of 29** native table blocks, because `orphan_rows` cannot tell a
  legitimate standard-error row from a broken one. The narrowed predicate set fires on 20/29 and
  every hit I inspected is a genuine defect of the p26 class.
- **No geometry is needed for B1's own acceptance criterion.** p26 is caught by shape alone.
- **The A2 ordinal predicate is not salvageable as written** — it is computed *from* the modal
  vote, not independently of it, and its `value_col_count == len(centres)` gate disables it
  exactly on the damaged pages. What *is* salvageable is the underlying idea, re-expressed as two
  per-row absolute predicates (x-order inversion, lane collision) that need no clustering and no
  vote. That is a separate ticket, not B1.
- **There is no p26 PDF fixture and page 26 of the real paper no longer reproduces the issue's
  markdown on current `main`.** The `Done when` must be restated. Details in §5.

## 1. What exists today

### 1.1 A1 landed and is a pure diagnostic

`src/socr/tables/structure_check.py:95-133` — `check_grid` returns `GridStructureReport` with
exactly two findings that can ever fire: `FINDING_RAGGED` and `FINDING_ORPHAN_ROWS`
(`structure_check.py:55-56`, `:119-123`). Density is explicitly barred from voting
(`structure_check.py:8-13`). `defective` is `bool(findings)` and is documented as "a fact about
the evidence, explicitly not a routing decision" (`structure_check.py:87-92`).

`check_markdown` (`structure_check.py:136-145`) delegates parsing to `reconcile.find_table_blocks`
and inherits its blind spot: an **all-blank pipe row is treated as a separator and silently
dropped** (`structure_check.py:22-34`). A1's docstring hands that to B1. It is a `reconcile.py`
parser fix, not a gate design — see §7.

### 1.2 The flag and the fail-closed machinery B1 is told to mirror already exist

`PageState.native_table_structure_failed` (`src/socr/core/state.py:45`) is **already** a live,
fully-threaded fail-closed flag. It is:

| Surface | Where |
|---|---|
| page routing | `state.py:68-89` (`needs_repair` → forces a real repair pass) |
| page output | `orchestrator.py:3695-3702` (sets `audit_passed=False`, clears `best_output`) |
| sidecar / manifest metadata | `orchestrator.py:4282-4284`; restored on resume at `orchestrator.py:4471-4473` |
| document status | `orchestrator.py:4674-4696` (`d3_floor_pages`, `native_fallback_pages`); `core/manifest.py:311-342` |
| CLI | the same doc-level lists drive the console summary and `audit_log.json` events (`orchestrator.py:4722-4744`) |
| failure mode | `FailureMode.NATIVE_TABLE_STRUCTURE_FAILED` (`core/result.py:57`), in `_ESCALATION_MODES` (`core/audit_log.py:33-39`) |
| release path | `_clear_fail_closed_flags` (`orchestrator.py:1796-1830`) clears it only after a *measured* improvement, and records the clearing as its own event |

So B1 is **not** building a fail-closed path. It is replacing the *predicate* that decides when
one fires.

### 1.3 The predicate that exists today is blind to p26 — measured

The current predicate is `HeuristicsChecker._native_table_structure_failure_reason`
(`src/socr/audit/heuristics.py:326-360`), reached via `check_native_table_structure`
(`heuristics.py:289-308`) → `FailureModeScorer.score_native_table_structure`
(`src/socr/audit/scorer.py:141-143`) → `_score_per_page` (`orchestrator.py:3673-3703`), gated by
`_native_table_structure_gate_applies` (`orchestrator.py:3665-3671`: native engine + page has
tables).

Run against the exact p26 markdown from the issue (`tests/test_structure_check_gh151.py:16-25`):

```
reason: None
metrics: [('Native table structure', 'usable', True)]
```

**p26 passes today's gate.** Why: `_markdown_separator_context_quality` tolerates
`abs(header_cols - separator_cols) > 1` only (`heuristics.py:400-403`) — p26 is 8 vs 7, exactly
one off — and `_markdown_data_rows_quality` accepts on `aligned_rows` within ±1
(`heuristics.py:478-508`) with `_MIN_ALIGNED_ROW_SHARE = 0.40` (`heuristics.py:66`). It is a
tolerance-laden shape check tuned against *collapse*, and p26 is not collapsed — it is misaligned.

A1's report on the same string: `findings=('ragged','orphan_rows')`, `row_widths=(8,6,7,7,7,7,7)`,
`orphan_rows=(3,6)`. **A1 sees exactly what the heuristic misses.** That is the whole case for B1.

### 1.4 Where a table page actually goes

- Non-agentic: `_score_per_page` (`orchestrator.py:3673`) is the only place a native table page's
  grid is judged.
- Agentic: a page with tables is **never** trusted-native — `_is_trusted_native_without_ocr`
  returns `not self._page_has_tables(...)` (`orchestrator.py:1186-1213`), so every table page
  enters `ocr_pages` (`orchestrator.py:2007-2017`). The native grid then matters on the
  **fallback** path (`orchestrator.py:2128-2153`, `1071-1078`) and when the judge rejects all rungs
  (`orchestrator.py:2596`). p26 shipped SUCCESS as *native* output — that is the lane B1 must close.
- `--native-only` short-circuits and ships the native grid directly (`orchestrator.py:1204-1211`).
  This is the worst case for p26 and the one B1 most needs to cover.

### 1.5 The freshest wiring precedent — GH-147 A2

`PageAssessment.native_table_lane_refused` (`src/socr/core/born_digital.py:315-322`) is set **only
inside the refusal branch** (`born_digital.py:915-941`, constructed at `:998`) and consumed in
`_phase_analyze` (`orchestrator.py:634-658`) to emit a `landscape_page_refused` `AuditEvent`. Its
docstring states the rule B1 must follow verbatim: *"Audit code must key off this flag, not
re-derive 'refusal happened' from conditions that merely correlate with it."*
(`born_digital.py:319-322`).

Note the residual recorded in `extraction-defects/STATUS.md:222-226`: one call site still
re-derives the refusal. Do not add a second.

## 2. Measurement: what each candidate predicate actually fires on

Read-only probes (`/tmp`, `~/venvs/socr/bin/python`), over `BornDigitalDetector.detect()` →
`find_table_blocks` → `check_grid` on four locally-materialised papers. Only born-digital pages
with `has_tables` counted. **Current `main` source** (includes GH-144 A2/A2b, `d645b24`).

| Papers (4) | native table blocks | `ragged` | `orphan_rows` | `defective` | **detached-label** |
|---|---|---|---|---|---|
| bauer_pflueger_sunderam QJE, kuttner JME, cieslak_mcmahon WP, he_krishnamurthy_milbradt AER | 29 | **0** | 27 | 27 | **20** |

Today's heuristic (`§1.3`) flagged **2** of those 29 blocks' pages, both by the flat-stream branch,
and zero by the markdown branch.

**Why `orphan_rows` alone over-fires.** From `cieslak_mcmahon` p25, block 0 (verbatim parsed grid):

```
  0: ['', 'RP overall', 'components CRP', 'HRP', 'EH overall', 'components G', 'MP']
  1: ['HDGapt', '-0.19***', '-0.17***', '-0.017', '0.043', '0.0097', '0.033']
 *2: ['', '(-3.29)', '(-3.52)', '(-0.48)', '(0.98)', '(0.37)', '(1.31)']
  3: ['R2', '', '', '', '', '', '']
 *4: ['', '0.046', '0.066', '0.0011', '0.0060', '0.00074', '0.0087']
  5: ['N', '227', '227', '227', '227', '227', '227']
```

Row 2 is an orphan and is **correct** — a t-statistic row under its coefficient row is standard
econ table presentation. Row 4 is an orphan and is **broken** — `R2`'s values were split onto a
separate row (the superscript-2 breaks the row), the exact defect the issue names for p26.

The distinguishing fact is *local, absolute, and threshold-free*: row 3 carries a label and **no
values at all**, and row 4 carries values and **no label**. A legitimate continuation row (row 2)
follows a row that *has* values. No voting, no majority, no reference to any other row in the
table.

**Definition (proposed, `FINDING_DETACHED_LABEL`).** For body rows `i >= 1`:
`grid[i][0]` non-blank ∧ every `grid[i][1:]` blank ∧ `grid[i+1][0]` blank ∧ any `grid[i+1][1:]`
non-blank.

On the p26 fixture string this fires at row 5 (`R2`) — the issue's headline defect — alongside
`ragged`. On the corpus it fired 20/29 times, and every hit printed was `R2` / `¯R2` / `t` /
`aNote:` — i.e. a label genuinely severed from its row. Sample of hits:

```
cieslak p20/p25/p32/p34/p41/p55/p56: ['R2'] / ['¯R2']
bauer p36: ['t','t']        kuttner p4/p11/p14/p15/p17/p20: ['aNote:']
```

The 20/29 rate is not a false-positive rate — it is the true prevalence of this defect in
regression tables, and the owner must know that gating on it **will route most regression-table
pages to repair**. That is a cost decision, stated in §6, not something to hide behind a
threshold.

`ragged` fired **0/29** on real pages and fires on the issue's p26 snapshot. Rare and precise:
keep it.

## 3. Is `GridStructureReport` alone sufficient?

**For B1's acceptance criterion: yes.** p26 is `ragged` and has orphan rows; either finding
carries it. No geometry, no model, no page object required.

**As a gate: not as-is, and not by itself.** Three gaps, in order of how much they matter:

1. **`orphan_rows` is not a defect predicate** (§2). Gating on `report.defective` conflates the
   standard-error row with the severed `R2` row. Needs the row-pair refinement.
2. **A rectangular, fully-labelled grid whose values sit in the wrong columns is invisible to it.**
   Shape is intact; binding is wrong. Detecting that requires native x-geometry — §4. p26 does not
   need it; the general gate eventually does.
3. **The dropped all-blank row** (`structure_check.py:22-34`). A row that vanishes in
   `reconcile._parse_grid` before `check_grid` ever runs is silent content loss and cannot be seen
   from the report. Out of B1's file scope (it is `reconcile.py`, and `reconstruct.py` is barred
   for wave 3); file it, do not smuggle it into B1.

**What the additional evidence must be derived from, and why it can be absolute.** The detached-
label predicate is derived from the *same parsed grid* A1 already reports on — no new input, no
page object, no clustering, no tolerance. It distinguishes damaged from legitimately-different by
an **adjacency invariant** (a label row with zero values immediately above a value row with zero
label is a split row), never by comparing a row against what other rows look like. That is the
property the wave-1 ruling demanded and modal consensus cannot have.

## 4. Is the A2 ordinal predicate salvageable?

Read from `gh pr diff 184 --patch` (branch `feat/151-a2-column-binding`, draft, not merged; the
code is not in the working tree).

**As written: no.** Two independent reasons.

1. **It is not independent of the vote.** The ordinal block iterates `modal_single_lane`, and
   `modal_single_lane[col_idx]` is assigned from `modal_sig` — the winner of
   `Counter(row_sigs.values())`. Its "expected" lane is therefore *the majority's* lane, renamed.
   Delete the modal computation and the ordinal predicate has no input. Calling it an absolute
   predicate is a description of intent, not of the code.
2. **Its gate turns it off precisely when it is needed.** `value_col_count == len(centres)`, where
   `centres` come from `_derive_lane_centres` → `_cluster_x_positions`
   (`src/socr/tables/native_verifier.py:149-160`), a single-linkage chain with `_LANE_X_TOL_PT`
   (6.0 pt, `native_verifier.py:48`). Lane *count* is therefore a clustering artifact of the very
   page whose extraction is in doubt: a damaged page is exactly where the count stops matching, so
   the absolute check silently yields and the modal vote runs unqualified. The gate is not "too
   narrow" — it is measuring the wrong thing. Additionally `_nearest_lane_index` has **no
   rejection branch**: a token arbitrarily far from every centre still snaps to the nearest lane,
   so a lane assignment is never "unknown", only "nearest".

**What survives, as a separate ticket (proposed GH-151 A2R).** Two per-row predicates that need
neither clustering nor voting, computed over one paired native row:

- **x-order inversion** — if the token emitted in output column `j+1` has a smaller native `x`
  than the token emitted in column `j`, that row's binding is provably wrong. Strict inequality on
  raw coordinates: no tolerance, no constant, no lanes.
- **intra-row lane collision** — two distinct output columns in the same row resolving to the same
  native token/position: two cells claim one physical column.

Both are local to a row and absolute. Both reuse A2's genuinely useful plumbing (`_rows_by_y_from_words`,
`_pair_output_to_native_rows`, `_resolve_value_lane`'s exactly-once resolution rule, and the
`unresolved`/`checked` tri-state contract), and discard `Counter`, `modal_sig`, `_derive_lane_centres`,
`_nearest_lane_index`, `column_order_violation` and `lane_shared_across_columns`.

**PR #184 should be closed, not merged and not "fixed in place".** `native_verifier.py` is not in
B1's write set (`extraction-defects/STATUS.md:45,47`), and the wave-1 ruling's stated risk is
adoption-by-having-been-merged.

## 5. The p26 fixture — what actually exists

**Findings, measured, not assumed:**

1. The only p26 artifact in the repository is the markdown **string** `GH151_P26_MD`
   (`tests/test_structure_check_gh151.py:16-25`). There is no p26 PDF, no p26 page image, no p26

2. The source PDF exists **outside** the repo, in the user's iCloud papers library:
   `.../library/Papers/papers/2024__bauer_pflueger_sunderam__perceptions_about_monetary_policy__QJE.pdf`
   (a `__WP.pdf` sibling also exists).
3. **On current `main`, page 26 of that QJE PDF does not reproduce the issue's markdown.** Running
   `BornDigitalDetector.detect()` on it, page 26 is `is_born_digital=True, has_tables=True` and
   `find_table_blocks` returns **zero** table blocks — the page comes out as a flat cell stream
   (`TABLE II / SENSITIVITY OF INTEREST RATES TO MACROECONOMIC NEWS / ... / 0 .003 / 0 .004 ∗ ...`).
   The issue's grid was captured before GH-144 A2/A2b (`d645b24`) and GH-146 (`#149`) changed
   `reconstruct.py`. The paper's flagged table pages today are 19, 30 and 36, not 26.
4. The NS QJE reference PDF cited in `extraction-defects/STATUS.md:189` is **0 bytes locally**
   (iCloud placeholder, `EmptyFileError`), so I could not extend the base-rate measurement to it.

**Consequence: the `Done when` as written is not executable.** "Processing the p26 fixture" names
an artifact that does not exist, and the nearest real thing no longer produces the defect.

**What the fixture must contain for the criterion to be meaningful.** Recommended, in order:

- **(a) A checked-in synthetic PDF** — `tests/fixtures/gh151/p26_like.pdf` plus its generator,
  mirroring the existing precedent `tests/fixtures/table_repair/generate_fixture.py:221-246`
  (`fitz` + `insert_text`). It must place, at minimum: a label token (`R2`) on its own text line
  with **no numerals on that line's y-band**, and the corresponding six values on the **next**
  y-band with **no label token** — so that `extract_structured` emits the label-row/value-row split.
  That gives a genuine end-to-end assertion: run the pipeline, assert one
  `AuditEvent(kind="table_structure_failed")` on that page **and** that the page's shipped output
  is not `audit_passed=True`.
- **(b) A seam-level test using `GH151_P26_MD`** — inject it as `PageAssessment.native_text` and
  assert the flag + event. Cheap, hermetic, and pins the wiring, but it does **not** prove the
  extractor produces that grid, so it cannot stand alone as the acceptance evidence.

Ship **both**: (b) pins the wiring, (a) pins the behaviour. Do **not** re-word the criterion to
say "the p26 fixture" while quietly meaning the markdown string — that is the kind of drift the
STATUS files exist to prevent. Any test that drives `process()`/`_phase_agentic` must patch
`_available_engines_for_agentic` or it will pass locally and fail in CI (`CLAUDE.md`).

## 6. The wiring (following the `native_table_lane_refused` precedent)

**Signal.** In `born_digital.py`, immediately after the structured-extraction branch
(`born_digital.py:936-941` — the `else` that calls `clean_native_text(self.extract_structured(page))`),
run `structure_check.check_markdown(native_text)` and evaluate the gate predicate:

```
gate_failed = any(r.ragged or r.detached_label_rows for r in reports)
```

Set at the moment of the evidence, never re-derived — the GH-147 A2 rule
(`born_digital.py:319-322`). Do **not** run it in the refusal branch (there is no table markdown
there) and not for non-table pages.

**Flag.** Add `PageAssessment.native_table_structure_defective: bool = False`
(alongside `born_digital.py:315-322`) and `PageState.native_table_structure_defective: bool = False`
(alongside `state.py:45-49`), propagated in `apply_born_digital` (`state.py:176-191`, the same
shape as the TR-3 propagation at `:188-191`).

**Why a new field rather than setting `native_table_structure_failed` directly** — one concrete
hazard: `_score_per_page` **clears** that flag on a passing heuristic score
(`orchestrator.py:3702` and `:3727`, `= False`). A structural verdict set at extraction time would
be silently erased by the weaker predicate that missed p26 in the first place. A dedicated,
evidence-carrying field that only `_clear_fail_closed_flags` may release (add it to the tuple at
`orchestrator.py:1810-1815`) preserves the "set at the event" invariant. This mirrors how PP-7
added `chart_asset_render_failed` (`state.py:49`) rather than overloading an existing flag.

**Routing consequence.** OR the new field into the existing consumers so no new fail-closed path is
invented:

| Surface (house rule requires all four) | Change |
|---|---|
| **page status** | `state.py:68-89` `needs_repair`: add the new field to both the entry condition and the "audit rejection demands a real repair pass" clause, so a defective native grid is never shipped as trusted native. Also `orchestrator.py:1204-1211`: `--native-only` must not bypass OCR for a page whose grid is defective — the same narrowing GH-147 A2 applied for rotation. |
| **document status** | `orchestrator.py:4674-4696`: include it in `native_fallback_pages`; `core/manifest.py:311-342` `_winning_page_output` must not re-stamp such a page `audit_passed=True` (this is the exact PP-7-R1 bug, `orchestrator.py:2407-2411`). |
| **metadata / sidecar** | `orchestrator.py:4282-4290` add the key; `orchestrator.py:4471-4476` restore it on resume, or the flag evaporates on a resumed run. |
| **CLI / audit log** | one `AuditEvent(kind="table_structure_failed")` per affected page, appended in `_phase_analyze` in the same loop shape as `landscape_page_refused` (`orchestrator.py:634-658`), with `data={"findings": [...], "row_widths": [...], "detached_label_rows": [...]}` so a batch run is inspectable; plus the doc-level console line alongside the existing native-fallback summary. |

**Where `FINDING_DETACHED_LABEL` should live.** Naturally in `structure_check.py` next to the other
two findings — but that file is A1's, listed as wave-1-only in the ownership table
(`extraction-defects/STATUS.md:46`), and it is not in B1's declared write set. Wave 1 is closed and
nothing else claims the file, so extending it is safe *in fact*; it still needs the owner's
explicit go-ahead to keep the ownership table honest (question Q2 below). If refused, the predicate
can live in `born_digital.py` over the same parsed grid — worse (splits the structural vocabulary
across two modules) but not wrong.

**Do not touch** `src/socr/tables/reconstruct.py` (GH-152 A1 critical path) or
`src/socr/tables/native_verifier.py` (not in scope; see §4).

inert-by-default behind a config flag? I recommend accepting the cost: the flagged pages are
genuinely damaged, and "no silent content loss" outranks throughput.

## 10. `/consilium` question — paste verbatim

> A deterministic OCR pipeline for academic PDFs must decide, per page and with no model in the
> loop, whether a natively-extracted markdown table is structurally damaged enough that it must not
> ship as trusted output; the only evidence available without new work is the parsed grid itself
> (row widths, which cells are blank, which body rows have a blank first/label cell), and on a
> four-paper sample of 29 real table blocks the candidate signals fire as follows: "rows disagree
> on width" 0/29, "some body row has a blank label cell but populated value cells" 27/29 (it cannot
> distinguish a legitimate standard-error row under its coefficient row from a genuinely severed
> row), and "a row carrying a label and zero values is immediately followed by a row carrying
> values and no label" 20/29 (every inspected hit was a real defect — an `R²` label severed from
> its own values). Which predicate should the gate key on?
>
> **Option A** — Gate on the existing report's `defective` (width raggedness OR any blank-label
> body row). Simplest, already implemented, no new code; flags 27/29 real table blocks including
> correct standard-error rows, so nearly every regression-table page is routed to re-extraction.
>
> **Option B** — Gate on width raggedness OR the adjacency predicate (label-only row immediately
> followed by values-only row), leaving the bare blank-label row as diagnostic evidence that never
> gates. Threshold-free and purely local to a row pair — it never compares a row against what the
> other rows look like — but requires one new finding in the structural module and still marks
> ~2/3 of real regression-table pages defective, because that defect really is that common.
>
> **Option C** — Do not gate on grid shape at all; wait for a geometric check that compares each
> emitted value's x-coordinate on the PDF page against the column it was placed in, and gate on
> that instead. Strictly more information, but it needs page geometry rather than the grid alone,
> it is a second module and a second design pass, and it leaves the shipping-a-broken-table
> behaviour unfixed in the meantime.
>
> Constraint that must be respected in the answer: no majority/modal-consensus reasoning across
> rows is admissible (an earlier attempt was rejected for exactly that — in this corpus the
> minority row is frequently the correct one), and no numeric threshold may be introduced that is
> not derived from data.
