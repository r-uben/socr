# GH-223 — heading loss across every lane: design note

**Date:** 2026-09-16 · **Base:** `origin/main` @ `1d15f15` · **Scope:** design only, no `src/` change.

The issue ends on a deliberate fork and says not to guess it:

> Decide separately whether heading recovery belongs in a post-extraction structure pass that
> runs on **every** lane's output, rather than in either the native extractor or the VLM prompt.

This note re-confirms the defect on current `main`, maps the three candidate sites with the
access each actually has, and states the question for the panel.

---

## 1. What I re-confirmed on current main

The corpus measurement behind the issue was taken weeks ago at `3c750a2`. `main` has moved a
lot since. Everything below was re-checked at `1d15f15`.

### 1.1 The detector still exists — and still has no caller in `src/`

`detect_native_structure_loss` is at `src/socr/core/born_digital.py:2089`. A whole-tree grep for
the symbol returns exactly one hit — its own `def` line. Its only other references are in

## 2. The three candidate sites

### (a) Post-extraction structure pass, over every lane's output

**Hook point.** Inside the page-major loop `_phase_agentic`
(`src/socr/pipeline/orchestrator.py:8060`), after the page's winning text is settled and before
the provisional flush. Every lane converges there — native, qwen, gemini, chart_asset — so one
call site covers all four rows of the issue's table. Fragment/final byte-identity is preserved
because `_rewrite_all_fragments` (`orchestrator.py:12150`) rewrites fragments from the final
assembled text regardless.

**What it has access to — the decisive question, answered with code.** Font geometry is
**still available**, and there is an existing precedent for reaching it: `get_fitz_page`
(`orchestrator.py:10522`) reopens `state.handle.path` on demand and hands out a live
`fitz.Page`, closing the previous handle each call. Any post-extraction pass can do exactly the
same and get full span records — size, bbox, text. So (a) is **not** reduced to guessing
headings from text alone.

Two real limits on that access:

- **Born-digital only.** A scanned page has no text layer, so no font sizes. On such a page the
  pass is geometry-blind and can only no-op. (The issue's corpus is born-digital; a scanned
  corpus gets nothing from any of the three options except the prompt.)
- **Alignment, not identity.** Geometry says "these source spans are above body size". The
  emitted text is the *model's* rendering of the page, which may rewrap, join or lightly
  rephrase. Promotion therefore needs a match from an emitted line back to a source span.
  A strict match fails closed (no promotion, no false heading); a loose match buys coverage
  by buying over-promotion risk. `PageState.native_words` (`src/socr/core/state.py:193`) does
  **not** help here — `get_text("words")` carries bboxes but **no font size**.

**Cost.** One extra `get_text("dict")` per born-digital page — the same call the detector
already makes, in-process, no model, no network. Negligible against a VLM page. Deterministic
and replay-stable: identical input bytes → identical output.

**The architectural objection.** `_phase_agentic`'s docstring at `orchestrator.py:8100` states
the **post-verdict content contract**: "no post-verdict step may ADD or ALTER content", with
exactly three enumerated exceptions, two subtractive and one additive-and-guarded. Rewriting
`Box 3: …` to `# Box 3: …` **alters a judged line**. It is markup rather than a content token,
and the invariant tests are phrased over tokens outside marker spans — but this is a contract
question, not a detail, and it is the thing a panel should actually rule on.

### (b) The VLM prompt

**Hook point.** There isn't one in this repo. The qwen lane is a subprocess CLI:
`_build_command` (`src/socr/engines/qwen.py:209`) assembles
`qwen-ocr process <pdf> -o <dir> --backend … --dpi … [--model …] [-w] [-q] [--verbose]
[--reprocess]`. **No prompt flag exists.** The extraction prompt lives in a separate repo,
`~/repos/tools/qwen-ocr-cli` (pointed to by the module docstring at `qwen.py:5`). `src/socr/prompts/`
holds only judge/table/cell prompts — no page-extraction prompt.

**What it can reach.** The rendered page image only. No font sizes, no bboxes — the model
infers heading-ness from visual type size, which is how it already gets the other 31 qwen pages
right. It cannot reach the native lane (14 pages of that run) or chart_asset at all.

**Cost.** Cross-repo change plus a per-engine repeat (gemini, deepseek, glm each have their own
CLI and prompt). Non-deterministic: the fix is a request, not a guarantee, and it regresses
silently on a model or prompt revision. Zero marginal token cost.

**What it cannot do.** It cannot fix the lane where the *measured* per-lane heading loss is
proportionally worst (native: 14 of 14 pages flagged), and it puts the remedy for a structural
invariant inside a model's discretion.

### (c) The native extractor

**Hook point.** `BornDigitalDetector.extract_structured` (`born_digital.py:3440`) for table
pages, and the flat `raw_text` path (`born_digital.py:3135`) for table-free pages — **both**,
or the fix lands on only some native pages. It has the `fitz.Page` directly, so full geometry,
no alignment problem at all: it is emitting the text, so it knows which spans became which line.

**Cost.** Cheapest and most precise of the three. Contained inside one module, no contract
question, no model.

**What it cannot do.** It covers 14 of the 68 pages in the issue's run and **none** of the 20
flagged qwen pages. On its own it does not address the finding the issue exists to report.

## 3. What is actually being decided

The issue's own measurement already rules out (b)-alone and (c)-alone as *complete* answers:
escalation fixed lists and did not fix headings, so no single-lane site covers the defect.
What is genuinely open is a different pair of questions, and they are not the same question:

1. **Is deterministic geometry-derived promotion allowed to rewrite a judged line at all**, or
   does the post-verdict content contract mean heading loss must be *surfaced* (sidecar field,
   page status) and repaired only inside each lane's own emitter, before the verdict?
2. **If promotion is allowed, how conservative is the gate** — and what happens at the boundary?

A third shape deserves to be on the table because it is what the repo's own "no silent content
loss" rule most directly demands: **surface-only**. Wire the existing dead detector into the
per-page sidecar (`_flush_page_sidecar`, `orchestrator.py:10734`) and the page's notes, repair
nothing. Cost is one `get_text("dict")` per born-digital page; risk of a false heading is
**zero**; and it converts a silent loss into a recorded one, which is the repo's stated minimum.
It does not recover a single heading.

### False headings: which options risk one

| option | risk of a FALSE heading | why |
|---|---|---|
| (a) promotion, loose match | **High** | §1.3: page numbers, pull quotes and figure captions all clear `size > body_size`. A loose emitted↔source match compounds it. |
| (a) promotion, strict match | **Low but nonzero** | Fails closed on mismatch, so it under-recovers rather than over-promotes — but a genuinely large-type caption that matches exactly is still promoted. |
| (b) prompt | **Medium** | Asking a model to mark headings invites it to mark a cover title or a pull quote; unfalsifiable from socr's side because there's no post-check. |
| (c) native extractor | **Low but nonzero** | Same geometry rule, same §1.3 false positives — but it also sees block structure and neighbours, so it can gate harder. |
| surface-only | **None** | Writes no heading. |

Over-promotion is a real cost, not a hypothetical, and §1.3 is the receipt.

### Thresholds, and what happens at the boundary

No magic numbers are proposed. The only comparison available is the page's **own weighted modal
body size** (`born_digital.py:2139`: character-count-weighted mode over span sizes, so footnotes
cannot win the vote) and strict `>` against it (`born_digital.py:2160`). At the boundary — a
span *equal* to modal body size, or a page with a bimodal size distribution where the mode is
unstable — the rule must **not** promote: ties go to body text, since a missing heading is
recoverable downstream and a false section boundary is not. Any additional gate (line is short;
stands alone on its baseline band; is followed by body-size text) must likewise be derived from
the page's own measured geometry, never a tuned constant. Heading **level** (`#` vs `##`) is a
separate sub-question: ranking a page's distinct above-body sizes is page-local and will not be
consistent across a document, so a document-wide size ranking is the only coherent basis — and
if the panel picks promotion, it should say whether level is in scope or whether every promoted
line becomes the same depth.

## 4. Recommendation

**This is a genuine fork — panel it.**

I have a preference, stated so the panel has something to push against: **(a) as a deterministic,
fail-closed post-extraction pass, with surface-only as its mandatory floor** — whenever the pass
declines to promote, it records the declined cue in the sidecar, so the page never ships a
silent loss. That is the only shape that covers all four lanes with one code path, keeps a model
out of the decision, and satisfies "no silent content loss".

What I cannot settle alone is the contract question. `_phase_agentic:8100` enumerates exactly
three post-verdict exceptions and demands the same grade of justification for a fourth. Whether
"promote a judged line to an ATX heading on the page's own font geometry" earns that exception —
or whether it must instead move *before* the verdict, into each lane's emitter — is exactly the
sort of ruling the panel exists for, and it changes the implementation completely.

## 5. The consilium question

> In a multi-lane document-OCR pipeline where heading structure is lost on **every** lane —
> the native PDF-text lane emits no ATX headings at all, and on a measured 68-page run 20 of
> 51 model-extracted pages also emitted none despite the source PDF setting those lines above
> the page's modal body size — where should heading recovery live, given that the source PDF
> (and therefore per-span font size and bbox) can be reopened at any point in the pipeline, but
> the pipeline holds a standing contract that no step after a page's quality verdict may add or
> alter that page's content?

Options, verbatim:

- **A — Deterministic post-extraction promotion, all lanes.** After a page's text is final and
  before it is flushed, reopen the source PDF, compute the page's character-weighted modal body
  font size, and promote an emitted line to an ATX heading only when it matches a source span
  strictly above that size; fail closed (no promotion, record the declined cue) on any mismatch.
  One code path covers all lanes; no model; replay-stable. Requires granting a fourth exception
  to the post-verdict content contract, and risks promoting a large-type line that is not a
  heading (a figure caption, a pull quote, a cover title) — measured: on a synthetic page whose
  only above-body spans are a page number, a pull quote and a caption, the geometry rule fires
  three times with no heading present.

- **B — Lane-local emitters only, no post-verdict rewrite.** Fix heading emission inside the
  native extractor (which has the geometry directly and no alignment problem), and separately
  add a heading instruction to each vision model's extraction prompt — which lives in a separate
  CLI repo per engine and is reachable only as a request, not a guarantee. Honours the content
  contract untouched; per-engine and unverifiable for the model lanes; regresses silently on any
  prompt or model revision.

- **C — Surface only, repair nothing.** Run the existing (currently uncalled) structure-loss
  detector on every born-digital page and record the cue in the page's sidecar and status, so
  heading loss stops being silent, while emitting no heading of its own. Zero risk of a false
  heading, honours the contract, cheapest to build — and recovers no headings at all.

## 6. Acceptance-criteria readiness

GH-223 is a bug report and carries **no `### Acceptance Criteria` section** — there is nothing
to tighten yet. Whatever the panel picks, the criteria that follow have to be written fresh, and
three of them are option-independent:

1. **A page with a false-heading trap must not gain a heading.** The §1.3 fixture (page number +
   pull quote + figure caption, no heading) is the regression case and should be checked in as a
   synthetic PDF built in-test, never corpus content.
2. **A page with a real above-body title must gain one** (the §1.2 fixture), and a three-line
   title must produce **one** heading, not three — the span-count artefact must not leak into
   behaviour.
3. **Loss must surface when recovery declines.** Under every option including B and C, a page
   that carries above-body type and ships no heading must say so somewhere durable (sidecar,
   page notes, document metadata) rather than reporting a clean `status: success`, which is what
   all 68 pages of the measured run did.

Option-specific: A additionally needs a byte-identity criterion (fragments still equal the final
`.md`) and an explicit statement of which contract exception it claims; B needs a criterion that
does not depend on a model's cooperation, which is the hard part.
