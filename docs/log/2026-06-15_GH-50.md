# GH-50: Split figure extraction from VLM figure descriptions

Date: 2026-06-15
Ticket: GH-50
Status: DONE

## What changed

### `src/socr/core/config.py`
- Added `describe_figures: bool = False` to `PipelineConfig` with an explanatory
  comment separating it from `save_figures`.
- Added `"describe_figures"` to the `scalar_fields` list in `from_file()` so YAML
  config files can set it.

### `src/socr/cli.py`
- Replaced the bare `--save-figures` flag with an updated version that clarifies it
  does NOT generate VLM captions.
- Added `--describe-figures` as a new opt-in flag for VLM captions.
- Added `describe_figures: bool = False` parameter to `build_config()`.
- Logic in `build_config()`: `--describe-figures` implies `--save-figures` (captions
  require PNGs on disk); `--save-figures` alone does not enable captions.

### `src/socr/pipeline/orchestrator.py`
- `_run_fingerprint()`: added `"describe_figures"` to the `extra` dict so the resume
  cache invalidates when the flag changes.
- `_phase_assemble()`: `runs_figures` now fires on `save_figures OR describe_figures`
  (previously only `save_figures`).
- `_describe_and_embed_figures()`: the method is now split into two distinct phases:
  1. PNG extraction + image-ref block appending — always runs when `runs_figures` is
     True.
  2. VLM caption call (`_get_vision_engine()` + `describe_figure()`) — only runs when
     `config.describe_figures` is True. When it is False, a console note is printed and
     all figures get an empty description string.
  - The caller's `try/except` around this method still catches any caption-phase crash
    and preserves the already-written OCR markdown (existing AC3 behaviour).

### `tests/test_orchestrator.py`
- Updated `test_figures_with_vision_engine` to set `describe_figures=True` (the VLM
  path requires the new flag; old test used `save_figures=True` only which is now
  extraction-only).
- Added five new test classes covering the acceptance criteria:
  - `TestSaveFiguresNoVLM`: `--save-figures` alone never calls `_get_vision_engine`;
    image-ref block is still written.
  - `TestDescribeFiguresVLM`: `--describe-figures` calls VLM; `--save-figures` alone
    skips VLM.
  - `TestFigurePhasePreservesOCRText`: caption crash does not destroy OCR markdown.
  - `TestDescribeFiguresResumeFingerprint`: toggling `describe_figures` changes the
    run fingerprint; `save_figures` alone still invalidates the fingerprint (regression
    guard).
  - `TestCLIDescribeFiguresFlag`: CLI implication logic (`--describe-figures` implies
    `--save-figures`; neither flag leaves both False).

## Decisions / deviations

- `--describe-figures` implies `--save-figures` in `build_config()`. This is an
  intentional convenience: captions without saved PNGs would embed broken image refs.
  The implication is documented in CLI help text.
- `describe_figures=False` still activates `_describe_and_embed_figures()` when
  `save_figures=True` — the method handles both extraction and (optional) description.
  The VLM gating is inside the method, not at the call site, keeping the pre-figures
  provisional fingerprint logic intact.
- No backward-compat alias for old `--save-figures` behavior: the old flag did the
  same extraction; the only change is that captions now require `--describe-figures`.
  Users who previously got captions "for free" via `--save-figures` were relying on
  undocumented behavior and the ticket explicitly calls for separation.
