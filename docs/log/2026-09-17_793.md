# 2026-09-17 — GH-793: pin the production wiring PR #792 left unguarded

Test-only ticket. PR #792 (GH-789/GH-790) wired the destroyed-token
fallback's `orphan_drops` into `BornDigitalDetector._last_extraction_orphan_drops`
at `born_digital.py:3630-3637`, but its own regression test
(`tests/test_gh789_790_dark_drop_paths.py`) calls `reconstruct_table_regions`
directly and passes its own `orphan_drops` list — it never drives the three
lines that wire the helper's output into the detector's side channel. Delete
any one of them and every existing test still passed.

## Caller surface chosen: `UnifiedPipeline._phase_analyze`, real detector

Not `reconstruct_table_regions` (already covered, and not the gap), not a
bare `extract_structured` call (would prove less than the ticket asked:
"onward to the AuditEvent(kind=\"orphan_word_dropped\") surface"), not a full
`pipeline.process()` (would drag the entire agentic OCR loop in for zero
extra coverage of the three lines under test).

`_phase_analyze` is one hop past `extract_structured`: it is the literal
production method that (a) calls `self.bd_detector.detect()` — the real
`detect() -> _assess_page() -> extract_structured()` chain that owns the
wiring gap — and (b) contains the `AuditEvent(kind="orphan_word_dropped")`
emission itself. Using the REAL `BornDigitalDetector` (not mocked, unlike
`test_gh205_tr3_unconditional_event.py`'s pattern of mocking `bd_detector`
to pin `_phase_analyze` in isolation) is the point: the wiring gap lives
inside the detector, so mocking it away would prove nothing.

## Reachability

The destroyed-token fallback only fires when: (1) a page's default-strategy
`find_tables()` result is empty enough that `_table_to_markdown` ships
nothing, AND (2) a subsequent `vertical_strategy="text"` call finds a grid
that boundary-splits a numeric token (GH-144). This is real PyMuPDF
detection behaviour that PR #792 itself did not attempt to reproduce from
real PDF geometry — its fixture fakes `find_tables`/`get_text` outright.

`BornDigitalDetector.detect()` opens its own `fitz.Document` from a path, so
there is no page instance available to monkeypatch ahead of time the way
#792's fixture does (instance-level `page.get_text = ...`). This file
monkeypatches `fitz.Page.get_text` / `fitz.Page.find_tables` at the CLASS
level instead (via pytest's `monkeypatch` fixture, auto-restored), applied
to a real, on-disk PDF built with genuine `insert_text` content:

- `get_text("words")` is the only intercepted call; it returns the GH-789/790
  fixture's controlled word-geometry (same grid, same "n.a." orphan).
- `get_text("text"/"dict")` and every other call fall through to the real
  PyMuPDF implementation, reading the genuinely inserted text — so the
  born-digital heuristics (char/word counts, garbage ratio, direction) pass
  on real data, not simulated ones.
- `find_tables()` is strategy-dispatched: the default (lines) call sees a
  `_StubTable` (valid bbox, `extract() -> []`) so `has_tables=True` (routing
  into the `extract_structured` branch) while `_table_to_markdown` ships
  nothing for it, falling through to the text-strategy fallback under test;
  the `vertical_strategy="text"` call sees the GH-789/790 destroyed grid.

Verified interactively (`/tmp/try_fixture.py`, `/tmp/try_phase_analyze.py`)
before writing the test: `BornDigitalDetector.detect()` on the constructed
PDF produces `PageAssessment.orphan_word_drops == [{'word': 'n.a.', ...}]`,
and `UnifiedPipeline._phase_analyze` on the same PDF appends exactly one
`AuditEvent(kind="orphan_word_dropped", data={"dropped_count": 1, "words":
["n.a."]})` to `state.events`.
