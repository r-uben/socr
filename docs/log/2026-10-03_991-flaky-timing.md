# 2026-10-03 GH-991: flaky wall-clock tests

Tests only; no `src` change. No src bug found behind any of the four.

## Causes and fixes

| Test | Cause | Fix |
| --- | --- | --- |
| `test_gh974_review_pins::test_budget_is_shared_across_the_tables_on_one_page` (and sibling `test_same_page_only_the_budget_differs`) | Fake rungs `time.sleep(0.3)` against a 0.5s budget on the real clock. Under load a sleep overshoots, so the third call lands in or out of the budget unpredictably. | `PageLadderBudget` already takes a `clock`. The tests patch the class (at call time, as the orchestrator imports it) to read a virtual clock that each fake rung advances by `SLOW`. Same asserts, no scheduler dependence. |
| `test_gh172_killable_boundary::test_kill_is_process_group_wide` | `run_killable`'s deadline starts at spawn. The spawned child must import the test module (httpx, pytest) and fork the grandchild first. Under load the 1.5s deadline fired before the grandchild existed: no pidfile (`FileNotFoundError`), or a kill of a group with nothing in it. Pidfile was also written non-atomically. | `Connection.poll` is wrapped so the deadline's single `poll(timeout)` starts only after the pidfile exists (event wait, 60s hang guard). Pidfile published with `os.replace`. Death of the grandchild is polled (60s guard) instead of a 2s window. The sleeper is always SIGKILLed in `finally`. |
| `test_gh172_killable_boundary::test_run_killable_bounds_a_trickling_call` | Bound `1.5 + 2.0` is below `run_killable`'s own documented worst case (term grace 3s + kill grace 3s) and ignores process start-up, which scales with load. | Bound is now deadline + `DEFAULT_TERM_GRACE_SEC` + `DEFAULT_KILL_GRACE_SEC` + one start-up measured on the same host just before (a no-op `run_killable`). A trickle is unbounded, so this still separates bounded from not. |
| `test_gh172_judge_killable::test_probe_exits_in_a_child_process` (and sibling `test_judge_call_exits_in_a_child_process`) | The lifetime assertion timed the whole child process, including interpreter start and `import socr`, against a 5.5s bound. | The child prints `time.monotonic()` once imports are done; the lifetime is measured from that mark to full process exit, so interpreter teardown (the thing pinned) is still inside. The subprocess hang guard is 60s. |

## Follow-ups

- The two in-process tests in `test_gh172_judge_killable.py` (`..._bounded_and_typed_in_process`, `..._against_a_trickling_peer`) keep a `1.5 + 4.0` bound that includes `proc.start()`. They did not flake; same hazard in principle.
- `test_gh974_page_budget_daemon::test_budget_exhausted_page_...` still uses real sleeps, with a generous `elapsed` bound. Not touched.

## Review round 1 (Astra, cubic)

- Trickle test lost deadline sensitivity: a `poll(timeout * 3)` mutant (4.5s wait) passed the widened bound. Fix: the start-up allowance is now measured with a bare `multiprocessing` spawn child, not through `run_killable`, and a new deterministic test (`test_run_killable_hands_the_requested_deadline_to_poll_unchanged`) spies on `Connection.poll` and requires the requested timeout to arrive unchanged. The `* 3` mutant is killed by the new test (the broad bound still passes it, by design); the `* 8` mutant is killed by both.
- Group-kill test: the `poll` wrapper no longer raises when the pidfile never appears (that skipped `run_killable`'s kill and leaked the child). It returns, lets the real poll and kill run, and the test then fails with a clear message.
- Stress after (30 runs, 30 `yes` x 4 parallel streams): group-kill 30/30, trickle 30/30, probe 30/30, budget 30/30. Re-ran mutants `*3`, `*8`, direct-child-only kill: all killed.
