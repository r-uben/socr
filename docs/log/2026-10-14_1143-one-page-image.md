# #1143 — a withheld-table marker repeated the full page image once per table

Date: 2026-10-14. Branch `fix/issue-1143`. Base `main` 25daab9f.

## What shipped

Forney 1988 p22 (`scratch/routing-baseline/review-pages/in/d_forney_p22.pdf`,
output under `review-pages/out/d_forney_p22/`) is a scan carrying an old OCR
text layer. Its page sidecar records `scanned_prose_recovered: true`,
`ending: fail_closed_marker`, `primary_reason: scanned_table_unverifiable`, and
`d3_floor_png_ref: "![Failed table page 1](figures/failed_table_p1.png)"`.

The page shipped **twelve** copies of

```
[page 1 failed: unverifiable table — see image]

![Failed table page 1](figures/failed_table_p1.png)
```

— the same whole-page render, twelve times. Owner, reviewing that output:
"I see the figure repeated all the time."

## Diagnosis

One emitter, one call site.

`native_prose_floor_text` (`src/socr/core/manifest.py`) is the #649 / #652
prose-recovery lane: on a scan that reached the table floor with no table
geometry at all, it ships the page's own prose bands and replaces each
contiguous run of numeric bands with the fail-closed marker. Since #649 round 2
there is **one marker per contiguous withheld run**, deliberately: the
withholding predicate covers every printed digit, so a prose line carrying a
value is withheld mid-paragraph, and a single marker at the top of the page
would elide it in silence.

The bug was that the per-run block was `marker_line + "\n\n" + png_ref` — the
image EMBED travelled with every marker. Forney p22 has twelve withheld runs,
so the picture shipped twelve times. Its only production caller is
`manifest.py:3369` (the GH-90 scanned-table fail-closed branch).

Every other emitter of this marker already embeds once per page:

- `splice_failed_table_regions` — `if ordinal == first_failed_ordinal and png_ref`;
- `_all_native_text` — one marker, one embed, beside the text;
- `table_floor_text_for_source`'s whole-page fallback — one block;
- the `d3_floor_kept_model_output` path — one appended ref;
- `page_unchecked_mark` / `disputed_table_mark` — one embed, then plain links.

## The fix

`native_prose_floor_text` now embeds `png_ref` **once, directly under the
banner**, and every withheld run keeps its own marker, byte-identical, followed
by a plain `[page image](figures/failed_table_pN.png)` **link** to that one
file.

Under the banner, not at the first withheld run. The geometry lane
(`splice_failed_table_regions`) puts its single embed at
`first_failed_ordinal` because there the first failed ordinal **is** a table.
Here nothing is: this branch runs with `detected_table_count == 0`, the withheld
unit is a contiguous run of withheld bands (numeric bands, plus any band that
parses as markdown table syntax, numeral or not), and since #649 round 2 run 1 is
routinely a lone prose line that happened to print a year or a percentage while
the page's real table is run 8. Argon's review (2026-10-14) made that case: an
embed at run 1 would blow a paragraph apart over a stray digit and leave the
table itself holding a link that points backwards. A whole-page render is a
page-level artefact, so it belongs beside the page-level banner, and every
marker then carries identical bytes. This is also the arrangement
`page_unchecked_mark` (one embed, on the page's first line) and
`disputed_table_mark` (a plain `[page image](...)` link per table) already ship.

A new named helper, `page_image_link(png_ref)`, reads the path back out of the
pre-rendered embed with `_IMAGE_REF_PATH_RE`, the same regex those two marks
already use. There is no typed logical path beside `d3_floor_png_ref`:
`_render_d3_floor_png` (`src/socr/pipeline/orchestrator.py:5371`) returns the
markdown string and nothing else, `PageState.d3_floor_png_ref` stores exactly
that, and `AssetRef.logical_path` is only populated later, by
`_local_page_asset_refs` parsing the markdown. The regex is safe for this
producer: `figures/failed_table_p{N}.png` carries no space or parenthesis. The
helper returns `""` for anything that is not an embed, so a failed render ships
bare markers and no top embed at all.

A link rather than a second embed, on purpose. `page_unchecked_mark` records the
reason in its own comment: **manifest asset discovery collects embeds only**
(`_local_page_asset_refs` scans `![...]` tokens), so a page whose only reference
is a link loses the PNG on a replay into another directory. Keeping one embed on
the page makes the file a recorded asset, and the links lean on it.

### Why not per-table crops

Ruled out, and not for cost alone:

1. This branch runs with `detected_table_count == 0` and no bbox. That is the
   lane's precondition, not an accident — it is why the GH-520 coverage guard
   cannot apply here (see the caller's comment at `manifest.py:3312`). There is
   no table geometry to crop to.
2. A withheld "run" is not a table. Since #649 round 2 the unit is a contiguous
   run of bands at or above `ROW_SHAPE_MIN` numeric tokens, which can be a
   single prose line carrying a printed value mid-paragraph. A crop of that is
   one line of prose, not a table picture.
3. A crop per run is one more render each, and a new way to clip the numbers the
   floor exists to protect. The whole-page render is already the choice
   `_render_d3_floor_png` documents for exactly this reason: "the full page is
   always safe: it preserves everything visible."

between two runs of the same code in one process, changing only the band

  `banner \n\n png_ref \n\n`, and the embed precedes the first marker.

  embed, pinned as a difference against the arm that has an image.
- `page_image_link` abstains on a bare path and on a non-embed link.
- a `png_ref` that is non-empty but not a parseable embed (defensive: the only
  producer returns `""` or a well-formed embed) still ships it once and leaves
  the markers bare rather than linking something broken.
- through `process()`, hermetic (no provider, no judge, no ollama probe, no

## Found during review, NOT fixed here

Argon's adversarial pass (2026-10-14) named two live interactions. Neither is
introduced by this change; both predate it. They are recorded rather than
patched because each needs a ruling this ticket does not carry.

1. **`_apply_unverified_table_mark` can prepend a SECOND page-image embed above
   the banner, and break resume.** `manifest.py:4456` prepends
   `page_unchecked_mark(...)` — which emits `![page image](...)`, an EMBED — when
   `p.unchecked_table_kind` is set and the text does not already match
   `PAGE_UNCHECKED_MARK_RE`. A prose-recovery page is not a failure marker
   (`is_page_failed_marker` returns False on it, deliberately), so it is not
   exempt.

   Reachable: `settle_scanned_table_decision` (`pipeline/agentic.py:305-309`) can
   return a promoted attempt **and** set `decision.accepted = False`. The floor
   branch (`orchestrator.py:10192`) then fires on `not decision.accepted`, and the
   unchecked-mark branch (`orchestrator.py:10208`) fires on the returned attempt.
   Both flags land on one page. The result is two embeds — this ticket's own
   defect class — and a body that no longer starts with
   `SCANNED_PROSE_RECOVERED_FLAG`, so `_is_restored_prose_recovery` stops
   recognising it and the next run rebuilds instead of returning the frozen bytes.

   Not fixed here because the only cheap fix is to suppress the unchecked mark on
   such a page, and suppressing a warning signal is exactly what this repo
   forbids. Keeping the signal while changing its FORM (link instead of embed, as
   `disputed_table_mark` already does) is the shape a fix should take, and that is
   an owner call. Worth a ticket.

2. **A missing PNG leaves the links dangling.** `normalizer.strip_phantom_images`
   (`core/normalizer.py:200`, `_RE_MD_IMAGE` at L66) removes `![alt](path)` whose
   target does not exist, and ignores plain `[...](path)` links. If the render is
   recorded but the file later goes missing, the one embed is stripped and every
   `[page image](...)` link survives broken. The same exposure already applies to
   every link `disputed_table_mark` ships, so widening that shared helper is its
   own change. A dangling link is clutter, not a lost number, which is why it did
   not block here.

3. **Pre-existing: a page can ship with zero recovered prose.** `prose_bands` is
   filtered at `manifest.py:2741` *before* the `table_syntax` demotion at
   `manifest.py:2829`, so a page whose only numeral-free bands are pipe-table
   header/separator lines passes the `not prose_bands` guard and then has every
   band demoted — shipping banner + embed + marker and no paragraphs. Untouched by
   this change; noted because the review surfaced it.
