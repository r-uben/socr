## What the extraction produces on the dense fixture (proving the failure)

Running `BornDigitalDetector().extract_structured()` on `ce_like_p4_dense.pdf`:

1. `find_tables(strategy="lines")` detects 1 table (triggered by outer border + column
   separator strokes). The table is `_is_lane_stacked=True` because the 1-pt name/value
   offset causes cells with embedded `\n`-stacked tokens (e.g. first data row cell
   contains "Alpha Economics\nBeta Research\n..." stacked together).

2. Routes to `rowize_from_word_list` on the region's words. The rowizer groups words by
   `round(y0)`: value tokens at y=135.34 round to 135; name tokens at y=136.34 round to
   136. These are DISTINCT y-groups.

3. The median gap between the rounded y-groups is ~1 pt (alternating 1-pt and 10-pt
   gaps), so the split threshold = max(1.5*1, 10.0) = 10.0 pt. All name/value pairs
   stay in ONE segment — but produce INTERLEAVED rows:

   ```
   |  | 2.3 | 1.9 | 2.1 | 2.4 |   <- data row, empty label
   | Alpha Economics |  |  |  |  | <- name row, no data
   |  | 2.0 | 1.4 | 2.2 | 1.8 |
   | Beta Research |  |  |  |  |
   ...
   ```

4. The `TestDenseFixtureSanity::test_dense_extraction_reproduces_interleaved_failure`
   test PASSES (asserts that label-only rows and data-only rows are present), confirming
   the fixture faithfully reproduces the real-CE failure mode.
