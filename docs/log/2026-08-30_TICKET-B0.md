# 2026-08-30 — TICKET-B0: table witness preparation (GH-353)

## What changed

New `src/socr/tables/witness.py`: `prepare_table_witnesses(pdf_path, page_num,
markdown, *, crop_dpi=DEFAULT_CROP_DPI)`, a context manager yielding one
`TableWitness` per emitted markdown table block on the page.

- Blocks come from `reconcile.find_table_blocks` (reused, not reinvented).
- Boxes come from `locate.locate_tables`.
- Association is by count, not position-guessing when counts disagree:
  - `n_boxes == 0` → every block is `WitnessStatus.MISSING` (borderless table,
    no geometric anchor at all).
  - `n_boxes != n_blocks` (any mismatch, not just under-merge) → every block on
    the page is `WitnessStatus.AMBIGUOUS`. This covers the documented
    over-merge in `tables/locate.py:132` (`bands_from_rules` groups rules by
    x-overlap only, with **no vertical-gap check at all**, so two stacked
    booktabs tables sharing a column span always merge into one band
    regardless of how far apart they are) as well as the symmetric case of an
    extra spurious box.
  - `n_boxes == n_blocks` → 1:1 pairing in reading order, `WitnessStatus.LOCATED`.
- `LOCATED` witnesses get a rendered crop (`crop_path`), mirroring
  `TableCropExtractor._render_crop`'s geometry/rotation handling but wrapped in
  the context manager so every crop file is unlinked in a `finally`, even if
  the caller raises mid-ladder — no caller-owned cleanup discipline required.
- Every failure path (missing/unreadable pdf, `locate_tables` exception, crop
  render/save failure) degrades to a representable state (`MISSING`, with a
  `note`) instead of raising. `boxes_found_on_page` and `note` carry enough
  detail for the B1 gate's audit events.
- Stable per-page table ids: `f"p{page_num}-t{idx}"`, reading order.

Deliberately reused `_CROP_PADDING_PT` / `DEFAULT_CROP_DPI` from
`tables/extract.py` rather than re-deriving new magic numbers for the same
crop geometry (precedent for cross-module private-constant imports already
exists, e.g. `header_cut.py` importing from `reconstruct.py`).

## Deviations / follow-ups

- No `TableWitness.boxes` list of candidate boxes for the AMBIGUOUS case —
  kept it to a diagnostic count (`boxes_found_on_page`) plus a `note` string,
  since B1's audit events need a reason string more than a raw box list and
  nothing in TICKETS.md asked for the candidate geometry itself. If B1 needs
  the actual ambiguous boxes for a richer audit payload, that's a small
  additive change to `TableWitness`, not a redesign.
- B1 will need to call `prepare_table_witnesses` per page (not per document);
  the context manager's per-call `open_pdf`/`doc.close()` (once for locate,
  once per crop render) trades a few extra document opens for keeping this
  module's failure modes fully local and hermetic to test. If B1 measures
  this as a hot path across a long document, batching the opens is a
  contained follow-up inside `witness.py`, not a B1-side workaround.
