# 2026-08-30 — TICKET-B0: table witness preparation (GH-353)

## What changed

New `src/socr/tables/witness.py`: `prepare_table_witnesses(pdf_path, page_num,
markdown, *, crop_dpi=DEFAULT_CROP_DPI)`, a context manager yielding one
`TableWitness` per emitted markdown table block on the page.

- Blocks come from `reconcile.find_table_blocks` (reused, not reinvented).
- Boxes come from `locate.locate_tables`.
- Association is by count, not position-guessing when counts disagree:
  - `n_boxes == 0` → every block is `WitnessStatus.MISSING` (borderless table,
    no geometric anchor at all).
  - `n_boxes != n_blocks` (any mismatch, not just under-merge) → every block on
    the page is `WitnessStatus.AMBIGUOUS`. This covers the documented
    over-merge in `tables/locate.py:132` (`bands_from_rules` groups rules by
    x-overlap only, with **no vertical-gap check at all**, so two stacked
    booktabs tables sharing a column span always merge into one band
    regardless of how far apart they are) as well as the symmetric case of an
    extra spurious box.
  - `n_boxes == n_blocks` → 1:1 pairing in reading order, `WitnessStatus.LOCATED`.
- `LOCATED` witnesses get a rendered crop (`crop_path`), mirroring
  `TableCropExtractor._render_crop`'s geometry/rotation handling but wrapped in
  the context manager so every crop file is unlinked in a `finally`, even if
  the caller raises mid-ladder — no caller-owned cleanup discipline required.
- Every failure path (missing/unreadable pdf, `locate_tables` exception, crop
  render/save failure) degrades to a representable state (`MISSING`, with a
  `note`) instead of raising. `boxes_found_on_page` and `note` carry enough
  detail for the B1 gate's audit events.
- Stable per-page table ids: `f"p{page_num}-t{idx}"`, reading order.

Deliberately reused `_CROP_PADDING_PT` / `DEFAULT_CROP_DPI` from
`tables/extract.py` rather than re-deriving new magic numbers for the same
crop geometry (precedent for cross-module private-constant imports already
exists, e.g. `header_cut.py` importing from `reconstruct.py`).

## Deviations / follow-ups

- No `TableWitness.boxes` list of candidate boxes for the AMBIGUOUS case —
  kept it to a diagnostic count (`boxes_found_on_page`) plus a `note` string,
  since B1's audit events need a reason string more than a raw box list and
  nothing in TICKETS.md asked for the candidate geometry itself. If B1 needs
  the actual ambiguous boxes for a richer audit payload, that's a small
  additive change to `TableWitness`, not a redesign.
- B1 will need to call `prepare_table_witnesses` per page (not per document);
  the context manager's per-call `open_pdf`/`doc.close()` (once for locate,
  once per crop render) trades a few extra document opens for keeping this
  module's failure modes fully local and hermetic to test. If B1 measures
  this as a hot path across a long document, batching the opens is a
  contained follow-up inside `witness.py`, not a B1-side workaround.

## Round 2 (review fixes, 44e2d2e)

Reviewer verdict: REVISE, two unconditional fixes (pairing design deferred to a
consilium panel running in parallel):

1. Added `test_located_two_blocks_two_boxes_pair_in_order` — 2 emitted blocks,
   2 distinct non-overlapping-x-and-y ruled boxes → both `LOCATED`, asserting
   the correct block↔box pairing. This was the only untested shape (the most
   common real multi-table page).
2. Documented the residual assumption explicitly in the module docstring:
   index-pairing on count-match assumes markdown block order equals
   `locate_tables`'s geometric `(y0, x0)` sort order. Holds for single-column
   layouts (all fixtures so far); unverified for side-by-side / multi-column
   layouts, where two tables can share a `y0` band and geometric order need
   not match emission order.

Building the `two_ruled` fixture surfaced a real locator behavior: two
same-column-span ruled tables at different y-offsets produce not 2 but 3
boxes — `bands_from_rules` groups ALL horizontal rules on the page by x-overlap
only (`_RULE_X_OVERLAP = 0.6`), so it also emits a spurious third band merging
both tables' rules, and IoU-0.5 dedup doesn't catch it (its overlap with
either real box falls under the threshold). Fixed by giving the two tables
non-overlapping x-column ranges instead of non-overlapping fixture code paths.

## Round 3 (consilium-driven pairing corroboration, feat commit)

The panel (3 rounds) considered strict per-page verification of the index
pairing and rejected it: E1's mechanical binding check (`tables/binding.py
bind()`) is deliberately contradiction-only, NEUTRAL when there's no
coverage — and binding coverage was separately measured incomplete on 12 of
13 corpus table pages (see `docs/log/2026-08-30_table-judge-ladder.md`) — so
witness pairing cannot lean on E1 as a general-purpose safety net. But a
strict "prove the assignment" gate at B0 would itself mass-demote
count-matched pages under ordinary matching noise (sparse native text,
tables with few or no numeric values) — the exact failure mode E1's own
NEUTRAL-on-no-coverage rule exists to avoid. Verified this is not a
theoretical worry but the fixture's own most-common state: the
`test_corroboration_neutral_no_native_words_ships_index_pairing` case (blank
rule-only interior) still ships `LOCATED` — that's the majority-shape
behavior a naive "require corroboration" rule would break.

Decision: count-matched pairs get lightweight corroboration, not
verification. For every pair of indices `(i, j)` (n >= 2 boxes/blocks),
compare each box's native numeric-token evidence (page words clipped to the
box, reusing `native_verifier`'s numeric-token primitives —
`_numeric_tokens_from_text` / `_numeric_multiset_from_tokens`, the same
seam `source_evidence.py` already imports across module boundaries) against
both candidate blocks' emitted numeric tokens. Structural, threshold-free
majority test — swap `(i, j)` is a contradiction only when BOTH box `i`'s
matched evidence strictly favors block `j` over its own paired block `i`,
AND box `j`'s matched evidence strictly favors block `i` over its own
paired block `j` (two-sided strict inequality, no float score-difference
cutoff). Any tie, one-sided preference, or absent evidence is neutral by
construction (0 can never exceed 0) and ships the index pairing unchanged.
Contradicted pairs demote BOTH members to `AMBIGUOUS` — never a silent
swap, never an auto-repair.

Sanity-checked the contradiction path is not vacuous with an ad-hoc script
reproducing the swapped-content fixture standalone (outside pytest, printing
the raw `_corroboration_contradicted_indices` output) — confirms `{0, 1}` is
returned for the deliberately swapped case, not an empty set.

New tests (4): `test_corroboration_neutral_ships_normal_order` (corroborated
→ `LOCATED`, correct pairing), `test_corroboration_contradicted_swapped_content_demotes_to_ambiguous`
(swap → both `AMBIGUOUS`, no box/crop, note mentions corroboration),
`test_corroboration_neutral_no_native_words_ships_index_pairing` (zero
native-word coverage → `LOCATED`, pins the no-mass-demotion property),
`test_corroboration_tie_identical_tables_ships_index_pairing` (identical
tables tie → `LOCATED`, swap harmless). All via a new `_two_ruled_boxes_pdf`
fixture helper (two 2x2 ruled tables, non-overlapping x-spans, per-cell text
controllable to `None` for a blank/rule-only interior).
