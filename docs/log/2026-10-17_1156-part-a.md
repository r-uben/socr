# #1156 Part A — the earlier-OCR-layer family: trust, detection, routing, retention

Issue #1156 split by the owner on 2026-10-17 (evening). Part A merges first and unblocks
the Fed run. Part B (the comparator and the masked-prose ruling) re-finalizes the pages
Part A retains, with no re-OCR.

Built on a branch cut from `origin/main` `e4f87e04`, re-applying by hunk from
`fix/issue-1156` (`c00651fd..35a00024`), which is 9 behind and carries Part B.

## What ships

A page whose text layer is an EARLIER OCR run's reading, not the document's own
characters:

* is never native-trusted and contributes no numbers to any check;
* is routed to a model for a reading (`needs_ocr_enhancement`);
* if the reading is accepted, it ships, and the page is MARKED — never CHECKED;
* if the reading is rejected, or none ever ran (no provider, `--native-only`), the page
  ships the page image plus the "earlier OCR, not re-read" mark, with no prior-layer text
  and no numbers;
* either way `prior_ocr_retained_pages` keeps the document out of SUCCESS, and the
  acceptance meter raises `prior_ocr_unchecked` in BOTH lanes;
* the original layer is retained in the page sidecar as `prior_ocr_layer_text`, numbers
  included, unshipped, so Part B can recover its prose by re-finalizing from it.

No masking, no comparator, no `withhold_shreds`, no `numbers_withheld`.

## The #1189 collision, and why `get_bboxlog` is relied on

The detector's second route reads the page's DRAWING ORDER (`page.get_bboxlog()`) to find
text painted over by a later opaque raster — the shape #961's render-mode test cannot see,
and the one every CHECKED page of the Fed pilot had.

The old branch also added a guard to #961's `_has_invisible_text_over_raster`, which
called `page.get_texttrace()`: that call ABORTS the interpreter (`Fatal Python error:
none_dealloc`) on PyMuPDF 1.27.2.x by decrementing `None`'s refcount once per span. Not an
exception — no `except` runs. **That guard is dropped here: main merged #1189, which
removed every `get_texttrace` call** and answers the visibility question from the text
layer's own `alpha` (`source_evidence.text_layer_invisible_char_counts`). The finding the
guard answered (`test_the_aborting_trace_is_skipped_when_its_answer_cannot_be_yes`) is now
satisfied by main having no such call at all, which is strictly stronger; and the alpha
route also catches render mode 0 with a transparent fill, which the old render-mode test
scored as visible.

That left the detector depending on a PyMuPDF C API nobody had cleared of the same defect,
on a route meant for ~350,000 Fed pages. So it was measured, on the affected wheel
(PyMuPDF 1.27.2.3), before being relied on — `scratch/1156a/bboxlog_refcount_probe.py`.

Method: one process; a settling call plus `gc.collect()` FIRST, because import-time
temporaries release ~1,100 `None` references on the first collection of a fresh process and
otherwise read as a one-off leak on whichever page is measured first (this artefact was
initially mistaken for a real leak here); then N repeated calls on one page and the delta
in `sys.getrefcount(None)`. A real per-call leak is linear in N, so each page is measured
at N=20 and N=200.

Result, 239 page-measurements over the first three pages of 80 corpus PDFs
(`scratch/1156a/bboxlog_probe.txt`):

| API | leaking pages | worst per-call delta |
|---|---|---|
| `get_bboxlog` | 0 of 239 | +0.000 |
| `get_texttrace`, same harness, same pages | flagged on the first page measured | the interpreter ABORTED (exit 134) within 8 PDFs |

So the harness demonstrably detects the real defect, and `get_bboxlog` does not have it.
The measurement is of refcount deltas on this wheel and these pages; it is not a proof
about other PyMuPDF versions.

## Scope decisions inside Part A

**`reading_agreement` is omitted.** The old clause gave a suspect page an escape when the
comparator's record said `agreed`. Part A ships no comparator, so nothing could ever write
that record and the escape is unreachable. The clause therefore fires unconditionally on a
suspect page, which IS Part A's rule. Part B adds field, escape and comparator together.

**The withholding floor fires on POSITIVE detection by the #1156 route only** —
`prior_ocr_layer`, never `prior_ocr_layer_scan_failed` and never
`invisible_text_over_raster`. Four earlier review rounds found a flag meaning "trust this
less" removing a check instead of adding one; this flag's additive consequences (no trust,
no numeric evidence, the mark, the document bucket) run on the union flag, while the one
DESTRUCTIVE consequence runs only on a finding. A failed scan is "unknown", which is not a
finding. #1027's and #961's own key keeps its own ending, and the new branch is placed
AFTER #1027's so those pages are byte-for-byte as they were.

Unlike #1027's floor the new one is NOT gated on `_model_attempt_ran`: the owner's interim
names "rejected, or never ran" together.

**The document bucket is every suspect page with an output that did not fail** — no engine
or status narrowing. The page's mark and the document's status then read the same
condition, rather than two conditions that have to be kept in step; narrowing it to native
winners is what let a model reading of such a scan ship SUCCESS unmarked while the meter
flagged the same page.

**The page image is a key of its own** (`prior_ocr_page_png_ref`), not #1027's: that one
also gates the scanned-figure caption lane, which keys on `invisible_text_over_raster` and
must not start firing on this family.

## Two soundness fixes to the ported detector, each measured first

Neither is in the handover; both are the same shape as this issue's recurring defect — a
check answered from the wrong evidence.

**The opacity test paired images by list POSITION.** For the Nth image in the DRAWING
ORDER it read `get_image_info(xrefs=True)[N]`, an ordering agreement between two different
PyMuPDF APIs that nothing guarantees. Measured over 598 pages of 150 corpus PDFs
(`scratch/1156a/image_pairing_probe.py`): **25 pages disagree on the image count, every one
of them with FEWER images in the drawing order than `get_image_info` lists**, so from the
first missing one onwards each drawn image was judged by another image's metadata. Where
the counts agreed, every bbox agreed to better than 0.5 pt — zero mismatches — which is
where `_IMAGE_BOX_TOLERANCE_PT` comes from. The old code also had a desync of its own: it
advanced its counter only for images whose box survived clipping to the page, while `infos`
lists them all. `_image_info_for_box` now pairs on geometry and returns `{}` when nothing
matches, which `_image_is_opaque` reads as NOT opaque — fail-closed for both callers (the
page keeps its native check; the witness test says "no independent reading").

Effect on detection, measured by running both pairings side by side against the live
helpers (`scratch/1156a/pairing_effect_probe.py`): **0 flips over 594 pages**, 80 pages
detected either way. So this removes an unguaranteed assumption and is inert on everything
measured. It is not a fix for an observed detection error, and is not claimed as one. The
shape where it would matter is pinned synthetically by
`test_the_opacity_test_is_not_fooled_by_an_extra_metadata_entry`.

**The furniture cache was keyed on `id(doc)` without holding the document.** `id()` is
unique only among LIVE objects, so a `fitz.Document` freed between two calls lets CPython
hand its address to the next one, and the witness test would then be answered from another
document's running headers — in whichever direction that document's furniture happened to
lie. The entry now holds the document, which makes the key valid by construction and keeps
at most `_FURNITURE_CACHE_MAX` documents open on its account. Not measured in the wild: id
reuse is not reproducible on demand, so the test pins the invariant
(`test_the_witness_cache_cannot_hand_over_another_documents_furniture`) rather than the
collision.

Owner ruling when these were raised (2026-10-17): "Measured-harmless today doesn't mean
wrong-image lookups are safe tomorrow. Standing rule: fixes that tighten correctness plus
the runs they need never need my permission."

## A third fix: transparency is read strictly for the witness, loosely for the detector

Argon flagged that `_page_declares_transparency` does not dereference indirect graphics
states. Measured (`scratch/1156a/extgstate_probe.py`): the page-level reader finds partial
alpha on **0 of 598** corpus pages, because generators write `/ExtGState << /GS0 15 0 R >>`
and keep `/ca` inside object 15; following the references finds it on **76**. So the guard
added for Astra's round-2 finding had never fired on any corpus page.

It was NOT simply switched on. Measured effect on detection
(`scratch/1156a/transparency_effect_probe.py`): **80 → 78 over 594 pages, 2 flips**, and
both flipped pages are genuine JSTOR scans — 100% render-mode-3 text under full-page
rasters, 2,931 and 2,996 characters, all invisible. Switching the strict reader on
everywhere would stop detecting real prior-OCR scans, which is the harm this issue exists
to prevent.

The two consumers of opacity need OPPOSITE failure directions, and the flag is page-level
rather than per-image:

* the **witness** test asks "did anything independent read these pixels?", and a wrong
  "yes" lets a table skip row verification — the weakening found four times. More
  suspicion is pure gain, so the witness uses the dereferencing reader.
* the **detector** asks "is the page's text hidden under an opaque raster?", and a wrong
  "no" ships a prior-OCR layer as trusted native. So `detect` keeps the page-level reader
  and its measured 80 detections.

A per-image answer needs the graphics state at each placement, which means tracking `gs`
through the content stream — a PDF interpreter, which Argon separately advised against
reimplementing. Splitting by consumer is the honest bound: each side errs the way that adds
checks. Pinned by `test_an_indirect_alpha_state_denies_the_witness_but_not_the_detector`,
which drives the witness through its PUBLIC entry point, because asking the predicate
directly with the keyword passes even if that caller stops passing it.

# Round 2 of review (#1202): Grok, Argon and r-uben

Both seats confirmed every round-1 leak closed. What round 2 found is that round 1 fixed
them with the WRONG predicate, and the fix is a rule rather than four more patches.

## The rule, now named in the code

Round 1 wired four destructive gates to ``prior_ocr_layer_suspect``, the union, which
includes a FAILED scan. Suspicion has two different jobs and they take two different flags.
``manifest.prior_ocr_layer_found`` is now that rule, and its docstring states it:

* **The suspect layer is never EVIDENCE** -- the UNION. Nothing may pass, corroborate or
  credential a reading on the strength of the page's own text layer. Removing trust is
  always allowed, even when a model reading then falls to the floor.
* **The layer's OWN text is withheld only on a POSITIVE finding** -- ``prior_ocr_layer``
  or ``invisible_text_over_raster``. "Unknown" is not a finding, so a failed scan keeps
  its layer under the mark and every lane keeps its own artefacts: the chart figure link,
  the prose around table markers, the math splices.
* **Routing to a model may use the union**, because it only ADDS a reading. The math
  gate in ``orchestrator`` keeps it.

Measured consequence of getting this wrong (Argon 2.2, Grok P1): on a detector hiccup
alone, S1 and TR-3 deleted recovered born-digital prose, the chart lane lost its figure
link, and the math hybrid was suppressed. All four gates now read the positive finding.

## Rejected model readings inside S1 (Argon 1, P0)

The #1156 floor yields whenever ``_reaches_structure_class_branch`` is true, and three S1
branches then shipped an UNACCEPTED attempt on a flagged page:

* **``STRUCTURE_CLASS_GRID_CORROBORATED``** scored the candidate against ``p.native_words``
  -- the suspect layer itself -- and a hard-rejected grid shipped its numbers on that
  strength. ``_row_corroboration_scan`` now abstains on a suspect page (the UNION: unknown
  is not a reason to trust those words either). Abstaining removes trust without deleting
  anything; the page falls to its own floor, marker and image intact.
* **``STRUCTURE_CLASS_JUDGE_TIMEOUT_CREDENTIALED``** is credentialed by
  ``page_credential``: a rendered witness IMAGE's digest and scope plus a completed
  acceptance with a real rung for every table, bound to the bytes about to ship. That is
  independent of the text layer, so it STAYS, and this paragraph is the record of why.
* **``STRUCTURE_CLASS_GRID_FLAGGED``** ships the MODEL's disputed grid, not the layer, so
  principle 2 was already satisfied. What the owner's 2026-10-12 ruling also requires of a
  disputed scanned table is a page-image link beside the mark, and this branch carried the
  marks without one. On a flagged page that link is the only way a reader can check a
  disputed number, because the layer cannot be the check. Added, flagged pages only.

## A PyMuPDF ValueError is a failure, not an answer (r-uben blocker 5)

Round 1 stopped the transparency readers swallowing failures by narrowing the catch to
``(IndexError, TypeError, ValueError)``. PyMuPDF's own ``xref_get_key`` raises
``ValueError("bad xref")``, so the narrowed catch still swallowed the commonest real
failure.

**Correction (round 3, r-uben soft 6):** this paragraph first said the page "shipped clean
SUCCESS with ``3 Y,``" at round 2's head. It did not -- it floored. The swallowed
``ValueError`` made ``_page_declares_transparency`` answer False, which makes images read
as OPAQUE and therefore makes the detector LOUDER, not quieter, so the page was still
caught. The harmful direction is answering True, which makes no image opaque and the scan
invisible; that is what ships clean SUCCESS, and it is the direction the mutant now takes.
The fix is right either way -- a PyMuPDF failure must be "unknown" rather than an answer --
but the claim about what the defect DID was wrong, and the same error made two of my own
mutants inert in round 2.

A malformed VALUE raises ``ValueError`` too (``float()`` on a non-numeric alpha), so no
``except`` clause can separate them by type. They are separated by WHERE instead: the
document reads sit outside any try and propagate, and only the parsing of an
already-fetched string is guarded, in ``_any_alpha_below_one``. Both exception kinds are
now driven through ``process()`` in the test, and the docstrings that said "Raises
nothing" and "on any failure" are corrected.

## The marker must describe the body it ships with (r-uben 8)

A scanned-figure page carried "not transcribed, see PDF page N" beside a picture of
itself, because the figure guard appends its image after selection. The floor's marker now
counts any image that will ship, not only its own. gh1030's comparison test pins the
difference explicitly, which says more than the equality it replaced.

## The grid, rebuilt (Argon 2.4, Grok P2)

Round 1's grid had 45 green cells and 18 were vacuous: the ``s1_prose`` and ``tr3_splice``
families used synthetic bboxes over text with no parseable table, so neither lane was ever
entered and reverting their fix left every cell green. Rebuilt on gh520's real
``TWO_PARSEABLE_TABLES`` fixture and the header-unattributed branch; the accepted arms no
longer overwrite ``best_output``; a third flag family (#961's positive route) and a
scan-failed family were added, and each family's fix is reverted in its own mutant.

Two of my own mutants were themselves inert and had to be retargeted: they restored the
old swallow in the direction that makes the detector LOUDER, so the page was still caught.
The direction that hurts is answering "declares transparency", which makes no image opaque
and the scan invisible. The corroboration fix is pinned at the helper, because the S1 route
needs a real page's geometry to reach the pool and a synthetic end-to-end cell would pass
either way; its control arm asserts the unflagged page still produces a scan.

## The acceptance meter (Argon P1)

``PRIOR_OCR_UNCHECKED`` was missing from ``VIOLATION_CLASSES``, so even where a rule raised
it the class never reached ``to_json()["violations"]`` or ``format_report()``. ``rule_chart``
never raised it at all, which is the lane that ships the layer. Every lane now names it --
including ``rule_native_math``, which could not count a flagged page clean but said only
THAT a page was unclean, never WHY.

(Argon 2.1/2.4, reproduced from his probes):

* **positive** — `_binding_evidence_for_witness` binds a model table against
  `page.get_text("words")`. On a suspect page those are the earlier OCR run. When the
  VISUAL readers FAIL a table, `_resolve_table_guard_chain` lets `BindingEvidence.PASS`
  overrule them, `_mint_table_acceptance_credential` mints a credential, and
  `STRUCTURE_CLASS_JUDGE_TIMEOUT_CREDENTIALED` ships the visually-rejected numbers. Round
  2 checked what that credential WAS (an image-witness digest) and not what the digest
  attests — the acceptance behind it had been bought with the layer.
* **destructive** — a VLM read `-350` where the layer had dropped the minus.
  `forced_by_binding` clamps the visual PASS to UNVERIFIED and
  `_withhold_contradicted_unverified_tables` destroys that table and its siblings.
  Painted-under text is render mode 0, so `text_layer_is_visible` says the layer is
  visible and the contradiction check never abstains.

### Fixed at the source, with one predicate

`state.layer_is_admissible_evidence(ps)` — "may this page's own text layer be used as
EVIDENCE about a reading?" — takes the UNION, because unknown is not a reason to trust the
words either. Refusing evidence is never destructive: each consumer abstains into the
no-text-layer path it already has.
