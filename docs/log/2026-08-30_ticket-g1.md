# 2026-08-30 — TICKET-G1: flag, config, fingerprint prep (GH-353)

## What changed

Added the config surface for the table judge ladder — a default-off flag plus
every knob the ladder needs, so later tickets (A2/A3/B1/H1) can inject dummy
rung identities in tests instead of reading bare constants.

`PipelineConfig` (`src/socr/core/config.py`):
- `table_judge_ladder: bool = False`
- `table_judge_rung1_model: str = "glm-5.3-flash:cloud"` (the GH-356 bake-off
  winner)
- `table_judge_rung1_host: str | None = None` — resolves the same way
  `ollama_host` does (env var, then localhost default); NOT hardcoded
  localhost.
- `table_judge_rung2_binary: str = "gemini"`
- `table_judge_timeout_sec: float = TABLE_JUDGE_TIMEOUT_SEC_DEFAULT` (600.0) —
  a new named module constant, not a bare literal, documented with the
  bake-off measurement it comes from: glm-5.3-flash exceeded a 300s cap on a
  dense grid and was still *correct* on retry at a 590s cap
  (`docs/log/2026-08-30_gh356-bakeoff.md`), whose explicit follow-up reads
  "timeout >= 600 s". A timeout is documented as ¬S1
  (escalate-as-substitute), never a FAIL, per the ladder design.

Also documented (not implemented — B1's job) the `--strict-local` + ladder
interaction: both rungs are cloud, so the combination makes every rung
unavailable before the first call; the gate must fail-open to UNVERIFIED,
never a silent PASS or an exception.

CLI (`src/socr/cli.py`): added `--table-judge-ladder` (is_flag) to
`common_options` and a matching `table_judge_ladder: bool = False` parameter
on `build_config`. Set with the same **positive-only** pattern as
`strict_local` (`if table_judge_ladder: config.table_judge_ladder = True`) —
NOT the unconditional-override pattern used a few lines above for
`judge_backend`/`judge_model`/`max_cost_per_page`/`cost_budget`/
`write_manifest` (those clobber a loaded YAML config because their Click
options carry non-None defaults of their own; `is_flag` options default to
`False`, which is indistinguishable from "not passed" unless the setter stays
positive-only). Verified: a YAML config with `table_judge_ladder: true` and no
CLI flag survives `build_config`.

Fingerprint extras (flag identity, both rung model/binary, timeout, prompt
digest) are explicitly left for TICKET-B1 per the ticket's scope.
