# 2026-08-30 — TICKET-C1: terminal enums + serialization (GH-353)

## What changed
Added `FailureMode.TABLE_REJECTED` (`"table_rejected"`) and
`FailureMode.TABLE_UNVERIFIED` (`"table_unverified"`) to
`src/socr/core/result.py`. Both are the two terminals the table judge ladder
(B1, wave 4) will write; nothing sets them yet per the ticket's explicit
scope limit — this ticket only owns the enum contract and its
serialization, not any consumer.

`FailureMode` is a plain `str, Enum` and `PageOutput.to_dict`/`from_dict`
already round-trip via `self.failure_mode.value` / `FailureMode(d.get(...))`
generically, so no change was needed to the (de)serialization code itself —
adding the two members is sufficient for the round-trip contract.

## Files
- `src/socr/core/result.py` — two new `FailureMode` members with docstrings
  explaining the REJECTED (active FAIL corroborated) vs UNVERIFIED
  (S1-exhausted, never adjudicated) distinction, mirroring the design in
  `docs/log/2026-08-30_table-judge-ladder.md`.
- `tests/test_result_table_terminals.py` (new) — distinctness, uniqueness
  across the whole enum, `PageOutput` round-trip for both terminals via
  `to_dict`/`from_dict`, raw-string parsing (sidecar-on-disk case), and a
  default-unaffected guard (`FailureMode.NONE` stays default).
