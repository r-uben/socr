# TICKET-B2: lane-aware column alignment for table exactness

Implements the merged B2 (absorbing former B3/B4) per
`docs/log/2026-08-01_TICKET-B2-design.md` and the `/consilium` panel decision
(Option A: accept the map-search freedom, document it — see criterion 8 below).

## What changed

- `src/socr/tables/native_rows.py`
  - `LabeledRow` gained two parallel, position-derived fields: `lanes` (ground
    truth) and `columns` (markdown), both defaulting to `()` so hand-built
    `LabeledRow` objects in existing white-box tests fall back to the old
    positional comparison unchanged.
  - New `_assign_lanes(raw_rows)`: page-wide (not per-region) lane clustering.
    Clusters value tokens by right edge (`x1`) and by centre, picks whichever
    partition has lower total within-cluster dispersion (tie → right edge — a
    per-partition choice). Gap cutting is parameter-free: sort the anchor
    positions, sort the positive consecutive gaps, cut at the largest *ratio*
    jump. A cluster only becomes a real lane if it has support from >=2 distinct
    rows (mirrors the GH-113 grid-establishment rule); otherwise its tokens get
    the sentinel lane index `-1` ("lane-ambiguous") and stay in `cells`/`values`
    but are excluded from alignment.
  - `_rows_in_region` no longer builds `LabeledRow` directly or does any lane
    work — it returns raw `(path, positioned-values)` tuples; lane assignment
    happens once, afterwards, across the whole page. Its docstring's stale claim
    of reusing "the native verifier's lane clusterer" (`_cluster_x_positions`,
    driven by a magic `_LANE_X_TOL_PT` constant) is corrected: label-boundary
    detection (the last-non-numeral-word rule) is and always was decoupled from
    lane clustering.
- `src/socr/benchmark/table_exactness.py`
  - `markdown_rows` now records which emitted table-cell indices are non-empty
    as `columns`.
  - New `_best_lane_column_map`: an O(L*M) Needleman-Wunsch-style DP choosing
    one global monotone injective map from lanes to columns maximizing summed
    cell agreement, independently per side being scored (each engine gets its
    own best map — Option A/C from the design note, not "penalize unmapped
    columns" (b) or "score both sides under the incumbent's map" (c)).
  - `score_rows` rewritten: row matching by label is unchanged; once matched,
    a pair is scored via the lane/column map if both sides carry lane/column
    data, else via the legacy positional comparison (the backward-compat path).
    Lane-ambiguous ground-truth values are credited on presence within their
    own row's *unmapped* markdown columns, not merged into the map.
  - `ExactnessReport` gained diagnostics-only fields (`lane_ambiguous_cells`,
    `lane_count`, `column_count`, `lane_to_column`, `unmapped_nonempty_columns`)
    for future TICKET-C1 auditing. None of them feed the score.
  - Module docstring documents the uniform-shift limitation and the map-search
    freedom (criterion 8).
- `tests/test_metric_corruption_battery.py`
  - Removed the `xfail` marker from `shift_into_adjacent_empty_cell` (criterion 1).
  - Added `test_same_shift_plus_spurious_column_never_beats_the_incumbent`
    (escalation-asymmetry, criterion 5) and
    `test_padding_with_low_entropy_columns_never_beats_a_faithful_transcription`
    (criterion 4).
- `tests/test_gh96_table_exactness.py`
  - Added `test_lane_construction_skips_the_label_numeral_and_snaps_the_sparse_row`
    (criterion 7) and `test_cells_equals_the_number_of_ground_truth_values`
    (criterion 6).
- `src/socr/tables/escalation_decision.py`
  - Annotated the module-docstring calibration table (45.0/81.7/85.0%) as
    measured under the pre-B2 meaning of `exact`; re-measurement against the
    same 16-page corpus is out of scope for this ticket (orchestrator's job per
    STATUS.md's "the real acceptance test").

## Deviation from the design note (found during implementation, not silently patched)

The design note describes gap cutting as "cut at the largest ratio jump in the
sorted gap list" without saying whether the cut threshold is one of the two
magnitudes at the jump or something between them. A naive implementation that
returns the boundary gap value itself breaks on the single most common
real-world case: a **regular, densely-populated grid** (every row present,
uniform column spacing) produces exactly **one** distinct positive gap
magnitude, repeated across every row pair. Returning that value as the
threshold and comparing with the caller's strict `>` means `gap > threshold`
is never true — no cut ever fires, and every column collapses into a single
lane.

This was caught by `test_a_perfect_transcription_scores_100` (leading-gap
fixture), which scored 60.0% instead of the required 100.0% before the fix.
The fix: return the **midpoint** between the two magnitudes at the ratio jump
(`(positive[cut_index] + positive[cut_index + 1]) / 2`), and for the
single-distinct-gap-value case treat the implicit "within-lane" floor as `0`
and return `positive[0] / 2`. This is a strictly more correct reading of the
same rule, derived from the fixture data, not a new magic threshold.
