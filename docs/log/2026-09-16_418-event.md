# 2026-09-16 — GH-418 step 1: orphan-word drop event

## Scope

Step 1 of 2 (step 2 — capture into the trailing column — is out of scope,
explicitly parked in the panel ruling). `_rowize_segment` (`reconstruct.py`)
has always dropped a word that lands further than the snap radius from every
column lane — a bare `elif` with no `else`, no log, no event. This ticket
makes that loss **visible**: no cell, column count, or markdown byte changes.

Authoritative spec: `docs/log/2026-09-16_418-design.md` (panel ruling,
three-seat, unanimous — surface first, repair later, as two tickets).

## Where the ships-vs-prose distinction lives

Not inside `_rowize_segment` itself — it has no view of whether its own
grid will ship (that verdict, `_looks_tabular`, runs later on the *cleaned*
grid). The distinction is only available in `_rowize_word_group`, which
calls `_rowize_segment` once per y-segment: a local `_seg_drops` buffer is
passed in, and it is merged into the caller's `orphan_drops` list **only on
the same branch that accepts the segment's markdown** (`if md:`). A segment
the prose guard rejects still drops the word internally — that is
unavoidable, since the drop happens before the verdict exists — but the
record for it is discarded along with the grid, never reaching a caller.

`_rowize_segment`, `_rowize_word_group`, `rowize_from_word_list`,
`rowize_from_words`, and `rowize_from_words_chart_aware` all gained an
optional keyword-only `orphan_drops: list[dict] | None = None`, threaded
through every exit path. `None` (the default) is byte-identical to
pre-ticket behaviour — no allocation, no branch taken differently.

## Surfaces — final design, after two rounds of review

The first draft added a raw `orphan_word_drops` sidecar key and a new
`orphan_word_drop_pages` orthogonal-assemble bucket. Both were removed
(see "What changed under review" below); GH-195's `text_grid_rejections`
precedent, checked properly this time, adds **neither** — it carries a
list on `PageAssessment`, derives a conditional boolean on `PageState`,
and surfaces only through the audit-event channel. GH-418 now mirrors that
exactly:

- **Page level** — `PageState.orphan_word_drops: list[dict]`
  (`state.py::apply_born_digital`), sourced from
  `PageAssessment.orphan_word_drops` (`born_digital.py`), read back from a
  `BornDigitalDetector` instance attribute reset per page
  (`self._last_extraction_orphan_drops`). No new sidecar key: the record
  reaches the page sidecar only through its `audit_events` list (see
  next), the same way `text_grid_rejected_pages` does.
- **AuditEvent** — `_phase_analyze` emits one `orphan_word_dropped` event
  per page with drops (`kind="orphan_word_dropped"`, `data={"dropped_count",
  "words"}`, `detail` names every word). This reaches the page sidecar's
  `audit_events` list automatically (`_flush_page_sidecar` filters
  `state.events` by `page_num`) and `audit_log.json`'s per-kind `counts`
  (document-level metadata — `AuditLog.counts()` is generic per-kind, no new
  plumbing needed there).
- **CLI** — a `console.print` summary line in `_phase_analyze`, gated on
  `not self.config.quiet`, listing the total dropped-word count, the page
  count, and the page numbers.

No document-level orthogonal-assemble bucket, and page-level `audit_passed`
is untouched. A dropped word is a diagnostic, not an assemble decision — by
design this ticket changes no grid, no status, no disposition — and the
orthogonal-assemble vocabulary (`page_failed`, `table_structure_failed`,
`table_withheld_pages`, ...) records assemble outcomes, not diagnostics
(team-lead review). `AuditLog.counts()["orphan_word_dropped"]` already gives
the document-level surface the ticket asked for.

## What changed under review (two rounds)

**Round 1 — the orthogonal bucket.** Original draft added
`orphan_word_drop_pages` to `_ORTHOGONAL_ASSEMBLE_BUCKET_NAMES`, ANDed it
into `pages_ok`, and added a matching bucket to `tests/conftest.py`'s
`old_orthogonal_assemble_buckets` (a pre-existing, shared, cross-file
oracle used by `test_p6_stage_ab_difference.py` / `test_p6_stage_c_difference.py`
via the `p6_old_buckets` fixture — not this ticket's own test file, which
never used it). Removed: a diagnostic doesn't belong in a vocabulary whose
other members are assemble outcomes, and GH-195 — the precedent this
ticket claimed to mirror — adds no such bucket. `tests/conftest.py` and
`tests/test_p6_orthogonal_bucket_helper.py` reverted to their pre-ticket
state; no longer touched by this ticket at all.

**Round 2 — the sidecar key.** Removing the bucket did not close the P6
golden-capture failures (`test_p6_stage_ab_difference.py`,
`test_p6_stage_c_difference.py`, 6 tests) — isolated directly by diffing
`current["sidecars"]` against the golden capture with the bucket already
gone: every one of the 12 P6 corpus pages still showed
`extra in current: {'orphan_word_drops'}`. The raw sidecar key, written
unconditionally in `_flush_page_sidecar` even on pages with zero drops, was
sufficient on its own. GH-195 doesn't add a sidecar key either — checked
properly this round (`grep` for `text_grid_rejections`/`text_grid_rejected`
in the sidecar-writing code: zero hits) — so the key was removed, along
with the `expected_pre_keys` addition in
`tests/test_p6_disposition_persistence.py` that existed only to track it.
Surfacing now goes exclusively through `audit_events`, which was already a
sidecar key, already in the golden, already in `expected_pre_keys`.

Both rounds confirmed the initial "mirror GH-195" framing had it partly
backwards: GH-195's own carrying mechanism (`PageAssessment` →
`PageState`) was mirrored correctly from the start; the surfacing
mechanism (audit events only, no new sidecar key, no new bucket) was not,
and took two review passes to converge on.

## Tests (`tests/test_gh418_orphan_drop_event.py`)

1. `test_orphan_drop_reaches_every_surface` — drives the REAL
   `UnifiedPipeline.process()` (no provider, `_available_engines_for_agentic`
   → `[]`, `_resolve_judge_model` → `""`) over the real TR-1 fixture
   (`tests/fixtures/table_repair/ce_like_p4.pdf`) with one word inserted at
   the real baseline origin of an existing data row (measured off the
   fixture's own `get_text("dict")`, not guessed), 40/45pt from its two
   flanking lanes. Asserts the sidecar's `audit_events` (kind, detail,
   `data`), `audit_log.json`'s `counts["orphan_word_dropped"]`, and the CLI
   line (via `capsys`).
2. `test_shipping_segment_orphan_is_recorded` — positive control: a clean
   4-lane synthetic-word table (same construction convention as GH-342's
   `_four_data_lanes`) with a mid-gutter orphan word; the segment ships and
   the word is recorded.
3. `test_scoping_no_record_when_segment_is_rejected` — the load-bearing
   negative, same lanes and same orphan word as test 2, but diluted with
   single-numeric-cell rows so fewer than half the non-empty rows carry
   `>=2` numeric cells (`_looks_tabular`'s own majority gate). Confirmed by
   direct computation that this exact grid returns `False` from
   `_looks_tabular` before writing the assertion. Row/marker labels
   (`"Note"`/`"Extra"`) deliberately avoid embedded digits — an earlier
   draft used `"Dil0"`.."Dil4"`, and `_looks_tabular`'s numeric regex
   matched the digit *inside the label*, silently inflating the data-row
   count and shipping the table by accident (caught by printing the actual
   `_looks_tabular` grid before trusting the fixture).
4. `test_clean_page_produces_no_record_and_is_byte_identical` — the
   pristine (unmodified) TR-1 fixture's main-table words, run through
   `rowize_from_word_list` twice in the same process (with and without
   `orphan_drops` wired) — pinned as a **difference**: identical markdown,
   empty drops.
5. `test_grid_unchanged_on_the_ce_like_fixture_with_an_orphan_word` and
   `test_grid_unchanged_on_gh342_gutter_marker_fixture` — the same
   with/without-wiring comparison on the two real fixtures that DO have a
   drop today (my modified TR-1 fixture, and GH-342's own
   `_four_data_lanes(markers=True)`, reused directly from
   `test_gh342_stub_promotion_runaway`). Confirms wiring `orphan_drops`
   changes zero bytes of shipped markdown on a fixture with a real drop —
   the actual requirement ("do not change any grid cell"), not just an
   absence-of-drops check.

Each test exercises the new `orphan_drops=` keyword or a field that did not
exist before this ticket (`PageAssessment.orphan_word_drops`, the
`orphan_word_dropped` event kind), so each fails on
`AttributeError`/`TypeError`/a missing key at the pre-fix revision —
confirmed by mutation (below), not assumed.

## Mutation testing

Two isolated copies (`src` + `tests` outside the repo; `socr.__file__`
confirmed pointing into the copy before running), run against the design
as it stood at the time (round 1, before the sidecar key and bucket were
removed in review — the mutated lines are unaffected by that later
removal, so the results still hold):

1. **Revert only the event/CLI emission** (the `AuditEvent` append + the
   `console.print` block in `_phase_analyze`; the `reconstruct.py`
   plumbing is left intact). Result: `test_orphan_drop_reaches_every_surface`
   fails (`0 == 1` on the `audit_events` assertion). The other 5 tests
   correctly still pass: they assert `reconstruct.py`-level behaviour (the
   `orphan_drops` list itself, the grid), which this mutation does not
   touch.
2. **Revert the core drop-recording line** (`orphan_drops.append(...)` in
   `_rowize_segment`, back to a bare `elif` with no `else`). Result:
   `test_orphan_drop_reaches_every_surface` and
   `test_shipping_segment_orphan_is_recorded` fail (both assert a non-empty
   record). The other 4 correctly still pass:
   `test_scoping_no_record_when_segment_is_rejected` passes vacuously under
   this specific mutation (asserting an empty list is trivially true when
   nothing is ever recorded) — that is expected and is exactly why it is
   paired with test 2 as a positive control in the same file; the two
   `test_grid_unchanged_*` tests pass because they compare
   with-vs-without wiring, and with the append gone both sides are
   identical by construction, which is the correct (invariant-to-this-
   mutation) result for a "no cell changes" pin.

## Bugs found by the full suite (not visible in the targeted batch)

`self._last_extraction_orphan_drops` was reset only inside
`BornDigitalDetector._assess_page`, not `__init__` — so a caller invoking
`extract_structured` directly, bypassing `_assess_page` (as
`test_gh351_harness_matches_production` and
`test_gh372_booktabs_chart_misfire` both do), raised `AttributeError`. Fixed
by initializing the attribute in `__init__` as well. The pre-existing
`_last_extraction_grid_rejections` (GH-195) has the identical latent gap;
not touched here — out of this ticket's scope, flagged as a follow-up.
