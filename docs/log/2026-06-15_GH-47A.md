## What was done

Both defects described in the ticket were already partially implemented in a prior
work-in-progress commit on this branch. This agent completed the implementation,
ran the full test suite, applied ruff formatting, and committed.

### Defect 1: Silent cap

`ExtractionResult` dataclass gains a `cap_reached: bool = False` field.
`FigureExtractor.extract()` sets `cap_reached = True` and emits a `WARNING`-level
log line when `counter > max_total` causes early exit.

The orchestrator (`_describe_and_embed_figures`) checks `extraction.cap_reached` and:
- Prints a yellow console warning (suppressed under `--quiet`)
- Appends an `AuditEvent(kind="figure_cap_reached", ...)` to `state.events`, which
  the audit log persists durably alongside other non-fatal events.

### Defect 2: Logo / letterhead false positive

`_is_logo_or_letterhead(x0, y0, x1, y1, page_width, page_height)` returns True only
when all three geometry conditions hold simultaneously (all derived from page dimensions):

1. `y0 < page_height * LOGO_TOP_MARGIN_RATIO`  (image is in the top 20% of the page)
2. `(x1 - x0) >= page_width * LOGO_WIDE_WIDTH_RATIO`  (spans >= 50% of page width)
3. `(y1 - y0) <= page_height * LOGO_HEIGHT_RATIO`  (height <= 15% of page height)

Constants are named module-level values (`LOGO_TOP_MARGIN_RATIO`, `LOGO_WIDE_WIDTH_RATIO`,
`LOGO_HEIGHT_RATIO`), not buried literals. A real top-of-page figure fails at least one
condition (too tall, or not wide enough), so the filter is conservative.

The filter is applied in both Strategy 1 (IMAGE blocks from text dict) and Strategy 2
(raw embedded images via xref).

## Residual risks

- The logo filter is image-block geometry only (PyMuPDF `get_text("dict")` bbox and
  `get_images()` placement rects). Vector-drawn logos (e.g., SVG-style institutional
  marks drawn with `draw_*` calls) fall through the vector clustering path, which has a
  separate header/footer margin check (`HEADER_FOOTER_MARGIN = 0.1`) but no width/height
  gate. Low risk: vector logos are rare in the target corpus (PDF reports with raster
  letterhead), and the vector path already guards against small clusters.
- The three ratio constants (`0.20`, `0.50`, `0.15`) are named and documented but not
  yet exposed in `PipelineConfig`. If edge cases are found in a new corpus, they can be
  wired up as config parameters in a follow-up without changing the logic.
