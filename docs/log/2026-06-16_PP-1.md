## What changed

### New module-level helper
- `_page_blob_key(page_output_dict) -> str` — content-addressed SHA-256 key for
  a serialised PageOutput dict; used in sidecars as a lightweight `page_fingerprint`
  that changes whenever the winning page text changes.

### New methods on UnifiedPipeline
- `_page_fragment_path(output_dir, state, page_num) -> Path` — canonical path for
  a per-page markdown fragment: `<doc_dir>/pages/NNN.md` (zero-padded to 5 digits).
- `_flush_page_fragment(state, page_num, text, output_dir) -> Path` — atomic
  temp-write+rename of the body-only page text to `pages/NNN.md`.
- `_flush_page_sidecar(state, page_num, output_dir) -> Path` — atomic write of
  `pages/NNN.json.tmp` → `pages/NNN.json` carrying provenance: `page_num`,
  `status`, `terminal`, `engine`, `provider`, `cost_usd`, `run_fingerprint`,
  `page_fingerprint`, and the PageState decision flags NOT in `PageOutput.to_dict`
  (`needs_ocr_enhancement`, `native_table_structure_failed`, `judge_rejected`),
  plus page-local audit events and figure refs.
- `_stitch_fragments(state, output_dir) -> str` — reads `pages/*.md` in numeric
  order and joins via `contract.assemble_pages(..., page_numbers=[...])`, producing
  the canonical `## Page N` body.

### Modified method
- `_phase_assemble` — refactored to flush per-page fragments + sidecars from the
  in-memory canonical page texts (via `canonical_page_texts(state)`), stitch them
  back, and verify byte-identity vs the in-memory body. On match, uses the
  stitched body (confirming the new code path). On mismatch or error, logs a
  warning and falls back to the in-memory body (fail-open).

## Byte-identity proof
`TestByteIdentity.test_stitch_equals_canonical_body` directly asserts
`_stitch_fragments(state, output_dir) == _canonical_body(state)[0]` after flushing
fragments from `canonical_page_texts(state)`. The assertion is byte-level equality
(`==`). Both single-page and multi-page cases are covered.

## Decisions / deviations
- Fragment text = body-only (no `## Page N` header). `canonical_page_texts` already
  strips leading markers via `_strip_leading_page_marker`; `_stitch_fragments` passes
  explicit page_numbers so `assemble_pages` adds the canonical headers.
- `_flush_page_sidecar` uses the run fingerprint from `_run_fingerprint()` (existing
  machinery) — no new fingerprint scheme invented.
- No second `metadata.json` writer introduced; only `pages/` artefacts created.
- Fragment flush is non-fatal (try/except around the PP-1 block in `_phase_assemble`).

## Residual risk
- The fragment/stitch path in `_phase_assemble` activates only when `has_text` and
  `page_texts` are both truthy. A purely-failed document (no page text) skips
  fragment flush, which is correct (no `pages/` artefacts for empty docs).
- Whole-doc CLI engines that emit a `page_num=0` blob still work: `canonical_page_texts`
  splits them via `split_native_pages` and returns one entry per PDF page; each entry
  gets its fragment. The stitch reproduces the same body `assemble_pages` would build
  from those texts.
- PP-2 (incremental per-page write during backbone) can now move the fragment write
  into the per-page OCR loop; the stitch path in `_phase_assemble` will still verify
  byte-identity at end-of-run.
