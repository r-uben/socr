# TR-3 decision log — 2026-06-17

Ticket: TR-3 (D3 fail-closed floor + selection-policy fix)
Branch: `feat/56-tr3-fail-closed`

## What changed

### 1. Selection-policy fix — `_winning_page_output` in `manifest.py`

Added the D3 fail-closed branch at the top of the native-text arm of
`_winning_page_output`. When ALL of:
- `p.native_table_structure_failed = True` (OCR ladder rejected every rung)
- `p.native_table_unverifiable = True` (per-region geometry verifier hard-failed)
- `p.attempts` is non-empty (OCR was actually tried)

…the page ships the explicit `page_failed_marker(page_num)` with `PageStatus.ERROR /
audit_passed=False`, never the collapsed or ragged native table.

If only the OCR ladder fails (but `native_table_unverifiable=False`, i.e. the
per-region verifier did not hard-fail), the existing `native_fallback` path is
unchanged: native text ships as WARNING.

`FailureMode` was added to the import set in `manifest.py` (was missing before).

### 2. New state flag — `native_table_unverifiable` in `state.py`

Added `native_table_unverifiable: bool = False` to `PageState`. Set by
`apply_born_digital` when the `PageAssessment.has_unverifiable_table_region` flag
is True. The flag is `False` by default so no existing page is spuriously demoted.

### 3. Per-region gate wiring — `born_digital.py`

**What was converted:**
- Added `has_unverifiable_table_region: bool = False` field to `PageAssessment`.
- Made `_verify_regions` return `bool` (True when any region hard-fails). Previously
  it returned `None`.
- `extract_structured` captures the return value of `_verify_regions` and stores it
  on `self._last_extraction_had_unverifiable` (an instance-level attribute written
  during extraction, read immediately after by `_assess_page`).
- `_assess_page` resets `self._last_extraction_had_unverifiable = False` before
  calling `extract_structured` (so pages without tables are never flagged), then
  reads it after and sets `has_unverifiable_table_region` on the returned
  `PageAssessment`.
- `apply_born_digital` in `state.py` propagates `has_unverifiable_table_region`
  to `PageState.native_table_unverifiable`.

**What remains (explicitly scoped to TR-3):**
The agentic-path whole-page verifier in `agentic.py:~405` (the `NativeTableVerifierJudge`
that gates each VLM ladder rung) is NOT yet converted to per-region. Converting it
would require routing the per-region verdict into the ladder's accept/reject decision
and is a larger rework of the OCR path — scoped as a v2 item (TR-4/TR-5). The D3
floor in TR-3 is authoritative at the selection layer (`_winning_page_output`), which
is downstream of all ladder rungs, so the per-region gate wiring here is sufficient
for v1.

### 4. Distinct audit event — `audit_log.py` + `orchestrator.py`

Added `table_region_unverifiable` to the sort rank dict in `build_run_audit`
(rank 4, after dual-pass but before `native_fallback` at 5 and `page_failed` at 6).

In `_phase_assemble` in `orchestrator.py`:
- Compute `d3_floor_pages`: pages with `native_table_structure_failed=True AND
  native_table_unverifiable=True AND attempts non-empty`.
- D3 floor pages are **excluded from `native_fallback_pages`** (distinct event, no
  double-counting).
- Emit `table_region_unverifiable` `AuditEvent` for each D3 floor page with
  `data={"d3_floor": True}`.
- CLI summary: red line "N table page(s) hit the D3 fail-closed floor: [pages]".

### 5. PNG render for D3 floor pages (reviewer REVISE fix 1 — BLOCKING)

Added `_render_d3_floor_png` method to `orchestrator.py`.  When a page is a D3
floor candidate (`native_table_unverifiable=True AND native_table_structure_failed=True`),
the orchestrator renders a full-page PNG via `_render_chart_page_png` (the existing
chart-page renderer), renames the file to `failed_table_p{N}.png`, and stores a
markdown image ref `![Failed table page N](figures/failed_table_pN.png)` on
`ps.d3_floor_png_ref`.

The call is wired in `_phase_agentic` after the TR-2 `_render_chart_region_pngs` block:
if `ps.native_table_unverifiable` is True and `_chart_figures_dir` is available, call
`_render_d3_floor_png` and set `ps.d3_floor_png_ref`.

`manifest.py:_winning_page_output` builds the shipped text as
`[page N failed: unverifiable table — see image]\n\n{png_ref}` when `png_ref` is set,
or just the marker when PNG rendering was not available (fail-open: the marker alone
is still fail-closed; it just lacks the image attachment).

`is_page_failed_marker` was updated with `_PAGE_FAILED_ANY_RE` that matches the first
line of ANY `[page N failed: ...]` text (handles multi-line D3 text containing the
PNG image ref block).

### 6. Sidecar serialization of TR-3 flags (reviewer REVISE fix 3 — MINOR)

Added to `_flush_page_sidecar` payload:
- `native_table_unverifiable` (bool)
- `d3_floor_png_ref` (str)

Added to `_restore_terminal_page_state`:
- `ps.native_table_unverifiable = bool(meta.get("native_table_unverifiable", False))`
- `ps.d3_floor_png_ref = str(meta.get("d3_floor_png_ref", ""))`

### 7. Status propagation at every level

| Level | How |
|-------|-----|
| Page output text | `[page N failed: unverifiable table — see image]` + PNG image ref |
| PageStatus | `ERROR` (not WARNING or SUCCESS) |
| `audit_passed` | `False` |
| `failed_pages` list | D3 floor pages appear here (`is_page_failed_marker` broadened) |
| Document status | Already AUDIT_FAILED via `failed_pages` being non-empty |
| Audit log | `table_region_unverifiable` event (distinct from `native_fallback`) |
| CLI summary | Red line for D3 floor pages |
| Sidecar JSON | `native_table_unverifiable` + `d3_floor_png_ref` persisted for resume |
