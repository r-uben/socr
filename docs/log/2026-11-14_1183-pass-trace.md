# #1183 / #1222 / #1249, C2 part 1: the per-page pass trace

Branch `fix/issue-1183-c2`. Scope: the pass trace only. The commit SHA, `processing_time`, the judge
stamps (`judge_outcome=not_run`) and the `check=unknown` mapping are later PRs.

## Problem

A page verdict lists the checks that did not pass. On run `fed_rerun_51270eb5_words` all 8,017 native
success pages carry an empty verdict and no events, so a reader cannot tell "every check passed" from
"no check ran". No production code built `CheckResult.PASS`; every clause function returned `None`
for both "ran and found nothing" and "does not apply / did not run" (Fable, advice on BRIEF-C2,
point 1).

## What was built

`src/socr/core/pass_trace.py`: `TraceResult` (PASS, FAIL, UNKNOWN, NOT_APPLICABLE, NOT_RUN),
`TraceEntry {check, result, scope, reason}`, and the (de)serialisers. `trace_from_dicts` returns
`None` for an unreadable trace and `()` for a recorded empty one.

`src/socr/core/verdict.py`:

* `CheckOutcome(entry, clause)`: every check function now answers with its trace entry, and with its
  clause when it found something. The existing clause functions are thin wrappers over the outcome
  functions (`text_layer_numbers_clause` = `text_layer_numbers_outcome(...).clause`, and so on), so
  clause results are unchanged. `silent_success_clauses` still calls the module-level clause
  functions (several tests monkeypatch `page_missing_words`, `text_layer_words_clause` and
  `text_layer_drops_clause` to simulate an older run), and the trace calls the outcome functions.
* A trace is never derived from "no clause". Per check:
  * `text_layer_numbers`, `text_layer_drops`: PASS only when the comparison ran and found nothing.
    NOT_APPLICABLE for native text / no text. NOT_RUN for a failure marker, an earlier-OCR layer, a
    layer that cannot count (drops), an empty drop reference, and a socr-withheld table (drops).
    Consensus winners count as model readings. `text_layer_drops` reads TABLE ROWS only, so every
    one of its non-clause entries sits at the named scope `table_rows`, never `page` (its FAIL
    clause keeps the page scope the verdict gives it); it is not a page-scope pass.
  * `text_layer_words`: PASS only when words were owed (`compared > 0`) and the layer is evidence
    (born digital, no unrecovered symbol glyphs). NOT_APPLICABLE for no text, no layer of its own,
    or no word owed (a shipped figure takes its words off the debt). NOT_RUN for a marker, an
    earlier-OCR layer, a withheld table, an empty reference on a page that has a layer, or a
    refused / glyph-damaged layer whose words agree (agreement with it is not evidence).
  * `control_bytes`: PASS when the damaged-layer guard scanned the text (it scans every text that is
    not a failure marker) and found none.
  * `prior_ocr_layer`: PASS when the page has its own layer and the scan (a failed scan counts as
    suspect) did not flag it. NOT_APPLICABLE when it has no layer.
  * `equation_fidelity`, `figure_text` (untranscribed chart), `page_judge` (deterministic accept
    without a judge): event-keyed, so they can find a problem and can never PASS. NOT_APPLICABLE when
    the event is absent, except `equation_fidelity`: NOT_RUN without a provider ladder, NOT_RUN
    when a ladder exists but no equation-reading lane was enabled on the run
    (`DocumentState.equation_lane_enabled`), NOT_APPLICABLE only when a lane was enabled and
    attached nothing. The `page_judge` entry says in its reason that it does not say whether a
    judge ran (C3 owns that).
  * `row_binding` (#1267): a trace-only check (its failures are table marks, not `Check` clauses),
    one entry per table that SHIPS in `output.text` at its own `table:N` scope from
    `PageState.row_binding`: PASS bound, FAIL contradicted, UNKNOWN unverifiable, only when the
    output is a model reading, not a failure marker, and the record's `table_index` is one of the
    shipped table blocks. A shipped table with no record: NOT_RUN (NOT_APPLICABLE for a native
    table). A record whose table does not ship (page-granular withhold, late demotion to a marker,
    a native text): NOT_RUN with that reason. No table: NOT_APPLICABLE. A table pass never reads as
    a page pass: there is no `(row_binding, page)` entry, and a resumed page with no trace states
    NOT_RUN per shipped table, not a page slot.
* Model-dependent checks (`text_layer_numbers`, `text_layer_drops`, `equation_fidelity`) report
  NOT_RUN with the reason "no provider ladder in this run" when no ladder exists
  (`bool(state.agentic_ladder)`), and NOT_APPLICABLE when one exists and the page is native text.
  Pinned as a difference between the two provider states.
* `build_pass_trace`: every verdict clause is an entry (the verdict is the authority, including the
  status-dependent clauses and the fail-closed `unknown`), plus each other check's own outcome. A
  check that found a clause the verdict does not carry contributes nothing.
* Guard-derived clauses (chart region, native glyphs, table label, judge refusal, the mode table)
  keep no record of having run. They appear only when they fire. They are not given NOT_APPLICABLE
  on SUCCESS pages because that would be an inference, not a record. Same for the unshipped-figure
  lane (`figure_text` at `figure:N`).

Persistence and resume:

* `FinalizedPageRecord.checks` is computed at the finalisation seam from the final bytes and the
  final verdict, so late assembly clauses (figure phase, final-body guard, chart-region preserve) are
  included. `_flush_page_sidecar` writes `checks` (a list, on every sidecar) from the record. The
  authoritative write is the final-records flush that follows `_rewrite_all_fragments`;
  `_rewrite_all_fragments` itself only writes the `.md` fragments, so the trace is written beside the
  verdict by the same flush rather than inside that function.
* `PageState.published_checks`: the resume reader restores the list. A terminal resumed page REPLAYS
  it unchanged (`build_pass_trace(replay=...)`); `pass_trace_outcomes` is not called for it
  (spied in the test). A resumed page whose sidecar predates the trace states every slot NOT_RUN
  with a reason, never PASS.
* The four offline re-finalize tools (`socr-refinalize-own-text`, `-point-drops`, `-prior-ocr`,
  `-unshipped-figures`) change a verdict without re-running the page, so they now call
  `reconcile_pass_trace`: clauses they add become entries, an entry that recorded a clause they
  removed becomes NOT_RUN (not PASS), everything else is kept. `-point-drops` also ran the two
  number checks and the row-binding check again, so those outcomes are its own. A sidecar with no
  trace gets none (a tool never invents one). `test_offline_bytes_equal_live_bytes` pins offline ==
  live including `checks`.
* Not hashed into the run fingerprint, and no `.md` byte moves (test: the trace on vs off, md and
  every other sidecar key identical, both provider states). The source digest in the fingerprint
  still changes with any code change, so a corpus is re-read once after this lands; that is not
  specific to this feature.
* p6 oracle: `checks` is in `ADDITIVE_SIDECAR_KEYS`, pinned per page by
  `PASS_TRACE_SIDECAR_1183_DIFFERENCES`. `test_p6_disposition_persistence` allows the key.
  `test_gh1267_row_binding_pipeline` excludes it from the arm comparison and asserts the row-binding
  entry explicitly (PASS with the check, NOT_RUN without).
* No new audit event kind, so `test_resume_restore_kinds` is untouched.

Scoreboard (`src/socr/benchmark/scoreboard.py`): `records.pages_checks_any_pass`,
`records.pages_checks_page_scope_pass` (a table-scope or `table_rows` pass is not counted here),
`records.pages_checks_empty`, `records.checks_not_run.<check>`, and the JSON-only
`records.check_result.<check>@<scope kind>|<RESULT>` matrix.

## Measurement

The cached 156-doc run (`fed_rerun_51270eb5_words`) holds sidecars only; its PDFs are on the cluster,
and the trace inputs (own-layer text, word and drop references) live in memory during a run, so an
offline application from sidecars alone would report words, drops and numbers as NOT_RUN for a reason
that is not the page's. Not done. Instead, fresh hermetic in-process runs (no provider ladder, table
rungs forced unreachable; this is the no-provider state, so it measures that state only):

1. 5 documents, 3 pages each (excerpts of economics papers), 15 pages, native lane. Result per page
   (counts of entries):

   | check | PASS | FAIL | UNKNOWN | NOT_APPLICABLE | NOT_RUN |
   | --- | --- | --- | --- | --- | --- |
   | control_bytes | 13 | 1 | 0 | 0 | 1 |
   | prior_ocr_layer | 15 | 0 | 0 | 0 | 0 |
   | text_layer_words | 14 | 0 | 0 | 0 | 1 |
   | text_layer_numbers | 0 | 0 | 0 | 0 | 15 |
   | text_layer_drops (scope `table_rows` since the review round) | 0 | 0 | 0 | 0 | 15 |
   | equation_fidelity (no provider: NOT_RUN) | 0 | 0 | 0 | 0 | 15 |
   | figure_text (page) | 0 | 0 | 1 | 14 | 0 |
   | page_judge | 0 | 0 | 0 | 15 | 0 |
   | row_binding | 0 | 0 | 0 | 15 | 0 |
   | other clauses (table_structure etc.) | | native_coverage 1, native_glyphs 1, unknown 1 | | | |

   12 of the 15 pages are native SUCCESS and now each names three checks that ran and found nothing
   (`control_bytes`, `prior_ocr_layer`, `text_layer_words`); before, they had an empty verdict. 15 of
   15 pages have a non-empty `checks` list.
2. 12 single-page Fed excerpts (table pages), same setup: 8 PASS `prior_ocr_layer`, 4 UNKNOWN
   (`prior_ocr_layer` flagged), 8 `table_structure` FAIL, every other check NOT_RUN or
   NOT_APPLICABLE. All 12 ship a failure marker or a withheld table (no provider, no table rung), so
   `control_bytes` and the words check are NOT_RUN on them with the marker reason.

Sidecar size: the trace adds 1.7 to 2.1 KB per page as written (indent 2), about 18 percent of the
15 measured sidecars (mean 9.9 KB). On a 12,413-page run that is about 22 MB. This is the one
figure: the "about 0.4 KB per page" in the PR description was an estimate made before the
measurement and is superseded by it. If that matters, the reasons can be moved to a constant table
and the entry reduced to `{check, result, scope}` plus a reason code; not done now (BRIEF-C2 owner
question 1 asked for the compact form; this keeps `reason` because NOT_APPLICABLE and NOT_RUN must
say why).

## Open points

* The `with provider` distribution (PASS counts for `text_layer_numbers` and `_drops` on model-read
  pages) was not measured on real data: no model was available here. It is pinned in the tests with a
  stub reader (provider state vs no provider on the same PDF) and in the p6 oracle for the no-provider
  state.
* The guard-derived clauses (chart region, native glyphs, table label, the judge refusal) and the
  unshipped-figure lane have no ran-record, so they cannot yield PASS or NOT_APPLICABLE until the code
  that sets their flags records that it ran. This limits C3: a release rule may rely only on entries
  that exist, at the scope they name.
* `page_judge` has no PASS. The judge stamps are unreliable (BRIEF-C2 root cause) and belong to the
  later PR.

## Review round (PR #1332)

Rule applied throughout: a PASS entry exists only for a check that RAN on the SHIPPED text at the
scope it names and found nothing; everything else is NOT_RUN or NOT_APPLICABLE with a true reason.

* Words PASS needs `compared > 0` and an evidence layer; drops entries sit at `table_rows`;
  row binding states only shipped tables and says NOT_RUN for every shipped table without a record
  and for every record whose table does not ship.
* Replay keeps the stored entries and overlays every clause of the verdict it is written beside.
* Offline tools: when `winning_output.text` changed, a kept PASS the tool did not recompute becomes
  NOT_RUN ("re-finalized offline, not run on the new text"). `-prior-ocr` takes the finalized
  record's own trace; `-own-text` states the words check it wrote; `-boilerplate` is covered; a
  malformed old list is dropped (`write_reconciled_trace`).
* `-own-text` and `-point-drops` hold the page state, so they run the text-dependent checks
  (numbers, drops, words, control bytes, prior-OCR layer) again on the text they wrote
  (`rerun_text_dependent_checks`) and those entries are their own; this keeps the existing
  offline == live byte tests true. A finding the verdict does not carry is not added (the verdict
  is the authority), and an old entry of a rerun check at another scope is not kept beside the new
  ones.
* Trace reader: an entry with a missing scope or a non-string check, scope or reason makes the
  whole trace unreadable (`None`); the scoreboard follows the same rule.
* Mutants (src and tests copied outside the repo, `socr.__file__` asserted inside, uncapped anchor
  count == 1 asserted): words damaged-layer guard removed, words owed guard removed, drops PASS at
  page scope, row binding states unshipped tables, replay without the clause overlay, reconcile
  without the text-changed rule. All KILLED by `tests/test_gh1183_pass_trace.py`.
* Known limit: `-prior-ocr` rebuilds a state with no provider ladder and no equation-lane flag, so
  the checks it states for a rewritten page read as a no-provider run (NOT_RUN with that reason).

## Review round 2 (PR #1332): a PASS names the text it was computed on

Rule (coordinator, structural; it replaces the case-by-case patches of round 1): every PASS entry
carries the digest of the exact text it was computed on. A page-scope PASS carries `text_sha`
(`sha256_text` of the shipped page text, the sidecar's own digest); a `row_binding` `table:N` PASS
carries `table_sha` (digest of that table block's own lines, taken when the check ran and stored in
the `row_binding` record). At every write of `checks` (the seam's `build_pass_trace`, which covers
the live flush, the resume replay and the assemble rewrite, and `reconcile_pass_trace`, which covers
every refinalize tool) `verify_pass_digests` turns each PASS whose digest is not the digest of the
text shipped now into NOT_RUN ("checked text changed after the check"). A PASS with no digest is
unreadable and becomes NOT_RUN too. This closes Fable A and B, and Carbon residuals 3 and 5 (a caption
table inserted above a bound table changes the block at that ordinal, so its digest no longer matches).

Also in this round:

* `control_bytes_outcome` scans `output.text` for `CONTROL_BYTE_RE`: a raw control byte is a FAIL
  clause, a PASS needs a clean scan. It no longer trusts `p.control_bytes_replaced`, which the offline
  tools never set (Carbon blocker; `-point-drops` splices layer cells without the guard).
* `_words_owed` subtracts the stripped hidden-footnote words exactly as `missing_words` does (Carbon
  residual 1).
* `reconcile_pass_trace`: a verdict clause removes every old non-clause entry of its check at any
  scope (Fable C); a recomputed FAIL or UNKNOWN the verdict lacks is KEPT as the recomputed entry
  (Carbon should-fix). `build_pass_trace` keeps such a finding too (the live seam and the offline
  tools state the same trace; `test_offline_bytes_equal_live_bytes` pins it). This supersedes the
  round-1 line that a finding the verdict does not carry contributes nothing: a slot that vanishes
  is the defect, and the outcome is what the check found on the bytes shipped.
* `DocumentState.equation_lane_enabled` is gated like `_equation_region_lane_enabled`: agentic and not
  native-only (cubic).
* Reading the trace: FAIL and UNKNOWN are findings (a check ran and the page has a problem or the
  check could not decide). NOT_RUN and NOT_APPLICABLE are not findings: the check did not run, or does
  not apply. A reader counting problems counts FAIL and UNKNOWN only; a reader counting assurance
  counts PASS only. NOT_RUN is neither.
* The broad `pytest.skip` in `test_refinalize_prior_ocr_takes_the_records_own_trace` is gone; its
  fixture already satisfied `_updated_sidecar`.

Tests: `tests/test_gh1183_pass_digests.py` (18): each breaking input of the two re-checks, the resume
case where assemble demotes a page to a marker or adds a caption (through the finalize seam, as a
difference between the saved text alone), a caption table inserted above a bound table, and a
control-byte cell spliced by the point-drops path.

Mutants (src and tests copied outside the repo, `socr.__file__` asserted inside the copy, uncapped
anchor count == 1 asserted; all KILLED by `tests/test_gh1183_pass_digests.py`): digest check disabled;
a PASS without a digest accepted; control_bytes not scanning the text; footnote words not subtracted;
a clause that leaves old non-clause entries of its check; a recomputed finding dropped.

Known effect on existing tests: four tests in `tests/test_gh1183_pass_trace.py` build PASS entries or
`row_binding` records by hand with no digest, which the rule now reads as NOT_RUN. They were left as
they were and reported to the coordinator.
