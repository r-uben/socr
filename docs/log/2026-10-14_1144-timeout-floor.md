# 2026-10-14 — #1144: a page-judge timeout withheld a whole born-digital page

Coca-Cola CDP 2022 p77, main `25daab9f`. The page shipped nothing but
`[page 1 failed: unverifiable table — see image]` plus the page PNG.

## Diagnosis

The reading that was discarded was **correct and complete**. It is still in the
run's own cache (`review-pages/out/e_cocacola_cdp2022_p77/cache/c5/c528dce4…json`):
every number of the text layer (42,548 / 228 / 42,776 / 4,070 / 524,332 /
2,469,400 / 2,993,732), both tables and the C8.2b/C8.2c prose, from
`qwen3-vl:30b-a3b-instruct` in 38.3 s. It carries a #713
`TableAcceptanceCredential` covering BOTH emitted tables, each with a real
witness-image digest and a real executing rung (`glm-5.3-flash:cloud`), and the
audit log has `table_ladder_accepted` for `p1-t0` and `p1-t1`.

Reconstructing the `PageState` from the sidecar and the cache record and calling
the production selection path:

```
page_judge_timeout_attempt     -> the qwen reading
verify_credential              -> VALID
_credential_admission_refusal  -> "outstanding contradiction (table_escalation_refused)"
credentialed_judge_timeout_winner -> None   # => fail-closed floor
```

So the credential verified and one audit event withheld it:
`table_escalation_refused`, engine `gemini`, *"provider returned
engine='native'; not the escalation engine, candidate discarded"*
(`pipeline/orchestrator.py:6723`). It is in `CREDENTIAL_BLOCKING_EVENT_KINDS`
(`core/manifest.py:1877`), checked at `core/manifest.py:2055`, and the floor is
selected at `core/manifest.py:3749-3766` →
`structure_class_ladder_exhausted_floor`.

### The argument I built on this, and why it was WRONG

Everything in this subsection is the REJECTED round-1/round-2 reasoning. It is
kept because it is the trap, not the answer: read "Round 1 and round 2 are both
REVERTED" below before relying on a word of it.

All three `table_escalation_refused` sites (`orchestrator.py:6659` budget cut-off,
`:6723` wrong engine returned, `:6737` candidate with no usable text) mean one
thing: *no escalation candidate was obtained, the page keeps its incumbent
table*. None is a verdict on the incumbent. The gate they feed exists for an
"outstanding applicable hard CONTRADICTION" (`core/page_credential.py` module
docstring; `manifest.py:1847-1876`). The escalation lane's job is to put a
second, stronger reader on a table socr flagged as suspect — and on this page
the table judge ladder did exactly that, per table, against a witness image,
bound to the same bytes.

**Where that breaks.** `_table_page_needs_escalation` also escalates on a
MEASURED grid shortfall and emits no event of its own for it, so this refusal is
often the only record that something was wrong; and the ladder's witness here was
`witness_scope == "page"` -- one shared whole-page crop, with
`_binding_evidence_for_witness` abstaining -- so nothing mechanical checked a
column swap or a dropped table. "Did exactly that" was the error.

Corroboration that the block was never meant to be durable:
`table_escalation_refused` is **not** in `UnifiedPipeline.resume_restore_kinds()`
(verified: `False`, while `table_escalation_timeout`/`withheld` are `True`). A
signal that destroys a verified page on the first run and vanishes on the next
is not a distrust policy.

### The 147.6 s route and the timeout

`timings_s`: route 147.6, extract 53.9, tables 2.6, ladder 11.4, total 215.5.
Route is the whole cost ladder — the model read plus the page-judge call. The
model read took 38.3 s (cache `processing_time`); the remaining ~109 s is the
page judge burning its budget to a kill. That budget is **120 s**
(`DEFAULT_JUDGE_TIMEOUT_SEC = DEFAULT_PROBE_TIMEOUT_SEC = 120.0`,
`core/ollama_utils.py:337`), not the 300 s outer `_TimeoutJudge` deadline
(`orchestrator.py:13279-13283`). The judge is `qwen3.8:27b`, a second large
model on the same shared Mac GPU as the 30 B reader. Measured here today:
a cold 1-token generation on `qwen3.8:27b` takes **15.5 s**, warm **0.6 s** — so
the load alone is not the 109 s, the generation over a page image plus the
candidate is, and the reader/judge swap is #1017's territory, not this ticket's.

### Why the native lane did not carry the tables

Not fixed here, and it is the second half of the page's problem: the sidecar has
`native_table_structure_failed: true`, `native_table_region_count: 0`,
`table_bbox_sane: false` while the detector found 2 table bboxes, and both
native attempts were rejected "empty/error output" -- which is a MISLEADING
message: the native text was not empty (1,053 exact chars). The judges reject on
`status != SUCCESS or not text.strip()` (`pipeline/agentic.py:804`, `:858`) and
the native fallback carries `status=WARNING` (`orchestrator.py:2657-2667`), so
these attempts were refused on status before anything read the text. The flag
itself is set merely because `_page_has_tables` is true
(`orchestrator.py:2662`, `:2858-2863`) -- no structure verifier ran and failed. The page also has 167 vector
drawings, which fired the chart lane (`chart_table_arbitration`, two
`chart_grid_not_reconciled`). So the page had no native fallback at all and the
model reading was the only candidate — which is why losing it lost everything.

## Round 1 and round 2 are both REVERTED

Round 1 subtracted `table_escalation_refused` from
`CREDENTIAL_BLOCKING_EVENT_KINDS`; round 2 gated that subtraction on a
predicate. Three reviewers rejected round 2 and I reproduced all three faults:

1. **Resume floored every page the change shipped.** The predicate read the
   `table_not_scorable` audit event, which is not in `resume_restore_kinds()`
   (verified: `False`). Run 1 shipped the page; run 2 destroyed it. The round-2
   test was set-membership, not lifecycle, which is exactly why it missed this.
2. **The detected-count condition failed open.** `detected_table_count` of 0 or
   None satisfied `len(tables) < detected` trivially, and detection is zeroed on
   resume by `_detected_invalid` (`orchestrator.py:15054-15060`).
3. **The signal it rested on does not mean what I read it to mean.**
   `table_not_scorable` is emitted at `table_grid.py:446` on
   `report.rows_not_found == len(gt) and predicted`, and the comment two lines
   below says so outright: *"That is as likely to be a parser failure as an
   engine failure, so the score is not evidence either way."* A candidate that
   transposes two columns on every row scores 0% and gets the same event.

Underneath all three: **p77 has no sound positive evidence that its tables are
right.** The page judge never answered; the table ladder judged a shared
whole-page crop with `witness_scope == "page"`, so `_binding_evidence_for_witness`
abstained (`orchestrator.py:7340`) and no mechanical binding ran; the grid could
not be graded; the escalation never happened. The credential dressed "one cloud
model glanced at a whole-page image" up as proof. Both rounds are reverted in
full. The only thing kept is the resume hardening (below).

## What ships (owner ruling, 2026-10-14)

Ship the page's own PDF text with every table withheld, through
`native_prose_floor_text` — socr's existing ratified mechanism for exactly this
(#649 / #652, owner ruling 2026-09-10) — plus one addition the owner required.

**1. The floor branch now offers prose recovery (`core/manifest.py`).**
`table_floor_text_for_source` grows `prose_recovery: bool = False`; when set,
each of its six refusal returns goes through a local `_refused()` that tries
`native_prose_floor_text` before falling back to the bare whole-page marker.
`structure_class_floor_text` passes `prose_recovery=True`. **It is off by
default**, so P1's withhold path — which passes a MODEL winner's text — can never
reach it: shipping a model's prose from a floored page is the design the owner
closed unmerged in PR #1047 (#1043), where the strict ordered check recovered 1
of 109 pages. This lane ships the native layer's own bytes, never a model's.

Why the GH-520 splice is refused on p77 and this is not: the splice needs each
detected table paired with a parsed block, and p77 reconstructed no region at
all (`native_table_region_count == 0` against two detected tables). The band lane
needs no pairing — it withholds by geometry.

**2. A detected table box withholds its bands outright
(`tables/row_corroboration.py`).** `partition_prose_bands` grows
`table_boxes`, and `_band_meets_a_box` withholds any band with a word whose
CENTRE lies inside a detected box, numeral or not. The numeral count alone
cannot see p77's C8.2b grid — it is Yes/No, with no printed numeral anywhere —
so that table shipped as loose text and its answers landed beside the wrong
questions. A detected box is independent of the parser whose output the floor is
refusing (`find_tables()` runs before reconstruction), which is the same evidence
GH-520 already trusts.

No new threshold: a point is inside a rectangle or it is not. Deliberately NOT
the rule `partition_prose_bands`' own docstring records as tried and rejected
("withhold every zero-token band inside the WITHHELD BANDS' y-span"), which
swallows a paragraph printed between two tables — this asks about a box the
detector drew, not about a span inferred from the withholding itself, so a
paragraph between two tables falls outside both boxes and still ships. A page
with no boxes partitions exactly as it did before.

**3. Resume hardening, kept from round 1 (`pipeline/orchestrator.py`).**
`table_escalation_refused` added to `_RESUME_REPLAYED`: `tables_trust` reads the
kind to keep a page untrusted and `_escalate_table_page` is skipped by a terminal
resumed page. `tests/test_resume_restore_kinds.py`'s exact-set guard fired on the
addition — which is what it is for — and its expectation was updated with the
reason, 49 → 50.

`core/manifest.py`).** Found by GH-147's own hermetic `process()` test failing on

corpus; if it ever is and the rate is non-trivial, the fix is a

## Round 5 — the reading-order gate (owner ruling, 2026-10-15)

Round 4's two-column refusal was partial, so I measured what it left: using the
page's own native text in PyMuPDF BLOCK order as ground truth, **89 of the 237**
pages the lane gave prose to shipped words in an order the page does not have.
Verified not to be a measurement artefact: on three failures the first divergent
token exists in the ground truth at an EARLIER position.

The owner's ruling turned that measurement into the gate.
`_prose_follows_native_order` requires the recovered prose's word sequence to be
an in-order SUBSEQUENCE of `p.native_text`. No new heuristic and no threshold:
the prose is a subset of the page's words (bands are withheld), so a subsequence
is exactly the right test, and any reordering fails it. `native_text` is already
`get_text()` — checked: it and a fresh `get_text()` differ by one trailing
character and their word sequences are identical, which is all this reads, so
the gate needed no new plumbing.

**Round 4's gutter check is REMOVED as subsumed.** Measured over all 808
structure-class floors: it refuses **zero** pages the order gate would not. Two
predicates for one property is the shape that drifts, so the proxy goes and the
direct test stays. It was also only partial — a full-width line makes the gutter
detector fail closed by design, so `jorda p9` passed it.

### A residual the removal exposed, pinned with its rate

Round 4's gutter check had been masking a different hole: **any boxless row of
short word CELLS** is caught by nothing. Round 5b widened this from the "one
answer column" wording, which was narrower than the hole (Fable) -- "Sample Full
Full Restricted Full" and "Estimator OLS IV OLS IV" pass exactly as "generation
of electricity Yes" does. The box rule needs a box over it; the categorical-row
rule knows only the Yes/No vocabulary and needs two ADJACENT cells; and the order
gate passes because the order is right and only the BINDING is lost. Removing the
gutter check made it visible again, which is the honest state.

Measured rather than argued, with the WIDE vocabulary: **0 of the 138** gaining
pages ship such a row, and Fable measured the same independently. Real in
principle, absent in this corpus. Pinned by
`test_a_boxless_word_cell_row_of_any_vocabulary_is_the_known_residual`, whose
assertion fails if something ever does catch the shape, so the pin cannot rot
into a false claim.

### What the order gate's ground truth actually is (round 5b, Fable P2)

`native_text` is `get_text()`: the text layer's **STREAM order** in PyMuPDF
block order, not true reading order. On a PDF whose content stream emits a
two-column page ROW-MAJOR, the stream itself interleaves the columns and the
gate is VACUOUS -- the welded band matches the stream and passes. So the gate
catches pages where the lane's y-clustering disagrees with the stream, which is
the common case and the one measured at 89 of 237, and it cannot catch a page
whose stream is itself interleaved. Fable measured no welded two-column bands
remaining on the corpus, so nothing is known to slip through -- but the
guarantee is "agrees with the text layer's order", not "is the page's reading
order", and this log should not claim the stronger thing. True reading order is
#1159's.
