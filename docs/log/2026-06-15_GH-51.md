# GH-51 — Qwen model resolution is ambiguous

Date: 2026-06-15
Ticket: GH-51
Agent: socr-implementer (claude-sonnet-4-6)
Commit branch: feat/001-issue-plans

## What changed

### Problem

`QwenEngine._build_command()` only substituted the validated local instruct model
(`qwen3-vl:30b-a3b-instruct`) when `qwen_backend == "ollama"`. With the default
`qwen_backend == "auto"` and `qwen_model == "qwen3.5:cloud"`, the cloud model string
was silently passed to the CLI, which can then resolve `auto` to a local Ollama backend
and attempt to use a cloud model tag locally — producing either a model-not-found error
or undefined behavior.

### Solution

Introduced `resolve_qwen_intent(config)` in `src/socr/engines/qwen.py` as the single
authoritative resolver for (backend, model) intent. Rules:

1. If `config.qwen_model_pinned` is True (user passed `--qwen-model`), pass model through unchanged.
2. If backend is non-local ("vllm", "api"), pass model through unchanged.
3. If backend is local/auto ("auto", "ollama") and model is not pinned, use `OLLAMA_MODEL`
   (`qwen3-vl:30b-a3b-instruct`) — the validated instruct MoE.

The resolver also emits a `logger.info` line with resolved backend and model on every
invocation (plan item 4).

### Files changed

- `src/socr/engines/qwen.py`: Added `_LOCAL_BACKENDS` frozenset, `resolve_qwen_intent()`
  function, and updated `_build_command()` to use the resolver instead of scattered
  string checks.
- `src/socr/core/config.py`: Changed `qwen_model` default from `"qwen3.5:cloud"` to `""`
  (empty = unset, resolver picks the correct default). Added `qwen_model_pinned: bool = False`
  field to track explicit user overrides. Added `qwen_model_pinned` to `from_file()` scalar
  fields.
- `src/socr/cli.py`: Updated `--math-model` default from `"qwen3-vl:8b"` to `None` (now
  only sets config when explicitly passed, avoiding overwriting the config default). Help
  text now clarifies this is the math-only path, NOT the OCR qwen tier (plan item 5).
  `build_config()` sets `config.qwen_model_pinned = True` when user passes `--qwen-model`.
- `tests/test_qwen_engine.py`: Replaced old `test_qwen_model_defaults_to_cloud` (tested
  the bug) with a comprehensive set covering all acceptance criteria: auto backend,
  explicit ollama backend, explicit model pin, cloud model pin, blank model, vllm backend,
  api backend, build_command integration, and agentic local profile.

### Decisions

- Used `qwen_model_pinned: bool` field rather than `None`-sentinel in `qwen_model` to
  avoid breaking the existing `qwen_model=""` → "no --model flag" behavior that
  `test_qwen_model_omitted_when_blanked` relied on.
- Pre-existing ruff E501 on `cli.py:47` is out of scope (confirmed pre-existing via
  git stash check); not introduced by this change.
- `math_model` CLI default changed to `None` so it only sets the config when explicitly
  passed, leaving the config's own default (`qwen3.5:cloud`) in effect for unattended runs.
