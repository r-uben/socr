# GH-779 — band-split regions leave a duplicate plain-text copy

Status: DONE.

## Files
- `src/socr/core/born_digital.py` — `_regions_are_band_siblings`, `_union_coverage`,
  and the union check at the suppression call site (~line 3708-3812)
- `tests/test_gh779_band_union_coverage.py` — 12 tests, all new

## The defect (confirmed on main, reproduced first)

GH-152 splits one wide table into a left-band and a right-band region at a single x
gutter when it detects two genuinely side-by-side tables. Both bands cover the SAME
row range (they come from the same words, partitioned only by x). When a row's own
PyMuPDF block/line grouping spans both bands — measured directly: on an unruled page
with one `insert_text` call per row, each row becomes its own block spanning the full
row width, confirmed against `page.get_text("dict")` — neither narrow band clears
`_REGION_COVERAGE_DROP` (50%) alone (measured ~37% left, ~32% right on the reference
fixture), so the row's lines survive untouched and ship a second time as a plain-text
duplicate beneath the two correctly-split markdown tables. Every value stays
individually correct and correctly attributed in both copies — redundancy, not
misattribution — and it is silent: nothing in status, metadata, or logs flags a
skipped suppression.

## The two questions team-lead asked to work out, not guess

**1. Union of area, not any-of-a-set.** `_union_coverage(inner, outers)` clips each
outer rect to `inner`, then rasterises the clipped pieces onto a grid built from their
own x/y boundaries and sums only cells covered by at least one piece — exact for
axis-aligned rects, and it does not double-count overlap between the outer rects
themselves. Verified directly: `test_union_coverage_does_not_double_count_overlap`
shows the naive sum of two individually-measured coverages exceeds 1.0 for two
overlapping regions, while the union function correctly caps at 1.0. A block half in
band A and half in empty space is handled by construction, not by a special case: a
region that does not touch the block contributes zero area to the union regardless,
so it never inflates coverage — pinned by
`test_below_union_threshold_a_spanning_row_still_ships` (a wider gutter leaves ~44%
combined coverage across two bands that DO both touch the block, and the row still
survives un-suppressed).

**2. Band provenance is NOT available at this call site — confirmed by reading
`reconstruct_table_regions`, not assumed.** It returns `left_out + right_out`, a flat
`list[(rect, markdown)]` with no tag distinguishing which regions came from the same
split. This file must not touch `reconstruct.py` to add that bookkeeping (out of
scope, and it would reopen GH-152's own split logic). The substitute is a geometric
proxy: `_regions_are_band_siblings(rects)` — every pair must be disjoint in x AND
overlapping in y, exactly the signature a single band split produces (columns of the
same row range) and nothing else on an ordinary page reliably produces. Two unrelated
tables stacked vertically (different y, the ordinary case) fail the y-overlap test and
are never unioned — pinned directly (`test_y_disjoint_regions_are_not_siblings`) and
end-to-end via the fact that `test_tokens_are_matched_against_the_covering_region_only`
(GH-145/#718b's own guard, in `tests/test_region_overlap_gh145.py`) still passes
unmodified: a combined token index across unrelated regions is still exactly the bug
it always was, this change only widens the coverage GATE that decides which regions
feed the index, never the index-building itself, and only for regions that are
geometric siblings of one split.

## Call-site wiring

Only engages when the existing per-region check finds nothing (`if not covering:`) —
strictly additive. Among the regions that actually touch the block at all
(`_rect_coverage(...) > 0.0`), if there are 2+ AND they pass the sibling test, and
their union coverage clears `_REGION_COVERAGE_DROP`, they become the `covering` set
fed to the unchanged content check (`_region_token_index` / `_line_is_in_region_text`)
below. No new threshold — reuses `_REGION_COVERAGE_DROP` for both the per-region and
the union test, as instructed.
