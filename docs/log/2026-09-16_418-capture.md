# GH-418 step 2/2 — capture the orphan word into the trailing column

Branch `fix/418-orphan-capture`, off `origin/main@daa7a6f`. Continues step 1
(`docs/log/2026-09-16_418-event.md`, PR #788) and implements the panel ruling
in `docs/log/2026-09-16_418-design.md` (Option 3: surface then repair).

## What changed

`_rowize_segment` (`src/socr/tables/reconstruct.py`) now computes, per row,
`is_data_row = len(row_numeric_lanes) >= 2` — the same predicate
`_looks_tabular` (`reconstruct.py:978`) already uses to call a row a "data
row", applied one step earlier and over the same snap rule the lane-cell
branch already uses. An orphan word (further than the snap radius from every
lane) on a row that clears this gate is appended to `orphan_marginals` (the
trailing column) instead of being deleted. A row below the gate (sparse, or a
header) still deletes the word and, when `orphan_drops` is wired, still
records it — this residual is the panel ruling's explicit requirement, not a
gap left by the fix.

No new threshold was introduced; the `>= 2` gate is reused verbatim from
`_looks_tabular`, per the ruling's instruction that the gate is measured and
not open for re-litigation this ticket.

## Decision: reuse `orphan_marginals`, not a new column

Reused GH-461's existing trailing column rather than adding a second one.
Evidence:

1. The design note's "What you are building" section names `orphan_marginals`
   as the target column directly — this reads as the directive, not merely a
   suggestion.
2. Both a GH-461 margin note and a GH-418 captured qualifier are the same
   *kind* of thing from a downstream consumer's perspective: an annotation
   riding along a row, not a value. Splitting them into two trailing columns
   would ask every consumer (the markdown renderer, `_clean_grid`,
   `_prepend_header_band`'s own note column) to distinguish two annotation
   columns with no behavioural difference between them.
3. A second column would require threading a second sideband through
   `_clean_grid`'s "drop iff every row's trailing cell is empty" rule and
   through `_prepend_header_band`'s own band-note column, which already
   aligns structurally with the single trailing column. That's strictly more
   surface for the same outcome, with no measured defect motivating it.
4. No defect was measured that a shared column would cause (e.g. no fixture
   in the design note or in this ticket's own new tests ever needed to tell
   a GH-461 note and a GH-418 capture apart in the same cell) — this is
   because a capture inserted alongside a folded marginal note requires two
   independent sources on the SAME row, which none of the measured corpus
   or the constructed worst-case fixtures exhibit.

If a real corpus case later needs to distinguish a folded margin note from a
captured orphan qualifier in the same row's trailing cell, that's new
evidence for a follow-up ticket — not a reason to split the column now.

## Residual-loss contract (explicit, not implied)

A word further than the snap radius from every lane is captured into the
trailing column IF AND ONLY IF its own row already has `>= 2` numeric lanes
populated. Two cases still delete the word and still record it via
`orphan_drops`/`orphan_word_dropped`:

- **Single-lane (sparse) rows** — a row with 0 or 1 populated numeric lanes.
  The word is deleted from the grid; `orphan_drops` still names it
  (`{"word", "x", "y"}`), and step 1's audit/event surfacing is unaffected.
- **Header rows** (inside the same y-segment, not `_prepend_header_band`'s
  separate multi-line-header path) — 0 numeric lanes by definition, same
  outcome as above.

This is the panel ruling's explicit design, not a limitation of this patch:
the `>= 2` signal is what separates a genuine table row from prose, and rows
that don't clear it get no benefit of the doubt.
