## What changed

### New file: `src/socr/tables/native_verifier.py`

Deterministic two-tier PyMuPDF-only verifier for born-digital table pages.
No model call. Implements Consilium Option C.

**Named tolerances and their basis:**

- `_WELL_SEPARATED_GAP_PT = 18.0 pt` (= 2 × `_LANE_X_TOL_PT` + 6.0):
  Minimum gap between two distinct lane centres for the hard-fail predicate.
  Basis: a two-digit number "12" at 9pt font is at most ~12pt wide; a safe
  inter-column gap in a well-formatted econ table is >= 30pt. Setting to
  2 × lane-cluster-tolerance + one extra grid unit gives headroom over glyph
  spread while staying well below real inter-column whitespace.
  Derived from `_LANE_X_TOL_PT` (imported from `reconstruct.py`) — not a
  bare literal.

- `_MIN_HARD_FAIL_LANES = 2`:
  Minimum number of distinct well-separated lanes in a row required before
  a collapse can be called geometry-impossible. A single-column row cannot
  collapse by definition.

- `_LANE_X_TOL_PT = 6.0 pt` (reused from `reconstruct.py`):
  Numeric tokens within this x-distance share a lane. Basis: sub-column
  glyph spread on proportional-width fonts, validated on Fama-French 1997.

### Modified file: `src/socr/pipeline/agentic.py`

## Hard-fail predicate name

`geometry_impossible_collapse` — a native data row has K >= 2 well-separated
numeric token lanes, but the output markdown data row has fewer populated cells.
Populated cell count < native well-separated lane count → structurally impossible.

## Notes on CBO-style sparse drift

The GH-46-D2 sparse drift case (value in wrong column) is NOT caught by the
hard-fail tier. This is intentional per the Consilium Option C spec: the
hard-fail predicate is `geometry_impossible_collapse` (fewer cells than native
lanes), NOT `value_in_wrong_lane` (correct cell count, wrong column). The
latter would require per-value x-position matching (Option B) and would
false-fail on repeated values across columns ("1,204" N row). The VLM judge
and the existing prompt mitigation (GH-46-D2) remain the catch for that case.

## Residual risk

- The hard-fail predicate pairs native rows to output rows by ordinal
  position, not by value matching. On a page where native rows and output
  rows have different counts (e.g. header repetition, footnote rows in
  output), the pairing may be off by one and a genuine collapse could be
  missed. This is conservative (false-negative), never a false-positive.
- Tables where ALL numeric values repeat (e.g. a constant N column of
  "1,204" across all specs) correctly pass the hard-fail gate because the
  populated-cell count still matches the lane count.
- A fitz.Page is opened fresh per `assess()` call inside the verifier judge
  via `fitz.open(pdf_path)[page_num - 1]`. The document object is opened and
  garbage-collected per call (no caching). For typical 2–5 page table batches
  this is negligible; for a 300-page document with table pages on every page,
  profiling recommended if latency becomes an issue.

## Post-review fix (2026-06-15 — reviewer critical finding)

Header-row pairing bug: `_rows_by_y` included header rows whose spec-number or year-label tokens match `_NUM_TOKEN_RE`, so the ordinal-position pairing compared output data row i against native_row_list[i] (the header row), producing a false `geometry_impossible_collapse` on legitimately sparse data rows in regression tables. Fixed in `native_verifier.py:333-357` by computing `_offset = max(0, len(native_row_list) - len(output_data_rows))` and indexing `native_row_list[_offset + out_idx]` (trailing alignment, conservative/false-negative bias). Added `test_no_false_fail_with_spec_number_header_and_sparse_se_row` (FAILED on 7026dc8, PASSES after fix); strengthened all four existing `TestFalseFailGuard` tests to include header tokens via `_make_fitz_page_explicit`. 865 tests pass.

## Pairing reimplementation: value-overlap matching (post-review, supersedes trailing-offset)

The initial fix for the numeric-header false-fail used a trailing-offset alignment
(`_offset = max(0, len(native) - len(output))`, commit 3995003). That relies on the
positional assumption "extra native rows are leading headers," which misaligns on tables
with trailing footnote rows. It was replaced with a **value-overlap pairing**
(`_pair_output_to_native_rows`): each output row is matched to the native row with the
greatest numeric-token multiset overlap (`Counter & Counter`); ordinal pairing is used only
as a fallback when row counts match exactly; ties and unmatched rows are deferred to the VLM
(never guessed). This is robust to header AND footnote position and to repeated values.

A second adversarial review (the value-overlap version was originally uncommitted and never
reviewed as a unit) found one more false-fail: a **label-only panel/section-header output row**
(zero numeric tokens, e.g. AER/QJE "Panel A." rows) with equal native/output row counts fell
through to the ordinal fallback and got compared against a native spec-number header row.
Fixed by guarding the ordinal fallback with `and output_tokens` — a row with no numeric output
tokens cannot demonstrate a geometry-impossible collapse, so it is skipped/deferred.
Regression test: `test_no_false_fail_panel_header_row_with_spec_number_header_and_data`
(fails pre-guard, passes post-guard). Full suite 868 passed.
