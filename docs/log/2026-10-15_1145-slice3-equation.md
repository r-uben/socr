# #1145 slice 3 (equation) — an attached equation reading is not a verified one

2026-10-15. Branch `feat/issue-1145-slice3-equation` off `origin/main` (c4e7c725). Carries
slice 2's review-round-3 fixes as its first commit, per the orchestrator.

## What the clause is

399 pages of run 23192118 ship SUCCESS, `failure_mode=none`, `audit_passed=True` and NO
mark, having spliced a model's LaTeX reading of an equation crop into the page. The lane
validates **LaTeX syntax only**. A candidate that parses — even one that aligns to the
source span — is not a candidate that says what the crop says. So the mathematics on those
pages is unverified by construction and nothing told the reader.

`equation_fidelity=UNKNOWN`, plus a demotion. UNKNOWN rather than FAIL because no check
decided against the page: none ran.

### The design named the wrong input, and checking it mattered

The design says the clause keys on `semantic_fidelity_verified` "per attached reading". It
is not a per-reading anything: it is a literal `False` inside two audit-event payloads
(`orchestrator.py:3538` and `:4377`), never computed, never varying, and not a field on
`PageOutput` at all. What it records is that the validation scope is `latex_syntax_only`.

So the clause keys on the lane's own record that it ATTACHED a reading —
`equation_region_reading_attached` — and not on the `native+equations` engine label either,
though the two agree on every page of the corpus (403 of 403). The event is what the lane
did; the engine label is a routing artefact a future lane could set for unrelated reasons.
Checked before relying on it: that kind is in `EQUATION_LANE_EVENT_KINDS`, the explicit
replay allowlist, so it survives a resume rather than vanishing with the audit log.

Measured: **403** pages carry the attach — 399 shipping SUCCESS (demoted here) and 4 already
WARNING (which gain a second, true clause; see below).

## Two findings from this slice's own tests

**1. The seam was not idempotent for a demoting clause, and the mark and the record
disagreed.** Caught by this file's three-pass idempotence test. The demotion makes the page
WARNING, so on the next pass — and `_rewrite_all_fragments` re-runs the seam over every page
at assemble — a SUCCESS-only clause was not re-derived, nothing else named a check, and the
**fail-closed fallback fired**: the page's line still said `equation_fidelity=UNKNOWN` while
its sidecar verdict had become `unknown=UNKNOWN`. That is the same conflation of "what is
true" with "what is written" that `build_page_verdict` and `marks_to_write` were split apart
to prevent, reappearing through the new path.

Fixed by deriving the silent-success clauses for **every** status, not only SUCCESS. The
fact is true whatever the status says. A CHECKED page still stays byte-identical because it
has none of these clauses, and a page already WARNING for another reason now gains a second
clause — which design §1 asks for explicitly ("the reader is owed both reasons, not the
first one"). Measured consequence: `equation_fidelity` clauses went 1,517 → 1,521, exactly
the 4 already-WARNING pages.

**2. The demotion made 399 pages permanently non-resumable.** Found by the equation lane's
own resume tests failing, not by review, and it is not a test-expectation problem:
`_load_terminal_page` requires `status == SUCCESS`, so every resume re-OCR'd all 399 and
re-called the equation model — and the next run demotes them again, so **the work never
converges**. That is the precise failure #713's credentialed exception exists to prevent,
reached through a new door.

A **third deliberate exception** to the resume gate, with the same argument as the two
already there: a page demoted only because a check can never run is a CONTENT verdict, not
an infra doubt. `_resume_verdict_is_permanently_unverifiable` admits a page only when EVERY
non-PASS clause in the verdict its own run published is in
`PERMANENTLY_UNVERIFIABLE_CHECKS`, which is `{equation_fidelity}` and nothing else.

**The set is keyed on `(check, result)`, and the RESULT is load-bearing.** Keying on the
check alone was a bug, and
`test_orchestrator.py::…::test_agentic_corrupt_math_flag_uses_region_recovery_not_whole_page`
caught it: that test pins that a corrupt-math-hybrid page must re-OCR, and slice 1's clause
for it is `equation_fidelity=FAIL`. Two clauses share the check and must be treated
oppositely — `UNKNOWN` means no check decided and none ever will, while `FAIL` means one did
and found the mathematics damaged, which a run with a provider available can genuinely fix.
That is the general rule for this set rather than a carve-out: something wrong may be
fixable; something never checked will not be.

**The narrowness is the entire safety argument, and a surviving mutant proved nothing pinned
it.** Widening the set to every `Check` left the whole suite green. The distinction: an
`equation_fidelity` clause can never be resolved by reprocessing, while a `page_judge`
timeout may well answer next time — skipping that would keep text no judge accepted. There
is now a test with one row per side plus the MIXED case, which is the one that matters: a
page carrying both must reprocess, so an admissible clause cannot carry an inadmissible one
past the gate.

## Review round 1 on PR #1171 — the idempotence fix opened a hole

**P1, and it is this slice's own doing.** Deriving the silent-success clauses for every
status (finding 1 above) meant a page demoted by a STATUS-ONLY guard that sets no failure
mode — `_apply_ditto_guard`, which names no check anywhere — and which also carries an attach
event came out with exactly `{equation_fidelity=UNKNOWN}`. Not empty, so the fail-closed
fallback stayed silent; and the page then looked to the resume exception like one whose every
clause is unresolvable, so it would be **restored for ever under a reason that is not the one
that demoted it**. Before this ticket it was re-OCR'd. 0 corpus pages, plainly reachable.

The fix needed two changes, and the first reverses a decision made an hour earlier.

**The demotion now records a failure mode**, `EQUATION_FIDELITY_UNVERIFIED`. The first draft
was status-only "with no new `FailureMode`: the mode has nothing true to say here that the
clause does not say better", and that was wrong: a status-only demotion leaves the page
indistinguishable from one demoted by a guard that names nothing, so re-running the seam
could not tell whether the clause justified the status or the status was unexplained. Either
the fallback fires on a page whose reason IS named (breaking idempotence) or it stays silent
on a page whose reason is not (this hole). The mode closes both, `_MODE_CLAUSES` maps it back
to the same clause so a re-pass derives exactly what the first pass did, and it is the same
purpose `HEADER_BINDING_UNVERIFIED` already serves one check over — "this mode exists to stop
a clean-passing winner shipping silently as an undemoted SUCCESS". An existing, more specific
mode is never overwritten.

**The fallback condition is now "is the status explained", not "are there clauses".** A
silent-success clause says something true about the page but nothing about its STATUS — it
would be there on a SUCCESS page too — so it cannot discharge the fail-closed duty. The mode
is asked directly rather than inferred from the surviving clause list, because the mode's own
clause is correctly DEDUPED away as a duplicate of the silent-success one, and reading that
absence as "nothing explains the status" is what re-broke idempotence on the first attempt.

### The legacy equation seam, and a comment that asserted what nobody had checked

`_attach_equation_latex_sidecars` (under `--detect-equations --recover-clean-equations`)
splices model readings exactly as the region lane does and emits `equation_latex_accepted`,
no attach event — so keying the clause on the region kind alone let every page of that seam
escape. 0 corpus pages, because those flags are off by default. Covered anyway: the cost is
one more member of a frozenset, and the alternative is a known silent gap waiting for someone
to turn the flags on.

Writing that, I added a comment saying both kinds are in `EQUATION_LANE_EVENT_KINDS` and that
this was "checked, not assumed". It was not checked and it was false:
`equation_latex_accepted` was **absent** from the replay allowlist.

**And there was a guard whose whole job was to catch that, which could not see it.**
`tests/test_gh522_lane_events_survive_resume.py::test_every_emitted_lane_event_is_replayed
_or_explicitly_not` scans the orchestrator's parse tree for `kind="equation_*"` KEYWORD
arguments. The legacy seam picks its kind in a branch and assigns it to a local
(`kind = "equation_latex_accepted"`) before passing `kind=kind`, so that whole family was
invisible to the guard in BOTH directions — no allowlist entry, and "every emitted kind is
replayed or explicitly not" passed anyway. The scanner now sees both shapes, with a named
test (`test_the_scanner_sees_a_kind_assigned_to_a_variable`) and a mutant that narrows it
back, so this cannot regress to keyword-only while every guard in that file stays green.

Widening it immediately surfaced a second gap: **`equation_latex_rejected_kept_crop`** was
also never replayed. Added, by the GH-522 argument already made for the region lane's own
refusal record — "refusing a reading is only acceptable BECAUSE the crop survives for a
human to check; without this the record was dropped on resume and the guarantee held only
until the next run" — which is exactly as true for the legacy seam's refusal, which also
retains a crop. That one is nothing to do with #1145 and would still be worth fixing if this
ticket did not exist.

`tests/test_resume_restore_kinds.py`'s frozen union and its size pin both move, 52 → 54,
each with its reason at the line: that pin exists so an addition is explicit rather than
drift, and it did its job. By that set's own
docstring a missing kind "disappears from `audit_log.json` the moment the page resumes",
which was already the #252 shape for that seam and independent of #1145 — and #1145 makes it
load-bearing, because a clause whose evidence is dropped on resume would silently un-demote
the page. Added, and the comment now says what actually happened.

### P2 not taken: the fragment digest

The comment claimed "everything else the gate checks still applies: fingerprint, input
checksum, the verdict's presence, the fragment digest". The digest check runs only under
`is_credentialed_judge_timeout`. **The comment is corrected rather than the check added**,
and states exactly what this branch is protected by: the run fingerprint (which hashes every
shipped `socr` source file), the input checksum, the verdict's presence AND parse, the
non-empty-body and failed-marker refusals, and the label-canonicalisation check — the same
protections the ordinary SUCCESS path has, and no more. A hand-edited fragment restores
verbatim here exactly as it does there: a property of the ledger that predates this branch.
Closing it needs a finalized-body digest recorded for this class, which nothing records
today; #713 had to mint a credential to get one. Noted rather than half-built, and I would
rather Fable overrule this than have it pass unexamined.

### The table-count cost, measured because it was promised

`core/table_counts.py:110` computes `verified = status == SUCCESS and not reasons and not
unverified`, so a demoted page's table blocks leave `verified_text`. Of the 399 pages, **16
carry a table block at all, totalling 23 blocks — 3.07%** of the 748 blocks currently
counted verified.

Accepted, in the under-claiming direction: a table on a page with an unresolved check is
shipped but not on a page socr confirmed, and for a citation corpus under-claiming
verification is the safe error. The blocks are not reclassified as `unverified_text` (that
needs its own signal), so they count as shipped only — a loss of precision, not of data.
**Follow-up worth its own ticket:** teach `table_counts` the verdict, so a clause about
EQUATIONS does not un-verify a TABLE. I did not do it here because it reaches into another
module's rule on behalf of this one.

### Library curation: zero documents move

`library._BAD_PAGE_STATUSES` makes a DOCUMENT `unverified` if any page is warning/error, so
this demotion is a curation change too. The 399 pages sit in **108** documents and **none**
of those 108 is clean today — every one already carries a warning or error page, so all 108
are already `unverified`.

- `test_gh140_math_font_audit.py::test_fully_covered_page_raises_no_event` — `status is
  SUCCESS` was its proxy for "not demoted FOR THIS REASON" and is no longer valid: the page
  IS demoted, correctly, by a different clause. `test_gh165_unresolved_math_outcome.py`

- `test_equation_lane_pipeline_p4r.py::test_manifest_selection_ships_the_attached_output
  _unchanged` — compares through the strip helper, which asserts the mark was present and
  well-formed, and keeps the real guarantee (the attachment is not discarded).
- `…::test_resume_restores_the_attached_page_without_a_second_model_call` — now compares the
  page FRAGMENT across runs rather than `best_output`. `best_output` legitimately differs
  between a fresh and a resumed page: the resume reader sets `page_out.text` from the
  fragment on disk, while a fresh run's is the pre-seam candidate. That asymmetry PREDATES
  this ticket and was invisible only because the seam used to leave the bytes alone. The
  fragment is the authoritative artefact, so this is a stronger assertion than the one it
  replaces.
