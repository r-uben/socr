Date: 2026-06-15
Branch: fix/47-figure-caption-antifab

## What changed

### Shared prompt module (reviewer fix: third HPC caption path)

After the initial commit, the reviewer identified a third live caption path:
`VLLMEngine.describe_figure` in `src/socr/engines/vllm.py` (used by
`--hpc-sequential`) had its own copy of the OLD fabrication-encouraging prompt
("Be specific about numbers, labels, and relationships shown") and returned
`FigureInfo` without `_wrap_caption`. Both acceptance criteria were unmet on the
HPC path.

Fix: extracted the hardened prompt and the marker/wrapper into a single shared
module `src/socr/engines/_figure_prompt.py` so all three engines (`GeminiAPIEngine`,
`OllamaFigureEngine`, `VLLMEngine`) import from exactly one definition and cannot
drift. `gemini_api.py` and `vllm.py` now both import from `_figure_prompt` and the
local duplicate in `vllm.py` was deleted.

Write ownership extended to: `src/socr/engines/vllm.py` (third live path, per
reviewer) and `src/socr/engines/_figure_prompt.py` (new shared module).

### Shared module: `src/socr/engines/_figure_prompt.py`

Exports:
- `CAPTION_MARKER = "[model-generated, non-authoritative gist]"`
- `build_figure_prompt(figure_type, context) -> str` — hardened anti-fabrication prompt
- `wrap_caption(description) -> str` — idempotent marker prepend; no-op on empty string

### Hardened prompt (all three engines)

The old prompt ("Be specific about numbers, labels, and relationships shown") was
replaced with:

> Describe what this figure visibly shows. Focus on the overall structure, general
> trend or pattern, and any clearly legible labels or categories that you can read
> directly from the image. IMPORTANT — omit anything you cannot clearly read: do NOT
> guess or infer specific numeric values, axis ranges, tick-mark numbers, thresholds,
> or arrow labels that are not unambiguously legible. If a value is blurry, small, or
> uncertain, skip it entirely rather than estimating. The goal is a concise, honest
> gist that avoids fabricating details.

### Model-generated marker — all three engines

`wrap_caption` is called at the VLM-output return point in each engine:
- `GeminiAPIEngine.describe_figure`: after `_extract_text`; skipped when text is the
  "Unable to generate description" fallback.
- `OllamaFigureEngine.describe_figure`: after `content.strip()`; always wraps (empty
  is guarded by `wrap_caption`'s own empty-check).
- `VLLMEngine.describe_figure`: after the `< 10 chars` guard; only genuine ≥10-char
  responses are wrapped. API errors, timeouts, connection errors, and "not available"
  strings return unwrapped.

### Where the marker appears in output markdown

`orchestrator._build_figure_blocks()` (NOT touched) builds:
```
**Figure N** (page P): [model-generated, non-authoritative gist] <description>

![Figure N](figures/figure_N_pageP.png)
```
The PNG path is preserved adjacent to the caption.
