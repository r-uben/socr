# #1306 (A5 part 1): control bytes and hidden duplicate footnotes

Branch `fix/issue-1306`, from main dcc957a6. Scope: control bytes and the hidden footnote
wrapper. Dropped fi/fl letters and stacked fractions are out of scope: they stay mark-only
(already flagged by existing clauses) and get a repair in a separate change (A5 part 2), because
a repair of dropped letters needs the PDF's glyph geometry, not a text rule.

Review round on PR #1308 (Astra, cubic): the footnote strip now needs PDF evidence that the
wrapper is hidden, keeps the token boundary, strips native text only, and the test and
measurement points below were fixed. Sections below describe the final state.

## Problem
The native lane ships the PDF text layer as is. Two defects of that layer reached the reader
unmarked:
- A control byte stands for a glyph the layer could not map (often a minus). #990 reroutes only a
  byte before a digit; a NUL before `%`, an ETX before `(` or a word shipped as trusted SUCCESS.
  Deleting the byte is not an option: `\x010.47` would ship as a clean, positive `0.47`.
- The Fed's accessible PDFs carry an invisible tagged copy of each footnote,
  `[Footnote N. ... End footnote N.]`, next to the printed one. Both shipped.

## Change
`core/damaged_layer.py` (pure) and one guard at the finalisation seam,
`manifest._apply_damaged_layer_guard`, step 9e2, after every status guard and before the
verdict reads the bytes. It runs on every shipped text whatever its engine and status, so
`--native-only`, NATIVE_FALLBACK and the chart lane are covered. The final `.md` and the
fragments come from the same seam output, so byte identity holds (pinned by the tests: the
shipped page text is inside the final `.md`).

Control bytes:
- C0 except tab, LF, CR (VT and FF included, the set #990 counts) becomes U+FFFD, one character
  per byte, never nothing.
- Verdict clause `control_bytes` (FAIL, page scope, silent-success class): mark naming the count
  and code points, SUCCESS demoted to WARNING with mode `control_bytes_replaced`
  (`PERMANENTLY_UNRESOLVABLE_MODES`: the same layer holds the same bytes, so a resume restores it).
- Document: bucket `control_bytes_pages` from the verdict, document not SUCCESS, CLI line and
  `result.error` note.
- Event `control_bytes_replaced` (`count`, `codes`), written by the sidecar flush.
- #990 is unchanged. Its digit case still reroutes to the provider; under `--native-only` or with
  no provider it ships WARNING with `native_minus_as_digit` and now also carries the U+FFFD and the
  `control_bytes` mark. A model reading is marked the same way when its own text carries a control
  byte; the clause needs the guard's record AND U+FFFD in the shipped text, so a clean model
  reading is never marked.

Hidden footnote wrapper:
- Recognised on one line: `[Footnote N. text End footnote N.]`, `End of footnote N.` as closer,
  brackets both present or both absent, case-insensitive. Opening and closing N must agree.
- Stripped only when ALL hold:
  1. Native text only. A model reading is never rewritten (`engine_ships_native_text`).
  2. Hidden-text evidence from the PDF, not from the text. Page analysis
     (`BornDigitalDetector._painted_layer_text`, carried on `PageState.painted_layer_text`,
     refinalize reads the same field) reads the glyphs the page paints: the text with
     `TEXT_IGNORE_ACTUALTEXT`, page-clipped, minus spans with alpha 0 (render mode 3 and zero
     opacity both report 0). The Fed wrapper is `/ActualText` replacement text on the printed
     footnote-reference digit: the layer returns the wrapper, the page paints only the `1`
     (checked on real pages, e.g. 2009-09-23 bluebook p4, whose span is 3.5 pt wide). If the
     painted glyphs contain the wrapper's `Footnote N.` or `End [of] footnote N.` frame, or were
     not read (`None`), the wrapper is kept (reason `hidden_not_evidenced`). Not
     `get_texttrace`: on PyMuPDF 1.27.2 it corrupts a refcount and killed the interpreter after
     a few hundred Fed pages.
  3. A complete printed note line outside every wrapper: it starts a line with `N`, `N.` or
     `N)`, carries exactly the same words (whitespace-normalised, a printed wrap is fine) and
     ends where its line ends. A longer printed note that only begins with the wrapper's words,
     and a copy in the middle of a line, do not count. The wrapper never vouches for itself.
- Removal keeps the token boundary. The wrapper is replaced by ONE space iff the text had
  whitespace immediately before or after it, or both neighbours are word characters; otherwise by
  nothing (`rate[..].` -> `rate.`, `Growth[..] slowed` -> `Growth slowed`, `1[..]2` -> `1 2`).
  A wrapper at the edge of its line leaves no separator. A separate guard keeps a space whenever
  removal would join a digit, sign or point on the left to a digit or a point-and-digit on the
  right, so no new numeric token is ever formed (`1[..] .2` -> `1 .2`, `1[..].2` -> `1 .2`,
  `-[..]5` -> `- 5`; `2020[..].` -> `2020.`).
- One `hidden_footnote_stripped` event per strip (`note`, `chars`, `printed_copies`, `text`).
  Strips happen only on native text, so every strip has its event (the writer keeps its engine
  gate for a stale record). No mark, no demotion: it is a repair.
- Kept untouched: lone, continued (printed copy shorter), differing, multi-line, number
  mismatch, a wrapper the PDF paints, a page whose painted glyphs were not read, a printed copy
  that is not a complete line, the older lowercase `footnote 1 ... end of footnote 1` form.
- Words check: `missing_words(..., excused=)` subtracts the stripped wrappers' words one for one
  from what the page owes. A word printed only in the wrapper stays owed; a model reading is
  never excused (gated on `engine_ships_native_text`).
- A model reading that carries a control byte gets the same U+FFFD and mark: the control-byte
  repair runs on every shipped text, whatever its engine.

Resume: both kinds are in `_RESUME_REPLAYED` and `tests/test_resume_restore_kinds.py` (69 -> 71).
A resumed terminal page restores the repaired text and never runs the guard again, so the
events are the only record. The mark comes from the published verdict.

## Measured (cached run, no OCR; `docs/log/2026-11-13_1306-measure.py`)
Stage 1 applies the guard to every shipped fragment, with the painted glyphs read from the PDF
(all 156 PDFs opened, 0 skipped). Stage 2 rebuilds the words reference from the PDF with socr's
page analysis on the pages that carry a wrapper.
- Control bytes: 12 -> 0 (7 pages). 12 U+FFFD ship instead (0 were already in the fragments). All 7
  pages are marked; the 3 unmarked SUCCESS pages become WARNING.
- Hidden footnotes: 366 well-formed wrappers (number agrees) on native-lane pages, all with
  hidden-text evidence (366 of 366: none of their frames is painted; no visible wrapper in the
  corpus). 312 stripped on 242 pages. 54 kept: 24 `printed_copy_absent`, 30
  `printed_note_differs`, 0 `hidden_not_evidenced`. Compared with the first version of this PR
  (text coincidence alone, 330 stripped), 18 wrappers moved to kept because their printed copy is
  not a complete note line: the layer runs several footnotes together in one paragraph
  (`6 The single-equation ... Bluebook. 7 In the current projection ...`, 2009-09-23 bluebook p29;
  2009-11-04 bluebook p12-13; 2012-10-24 tealbook-partb p8). They keep a visible duplicate; no
  word is lost. Of the 330 first-version strips, 0 were on model pages. 7 pages that carry a
  wrapper ship a model reading and are untouched. 11 pages have both a strip and a kept wrapper.
  I did not hand-check the differing notes against the render; the rule keeps them.
- Words check on the 242 stripped pages: new missing words with the excuse 0. Without the excuse
  34 would have gained words_missing_from_page (the wrapper's "footnote" and the note's words
  counted twice in the layer).
- Not recognised, left as shipped: the older lowercase form (`footnote 1 text.end of footnote 1`,
  2002-2003 transcripts, 24 occurrences). The printed copy is not on the page in a matching form
  (2002-06-26 p2: the layer scrambles the order and note 2 is empty).
- Round 3 re-measure (same cached run, 30 min): identical counts. 312 stripped on 242 pages, 54
  kept (24 / 30 / 0), 41 pages with a kept wrapper, 0 skipped docs, 0 failed painted scans. The
  leading-zero, punctuation-boundary and render-mode-3 changes move no wrapper in this corpus;
  they close inputs the corpus does not contain.
- False alarm on clean pages: the control-byte clause fires only where a C0 byte exists (7 pages of
  12,413), so 0 on pages without one. Rerouted pages: 0 (no routing change).
