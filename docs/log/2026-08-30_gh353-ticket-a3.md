# 2026-08-30 — TICKET-A3: CLI2 rung, gemini CLI table judge invoker (GH-353)

## What changed

New `src/socr/judge/table_rung_gemini.py`: a per-crop subprocess invoker for rung 2
of the table judge ladder (the `gemini` CLI, Google One AI Pro headless surface —
design: `docs/log/2026-08-30_table-judge-ladder.md`).

- `build_gemini_argv(binary, crop_path, prompt)` — pins the exact argv:
  `[binary, "--skip-trust", "--approval-mode", "plan", "--include-directories",
  str(crop_path.parent), "-p", "Image crop: @<crop_path>\n\n<prompt>"]`.
  `GeminiEngine` (`socr.engines.gemini`) is a *document-level* wrapper around a
  different CLI (`gemini-ocr`), not reusable for a per-crop judge call, so this
  invokes the actual `gemini` agent CLI directly. Headless `gemini -p` has no
  dedicated "attach image" flag; the `@<path>` reference inside the prompt text is
  its documented file-inclusion mechanism, so the crop is handed off as a real file
  path (not re-encoded). `--include-directories` grants read access to the crop's
  (scratch/temp) parent dir; `--skip-trust` avoids an interactive workspace-trust
  prompt that would otherwise hang the subprocess past its timeout;
  `--approval-mode plan` keeps the call read-only.
- `judge_table_gemini(crop_path, markdown, prior_findings, config)` — builds the
  prompt via A0 (`build_table_judge_prompt`, with `prior_findings` in tiebreak
  mode), runs `_run_gemini_cli` (the module-local subprocess seam) under
  `config.table_judge_timeout_sec`, and turns every ¬S1 case — missing binary
  (`FileNotFoundError`), timeout (`subprocess.TimeoutExpired`), transport error
  (`OSError`), non-zero exit, or unparseable stdout — into
  `RungResult(ok=False, ...)` via A1's `rung_result_from_output`. Never raises for
  a judge-side failure.
- `make_gemini_rung(config)` — closure binding `config`, producing the exact
  `RungCallable` shape (`(crop_path, markdown, prior_findings) -> RungResult`)
  A4/B1 will inject.

Config knobs consumed (from G1, already committed): `table_judge_rung2_binary`
(default `"gemini"`), `table_judge_timeout_sec` (default 600s).

## Review fix (2026-08-30, follow-up commit)

Reviewer verified the `@<path>` image-attachment design against the bundled
`gemini` CLI source — CORRECT: headless `-p` does resolve `@<path>` to a real
`inlineData` image part, and `--include-directories` is required and
sufficient for a scratch path outside the default workspace. Three fixes
landed on top of the review:

1. **Dropped `--approval-mode plan`.** Verified against the bundle:
   `ApprovalMode.PLAN` injects a planning workflow into the system prompt (an
   Inquiry-vs-Directive classification). "Judge this crop, emit strict JSON"
   is directive-shaped and risked being classified a Directive — the model
   would draft a plan file instead of answering (silent ¬S1 for the wrong
   reason, plus a stray write attempt). The judge task invokes no tools, so
   the default approval mode never blocks on a confirmation prompt either.
   Docstring's "keeps the call read-only" claim corrected.
2. **Pinned subprocess `cwd` to the crop's parent (scratch) directory.**
   Without it the CLI would treat this repo's checkout (the process cwd) as
   workspace root and load `GEMINI.md`/`.gemini/` context and MCP servers —
   breaking the design's "crop + markdown, nothing else" judge-input
   isolation. `_run_gemini_cli` now takes `cwd` as a required third
   parameter.
3. **Test gap closed.** No prior test inspected subprocess kwargs, which is
   why the missing `cwd` passed silently. Added
   `test_subprocess_cwd_is_the_crop_scratch_dir_not_the_repo` plus `cwd`
   assertions on the existing argv-inspection tests; updated the argv-pin
   test for the dropped flag.

`~/venvs/socr/bin/pytest tests/test_table_rung_gemini.py -q` — 15 passed
after the fix. `uvx ruff@0.16.0 format --check` clean on both files.

**Live-smoke placement:** at B1 wiring time, before B1 merges (not in CI,
