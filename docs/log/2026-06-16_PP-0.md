# PP-0 — Crop-reread releasing wall-clock deadline + timeout audit + cascade guard

**Date:** 2026-06-16  
**Branch:** `fix/55-dual-pass-deadline`  
**Ticket:** PP-0 / GitHub #55

## What changed

### `src/socr/tables/extract.py`

- Added `_CROP_WALL_CLOCK_MULTIPLIER = 1.5` and `_CROP_DEADLINE_FLOOR_S = 30.0` as named
  documented constants (no magic literals).
- Added `crop_wall_clock_deadline(reader_timeout_s)`: derives the ThreadPoolExecutor wall-clock
  deadline from the reader's httpx timeout so both guards scale together.
- Added `probe_ollama_idle(host, timeout)`: lightweight `/api/tags` ping used as the cascade guard
  after a crop timeout; reuses the same pattern as `OllamaVisionJudge.is_available()`.
- Added `_CropTimeoutError`: internal sentinel raised by `_read_with_deadline` to decouple the
  timeout path from the general exception handler.
- `TableCropExtractor.extract()`: added `deadline` and `cascade_probe` kwargs; each VLM call is
  now wrapped in a `ThreadPoolExecutor(max_workers=1) + future.result(timeout=deadline)` guard
  mirroring `agentic.py route_page`. Timed-out crops emit a sentinel CropTable with
  `_timed_out=True`; after a timeout, `probe_ollama_idle` is called and `_backend_degraded` set if
  unhealthy; subsequent crops in the same loop check `_backend_degraded` and skip.
- Added `_read_with_deadline()` private helper that encapsulates the executor pattern and
  documents the residual: closing the client does NOT abort Ollama server-side generation
  (`stream:false`), so strict-local stays serial.

### `src/socr/pipeline/orchestrator.py`

- `_phase_dual_pass_tables`: moved `AuditEvent` import to the top of the function; after
  `extractor.extract()` returns, separated timed-out sentinels from real crops; emits a durable
  `AuditEvent(kind="dualpass_crop_timeout")` for each sentinel with `page_num + source +
  backend_degraded`; degrades to flag-only reconcile (page flows to assemble unchanged).
- `get_fitz_page` closure in `_build_page_judge`: introduced a single-slot `_fitz_doc_cache`
  list that closes and evicts the previous doc before opening a new one. At most one open file
  handle at a time; the page remains valid during `verify_native_table` because the doc stays
  in the cache until the next call.

### `tests/test_dual_pass_tables.py`

New tests for acceptance criteria:
- `test_crop_wall_clock_deadline_scales_with_timeout`: verifies the multiplier/floor formula.
- `test_extractor_releases_within_deadline`: monkeypatched slow reader (60s sleep), deadline=1s;
  verifies elapsed < 5s and sentinel emitted.
- `test_timeout_produces_audit_event`: verifies `dualpass_crop_timeout` AuditEvent appears in
  `state.events` with correct `page_num`; corpus untouched.
- `test_cascade_guard_stops_next_crop_after_timeout`: pre-sets `_backend_degraded=True`; verifies
  zero VLM calls fired.
- `test_cascade_guard_triggered_by_first_timeout`: monkeypatches `probe_ollama_idle` → False;
  verifies first crop attempted, second skipped, `_backend_degraded=True`.
- `test_no_fitz_doc_handle_leak`: two sequential `extract()` calls on the same PDF both return
  results (no "document closed" error from a stale handle).
- `test_fitz_page_judge_handle_closes_between_calls`: two `get_fitz_page()` calls; verifies no
  raise and pages are distinct objects.

## Deviations / follow-up

- `probe_ollama_idle` cannot detect whether a generation is still running server-side (Ollama does
  not expose that). The cascade guard prevents NEW crop calls but the GPU may stay busy until the
  model finishes. Documented in a code comment. Ollama-side cancellation is out of scope.
- `_backend_degraded` is an instance attribute set dynamically; a future PP-2 document-level halt
  can read it to abort the whole document without changes to the current interface.
- The fitz handle fix for `get_fitz_page` uses a single-slot list cache. If `NativeTableVerifier`
  ever starts storing the page reference across calls (it currently doesn't), the cache would need
  a reference count. Current usage is safe.
