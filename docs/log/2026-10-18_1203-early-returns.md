# #1203 — an early born-digital rejection no longer hides what the text layer is

Branch `fix/issue-1203`, cut from `origin/main` `3bcc43db` (the #1202 merge). Part A's
rule is in `docs/log/2026-10-17_1156-part-a.md`; this issue is one hole in its reach.

## The diagnosis

`BornDigitalDetector._assess_page_signals` returns ten times before #1156's drawing-order
check runs. Each of those returns is a born-digital rejection, so the page was routed to
OCR either way — but it recorded no `prior_ocr_layer`, and therefore got no page mark, no
sidecar retention, no document bucket and no meter lane. Not the floor: see "What ships".

The fix follows the method's own documented discipline. `_assess_page` already exists as
the single stamping point for signals that must survive those returns (the dominant text
direction, GH-520's table counts, #1144's `/Rotate`), with the comment "a detection signal
missing from one of them is a silent zero". #1156's answer is now computed there, before
the body runs, handed over on a side channel the body consumes, and stamped onto whichever
`PageAssessment` comes back. The predicate still runs exactly once per page.

The side channel is CONSUMED at the TOP of the signals body, not at the #1156 block. The
first attempt popped it at the block — which an early return never reaches, so the value
survived to answer the NEXT caller: a direct `_assess_page_signals` call after a rejected
page read `True` off it. Found by writing the test Argon asked for, and pinned by it.

## What ships

Nothing new. Measured, not assumed — twice, by two routes that agree:

* `scratch/1203/ending_matrix.py` runs the selection cascade on a state taken FROM THE
  DETECTOR, over all four attempt states (none / errored / rejected / accepted), with the
  flag off and on. On an early-return page every cell is **SAME**; on the born-digital
  control page three of four cells change, which is Part A working.
* the `process()` difference pin in the new test file compares the shipped body between
  the two arms and finds it identical.

The reason is structural: Part A's withholding floor, #1027's, TR-3's and every other
native floor live inside `if p.is_born_digital and p.native_text:` (`manifest.py:4348`),
and an early-return page satisfies neither half. **So the count of newly floored pages is
zero, not ~4,200.** The brief expected the floor to start firing on these pages; it does
not, and that is reported rather than engineered, because making it fire would withhold a
MODEL's reading on ~4,000 Fed pages and that is a shipping decision, not a surfacing one.

What the fix does add, on exactly the pages that gained the flag:

* `prior_ocr_layer_suspect` in the sidecar, so the acceptance meter raises
  `prior_ocr_unchecked` in both lanes instead of counting the page CHECKED;
* `prior_ocr_layer_text` in the sidecar — the page's own layer, numbers included,
  unshipped, which Part B re-finalizes from. It needed a new carrier
  (`PageAssessment.prior_ocr_layer_text` → `PageState.prior_ocr_layer_text`): on these
  pages `native_text` is empty BY DESIGN, and putting the layer there instead would make
  the page native-eligible under `--native-only` and ship an earlier OCR run's numbers;
* the page MARK (`prior_ocr_layer=UNKNOWN` in the verdict banner), on an accepted and a
  rejected reading alike;
* the document bucket `prior_ocr_retained_pages`, its `prior_ocr_layer_retained` audit
  event and the CLI line, so the document can no longer report a clean SUCCESS over it;
* the #1156 reason in the assessment notes, in one shared wording (`_prior_ocr_note`) so
  the two stamping points cannot drift.

## The cost of the extra call

`_has_prior_ocr_layer` now runs on pages that used to return before reaching it. On every
other page the number of calls is unchanged — one per page, before instead of after — so
the cost IS the predicate's own time on an early-return page. Measured on all 325 census
early-return pages, 3 repeats each, best per page, document furniture excluded because it
is read on every page already (`scratch/1203/cost_probe.py`):

| mean | median | p95 | worst |
|---|---|---|---|
| **15.9 ms** | 15.1 ms | 18.3 ms | 46.5 ms (a 2003 presentation-materials page) |

At ~4,000 such pages that is **~64 s of extra CPU for the whole 5,870-document Fed run**.
End to end it is inside the noise: the 2,773-page corpus probe took 506 s before the change
and 484 s after.

## Argon's design review, and what came of it

Consulted before building (`scratch/1203/argon-design.{md,out}`).

* **Right, and fixed** — a direct `_assess_page_signals` caller could be answered from the
  previous page's side channel. It gave the wrong mechanism (an uninitialised attribute);
  the real one is an early return skipping the consume site. Pinned.
* **Right, and taken** — the written design omitted the `pa -> ps` copy in `state.py`.
* **Right about the direction, declined on the evidence** — it asked for the retention to
  be gated on the sidecar's four-flag union so a #961-only page is retained too. #961's
  two keys are computed in the same stretch of the body as #1156's, AFTER all ten early
  returns, so they are provably False on any page reaching the retention branch with no
  native text. The two extra terms would be a guard that cannot fail, so the gate is the
  #1156 pair.
* **Not real, but worth the look** — it called the floor interception a P0 content loss
  (a rejected model reading replaced by the floor's marker). The ending matrix shows the
  floor is unreachable on these pages, so no page changes what it ships.
* **Wrong on the resume** — it proposed gating the `native_text` restore on
  `ps.is_born_digital`. `_restore_terminal_page_state` never restores
  `is_born_digital`, so that gate would be answered from an unrestored field and would
  always be False, silently breaking Part A's own retention restore. The existing line is
  left exactly as it is and the new carrier is restored beside it.

## Argon's review of the finished diff, and what came of it

`scratch/1203/argon-diff.{md,out}`. It found one real P0 that this change had widened, and
three assertions of mine that could not fail.

**P0, REAL, fixed — the resume put the retained layer into `native_text`.** Part A's
restore line reads "if the sidecar has a retained layer and `native_text` is empty, put it
there". Before #1203 that key was only ever written from `native_text`, so it only came
back to a born-digital page. Since #1203 it is also written for a page an early return
rejected, where `native_text` is empty BY DESIGN — so `not ps.native_text` is always true
there and every such restored page came back with an earlier OCR run's numbers in the one
field that decides native eligibility. The line now restores the CARRIER and nothing else;
`is_born_digital` could not have gated it, because this restore never brings that field
back and the gate would have been answered from an unrestored field (Argon proposed that
gate in the design round; it was checked and declined for exactly this reason). Pinned
from both sides: `native_text` must stay empty after a restore, in the new test and in
#1156's own, and a mutant that puts the line back is killed.

**P1, REAL, fixed — three assertions that could not fail.** The resume test's re-flush
check passed through the polluted `native_text` and never read the carrier; "the layer's
numbers never ship" could not fail on a fixture whose stub engine never emits them, and is
now asserted beside the sidecar's own copy of the same tokens, which does discriminate; and
"the document is not SUCCESS" was true in both arms of the rejected case, so the paired
`main` assertion is now made only on the accepted arm, where main DOES report a clean
SUCCESS over the page and the flagged run cannot. That pair is the clearest statement of
what this fix buys.

**P2, REAL, fixed — the side channel was set three statements too early.** It was assigned
before `dominant_text_direction`, which is not inside the surrounding guard, so an
exception there would leave the value on `self` for the next caller. It is now set on the
line before the call it feeds. Argon also notes the channel is not thread-safe if one
detector is shared across threads — true, and the same for the pre-existing
`_detected_regions_this_page`; no new class of problem, and nothing in socr shares a
detector across threads.

**P2, REAL, covered — the failed-scan arm was untested on this page class.** Added
(`test_a_failed_scan_on_an_early_return_page_is_unknown_not_clean`), with a mutant.

**Agreed, and worth recording as residual scope:** an early-return page whose prior-OCR
layer is only visible to #961's render-mode route still gets nothing, because that check
also sits after the ten returns. The census says the #1156 route is the one that matters on
the Fed corpus (the whole 307), so it is not moved here.

## Open, not addressed here

* **A rejected model reading still ships on these pages**, where Part A withholds one on a
  born-digital flagged page: `best_output_unverified` (`manifest.py:5075`) is reached
  because the floor family is inside the `is_born_digital and native_text` branch. Not
  touched by #1203, and a ruling rather than a bug: the earlier layer never ships either
  way, so no prior-OCR number reaches the page.
* **`prior_ocr_layer` itself is not restored on a resume** — only `prior_ocr_layer_suspect`
  is (`orchestrator.py:16192`). The floor keys on the positive flag, so a restored page
  cannot reach it. Latent for Part A's own reason (the ledger admits only terminal SUCCESS
  pages and a flagged page is always WARNING), unchanged here, and Part B's territory.
* **An accepted reading on one of these pages stays a terminal SUCCESS page** with
  `audit_passed=True`, because Part A's demotion of an accepted reading also lives inside
  the `is_born_digital and native_text` branch. The page is still MARKED and the document
  still cannot report SUCCESS, and the acceptance meter still raises `prior_ocr_unchecked`
  on it, so nothing reads as checked — but the page ledger will skip it on a resume. Part
  B's territory, and the reason the restore above had to be made safe rather than left
  latent.
