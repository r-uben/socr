# #1203 — an early born-digital rejection no longer hides what the text layer is

Branch `fix/issue-1203`, cut from `origin/main` `3bcc43db` (the #1202 merge). Part A's
rule is in `docs/log/2026-10-17_1156-part-a.md`; this issue is one hole in its reach.

## The diagnosis

`BornDigitalDetector._assess_page_signals` returns ten times before #1156's drawing-order
check runs. Each of those returns is a born-digital rejection, so the page was routed to
OCR either way — but it recorded no `prior_ocr_layer`, and therefore got no page mark, no
sidecar retention, no document bucket and no meter lane. Not the floor: see "What ships".

The fix follows the method's own documented discipline. `_assess_page` already exists as
the single stamping point for signals that must survive those returns (the dominant text
direction, GH-520's table counts, #1144's `/Rotate`), with the comment "a detection signal
missing from one of them is a silent zero". #1156's answer is now computed there, before
the body runs, handed over on a side channel the body consumes, and stamped onto whichever
`PageAssessment` comes back. The predicate still runs exactly once per page.

The side channel is CONSUMED at the TOP of the signals body, not at the #1156 block. The
first attempt popped it at the block — which an early return never reaches, so the value
survived to answer the NEXT caller: a direct `_assess_page_signals` call after a rejected
page read `True` off it. Found by writing the test Argon asked for, and pinned by it.

## What ships

Nothing new. Measured, not assumed — twice, by two routes that agree:

* `scratch/1203/ending_matrix.py` runs the selection cascade on a state taken FROM THE
  DETECTOR, over all four attempt states (none / errored / rejected / accepted), with the
  flag off and on. On an early-return page every cell is **SAME**; on the born-digital
  control page three of four cells change, which is Part A working.
* the `process()` difference pin in the new test file compares the shipped body between
  the two arms and finds it identical.

The reason is structural: Part A's withholding floor, #1027's, TR-3's and every other
native floor live inside `if p.is_born_digital and p.native_text:` (`manifest.py:4348`),
and an early-return page satisfies neither half. **So the count of newly floored pages is
zero, not ~4,200.** The brief expected the floor to start firing on these pages; it does
not, and that is reported rather than engineered, because making it fire would withhold a
MODEL's reading on ~4,000 Fed pages and that is a shipping decision, not a surfacing one.

What the fix does add, on exactly the pages that gained the flag:

* `prior_ocr_layer_suspect` in the sidecar, so the acceptance meter raises
  `prior_ocr_unchecked` in both lanes instead of counting the page CHECKED;
* `prior_ocr_layer_text` in the sidecar — the page's own layer, numbers included,
  unshipped, which Part B re-finalizes from. It needed a new carrier
  (`PageAssessment.prior_ocr_layer_text` → `PageState.prior_ocr_layer_text`): on these
  pages `native_text` is empty BY DESIGN, and putting the layer there instead would make
  the page native-eligible under `--native-only` and ship an earlier OCR run's numbers;
* the page MARK (`prior_ocr_layer=UNKNOWN` in the verdict banner), on an accepted and a
  rejected reading alike;
* the document bucket `prior_ocr_retained_pages`, its `prior_ocr_layer_retained` audit
  event and the CLI line, so the document can no longer report a clean SUCCESS over it;
* the #1156 reason in the assessment notes, in one shared wording (`_prior_ocr_note`) so
  the two stamping points cannot drift.

other page the number of calls is unchanged — one per page, before instead of after — so
the cost IS the predicate's own time on an early-return page. Measured on all 325 census
early-return pages, 3 repeats each, best per page, document furniture excluded because it

| mean | median | p95 | worst |
|---|---|---|---|
| **15.9 ms** | 15.1 ms | 18.3 ms | 46.5 ms (a 2003 presentation-materials page) |

At ~4,000 such pages that is **~64 s of extra CPU for the whole 5,870-document Fed run**.
End to end it is inside the noise: the 2,773-page corpus probe took 506 s before the change
and 484 s after.

## Argon's review of the finished diff, and what came of it

`scratch/1203/argon-diff.{md,out}`. It found one real P0 that this change had widened, and

**Agreed, and worth recording as residual scope:** an early-return page whose prior-OCR

### Measured for the open ruling (r-uben blocker 1)

Since #1202, a suspect page covered by an opaque raster skips `NativeTableVerifierJudge`'s
row check. The pages where that can change a table's ending, on the census sample
(`scratch/1203/r1_counts.py`):

| | census | corpus (×12.9) |
|---|---|---|
| this PR's new exposure (early-return + flagged + table + opaque cover) | 132 | ~1,700 |
| #1202's own pages (born-digital flagged + table + opaque cover) | 1,151 | ~14,850 |

The mechanism is therefore already live on ~14,850 corpus pages and this PR widens it by
about 11%.

The divergence itself reproduces, and the fixture is the whole trick. A RULED table reports
a detected table REGION and takes another path through the source-evidence judge — on that
fixture both arms withheld the table and nothing differed, which is what my first attempt
measured and wrongly reported as "does not reproduce". A COLUMN-LAID-OUT table (whitespace
columns, no rules) reports `has_tables=True` with `detected_table_count=0`: `is_table_page`
true, no table geometry, which is the state in which `NativeTableVerifierJudge` runs.
There, with the classical-OCR witness absent in both arms:

* route neutralised: `native_table_verifier_hard_fail`, page `error` /
  `no_witness_backend`, table withheld;
* route live: no verifier event, `table_ladder_unverified`, page `warning` /
  `table_unverified`, and the table ships with the three cells the layer disagreed about
  (`521`, `380`, `18` where the layer read `512`, `-380`, `-18` — two dropped minus signs,
  which is #1202's own case).

So the flag lets a reading through that the layer would have vetoed, and nothing else
checked it.

### The owner's ruling (2026-10-18): WITHHOLD — and not by re-running the verifier

> When a suspect page is covered by an opaque raster and NO independent witness actually
> ran on its table, the table is WITHHELD. It ships as the page picture plus a mark. The
> model's table stays in the sidecar, so a later second reader can release it by
> re-finalizing, with no new OCR.

The ruling also rejected the obvious patch, which I had drafted: re-running the native
verifier hands the layer back BOTH its veto (the -350 case) and its licence to pass a
table that happens to agree with it. The agreeing-table arm of the test below is that
objection, measured: with the route neutralised, the layer passes the model's table
(`native_table_verifier_exact_pass`) and it ships carrying `512`, `-380`, `-18`.

What implements it:

* `NativeTableVerifierJudge` REPORTS the skip through a new `on_layer_not_evidence`
  callback; it decides nothing with the layer. The orchestrator records
  `PageState.native_table_check_skipped_no_evidence`, a fact about what ran rather than a
  predicate re-derived later.
* the scanned-table floor (`_apply_scanned_table_floor`) now fires when that skip happened
  AND nothing read the pixels, even though the ladder "accepted" the reading. "Nothing read
  the pixels" is the source-evidence judge's own
  `source_evidence_no_witness_backend` event, NOT the `_source_ev_no_witness` reduction
  over attempt failure modes: measured, that reduction reads `False` on exactly the page
  whose table shipped unwitnessed, because #1048's settling clears the mode to `NONE`.
* the recorded cause is `no_witness_backend`, not `hallucination` — the model did not
  invent the table, nothing could check it — which also keeps the page in the unwitnessed
  rollup and its CLI line.
* the reading is retained unshipped as `withheld_table_text` in the sidecar. Without it the
  ruling's release path does not exist: the sidecar keeps only an attempt SUMMARY, never an
  attempt's text, so the withheld table would have been gone for good.

Pinned at `process()` with the real judge chain in four arms — model disagrees, model
agrees (the arm that rules the verifier out), a witness present (today's ending kept), and
a clean born-digital table page (untouched).

**How many pages change ending.** Of the census frame above, the rule can only reach the
132 pages of (a) — the floor it fires is the scanned-table floor, which keeps its
`not ps.is_born_digital` gate, so **none of #1202's 1,151 born-digital pages are touched**.
Whether it fires on those 132 is an ENVIRONMENT fact: with no classical-OCR witness
installed, which is CI's state and the cluster's, all 132 (~1,700 corpus pages); on a box
with tesseract, none of them. The Fed run on Rorqual therefore withholds ~1,700 pages'
tables that this PR would otherwise have shipped marked unverified.

## Review round 2: the rule restated as CONFIRMATION, not as "a witness ran"

Round 1 keyed the withhold on whether a witness RAN. Both reviewers broke that from
opposite sides, and both were reproduced here before anything was changed:

* **r-uben 1b.** A witness that ran and CONTRADICTED the model (it read 512/-380/-18, the
  model 521/380/18) let the table ship `warning` / `table_unverified` — and round 1's own
  test pinned that as correct. Main withholds that page. "A witness ran" is not "a witness
  checked the cells".
* **Argon P1a.** Rung 1 hit a transient `WITNESS_EXEC_ERROR`, which emits the page's
  no-witness event; rung 2's witness then CORROBORATED the table. Round 1 destroyed it
  anyway, because the event existed.
* **Argon P1b.** The skip was reported only when `_is_table_page` was true, and that
  predicate asks `has_numeric_columns` of the UNTRUSTED layer. A layer with one value per
  row failed it, so the rule never fired and the unwitnessed table shipped.

### What the rule is now

A model table on one of these pages ships **only if an independent reader confirmed its
cells**. The confirmation is recorded by the only independent reader these pages have —
the scanned-table gate's witness over the page's own pixels — on the CANDIDATE it passed
(`PageOutput.table_cells_witness_confirmed`). The native row verifier reads the suspect
layer, so it is not independent; the heuristic leaf reads nothing.

Candidate-associated, not page-level, for a reason the round-1 shape shows: a page flag
said yes when rung 1's witness passed and rung 2 — a different, unconfirmed table — was
what shipped.

Nothing in the rule is derived from the layer, and nothing from the absence of an event:
round 1's callback, its `PageState` flag and the no-witness event lookup are all deleted.

### Two signals that #1048's settling had been quietly breaking

Both found by instrumenting the gate, not by reading it.

* `_source_ev_no_witness` and `_source_ev_contradicted` read the attempts' FAILURE MODES,
  and #1048's settling rewrites the winning attempt's mode to `NONE`. On the
  rung-1-error / rung-2-dispute page the mode said `NONE` while the attempt carried
  `table_disputed = "521, 380, 18"` — the witness's own list of refused cells. The cause
  now reads that FIELD, so a dispute wins over a no-witness, which is #658's own
  precedence.
* The same settling is why round 1 could not use `_source_ev_no_witness` at all and fell
  back to the event. The field-based signal replaces both.

### Also fixed

* a withheld page no longer carries #1048's stamping (`unchecked_table_kind`,
  `table_ladder_superseded`, "table shipped marked unverified") beside a marker-only body
  (Argon P2);
* `withheld_table_text` is written only when the table is actually withheld, so a page
  that SHIPS its table never grows the key, and #1202's born-digital pages never do
  (Argon P2);
* one conjunct was written and then REMOVED: `find_table_blocks(winner.text)`.
  `_source_ev_rejected` already means the gate adjudicated a table, so the term could not
  be made to fail on any input — a flagged table page whose model reading was prose behaved
  identically with and without it (`scratch/1203/r2_prose_winner.py`). An unkillable guard
  is not a guard.

## Open, not addressed here

* **A rejected model reading still ships on these pages**, where Part A withholds one on a
  born-digital flagged page: `best_output_unverified` (`manifest.py:5075`) is reached
  because most of the floor family is inside the `is_born_digital and native_text` branch.
  Not touched by #1203, and a ruling rather than a bug: no prior-OCR number reaches the
  page. (Round 1: the sentence here used to say "the earlier layer never ships either
  way". It did ship, through #649 — fixed, see the round-1 section.)
* **`prior_ocr_layer` itself is not restored on a resume** — only `prior_ocr_layer_suspect`
  is (`orchestrator.py:16192`). The floor keys on the positive flag, so a restored page
  cannot reach it. Latent for Part A's own reason (the ledger admits only terminal SUCCESS
  pages and a flagged page is always WARNING), unchanged here, and Part B's territory.
* **Every resume re-reads these pages, and that is #1192.** The paragraph that stood here
  claimed an accepted reading stays a terminal SUCCESS page the ledger would skip. Wrong,
  measured at `process()` (`scratch/1203/r1_accepted_status.py`): an accepted early-return
  page ships **`warning` / `prior_ocr_layer_unverified`**, because #1145's verdict
  demotion runs off the flag. The page status change belongs in the "what it adds" list
  above and is now there.
  The consequence for the Fed run: the per-page ledger admits only a terminal SUCCESS
  page, so these pages are never admitted. Run 1 called the engine for the page; run 2 with
  the document index intact skipped the whole document; run 3 with the index removed — the
  state in which the per-page ledger actually decides — called the engine for the page
  again. So any resume that reaches the ledger re-OCRs all ~3,960 of them. Tracked as
  #1192; not changed here.
* **The restore change is defence only.** Because of the line above, a page of this class
  never becomes terminal SUCCESS, so `_restore_terminal_page_state` is unreachable from
  `process()` for it, and the carrier restore is exercised by tests that call that method
  directly. It is still the right shape — it is what stops a future ledger or status change
  from making the `native_text` route live — but nothing in a normal run reaches it.
