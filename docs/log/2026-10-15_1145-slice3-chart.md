## The clause

210 pages of run 23192118 ship SUCCESS, `failure_mode=none`, `audit_passed=True` and NO
mark, having routed a chart to an image asset. That routing is the lane WORKING — a chart is
not prose and socr does not pretend to read it — but the numbers a reader would cite are then
present only as pixels, and the page said nothing about it. `figure_text=UNKNOWN`, plus a
demotion, with a reason that tells the reader what to do instead ("read them off the image
before citing").

**Keyed on `visual_values_not_transcribed` alone, and that is a checked decision.**
`chart_asset_page` is **not** in the resume replay allowlist, so a predicate requiring both
would have lost the clause on every resumed page and the next run would have silently
un-demoted it. On the corpus the two identify exactly the same 1,353 pages (every one with a
`chart_asset` winner), so nothing is given up. Checking this BEFORE building is the habit
the equation slice's `equation_latex_accepted` omission taught.

## Resume admissibility moved from the clause pair to the MODE

The equation slice keyed the resume exception on `(check, result)`. The chart clause broke
that, and the break is instructive: **`figure_text=UNKNOWN` has three sources** — this lane,
the `FIGURE_WORDS_UNREAD` mode, and the scanned-figure flag — **and only this one is
unresolvable.** A reader that could not transcribe a figure crop today may succeed next run,
so admitting the pair would have let those pages skip for ever and nothing would ever read
them. The mode is already the field that explains the status, which is why the demotion
records one, so it is the right key: `PERMANENTLY_UNRESOLVABLE_MODES`.

**And the extra-clause half of that check was DELETED as unreachable.** A mutant removing it
survived every test. Rather than invent a fixture, the reachability was traced: these modes
are written in exactly one place (`manifest._verdict_demotion_mode`), reached only by the
demotion, which only fires on a page still SUCCESS at the verdict step — and a SUCCESS page's
clause set is the silent-success clauses alone. Every other clause source arrives with its
own demotion and leaves the mode as it found it. So the argument replaced the code, and
`test_an_admissible_mode_is_only_ever_set_by_the_verdict_demotion` pins it by counting the
WRITING FUNCTIONS in the source: it fails if a second ever appears, which is the event that
would make the deleted check necessary again.

## Correction: the mark contradicted the record on 388 pages

This log claimed the 1,143 already-WARNING chart pages "gain a second, true clause". False
for **388** of them, and Fable reproduced it on monacelli p21.

#1053's `figure_words_unread` and this clause both produce `figure_text=UNKNOWN`, so they
collapse to one line. The rule was "the first wins, and the order is from most specific to
least" — written in slice 1, true while the status-dependent clauses came first, and
silently INVERTED when slice 3 moved the silent-success clauses to the front of the list. So
the chart clause REPLACED #1053's reason: the page's line said "this page's chart ships as an
image" while its recorded mode still said `figure_words_unread`. A mark contradicting the
record is worse than either alone — the reader and the corpus disagree about the same page
and nothing says which is right.

Fixed by making the **MODE arbitrate** rather than arrival order (`_merge_clause`). The mode
is the field that explains the status, so the clause whose wording it vouches for is the one
that shows; an incoming clause replaces an existing one only when the mode names the
incoming text and not the existing one. Where the mode names neither, first-wins still
holds, which preserves the old behaviour for the mode-table clauses that are all that can
reach that case.

My own design decision from slice 1 was the thing my slice-3 change broke, and no test
noticed. The order of a list was carrying a guarantee; it is now carried by the field that
states the reason.

## Two more corrections from the same review

* The writer-count test matched source LINES, and `M7` walked past it: a writer spread over
  several lines, or passed positionally, has no line that looks like an assignment. It is
  now AST-based, locating every reference as a node and comparing the set of ENCLOSING
  FUNCTIONS, which is the unit the argument is about.
* The "ordering" comments in the #960/#990 live arms were wrong. Those guards RETURN None,
  so they refuse wherever they sit; #1145's exception only bypasses the SUCCESS/`audit_passed`
  gate, never a guard that has already returned. What those arms pin is that the guard still
  fires on a page #1145 has demoted and marked — which is the thing that could plausibly
  break — and they now say so.
