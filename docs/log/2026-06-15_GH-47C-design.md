# GH-47C — Free label cross-check for figure captions (design)

Date: 2026-06-15
Branch: `fix/47-figure-caption-antifab` (HEAD ddc3e21, contains GH-47A + GH-47B)
Status: design note for the consilium gate (no production code written)
Author agent: socr-designer (read-only on source)

## Scope recap

GH-47B made figure captions *qualified, omit-what-you-cannot-read gist*, each prefixed with
`CAPTION_MARKER = "[model-generated, non-authoritative gist]"`
(`src/socr/engines/_figure_prompt.py:10`). GH-47C asks for a **weaker, more explicit**
verification layer than the GH-49A native *table* verifier: native page text can confirm
that a **label** named in a caption is really present in the figure, but it can never confirm
plotted values, trends, or arrow directions. So this layer is, by construction, a
**warning-only** signal — an explicit acceptance criterion forbids it from rewriting a
caption. The parallel to GH-49A is the two-tier "deterministic check, warn/escalate, never
silently mutate" shape; the difference is that for figures the only verifiable claim type is
*label presence*, and even that is only recoverable for vector-rendered text.

## 1. What exists today

### Figure + caption flow (file:line)

- Extraction: `FigureExtractor.extract()` → `_extract_page_figures()`
  (`src/socr/figures/extractor.py:135`, `:231`) runs three strategies per page (vector
  clusters, IMAGE blocks, raw xref images) and returns `ExtractionResult(figures, cap_reached)`.
- **Critical gap for this ticket:** the per-figure **bbox is computed but thrown away**. Inside
  `_extract_page_figures` each figure has `(x0,y0,x1,y1)` (e.g. `extractor.py:272`, `:350`,
  and placement rects at `:404`), but `ExtractedFigure`
  (`extractor.py:71`) persists only `figure_num`, `page_num`, `image`, `saved_path`. There is
  **no figure rectangle available downstream**. Any region label cross-check first needs the
  extractor to persist the bbox (and, for xref images, the placement rect) on `ExtractedFigure`.
- Captioning + assembly: `_describe_and_embed_figures()`
  (`src/socr/pipeline/orchestrator.py:2455`) extracts, optionally calls
  `vision_engine.describe_figure(fig.image, context=...)` (`orchestrator.py:2546`, only when
  `config.describe_figures`), builds `FigureInfo` (`orchestrator.py:2553`), then
  `_build_figure_blocks()` (`orchestrator.py:2648`) emits
  `**Figure N** (page P): <CAPTION_MARKER> <description>\n\n![..](..png)`.
- `FigureInfo` (`src/socr/core/result.py:61`) carries `figure_num, page_num, figure_type,
  description, image_path, engine` — again **no bbox**, and `description` already includes the
  marker by the time it reaches the block builder.
- **The natural insertion point** is the per-figure loop in `_describe_and_embed_figures`
  (`orchestrator.py:2539-2561`), *after* the caption is produced and *before* / alongside
  `_build_figure_blocks`. The check needs: the figure's page, the figure's rect, and the
  caption text. The page handle is `state.handle.path`; the rect must come from the extractor
  fix above.

### Native/vector text actually recoverable for a figure REGION (confirmed, not assumed)

- `page.get_text("words")` returns `(x0,y0,x1,y1, word, block, line, word_no)` tuples and is
  **already used in-repo** at `src/socr/tables/reconstruct.py:119`. Filtering those tuples by
  the figure rect (token center inside the rect, or rect-intersection) is trivial,
  deterministic, O(words), and needs **no model and no network**.
- **What this recovers:** text that the PDF stores as *text operators* — vector-chart axis
  labels, tick labels, legend entries, data labels, and titles **when the chart was authored
  as vector + live text** (the common born-digital case in this corpus: report charts placed
  by Think-cell / Excel / matplotlib-PDF). This is exactly the label layer GH-47C wants.
- **What this does NOT recover:** text baked into pixels. Strategy-2 raw xref images
  (`extractor.py:388`) and any rasterized chart contribute **zero words** inside their rect —
  the labels are pixels in the embedded raster, invisible to `get_text`. Scanned pages are
  already skipped entirely (`orchestrator.py:2486-2494`, `skip_pages`), and on a true scan the
  words/drawings layers are empty (documented at `src/socr/tables/locate.py:91`).
  `page.get_drawings()` (`extractor.py:254`) returns vector *strokes/fills*, not glyphs — it
  does not help recover label strings.

**Net recoverability for this corpus:** axis/legend/title/data labels of **vector charts** are
recoverable as native words inside the figure rect; **all labels of rasterized/embedded-image
figures are not**. So a region with **zero native words** is *ambiguous* (could be a raster
chart with real labels we simply cannot see), not evidence of a bad caption — the check must
treat "no recoverable text in region" as **inapplicable**, never as a fail.

### Which caption claim types are cheaply verifiable

Given GH-47B captions are qualified gist:

| Claim type in caption | Verifiable from native region words? |
|---|---|
| Named legend entry / series name ("the *Euro area* line") | YES — string presence in region words |
| Axis label / category label ("x-axis: *quarters*", "bars by *country*") | YES (vector charts) |
| Figure title text | YES (vector charts) |
| Plotted numeric value ("peaks near 4.2%") | NO — values are geometry, not labels; GH-47B already tells the model to omit these |
| Trend / direction ("rising then falling") | NO |
| Arrow direction / relationship | NO |
| Anything on a rasterized/embedded-image figure | NO (no recoverable text) |

So the **only** cheap verification is: *named entities the caption asserts as labels are present
among the figure region's native word tokens.* Everything else is out of scope by construction —
which is itself a deliverable (AC1).

### How warnings are surfaced today (reuse, don't fork)

- `AuditEvent(page_num, kind, engine, detail, data)` (`src/socr/core/audit_log.py:43`)
  appended to `state.events`. The figure phase **already does exactly this** for the cap signal:
  `kind="figure_cap_reached"` at `orchestrator.py:2508-2516`. A label-check warning reuses this
  identical path with a new stable `kind` (e.g. `figure_caption_label_unverified`) plus
  structured `data` (page, figure_num, unmatched tokens, region word count). The table verifier
  (GH-49A) uses `AuditMetric` because it participates in accept/reject; GH-47C does **not** gate
  acceptance, so the lighter `AuditEvent` path is the correct match.

## 2. Options for the label cross-check

All options are deterministic + PyMuPDF-only, run only on the **described-figures** path
(`config.describe_figures`), require the extractor-bbox fix, and **never rewrite a caption**
(AC2 is hard). Any ratio/tolerance must be a **named, documented, configurable constant** — no
bare literals (repo rule; mirror GH-49A's reuse of named lane tolerances). A region with zero
recoverable words is **inapplicable** (skipped), never a fail, in every option.

### Option A — Noun-phrase / named-entity presence check (broad)

Extract candidate label-claims from the caption (capitalized tokens, quoted strings, and short
noun phrases) and flag the caption when one or more such claims is **absent** from the figure
region's native word tokens (case/whitespace-normalized, substring/fuzzy match within a named
threshold). Emit one `figure_caption_label_unverified` `AuditEvent` listing the unmatched terms.

- Verifiable surface: widest — tries to check every named thing the caption mentions.
- Determinism/replay: fully deterministic; no model, no network.
- **False-positive risk: HIGH.** A qualified GH-47B caption legitimately mentions things that
  are *not* labels in the vector layer: paraphrased categories ("countries" when the legend
  lists "DE, FR, IT"), the figure *type* ("bar chart"), surrounding-context terms (the caption
  receives 500 chars of page context, `orchestrator.py:2545`), and synonyms. Most "unmatched"
  terms would be legitimate gist, not fabrication. This floods the audit log with false warnings
  and trains operators to ignore them — the worst outcome for a safety signal.
- Scope: needs a noun-phrase extractor + a matching threshold; largest new surface.

### Option B — Legend / axis-label match only (narrow, high precision)

Only verify caption terms that are **explicitly framed as labels** — i.e. caption phrases the
model presented as legible labels/categories (the GH-47B prompt asks for "clearly legible labels
or categories"), matched against the region's word tokens. Concretely: flag only when the caption
*names a specific legend/series/axis label* (quoted or capitalized proper token) and that exact
token is **absent** from the region words **while the region has substantial recoverable text**
(so we know labels were readable and the named one genuinely is not there). Warn-only AuditEvent.

- Verifiable surface: narrow — exactly the claim type that is actually checkable.
- Determinism/replay: fully deterministic.
- **False-positive risk: LOW-to-MODERATE**, gated by the "substantial recoverable text yet named
  entity absent" condition: we only warn when the figure *demonstrably* has a readable label layer
  and the caption's specific named label is missing from it. Paraphrase/type/context terms are not
  candidates because they are not specific named labels.
- Scope: needs (1) the extractor bbox, (2) a region-word collector, (3) a conservative
  named-label candidate extractor, (4) one named "substantial text" threshold
  (e.g. `FIGURE_REGION_MIN_LABEL_WORDS`, documented basis) and one named match tolerance. Moderate.

### Option C — No automated caption check; strengthen marker + log recoverable labels

Do not compare caption against region text at all. Instead: (1) the marker already states
non-authoritativeness (GH-47B); optionally enrich it; and (2) for each described figure, collect
the region's native word tokens and **record them in an AuditEvent / metadata as the
recoverable-label set** for that figure, for human audit — no claim about the caption.

- Verifiable surface: none automated; provides operators the raw recoverable-label evidence.
- Determinism/replay: fully deterministic; smallest, safest change.
- **False-positive risk: ZERO** (it asserts nothing about the caption).
- Scope: smallest — bbox + region-word dump into audit data. Satisfies AC1 (the design note
  itself identifies verifiable vs not) and AC2 trivially (records labels, never rewrites).
- Cost: punts the actual cross-check; gives a human the material but no signal.

## 3. Recommendation — genuine fork, panel it (narrow fork)

This is **not** a pure skip-the-panel case, but the fork is narrow and bounded. Option A is
clearly wrong (high false-positive on legitimate qualified gist — it would make a safety signal
that operators learn to ignore). The real decision is **B vs C**: whether an automated
label-presence warning is worth its residual false-positive cost, or whether the safer move is
to log the recoverable-label evidence and leave the judgment to a human, given that the *only*
verifiable claim type is "named vector-chart label present" and a large share of corpus figures
(rasterized/embedded) yield **no recoverable text at all** and are thus uncheckable.

My lean is **Option B**, because it converts the verifiable case into an actual signal while its
"substantial recoverable text yet named label absent" gate keeps false positives low, and it
still reduces to Option C's behavior (no warning) on the uncheckable raster majority. But B
introduces two named thresholds and a label-candidate extractor whose precision I cannot validate
without a real described-figures run on the corpus, so the cost/benefit of B-over-C is exactly the
kind of determinism-vs-false-positive trade the panel should rule on. **Panel the B-vs-C fork**
(with A offered only to be rejected on the record).

## 4. The consilium question (verbatim, ready to dispatch)

> In socr's figure pipeline, captions are now non-authoritative model "gist" (GH-47B), and the
> ONLY claim type cheaply verifiable from native PDF text is *label presence*: a vector-chart's
> axis/legend/title labels are recoverable as native word tokens inside the figure's bounding box
> via `page.get_text("words")` (deterministic, no model), but rasterized/embedded-image figures
> yield ZERO recoverable text, and even on vector charts the caption legitimately paraphrases
> categories, names the chart type, and absorbs surrounding-page context. Given the hard rule that
> the check must be warning-only and must NEVER rewrite a caption, how aggressive should this
> deterministic label cross-check be? Options:
>
> - **(A) Broad noun-phrase presence check:** flag the caption whenever any capitalized/quoted
>   noun phrase it mentions is absent from the figure region's native word tokens (within a named
>   fuzzy threshold). Widest coverage, but HIGH false-positive risk — paraphrased categories, the
>   chart type, and page-context terms are legitimately absent from the label layer, so it would
>   warn constantly on correct qualified captions and train operators to ignore the signal.
> - **(B) Narrow named-label match, gated by recoverable text:** warn ONLY when the caption names
>   a specific legend/series/axis label (quoted or proper token) AND the figure region has
>   substantial recoverable native text (above a named `FIGURE_REGION_MIN_LABEL_WORDS` threshold)
>   AND that specific named label is absent from the region tokens — so we only flag a figure whose
>   label layer is demonstrably readable yet missing the caption's named entity. Low false-positive,
>   but adds two named/configurable thresholds and a label-candidate extractor of unvalidated
>   precision, and stays silent on the rasterized-figure majority.
> - **(C) No automated cross-check; log recoverable labels for human audit:** make no comparison;
>   instead record each described figure's recoverable native word tokens in the audit log/metadata
>   as the "recoverable-label set", and rely on the existing non-authoritative marker. Zero
>   false-positives, smallest/safest change, but provides only evidence — no automated warning.

(Any chosen threshold must be a named, documented, configurable constant — no bare literals — and
a figure region with zero recoverable native words must be treated as INAPPLICABLE, never a fail.)

## 5. Acceptance-criteria readiness

GH-47C ACs:

- **AC1 — "Design note identifies which figure claim types are cheaply verifiable and which are
  not."** Satisfied by this note (Section 1 table): only *named vector-chart label presence* is
  verifiable; plotted values, trends, arrow directions, and all labels on rasterized/embedded
  figures are not. Ready as written, independent of the B/C choice.
- **AC2 — "Any implementation records label-check warnings without rewriting captions silently."**
  Implementable as written for Option B or C: warnings go through the existing
  `AuditEvent`/`state.events` path (the same one `figure_cap_reached` uses), and no code path
  touches `FigureInfo.description` or the `_build_figure_blocks` output. The caption is immutable
  in this layer by construction.

**One precondition not stated in the ticket but required before any implementation ticket:** the
extractor must persist the figure **bbox** (and xref placement rect) on `ExtractedFigure`
(`extractor.py:71`) and carry it onto `FigureInfo` — today the rectangle is discarded, so the
region-word lookup has nothing to filter on. This is a small, deterministic, write-owned change to
`src/socr/figures/extractor.py` + `src/socr/core/result.py`, and should be called out as step 0 of
whichever implementation option (B or C) the panel selects. AC1/AC2 do not need tightening; only
this missing-bbox precondition needs to be added to the implementation ticket's scope.

## Consilium decision (2026-06-15, run 20260615T203853Z-9682) — ACCEPTED

**Panel:** Codex (gpt-5.5) + Gemini (antigravity). **Verdict: Option C (log-only), unanimous** —
overriding this note's openness to B.

Implement the evidence-only path; NO automated warning, NO comparison, NO threshold:
1. **Step-0 (precondition):** persist the figure bounding box — currently computed and discarded at
   `figures/extractor.py:71` — onto `ExtractedFigure` and `FigureInfo`.
2. Extract the recoverable native word tokens inside each DESCRIBED figure's bbox via
   `page.get_text("words")` filtered by the figure rect (deterministic, no model).
3. Record that "recoverable-label set" in the figure's audit record / metadata, reusing the existing
   `AuditEvent` / `state.events` path (the same one `figure_cap_reached` uses). A figure region with
   zero recoverable native words is INAPPLICABLE — an empty set, never a fail.
4. Do NOT add any caption-vs-label comparison, warning, or named threshold. The non-authoritative
   caption marker (GH-47B) plus the retained raw PNG remain the safeguards.

**Rationale:** alarm fatigue is the deciding factor — A/B inevitably false-positive on captions that
legitimately paraphrase categories, name chart types, and absorb surrounding-page context, which
would train operators to ignore all warnings. The miss is low-stakes (caption already marked
non-authoritative gist; raw PNG retained). **Future option B** (narrow gated named-label match) stays
documented behind an opt-in/experimental flag, to be reconsidered ONLY after a labeled sample shows
very high precision — not built now.

AC readiness: AC1 (design note identifies cheaply-verifiable vs unverifiable claim types) is
satisfied by this note. AC2 (records label-check evidence without silently rewriting captions) is
satisfied by the log-only path.
