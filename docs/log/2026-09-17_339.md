# GH-339 — URI links dropped inside a detected table cell

## What changed

`_table_to_markdown` (`src/socr/core/born_digital.py`) is the direct
`find_tables()` -> markdown path (the `else` branch in `extract_structured`,
taken when a table region is not lane-stacked). It built markdown purely
from `table.extract()`'s plain cell strings, so a link rectangle sitting
over a data cell never reached `_line_text` / `_apply_links_to_flat_text`
(where #323/GH-127 apply anchors) — the URI was dropped silently, not even
surfacing as raw text.

Fix:
- `_table_to_markdown` now accepts an optional `links` param and resolves
  each cell's own bbox from `table.rows[i].cells[j]`, which is aligned 1:1
  with `table.extract()`'s rows/columns (verified against a live
  `find_tables()` result, not assumed).
- New helper `_apply_links_to_cell(text, cell_rect, links)` mirrors
  `_line_text`'s per-span logic (anchor-substring match +
  `_anchor_offset_under` interpolation, right-to-left splice, no nesting,
  no whole-cell fallback) but keyed on the cell rect instead of a span rect.
- `extract_structured`'s call site now passes `links=_links` (the page's
  already-resolved `_uri_links()` result) through to `_table_to_markdown`.
- Docstring on `extract_structured` updated: GH-339 is closed for the direct
  `find_tables()`/`_table_to_markdown` path. Still out of scope (no per-cell
  bbox available there): the lane-stacked rowizer and the
  text-strategy/word-geometry fallback table paths.

## Follow-up (review round): None-cell guard

The team-lead's review verified the extract()/rows alignment independently
(confirmed) but caught a real gap: `fitz.Rect(None)` raises, and PyMuPDF
itself ships `None` cells for merged/absent spans (`table.py` guards
`cell is None` at several sites). The original `row_bboxes` build was a
single list comprehension over ALL cells in the table wrapped in one
`except Exception` — a single `None` cell anywhere in the table zeroed
`row_bboxes` entirely, silently dropping every link in that table, not just
the affected cell's.

Fix: added `_cell_bbox(cell)`, a per-cell guarded converter (`None` in,
`None` out on conversion failure, else `fitz.Rect(cell)`), and the use site
now checks `cell_bbox is not None` before calling `_apply_links_to_cell`.
The outer `except Exception` around the whole `row_bboxes` build stays as
the best-effort net for a genuinely malformed `table.rows` (e.g. it raises
on access), not widened to do per-cell work.

New hermetic test `test_a_none_cell_does_not_cost_the_whole_table_its_links`
(duck-typed `_StubTable`/`_StubRow`, since `find_tables()` offers no simple
portable recipe for forcing a merged cell out of a real ruled grid): a
None-celled header cell sits in the same table as a DOI-linked data cell;
asserts the DOI link is still wrapped and the sibling row's unlinked value
is untouched.

Mutation proof (second round, same protocol — copy `src`+`tests`+
`pyproject.toml` to `/tmp/wt-339-mut2`, canary confirmed `socr.__file__`
resolves inside the mutant copy, asserted the `_cell_bbox` call-site anchor
`row_bboxes = [[_cell_bbox(c) for c in r.cells] for r in table.rows]`
occurs exactly once before reverting it to the naive

10.2222/xyz.999 |'` — the None header cell blew `row_bboxes` for the WHOLE

## Follow-up (review round 3): cross-cell duplication + numeric decode-gap

rev-339 found, and the team-lead independently reproduced against the real
`_table_to_markdown`, two further real defects.

### Defect A: cross-cell link duplication (fabrication)

`_table_to_markdown` called `_apply_links_to_cell` independently per cell,
each testing `cell_rect.intersects(rect)` on its own with the FULL links
list. An oversized/straddling link rectangle that overruns a column rule can
satisfy `intersects()` on two adjacent cells; if both cells' text contains
the anchor substring, the anchor was wrapped in BOTH —
`| [2020](url) | [2020](url) |`, a fabricated duplicate neither vendor
emitted. Worse than the original drop this ticket exists to fix.

Fix: new `_assign_links_to_cells(row_bboxes, links)` in `born_digital.py`
assigns each link to AT MOST ONE cell — the one holding a majority
(`> 0.5`) of the link's OWN area, via the pre-existing `_rect_coverage`
helper. Mirrors the majority-overlap idiom `tables/binding.py` already uses
to bind a word to a table region (`_word_majority_overlaps_region`) —
never a bare intersection, never a centroid test. A link with no cell
holding a majority (a genuine near-50/50 straddle) is dropped rather than
guessed at twice or duplicated. `_table_to_markdown`'s cell loop now looks
up each cell's assigned links from this map instead of handing every cell
the whole list.

Tests (both directions, per the review's explicit requirement):
- `test_link_straddling_two_cells_binds_only_the_majority_cell` — a link
  with 1/3 area in the left cell, 2/3 in the right, binds ONLY to the
  right cell (`| 2020 | [2020](url) |`, not both).
- `test_ambiguous_50_50_straddling_link_is_dropped_not_duplicated` — an
  exact tie binds to neither (`| 2020 | 2020 |`).
- `test_a_well_contained_link_still_binds_under_the_majority_rule` — a
  normal, entirely-contained link still binds (guards against
  over-correcting to strict containment and silently re-dropping the
  ordinary case).

### Defect B: numeric decode-gap (silent value loss in the value guard)

Wrapping a numeric cell in a markdown link hides the number from
`native_verifier`'s NUMBER-COMPLETENESS multiset check: `_NUM_TOKEN_RE` is
anchored and does not match `[1204](https://x/note)`. Team-lead's repro:
`_numeric_tokens_from_text('| 2019 | 1204 |')` -> `['2019', '1204']`, but
`_numeric_tokens_from_text('| 2019 | [1204](https://x/note) |')` ->
`['2019']` (pre-fix) — the linked number vanished. `_table_to_markdown`'s
output feeds `verify_native_table_region` on the native route, so a
hyperlinked figure became invisible to the exact mechanism CLAUDE.md names
as most important. Same DECODE-GAP family as #766/#773/#690 — a
presentation wrapper in front of a numeric gate.

Fix, at the shared decode point (not by loosening the regex, and not by
patching only `native_verifier`): new `_MD_LINK_RE`/`_unwrap_markdown_link`
in `native_verifier.py`, applied inside `_decoded_numeric_candidate` (the
single shared first step of every numeric-token predicate in that module)
BEFORE `html.unescape`/`strip_presentation`. Anchored full-match (whole
token only) so a token that merely contains brackets elsewhere is left
alone.

Consumer sweep (required: report FIXED / NOT-AFFECTED with reason for every
consumer of table markdown, not just `native_verifier`):

| Site | Status | Reason |
| --- | --- | --- |
| `tables/native_verifier.py` | FIXED | Direct fix point (`_decoded_numeric_candidate`). |
| `tables/binding.py` | FIXED | Imports `is_numeric_token`/`_normalize_cell` from `native_verifier` — gets the fix for free. |
| `tables/row_corroboration.py` | FIXED | Same import. |
| `tables/adjudication.py` | FIXED | Same import. |
| `tables/crop_repair.py` | FIXED | Transitively: calls `verify_native_table` (native_verifier, fixed) and `header_repair.detect_header_column_collapse`, which itself uses `is_numeric_token` on markdown grid cells (fixed); `detect_general_column_collapse` doesn't test numeric-ness at all. |
| `tables/header_repair.py`'s raw-word checks (`_NUM_TOKEN_RE`/`_NUMERIC_RE` at lines 407/479/695/710) | NOT-AFFECTED | Operate on PDF word tokens (`page.get_text("words")`), not on `_table_to_markdown`'s markdown string — a PDF link is a separate object from word text, so a markdown link wrapper can never appear there. |
| `core/table_grid.py` | AFFECTED, now FIXED | Separate code path: `normalize_cell`/`is_numeric_cell` use their OWN regex (`NUMERIC_CELL_RE`), never routed through `native_verifier.is_numeric_token`. Used by the GH-96 GT-vs-model exactness scorer (`score_page`/`score_rows`, and `benchmark/scorer.py`) and by `tables/native_rows.py`'s grid detector. Without a fix here, a correctly-recovered linked cell would score as wrong against ground truth and would not be seen as numeric by the native-rows grid check — an accuracy regression the GH-339 fix itself would have introduced. Added the same whole-token `_MD_LINK_RE` unwrap, duplicated locally rather than imported (this module's own docstring is explicit that `core` and `socr.tables` must not reach through each other's private names — the #175 cycle). |

## Notes / deviations from the ticket framing

None found. The ticket's own reproduction recipe (ruled-grid fixture,
`page.search_for(anchor)` over a cell) worked as described once the anchor
was placed over a data cell instead of the surrounding prose.

Scope was kept to the direct `find_tables()` -> `_table_to_markdown` path,
per the ticket's own reproduction (which drives exactly that path) and its
"out of scope: `find_tables()` / dict-walk exception paths" note. The
lane-stacked rowizer and word-geometry table fallbacks build markdown
without per-cell bboxes and are architecturally separate call sites; closing
GH-339 for those would be new scope, flagged here rather than silently
folded in.
