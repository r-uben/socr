# 2026-10-10 - #1080 preflight check at the start of every run

## What

`socr process`, `socr batch`, `socr library` and `socr process --hpc-sequential`
run a preflight before any page, print a present / missing report, and exit
non-zero when a tool the run needs is missing. `socr preflight` prints the same
report for the given flags and config. `--allow-missing <check>` (repeatable,
restricted to the check names, CLI only: a profile cannot disable a check) opts
one tool out. The run then continues and records `ran_without` in the
per-document `metadata.json`, the root-index entry, `manifest.json` and the
end-of-run summary (`Ran without: ...`); the HPC lane writes it to its `.md`
frontmatter. `--dry-run` never probes. A plain check; no model judges it (owner
ruling 2026-10-10). The Python API (`UnifiedPipeline.process`) is not gated.

## Why

Corpus run 22922695 on Rorqual (main @ a257fd1d) learned about two missing tools
page by page:

- no `pytesseract` and no tesseract binary: 181 scanned-table pages in 74 papers
  shipped `[page N failed: unverifiable table]` with `NO_WITNESS_BACKEND`;
- maths readers that spoke only the Ollama API (#1063, since fixed: they now also reach an
  OpenAI-compatible server) on a vLLM-only cluster:
  2,748 formula regions on 1,159 pages detected, none read.

Earlier instance: the default page judge `qwen3.5:cloud` returned 410 for days
while `/api/tags` still listed it.

## Checks, and when each is needed

Preflight cannot know whether an input has scanned pages, so every run is treated
as possibly using a model, `--native-only` included (genuine scans still route to
OCR under it, `_agentic_no_provider_page`). Under the HPC lane only `model-server`
(an operator-run server; a managed one starts itself) and `engine-cli` (Nougat)
apply.

| Check | Probe reused | Needed when |
| --- | --- | --- |
| `model-server` | `probe_model_generation` (real 1-token generation) on the host `resolve_qwen_intent` + `ollama_host` resolve to; vLLM/API backend: `probe_openai_server_idle` (listing, then a generation canary on the served model, GH-221) | qwen is in `enabled_engines` |
| `engine-cli` | the OCR executable the engine shells out to: `BaseEngine.is_available` for `qwen-ocr`; the primary engine's own `is_available` when it is a concrete non-qwen CLI engine | always (when such an engine is in the run) |
| `page-judge` | `UnifiedPipeline._resolve_judge_model` | `judge_backend != heuristic` |
| `tesseract` | new `classical_ocr_backend_state` (same state names as `classical_ocr_with_state`) | always |
| `maths-readers` | `_equation_lane_backend_addressable`, then a real generation on every model a lane will call (`math_model`, `clean_equation_model`) | per lane, the pipeline's own run-level predicate (`_equation_region_lane_enabled`, `_corrupt_math_recovery_enabled`, `_clean_equation_recovery_enabled`), so `--native-only` switches the first two off |
| `table-judge` | `_any_table_judge_reader_reachable` (folds the two P1 startup notices) | `table_judge_ladder`, not `--strict-local` and not an explicit `--max-cost-per-page 0` (the two policies `_build_table_judge_rungs` refuses the rungs under) |

Under `--strict-local` the `table-judge` row is "not needed" and carries the old
notice text, so that choice stays visible.

`--strict-local` / `--max-cost-per-page 0` never see a request to a cloud model
from preflight: a cloud model they forbid is reported MISSING ("forbidden by
--strict-local, not probed") without a call. The page judge already skips such
candidates in `_resolve_judge_model`.

## Behaviour changes to be aware of

- Default invocations with the table-judge ladder on (the default) and no
  reachable table-judge rung now STOP, where P1 only printed a notice. Owner rule:
  stop when a tool an enabled feature needs is missing. Opt out with
  `--no-table-judge-ladder` (ships tables unjudged) or `--allow-missing table-judge`.
- `--quiet` does not hide a stop or an allowed miss: the report is printed.
- A Mac without Ollama running, a run with `--primary gemini` and no local model,
  and a `--native-only` convert-only run on a machine without a model now need
  `--allow-missing model-server` (and `tesseract`, `page-judge`, ...); the run
  records what it went without.

## What it does not cover

- Whether the tool keeps working for the length of the run.
- No retry on a transient probe failure: a stop is loud and fail-closed. Each
  parallel worker (shard) probes independently, so one failure stops only its
  own shard.
- The Python API is ungated; a library caller calls `run_preflight` itself.
- `socr benchmark run --engines ...` is deliberately ungated, like the Python API:
  `BenchmarkRunner` runs bare engines (`get_engine(...).process_document`) with its
  own `is_available` skip, and uses no judge, Tesseract, maths lane or table judge,
  so the pipeline's checks do not describe it and would block a legitimate
  `--engines gemini,deepseek` comparison on a machine without Tesseract.
- The HPC lane's managed vLLM server cannot be probed before it is started.
- `engine-cli` checks only qwen and a concrete primary engine, not every
  `enabled_engines` entry (the default enables all of them, most are optional).
