# TICKET-C3 — manifest: disposition survives winner selection (GH-353)

## What changed

`src/socr/core/manifest.py`: added a page-level ladder disposition guard,
applied at the single shared final-validation seam both consumers of
`_select_page_output_tagged` already share.

- `_LADDER_TERMINAL_FAILURE_MODES` — the two GH-353 terminals
  (`FailureMode.TABLE_REJECTED`, `FailureMode.TABLE_UNVERIFIED`).
- `_apply_ladder_disposition_guard(output, page_num, p)` — reads
  `getattr(p, "table_ladder_disposition", None)` (no field on `PageState`
  yet; B1 owns adding and setting it). If the page's disposition is one of
  the two terminals and the selected `output` currently carries
  `audit_passed=True`, it is demoted to `WARNING` / `audit_passed=False` /
  `failure_mode=<disposition>`. If the output is already non-passing, the
  disposition backfills `failure_mode` only when it is still `NONE` — a
  more specific existing reason (e.g. `NATIVE_TABLE_STRUCTURE_FAILED`, or
  GH-226's table-emission guard, applied first) is left alone.
- `_finalize_page_output(state, output, page_num)` — new shared seam: runs
  the GH-226 table-emission guard, then the ladder disposition guard. Both
  `_winning_page_output` (the manifest/per-page-flush freeze point,
  `orchestrator.py:4188`) and `finalized_page_outputs` (the assembled-.md /
  manifest-blob freeze point) now call this instead of applying only the
  table-emission guard, so the two can never disagree about whether a
  rejected page shipped SUCCESS.

The `_select_page_output_tagged` cascade itself is untouched — this fixes
the doc's stated hole (selection can still pick native text or another
attempt after the gate, and the native-only reconstruction ending in
particular — `NATIVE_CLEAN`, née "the :1271 path" — ships plain SUCCESS
whenever no OTHER distrust flag fired) by intercepting AFTER selection,
where every ending, present or future, is covered without special-casing
each cascade branch.

Semantics matches the ticket exactly: a rejected CANDIDATE can still lose
selection normally (nothing here changes which text is picked); the PAGE
just cannot regain SUCCESS while its disposition is REJECTED/UNVERIFIED.
`audit_passed` stays the winner-SELECTION flag mutated only on the copy
that ships (never on `best_output`/`attempts` themselves) — the same
discipline the surrounding D3/#259/#262/#263 branches already follow, so
this doesn't reintroduce the #252 round-1 defect (flipping `audit_passed`
in place would make assemble discard the page's text).

## Why inert today

Nothing in production sets `PageState.table_ladder_disposition` — B1 (wave
4, depends on this ticket among others) is the only ticket that will. The
guard reads the attribute via `getattr(..., None)`, so on every page today
`disposition` is `None`, fails the `_LADDER_TERMINAL_FAILURE_MODES`
membership check, and `_apply_ladder_disposition_guard` returns `output`
unchanged — confirmed by the two "inert" tests in the new suite and by the
full existing manifest/golden/byte-identity test runs below (byte-for-byte
unaffected).

## Tests

with no disposition (native-only clean page, passing best_output); both
terminals preserved through the native-only reconstruction path AND through
the ordinary passing-best_output path (parametrized over both modes);
backfilling `failure_mode` on an already-non-passing page whose reason was
unset; NOT overriding an already-specific failure_mode; the guard reading
page state rather than merely inspecting `best_output`/the winning
`PageOutput`; `finalized_page_outputs` applying the same guard (not just

## Deviations / follow-ups

None. `_finalize_page_output` is new (not in the ticket's literal file
list of edits, but is entirely inside `src/socr/core/manifest.py`, the
ticket's owned file) — it exists only to keep `_winning_page_output` and
`finalized_page_outputs` from re-deriving the same two-guard sequence and
drifting apart, mirroring the repo's own stated concern about exactly that
kind of drift (`_reaches_structure_class_branch`'s docstring). B1 should
set `PageState.table_ladder_disposition` from the page reducer's
REJECTED/UNVERIFIED verdict (A4) and can rely on this guard firing at both
seams without further manifest.py changes.
