# GH-418 — does a local signal separate "orphan in a table" from "prose near a lane"?

Date: 2026-09-16. Base: `main@f1272e2`. **Design pass only — no `src/` change, no fix implemented.**

**Answer up front: yes, one signal separates the two populations on every fixture measured —
row-level numeric co-occupancy (`>= 2` numeric lanes populated within the snap radius).**
It is not a new threshold: `_looks_tabular` already defines a data row as one with `>= 2` numeric
cells (`src/socr/tables/reconstruct.py:981`). The rule is that existing definition applied one step
earlier. x-distance and lane-span do **not** separate — both were measured and both overlap.

The separation is not perfect. A hand-built reference row whose numerals land on two lanes defeats
it (§3.4) — but in that case the rule is still strictly *less* lossy than today, because today the
same words are deleted outright.

---

## 1. What exists today

### 1.1 The drop

`_rowize_segment` (`src/socr/tables/reconstruct.py:2693`) builds one grid row per y-group. For each
word not claimed by the label branch:

- `src/socr/tables/reconstruct.py:2781` — `elif abs(lane_centers[best] - w[0]) <= _LANE_X_TOL_PT * _LANE_SNAP_MULT:` assigns the cell.
- There is **no `else`**. A word further than the snap radius from every lane falls out of the loop
  and never reaches `grid_row` (`src/socr/tables/reconstruct.py:2790`). No cell, no event, no log line.

Constants: `_LANE_X_TOL_PT = 6.0` (`:90`), `_LANE_SNAP_MULT = 3` (`:1143`) → snap radius **18.0 pt**.

### 1.2 The guard that makes the drop load-bearing

`_looks_tabular` (`src/socr/tables/reconstruct.py:958`) runs **after** the grid is built, in
`_rowize_word_group` (`src/socr/tables/reconstruct.py:2034`, gate at `:2115`). Its localization
clause requires a majority of non-empty rows to be data rows:

```python
data_rows = sum(1 for row in grid if sum(1 for c in row if c and _NUMERIC_RE.search(c)) >= 2)
...
return data_rows / nonempty_rows >= _MIN_DATA_ROW_FRAC  # 0.5, reconstruct.py:82
```

### 1.3 Precedent for the shape of a fix

`_rowize_segment` **already** has a dedicated non-lane column: GH-461's `orphan_marginals`
(`src/socr/tables/reconstruct.py:2764-2782`), emitted as the trailing cell of `grid_row`
(`:2790`) and dropped by `_clean_grid` when no row has one. An orphan column is an established
pattern in this function, not a new concept.

### 1.4 What the ticket assumed vs. what is true

| Ticket claim | Verified? |
| --- | --- |
| A word beyond the snap radius from every lane is silently dropped | **True** — `reconstruct.py:2781` has no `else`. |
| "Nearest lane regardless of distance" fails the prose test | **True, reproduced** (§3.1). |
| "Only capture orphans between first and last lane centre" fails the same way | **True, reproduced** (§3.1) — and it is also *incomplete*: it misses an orphan to the right of the last lane (§3.3). |
| The `n.a.` is the only thing lost on the GH-342 fixture | True. All 16 numerics survive. |
| Row-level numeric co-occupancy is worth checking | **Confirmed as the only separating candidate measured.** |

## 2. Method

`_rowize_segment` was replaced at runtime by monkeypatched copies of its own body
(`mode ∈ {baseline, nearest_always, span, numeric_cooccupancy}`), each differing from production in
exactly one branch. `src/` was never edited. Both populations are **synthetic fixtures** — no
corpus content.

- **Population A — orphan inside a genuine table.** The GH-342 fixture shape
  (`tests/test_gh342_stub_promotion_runaway.py::_four_data_lanes`): four full numeric lanes at
  x = 80/200/320/440, a label column, an `n.a.` at x = 150 mid-gutter on three of four rows. Plus
  `†`, a right-of-last-lane `*`, a sparse-row variant, and a header-row variant.
- **Population B — prose word near a spurious lane.** The adversarial fixture from
  `tests/test_reconstruct.py:176` (`test_prose_with_small_embedded_table_is_not_whole_page_gridded`),
  run unmodified through `BornDigitalDetector().extract_structured`. That page enters
  `_rowize_segment` as **one segment** (y 69..189, 8 rows, 6 lanes): 3 genuine table rows and 5
  prose/reference rows, with **16 words dropped** by the snap rule.

## 3. Distributions

### 3.1 Candidate signals, both populations

Snap radius = 18.0 pt in both.

| Candidate | Population A (orphan in table) | Population B (prose rows) | Separates? |
| --- | --- | --- | --- |
| **Row numeric-lane co-occupancy** (distinct lanes with a numeric token inside the snap radius) | **4, 4, 4** (all drops) | **1, 0, 1, 1, 1** (all 5 prose rows) | **Yes.** Gap at 2 — and 2 is `_looks_tabular`'s own data-row definition (`:981`), not a new constant. |
| Distance to nearest lane, in snap radii | 2.78 | 1.13 – 2.70 | **No.** Ranges abut; the 0.08 "gap" is fixture noise. |
| Orphan lies inside the lane span (`lanes[0] <= x <= lanes[-1]`) | True | True (all 16) | **No.** Reproduces attempt 2's failure exactly. |
| Fraction of the row's non-label words that snapped | 0.80 | 0.17 – 0.50 | Weakly. Monotone with co-occupancy on these fixtures; strictly more fragile (depends on prose word count). |
| Segment as a whole passed `_looks_tabular` | n/a — **not available**. `_looks_tabular` runs on the *cleaned, header-prepended* grid in `_rowize_word_group` (`:2115`), after `_rowize_segment` has already returned. Using it inside the loop is circular: the capture decision changes the grid the guard then judges. | | **Not usable as-is.** |

### 3.2 Why the two naive attempts actually fail — measured

Instrumenting `_looks_tabular` on the prose page (second call, the fallback rowizer):

| Mode | `numeric_frac` | `data_row_frac` | verdict | prose page gridded? |
| --- | --- | --- | --- | --- |
| baseline | 0.481 | **0.375** | False | no |
| `nearest_always` | 0.483 | **0.500** | True | **yes — prose destroyed** |
| `span` | 0.438 | **0.500** | True | **yes — prose destroyed** |
| `numeric_cooccupancy` | 0.481 | **0.375** | False | no |

(`_MIN_DATA_ROW_FRAC = 0.5`, `reconstruct.py:82`.)

The mechanism is not what the ticket text implies. The naive fixes do not fail by stuffing
non-numeric prose into cells — they fail because a reference line **contains numerals**
(`(2010)`, `427-465`). Capturing those promotes a prose row to a "data row" under `_looks_tabular`'s
`>= 2 numeric cells` rule, tipping `data_row_frac` from 0.375 to exactly 0.5 and flipping the
guard. Gating capture on the *same* `>= 2` predicate is therefore self-consistent by construction: a
row the guard would not count as data is not allowed to gain cells, so `data_row_frac` cannot move.

`nearest_always` has a second defect independent of the prose page: it merges the marker into an
occupied numeric cell — `| Row0 | 00.5 | n.a. 01.5 | 02.5 | 03.5 |`. That is misattribution, the
class GH-461 built the dedicated column to avoid.

### 3.3 Coverage on other genuine-table orphan shapes

Emitted-or-dropped, per mode:

| Orphan shape | baseline | `span` | `numeric_cooccupancy` |
| --- | --- | --- | --- |
| `n.a.` mid-gutter, full data row (GH-342) | dropped | kept | **kept** |
| `†` mid-gutter, full data row | dropped | kept | **kept** |
| `*` right of the last lane (x = 500) | dropped | **dropped** | **kept** |
| multi-word phrase mid-gutter, full data row | dropped | kept | **kept** |
| `n.a.` in a row populating only **one** numeric lane | dropped | kept | **still dropped** |
| `(pct)` on a header row (no numerics on that row) | dropped | kept | **still dropped** |

Two residual losses remain under the recommended rule. They are narrower than today's, and both are
knowable at the point of the drop, so they can be surfaced even if not recovered.

### 3.4 Where the signal breaks

Worst case, built deliberately: reference rows laid out so the year lands on lane 0 and the page
number on lane 1, with prose words mid-gutter. Those rows score `row_numeric_lanes = 2` and pass the
gate — **overlap with population A**.

Result (`rowize_from_word_list`, same words both modes):

- baseline: `| Fama | 1992 | 427 |  |` — `Journal` and `Finance` **deleted, silently**.
- rule: `| Fama | 1992 | 427 |  | Journal Finance |` — same page-gridding verdict, prose recovered
  into the orphan column.

So the rule's failure mode is *visible misplacement*, replacing today's *silent deletion*. Under the
repo's "a wrong/dropped number is worse than a missing one, and loss must surface" doctrine that is
a strict improvement, but it is an honest limitation, not a clean separation.

### 3.5 Blast radius on the existing suite

Targeted runs, baseline vs. rule, same command:

- `tests/tables/`, `test_header_repair.py`, `test_header_cut.py`, `test_gh696_*`, `test_gh248_*`,
  `test_gh592_*` — **145 passed under both.** No change.
- `test_reconstruct.py`, `test_gh342_*`, `test_gh152_*`, `test_gh349_*`, `test_gh419_*`,
  `test_gh467_*`, `test_gh301_*`, `test_header_attribution.py`, `test_gh778_*` —
  58 passed at baseline, **7 fail under the rule**:

| Failing test | Cause | Kind |
| --- | --- | --- |
| `test_gh342_…::test_no_data_value_is_lost_into_the_label` | `n.a.` now survives | **the intended flip** |
| `test_gh342_…::test_markers_do_not_change_the_column_count` | markers now add the orphan column (4 → 5 data-side columns) | guard must be restated |
| `test_gh342_…::test_a_dagger_footnote_behaves_the_same_as_n_a` | same | guard must be restated |
| `test_gh419_…::test_gutter_marks_do_not_change_the_table_shape` | same column-count shape, 5 → 6 | guard must be restated |
| `test_gh467_…::test_a_note_folded_onto_the_header_row_does_not_corrupt_a_header_cell` | prototype appends the orphan column at the index `_prepend_header_band` uses for its note column (`reconstruct.py:2683`) | **implementation constraint**, see §5 |

**`test_prose_with_small_embedded_table_is_not_whole_page_gridded` passes under the rule.** It is
untouched and stays untouched.

**The orchestrator's "one assertion to flip" is understated.** Three tests in
`test_gh342_stub_promotion_runaway.py` fail, not one, plus one in `test_gh419`. The
column-count guards are correct in *intent* (a gutter mark must not swallow a data lane) but their
proxy — total column count — stops holding once the marker legitimately gets a column of its own.
They must be restated against the **data-lane count**, not the total.

## 4. Options

### Option 1 — row-level numeric co-occupancy gate + dedicated orphan column (measured)

An orphan word is captured iff its row already populates `>= 2` distinct lanes with numeric tokens
inside the snap radius; captured orphans go to a dedicated trailing column, exactly as GH-461's
`orphan_marginals` does (`reconstruct.py:2764-2790`), never into a lane cell or the label.

- Cost: one extra pass over each row's words. Deterministic, no model, no new constant.
- Determinism / replay: unaffected — pure geometry, same inputs → same output.
- Risk: 7 test updates (§3.5), two of which (`test_gh152_*`) encode the loss as expected behaviour
  and need their fixture sanity assertions re-expressed. Residual loss on sparse rows and header
  rows (§3.3). Prose recoverable into the orphan column on the §3.4 shape.

### Option 2 — keep the drop, surface it as a rejection event (no grid change)

Do not change any cell. Plumb a `dropped_words` sideband out of `_rowize_segment` the way GH-195
plumbs `rejections` (`reconstruct.py:112, 140, 329`), and surface the count + texts on the page
record. Grid output stays byte-identical.

- Cost: new sideband parameter through `_rowize_segment` → `_rowize_word_group` →
  `rowize_from_word_list` → `rowize_from_words_chart_aware` → `extract_structured`. The fallback
  rowizer path currently receives **no** `rejections` list (`born_digital.py:3541` passes it only to
  `reconstruct_table_regions`), so this is genuinely new plumbing.
- Determinism / replay: unaffected.
- Risk: **zero** risk to the prose guard and to every fixture above. But the content is still not in
  the document — it satisfies "must surface", not "must not be lost".

### Option 3 — Option 2 now, Option 1 behind it

Land the surfacing first (it is independently correct and makes the residuals of §3.3 visible),
then land the co-occupancy capture on top, with the event retained for the orphans the gate still
refuses.

- Cost: two tickets instead of one.
- Risk: lowest. Each half is separately revertible, and the event gives a measurement channel for
  how often the §3.3 residuals actually occur before anyone widens the gate.

No option puts a model anywhere near the routing/verify path. All three are deterministic code.

---

## 5. Recommendation

**Option 3.** The separating signal is real and measured, so Option 1 is not speculative — but the
§3.4 overlap and the two residual drops in §3.3 mean the gate will keep silently deleting *something*,
and there is currently no channel that says so. Landing the sideband first converts "we think this is
rare" into a number, and it is the half with zero risk to the guard that killed both prior attempts.

Implementation constraints for whoever takes Option 1, from §3.5:

1. The orphan column must be inserted **consistently in every grid-row builder**, including
   `_prepend_header_band`'s `["", *row_cells, " ".join(band_note)]` (`reconstruct.py:2683`).
   The prototype did not, and that alone broke `test_gh467`.
2. `test_gh342_…::test_markers_do_not_change_the_column_count`, its dagger twin, and
   `test_gh419_…::test_gutter_marks_do_not_change_the_table_shape` must be restated against the
   **data-lane count**, not the total column count.
3. `test_prose_with_small_embedded_table_is_not_whole_page_gridded` must not be touched, and
   should gain the §3.4 lane-aligned-reference fixture as a second, harder case.

This is **not** a genuine fork on the signal question — that one is measured and settled. The fork
worth paneling is the *disposition*: recover into a column, or surface and keep dropping, or both.

## 6. The consilium question

> In a deterministic PDF table rowizer, a word further than the snap radius from every detected
> column lane is currently deleted with no cell, no log and no event — which is what stops a prose
> page being gridded whole, but also deletes qualifiers like `n.a.`, `†` and `*` from genuine data
> rows. Measurement shows one predicate separates the two cases on every fixture tried — capture the
> orphan only if its row already populates >= 2 column lanes with numeric tokens, which is the same
> ">= 2 numeric cells" definition the existing prose guard uses for a "data row" — but it still
> deletes orphans on single-value rows and header rows, and it can pull prose into the table when a
> reference line's year and page number happen to align with two lanes. Which disposition should
> ship?
>
> **Option 1.** Capture the orphan into a dedicated trailing column (never into a lane cell or the
> row label) whenever its row populates >= 2 numeric lanes; keep deleting it otherwise.
>
> **Option 2.** Change no cell. Keep deleting the orphan, but emit a structured per-page event
> naming every dropped word, so the loss is visible at page, document and CLI level.
>
> **Option 3.** Option 2 first as its own change, then Option 1 on top, with the event retained for
> the orphans Option 1's gate still refuses.

## 7. Acceptance-criteria readiness

GH-418 has **no `### Acceptance Criteria` section** — the issue ends at a "Wanted" paragraph
("a rule that keeps an orphan inside a genuine table without capturing prose"). As written that is
not implementable: it asks for a property no measured predicate achieves (§3.4).

Criteria that are implementable once the disposition is chosen:

- `n.a.`, `†` and a right-of-last-lane `*` on a full data row all appear in the emitted grid, in a
  column that is neither a numeric lane nor the row label.
- `test_prose_with_small_embedded_table_is_not_whole_page_gridded` passes unmodified, and a new
  lane-aligned-reference fixture (§3.4) does not flip the page to gridded.
- Pinned as a **difference**, per the repo's own rule: the same geometry with and without the
  markers yields the same *data-lane* count and the same numeric multiset.
- Every orphan the gate refuses is named in a surfaced record (Options 2/3).

Needs tightening before implementation: the issue must name the disposition (column vs. event), and
must state the residual-loss contract for sparse rows and header rows rather than implying none
remains.
