### Class 1

`native_glyphs` from the PUA clause only. `NATIVE_GARBLED_MATH` (23 pages) and
`NATIVE_MINUS_AS_DIGIT` (1 page) also map to `native_glyphs` and are untouched. That explains the
22-24 marked pages with no private-use codepoint (brief, "cause unknown"): they are the garbled-math
and minus modes, not PUA. Shipped bytes are unchanged (a raw U+F0B7 stays in the text).

### Class 2: evidence a page has nothing to check

The clause returns nothing for `compared == 0` with no layer number iff ALL of:

1. the words check agrees: #1294's record has `compared > 0` and `missing == 0`; or, where it
   recorded nothing, the WHOLE layer is held to the shipped page with no page-edge excusal
   (`_whole_layer_is_shipped`). The fallback exists because #1294 excuses repeated edge text, so
   the one line of a blank page leaves its reference empty: 16 of the 24 blank and divider pages
   had no words record. It demands more than the words check, never less;
2. the #1050 ink-vs-layer verdict is `passed` (the only check that sees a raster chart whose
   layer holds just a running header; Carbon condition 1);
3. the page has no embedded raster image (`has_figures`).

Any missing piece keeps the UNKNOWN. A tool that re-derives without a coverage verdict (the
refinalize tools) fails closed.

### Class 3: shape-refused layer (Carbon condition 2)

The shape returns are: too few characters, excessive spacing, average word length too short or too
long. Each now calls `_shape_refusal_layer_is_clean`: not prior-OCR (#1156), no CID artifacts, garbage
ratio, digit corruption, encoding corruption, #961 invisible text over a raster, minus-as-digit, control
byte before a digit; any exception answers False. The verdict trusts the layer only when
`layer_refused_for_shape_alone` AND none of `_DAMAGED_LAYER_FLAGS` is set. Choices:

- only AGREEMENT is claimed. A dispute with such a layer stays UNKNOWN with its own wording
  (`SHAPE_REFUSED_LAYER_PREFIX`); a dot-leader or spaced-digit layer is exactly the kind that splits
  numbers, so a FAIL on it would be a new false alarm;
- `_layer_is_damaged` is unchanged. The drops and words checks also read it, and a shape-refused
  layer is not shown to be the right reference for counting omissions.

### Class 4 (Carbon condition 3)

`FailureMode.WITNESS_DISAGREES` (witness read the page and disagrees) for `verifiable and not passed`;
`FailureMode.TABLE_UNVERIFIED_WITNESS` for `verifiable=False`. The second is a member of the
`table_unverified` family but not `TABLE_UNVERIFIED` itself: that mode is the table-judge ladder's
terminal and drives its retry and bucket logic, which the source-evidence gate must not enter.

Control flow is unchanged because every site that read `is HALLUCINATION` now reads
`result.WITNESS_REJECT_MODES = {HALLUCINATION, WITNESS_DISAGREES, TABLE_UNVERIFIED_WITNESS}`:
manifest 799/926/993/1032, the floor-cause helpers (`_floor_cause_is_contradiction`, the new
`_floor_cause_is_witness_unverifiable`), the ladder latch at ~12675. HALLUCINATION stays in the
set: old sidecars record it and fabricated image references still use it. The floor RECORDS the cause
in `manifest.py` (~5186) and `orchestrator.py` (`_apply_scanned_table_floor`); the scanned-table floor
latch (`"source_evidence_table" in att.reason`) is untouched, so `verifiable=False` still floors. The new
`PageState.scanned_table_witness_unverifiable` is DERIVED on resume from the persisted mode (no sidecar key,
as for its two siblings) and cleared with them. `_MODE_CLAUSES` names both: `source_evidence` FAIL and
UNKNOWN, instead of the `unknown=UNKNOWN` fallback (the legacy mode still falls there; so does
`no_witness_backend`, not touched here).

No new durable audit event, so `test_resume_restore_kinds.py` needed no change.
`_ESCALATION_MODES` and the scoreboard counters know the new modes.

### Class 5: not built, and why (Carbon condition 4)

**I did not hand-grade all 68.** The brief's 68 is not reproducible from the sidecars (the judge's reason is in
`winning_output.judge_reason`; 111 of the 391 `page_judge=FAIL` pages say "column", 79 match a
missing/extra-column pattern). I graded the pages where the proposed check would FIRE, against the
rendered page, and stopped when the result was clear. The check: withdraw "table T is missing column H" when H
is not among the text-layer words inside T's own region. Of 79 claims, 102 (page, H) pairs are extractable by
pattern and most name H as present in the image. Findings on the pages I opened:

- `2019-01-30 tealbook-parta p31`: H = "1996-2000" is not in the layer words. The image prints it wrapped
  ("1996-" over "2000"). The claim is TRUE; the check would withdraw it (Carbon's wrapped-header case).
- `presentation-materials-ab67012f p10` (/Rotate 90): "Maturity", "Policy Rate Features",
  "Administered/Market" are not found inside the region boxes, because words are unrotated and boxes rotated.
  The claims are TRUE (headers present); the check would withdraw them.
- `2008-06-25 greenbook-part2 p7`: "Rate and group" is on the page but outside the detected box. The
  sub-headings the claim names are in the image. Would withdraw a true claim.
- `bdde5aee p23` (RC-304, the one confirmed false claim): the detector reports ONE region for a page with
  four tables, and "Longer run" is inside it. The check cannot reach the only gold page. Reaching it
  needs table binding by title geometry, which is bespoke to this page.

Three of the four pages graded would lose a TRUE judge claim, and the gold page is out of reach. A true
claim withdrawn is a silent loss of a real warning, which is worse than the false alarm. The grading does
not support the check, so class 5 is unchanged. Not done: grading the remaining ~65 pages one by one (it
cannot rescue a check that already fails on a quarter of what it examines). Raw material:
`col_probe2.py`, claims extracted per page in the output of that script.
