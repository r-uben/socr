## Method

- Ollama cloud via `POST /api/chat`, base64 page image, `format=json`, the GH-353 judge
  schema (`verdict/confidence/findings[{code,where,detail}]`, closed 6-code enum).
- **The `ollama run --images` flag documented in older notes does not exist in ollama
  0.32.15** — the HTTP API is the integration path.
- Three rounds: (1) synthetic renders with planted defects; (2) the 7 hand-verdicted
  real pages from `~/.local/share/socr/tr3-judge/` (4 damaged, 3 not-a-table);
  (3) load-bearing real cases reconstructed from the issue record on real scans —
  Cochrane–Piazzesi p10 correct/GH-273-shifted, Nakamura–Steinsson p42
  correct/GH-270-fabricated, NS p13 GH-146 shipped output (verbatim from the hand
  ground-truth draft).
- Artifacts (scratch, not committed): `~/tmp/socr-356-bakeoff/` — harness, fixtures,
  raw judge JSON, `gh356-scoreboard.html`, and `gh356-evidence.html` (a side-by-side
  page-image ↔ markdown viewer; this is GH-220's shape and should graduate with the
  harness).

## Results

**Round 1 — synthetics (6 cases × 3 models):** 18/18 correct verdicts and correct
codes for all three. Establishes S1 + schema compliance + a floor only.

**Round 2 — real hand-verdicted pages (7 × 3): 21/21 correct verdicts.** Several of
these pages carry defects TR-3's numeric-multiset check cannot see (Herskovic header
band, Tsukioka star-only row) and all three judges caught them — the vision judge
covers the mechanical check's blind spots.

**Round 3 — load-bearing real cases:**

| case | expected | glm-5.3-flash | kimi-k2.6 | gemma4:31b |
| --- | --- | --- | --- | --- |
| CP p10 correct (v2) | PASS | ✓ PASS | ✓ PASS | ✗ FAIL (over-strict) |
| CP p10 GH-273 shift (v2) | FAIL/WRONG_BINDING | ✓ exact | **✗ PASS — missed** | ✓ FAIL (wrong codes) |
| NS p42 correct | PASS | ✓ PASS (320 s, retry) | ✓ PASS | ✗ FAIL (over-strict) |
| NS p42 GH-270 fabrication | FAIL/FABRICATED_VALUE | ✓ exact (302 s, retry) | ~ FAIL/MISSING_VALUE | ~ FAIL/WRONG_BINDING |
| NS p13 GH-146 header | FAIL/HEADER_MANGLED | ✓ exact (16.7 s) | **✗ PASS — missed** | ✓ exact (1.3 s) |

**Latency (per call):** gemma 0.4–2.9 s flat; glm 1.7–44 s typical, ~5 min worst case
on the dense NS p42 grid (one 300 s timeout, correct on retry at a 590 s cap); kimi
3.8–159 s and 260 s on retry.

## Findings beyond the ranking

1. **The judges out-verified the fixture author.** All three unanimously FAILed the
   first hand-built "correct" CP p10 fixture — correctly: it was missing the
   `Standard Errors` spanning header and carried a spurious column. The v1 round was
   discarded and the fixture corrected before the decisive v2 pair.
2. **¬S1 is real and model-specific.** glm exceeded a 300 s cap on a dense page and was
   correct given ~5 min. The ladder's rung timeout is a live parameter, not a
   formality; timeout must route as escalate-as-substitute, not as a reject.
3. **Wrong-code-right-verdict happens on hard fabrication.** kimi and gemma both FAILed
   the GH-270 page with plausible-but-wrong codes. Verdict-level accuracy is ahead of
   code-level accuracy; the ladder should gate on verdicts and treat codes as evidence.
