# 2026-08-01 — TICKET-B1: refuse to score a page with no table

## What changed

`score_page` no longer scores a page whose native text layer never establishes
a table grid. Page 54 of the OBR reference document is prose plus two fan
charts; socr correctly emits no table, but `native_rows_from_page` reads the
charts' axis labels and legend as if they were rows (a cover date, an axis
tick, a legend entry — each a single label paired with a single number), and
the page used to score 0.0%, silently counting a page with no table as an
engine failure.

`score_page` now runs the ground truth through the GH-113 grid predicate
(at least two value columns, at least two rows sharing that width) before
scoring. Below it, the report carries `ceiling_note`, `gt_rows=0`, `cells=0`
(so `.pct` is `None` via the existing `pct` property) and `.scorable is
False`.

`gt_rows=0` rather than the fabricated-row count matters: `escalation_decision`
gates on `incumbent.gt_rows >= _MIN_GROUND_TRUTH_ROWS` (2), not on
`.scorable` — deliberately, per its own docstring, because `.scorable` also
fires on a different ceiling (unmatched labels) that it wants to keep scoring
by exactness. Reporting the true fabricated-row count (5, on page 54) would
have left that gate open and let a chart page take the exactness path with
phantom ground truth. Reporting `gt_rows=0` closes it without touching
`escalation_decision.py` at all — it falls through to the canary gate, same
as any other page with no usable ground truth.

**The GH-113 predicate itself was duplicated, not reused**, before this
ticket: `orchestrator._table_page_needs_escalation` had its own inline
`collections.Counter` width check. Extracted it to
`native_rows.rows_establish_grid` and pointed both call sites at it, per the
ticket's explicit "reuse the GH-113 predicate" instruction — this is a
same-behaviour refactor of `orchestrator.py`, which was not in the ticket's
listed write ownership, but leaving two independent copies of "what counts as
a grid" was the thing the ticket was trying to prevent.

## Aggregate helpers checked

Grepped every caller of `score_page` / `.pct` / `.scorable` / `.gt_rows` in
`src/`:

- `escalation_decision.decide_escalation` — already excludes low-`gt_rows`
  pages from the exactness gate by its own `_MIN_GROUND_TRUTH_ROWS = 2`
  threshold; this ticket makes chart pages report `gt_rows=0` so that
  threshold now correctly excludes them too. No change needed to this file.
- `orchestrator._table_page_needs_escalation` — the escalation trigger itself;
  refactored (see above) to call the shared predicate instead of a second
  copy.
- No other aggregate/reporting helper in `src/` consumes `score_page`. The
  corpus-level rescoring scripts referenced in `docs/plans/metric-blind-spots/
  STATUS.md` live outside this repo (`~/data/fiscal-ballast/_experiments/`)
  and are out of scope for this ticket's "Files" list.
