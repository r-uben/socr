# GH-35-FU: Gate clean-short-text born-digital exception by raster image coverage

Date: 2026-06-15
Commit: feat/001-issue-plans
Consilium decision id: 20260615T104828Z-1577

## Context

GH-35 introduced a quality-aware word-count bypass: a sparse but clean native text layer
(figure caption, section heading) would skip the word-count gate and classify the page
as born-digital, avoiding spurious OCR on pages whose text is genuinely authored.

A /consilium panel (Codex + Gemini) identified this is UNSAFE on image-dominant pages:
a scanned page with a full-page raster image + baked-in OCR caption passes all text-quality
checks (no CID, low garbage ratio, normal word lengths, proper font) and is indistinguishable
from a genuine born-digital figure page by text quality alone. Silently skipping OCR on such
a page causes permanent content loss in a citation corpus.

## Decision: image-coverage gate

Gate the clean-short-text exception by raster image coverage, not text quality alone.

Named constant: `RASTER_DOMINANCE_RATIO = 0.90`

Basis for 0.90:
- A full-page scan rendered as a single raster hits >= 0.98 coverage (image fills
  essentially the entire printable area after margins; insert_image(page.rect) in tests
  confirms this empirically).
- A genuine born-digital figure page with a chart in the body and caption text at
  top/bottom typically reaches 0.50–0.80 coverage (caption area, header region, and
  surrounding whitespace all reduce image coverage well below 0.90).
- The 0.10 margin (0.98 − 0.90 = 0.08 clearance above) absorbs scanner over-crop and
  image-rect rounding without encroaching on the legitimate figure-page population.
- Over-correcting direction: routing a true born-digital page to OCR is suboptimal but
  recoverable; silently skipping OCR on a real scan is permanent content loss.
  The panel and ticket both endorse over-correction as the safer direction.

## Implementation

Files changed:
- `src/socr/core/born_digital.py`: added `RASTER_DOMINANCE_RATIO` class constant with
  documented basis comment; added `_raster_coverage(page)` static method using
  `page.get_image_info()` bbox data; gated the clean-short-text pass-through branch in
  `_assess_page` with the coverage check.
- `tests/test_born_digital.py`: replaced the former pinned tradeoff assertion with the
  corrected test `test_scan_with_clean_short_ocr_caption_routes_to_ocr` (asserts
  is_born_digital=False + image-dominant note); added guard test
  `test_genuine_born_digital_figure_page_not_image_dominant_remains_born_digital`
  confirming GH-35 win is not regressed.

## Text render-mode discriminator (Tr 3 invisible text) — SKIPPED

The /consilium panel noted that scanner baked-in OCR is often invisible text (render
mode Tr 3), while genuine captions are visible (Tr 0). PyMuPDF's `get_texttrace()` does
expose render mode per span, but the signal is FRAGILE for synthetic test fixtures:
`page.insert_text()` does not set the Tr key explicitly, so render mode reads as 0 for
all synthetic text including our scan fixture. The signal would work on real scanned PDFs
but cannot be validated against the existing fixture suite without significant fixture
complexity. The raster-coverage gate is sufficient to catch the problematic case robustly
and does not require per-span font attribute parsing. The Tr discriminator is omitted.

## Test results

160 tests pass (tests/test_born_digital.py: 7 new GH-35-FU tests included).
Relevant test class: `TestSparseAndFigurePageClassification`.
Key assertions:
- `test_scan_with_clean_short_ocr_caption_routes_to_ocr` — is_born_digital=False,
  native_text="", notes contains "image-dominant".
- `test_genuine_born_digital_figure_page_not_image_dominant_remains_born_digital` —
  is_born_digital=True for page with ~6% raster coverage.
- `test_full_page_figure_with_short_caption_is_born_digital` — prior GH-35 regression
  preserved: large figure + short caption in born-digital PDF still classifies born-digital.

## Residual risk

A born-digital PDF where a large figure occupies >= 90% of the page AND the text layer is
short (e.g. a single caption line) would now be routed to OCR (false negative for
born-digital). This is the safer direction (extra OCR call, not content loss) and the
figure page population in real academic PDFs rarely approaches 90% coverage (the chart
plus its surrounding LaTeX layout — margins, page number, caption area — typically keeps
coverage well below 0.90). No known real-corpus example of this failure mode was
identified at review time. The RASTER_DOMINANCE_RATIO constant can be tuned up if corpus
data shows over-routing.
