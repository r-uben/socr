## GH-658a — packaging + visibility

### What changed

`pyproject.toml`: added an optional extra, `scanned = ["pytesseract>=0.3.10"]`, with a
comment explaining why it is not a core dependency (the tesseract BINARY it drives is a
separate OS-level install; declaring the Python package alone would still leave a bare
`pip install` unwitnessed, and a default install should not carry a transitive OCR
dependency it may never need).

`src/socr/tables/source_evidence.py`: `verify_table_tokens`'s `bundle.no_reading` branch
already knew WHY a scanned-table page has no witness (`WITNESS_PACKAGE_MISSING` vs
`WITNESS_BINARY_MISSING` vs three others), but only logged it at `DEBUG`. Added
`_warn_witness_state_once(state)`, backed by a module-level `_WARNED_WITNESS_STATES` set,
called from that branch — the first occurrence of each distinct state gets a `WARNING`;
every later occurrence in the same process is silent (a 200-page scan with no tesseract
must not repeat the same install instruction 200 times).

### Acceptance criteria

1. Extra declared; core `dependencies` list unaffected —
   `test_scanned_extra_declares_pytesseract`, `test_core_dependencies_do_not_pull_in_pytesseract`.
2. Warning fires once per run, not once per page — `test_missing_package_warns_exactly_once_across_many_pages`
   (5 simulated pages, 1 `WARNING` record).
3. `WITNESS_PACKAGE_MISSING` vs `WITNESS_BINARY_MISSING` produce distinct messages, each
   gets its own first warning — `test_missing_package_and_missing_binary_each_get_their_own_first_warning`.
4. No behaviour change to the fail-closed verdict — `test_the_warning_does_not_change_the_verdict`
   (same bundle, same tokens, before/after the state is marked warned; identical
   `verifiable`/`passed`/`reason`/`cause`).
5. No new magic threshold: none introduced.

## GH-658b — the distrusted-text-layer rescue

### What changed

`src/socr/tables/source_evidence.py`, `verify_scanned_table`: when `native_trusted is
False` (GH-163's classification: a scanned page's OCR-baked text layer exists but is not
trusted) and the pixel-only evidence bundle (`build_scanned_evidence(...,
include_text_layer=False)`) produced NOTHING (`not bundle.has_content_evidence` — no crop
OCR, no full-page OCR, no witness at all), a second, independent, WEAKER gate now runs:
`row_corroboration.corroborate_rows(page.get_text("words"), output_text, None)`. If its
`.clears` is `True`, the page ships — but `content_unverified` is set to a
`header_binding_unverified: ...` message, reusing the exact channel #659 already wired end
to end (`pipeline/agentic.py`'s `SourceEvidenceTableJudge` → `table_label_unverified` on
the output → WARNING status at finalization → `TABLE_DISTRUST_KINDS` →
document-metadata / CLI note). No plumbing outside `source_evidence.py` was touched;
write ownership was `source_evidence.py` + `tests/` only, and the existing #659 channel
already reaches every level GH-658b's criterion 1 requires.

The distrusted layer is never merged into `bundle.numeric`/`bundle.content` — it is read
only inside the new `_corroborate_via_distrusted_layer` helper, passed straight to
`corroborate_rows`, and never assigned back onto the evidence bundle or the shipped text.

### Why `region=None`

`_corroborate_via_distrusted_layer` has no detected-table bbox available at this layer
(this gate runs independently of `locate_tables` scoping used by the manifest-level A1b
winner selection), so it scores against the whole page — the same abstention semantics as
an empty region (`corroborate_rows` never raises; `clears` is `None` when there is nothing
to check).

### A pre-existing guard this deliberately supersedes

`tests/test_gh163_scanned_native_trust.py::TestTheSuspectLayerCannotCorroborate::test_a_table_matching_an_untrusted_layer_is_not_verified_by_it`
(cubic P1 on #512) pinned a hard reject for exactly the fixture #658b's own root cause
targets: a 2-row candidate whose numbers are the untrusted layer's only content, with zero
independent pixel evidence. Running the full suite after implementing #658b's source
change alone (no test edits) produced exactly ONE failure — this test — out of 5399.

This is the ticket's design, not an accidental regression: #658b's own text says "use it
as a corroboration witness ... instead of shipping no witness at all," and criterion 1
spells out the invariant that must hold instead of a bare reject — FLAGGED, never a clean
SUCCESS. Renamed and rewrote the test
(`test_a_table_matching_an_untrusted_layer_ships_flagged_not_a_clean_success`) to assert
the new three-way outcome: `result.passed is True` AND `result.content_unverified` is set
and names `header_binding_unverified`. Also updated the class docstring to record why. The
underlying security property cubic P1 actually cared about — a hallucination that merely
reproduces an untrusted reading must never read downstream as an ordinary, unflagged
SUCCESS — still holds; only the shape of "does not pass silently" changed from "hard
reject" to "flagged accept," per this ticket's explicit design. Flagged to the
orchestrator for scrutiny rather than treated as routine.

### Acceptance criteria

1. **Ships FLAGGED, never silent.** `test_the_rescue_is_flagged_not_a_clean_success` and
   the rewritten GH-163 test above both assert `content_unverified` is set and names
   `header_binding_unverified` on the rescued result.
2. **Corroboration only, never merged into shipped text or promoted to trusted content.**
   `test_the_shipped_text_is_the_candidates_own_unmodified_text` (candidate markdown
   unchanged after the call); structurally, `_corroborate_via_distrusted_layer` never
   writes into `bundle` or returns anything containing the layer's own text.
3. **A page with no text layer at all still fails closed exactly as today.**
   `test_a_page_with_no_text_layer_still_fails_closed` — a blank fitz page + empty pixel
   witness still rejects, `content_unverified` empty. (Falls out of `corroborate_rows`
   abstaining — `clears is None` — on zero native words; no special-casing needed.)
4. **A candidate that genuinely disagrees with the distrusted layer must still be
   rejected.** `test_a_disagreeing_candidate_is_still_rejected` and
   `test_disagreement_still_fails_closed_identically_to_the_no_rescue_path` — a distrusted
   layer carrying none of the candidate's numbers does not rescue it.
5. **No new magic threshold.** `corroborate_rows`'s existing `ROW_CORROBORATION_MIN`
   (36/39), `EXTRA_NUMBERS_MAX_SHARE` (0.02) and `SKIPPED_ROWS_MAX` (0) are reused
   unmodified; nothing new was added to `row_corroboration.py`.
