# #1100: blank pages never reach a model

## Defect

Dougherty 2013 p3 and Levy 2016 p30 have no text and no ink. The agentic loop
sent them to `route_page`; the vision model invented a brochure / table. They
are 2 of the 181 pages that then failed the scanned-table check (corpus run
22922695).

## Rule (no new magic number)

A page is blank iff it has no native words and a **colour** render at
`DETECT_DPI` (the raster `tables.image_locate` already uses to find ink)
has no channel below 255. Greyscale is not used: RGB `(255, 255, 250)`
collapses to 255 in grey and is still ink. A single faint mark is ink.
Transparency composites onto white; unpainted stays white.

Dougherty p3 has one drawing — a white fill
`Rect(77.7, 82.8, 374.7, 559.3)` — and `dark_px = 0`. Drawings/images are
therefore not ink by themselves; the render is.

Marker: `[socr: blank page]` via `socr_marker`. House style
(`SOCR_MARKER_RE`), not a `[page N failed: …]` marker, so the page ships
`SUCCESS` / `engine=blank` / `failure_mode=none` and is skipped on resume.

## Surfaces

- Page: sidecar `engine=blank`, status `success`, audit `blank_page`
  (in `resume_restore_kinds`; a resumed run replays it).
- Document: `metadata.json` `blank_pages: [N]` lists only pages whose
  **shipped text** is `[socr: blank page]`, not detection-time `is_blank`
  (a blank page past a cascade halt ships a failure marker). Document
  status is not demoted.
- CLI: cyan line, same family as chart-asset visual-values notes.
- Assemble: `blank_page_retained`.
