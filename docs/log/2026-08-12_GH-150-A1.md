# 2026-08-12 — GH-150 TICKET-A1: accept framed thin-stroke clusters as chart marks

## Decision

Frame-plus-interior: a new detector-only helper, `_has_framed_data_cluster`, is
OR'd into the existing positive-signal gate inside `has_chart_marks`. It does
not modify `_has_vector_data_marks` — the two run side by side and either can
admit a cluster. This follows the accept-with-amendments ruling.

## Deviation from TICKETS.md A1

The ticket's parenthetical said to derive the qualifying condition "from the
cluster (count and bbox area relative to the page)". The implemented condition
is cluster-derived instead: frame coverage of the cluster bbox plus an
interior-mark count, not a page-area-relative rule. 972-page sampling during
design showed count/page-area rules cannot separate charts (n = 118-994
drawings observed) from table ruling (n up to 91 observed) — the two
distributions overlap when normalized by page area alone. The page-scale role
stays with the existing `CHART_MIN_CLUSTER_AREA` gate, which continues to
reject small decorative clusters before either positive-signal gate runs.

## `CHART_FRAME_MIN_CLUSTER_COVERAGE = 0.5` derivation

Two measured populations on real corpus pages:

- **Plot frames** cover 0.85-0.99 of their cluster's bbox area. Heston p10
  (page index 9): a 932-drawing cluster whose single largest mark covers 0.876
  of the cluster area, with 928 marks interior to that frame.
  `_has_vector_data_marks` returns False on this cluster (thin, neutral-
  coloured strokes only).
- **Table-ruling clusters**: the largest single mark covers <= 0.06 of its
  cluster area.

0.5 is the definitional bound, not a tuned value between the two populations:
a mark covering half its cluster's bbox area *is* the frame, not a datum. It
sits far from both measured populations (0.06 vs. 0.85-0.99).

## Known recall residual (not fixed here)

Open-axes charts with no enclosing frame rect stay False. Heston p14 has max
single-mark coverage ~0.464; p19 ~0.469 — both below the 0.5 bound. Widening
the gate to catch these was deliberately rejected: it would erode the margin
that currently separates the frame population from the table-ruling
population and risks flipping ruled-table clusters to chart. Left as future
work if a distinct signal for open-axes plots is found.

## Recursion issue — filed separately, not fixed here

`_cluster_drawings`'s union-find `find()` (extractor.py:672-675) is recursive
path compression; it hits `RecursionError` on deep union chains beyond
~1000 same-cluster drawings. Heston p10 has 932, close to the observed limit.
`_is_chart_asset_page`'s blanket `except Exception` (pipeline/orchestrator.py)
would silently convert that into a False, misrouting a chart page. Filed as a
separate GitHub issue; not in scope for A1 (see `mustNotDo`).

## Helpers intentionally untouched

- `_has_vector_data_marks` (extractor.py) — unmodified signature and body.
  Widening it would also change `_looks_like_table_grid`'s first-line
  short-circuit (`if has_data_marks: return False`, extractor.py ~832), which
  would start emitting ruled-table regions as figures — invisible to A1's
  Done-when and out of scope.
- `_looks_like_table_grid` — unmodified; still not called from

- `_has_filled_rects_or_thick_strokes` (tables/reconstruct.py) — docstring
  updated only (no longer claims to "mirror" `_has_vector_data_marks`; notes
  it does not implement the new framed-cluster gate). No body change.

## Review amendment (same day): structural guards on the frame gate

Post-review hardening of `_has_framed_data_cluster` (review of PR #182 +
Codex second opinion), three defects fixed without new tuned thresholds:

1. **Frame must be structurally a frame.** The original gate accepted any
   drawing whose *bounding box* covered >= 0.5 of the cluster — a large
   polyline, curve, or diagonal decoration could masquerade as a frame. Frame
   candidates now must consist entirely of axis-aligned strokes (`re` items
   and horizontal/vertical `l` segments, tolerance `AXIS_LINE_TOLERANCE_PT`,
   same 1pt convention as `_looks_like_table_grid`). Probing Heston p10 showed
   the real frame is NOT a single `re` primitive (its `re` item covers only
   0.001 of the cluster): it is an axis-aligned line path with tick marks —
   so the guard keys on stroke orientation, not on rect primitives. (A
   stricter require-`re` variant was tried first and regressed the motivating
   page to False.)
2. **Frame-sized drawings are not data.** Any drawing covering >= the same
   0.5 definitional bound is excluded from the interior-mark count ("a mark
   covering half its cluster IS the frame, not a datum"). This stops a
   duplicate frame copy (fill + stroke emitted as two drawings) from counting
   itself toward `MIN_DRAWINGS_FOR_VECTOR`.
3. **No wasted work.** `_has_framed_data_cluster` now runs only when
   `_has_vector_data_marks` failed, and the interior count early-breaks at
   `MIN_DRAWINGS_FOR_VECTOR` (the motivating cluster previously counted all
   ~931 interiors). The `gate_name` label is two-way accordingly.

Residual accepted false-positive class (documented, not guarded): a bordered
non-chart region whose interior contains >= 5 genuine vector drawings (e.g. a
form with ruled fields). Plain text sidebars/callouts do NOT qualify — text
is not drawings, so a border alone contributes no interior marks. Cost is
bounded: the chart lane retains native page text; a false positive costs a
spurious full-page PNG + audit flag.
