# GH-700 — column-aware banding for the scanned-prose floor (design)

Date: 2026-09-16. Branch: `docs/700-column-aware-banding`. Design only — no `src/` change.

Every behavioural claim below was executed against this worktree with
`PYTHONPATH=/tmp/socr-700-design/src` and a `socr.__file__` canary asserting the import
resolved inside the worktree, not the editable install.

## 1. What exists today

### 1.1 The defect site

The y-only banding GH-700 describes is **`cluster_band_words`**,
`src/socr/tables/row_corroboration.py:266`. It clusters every word on the page by y-centre,
with a tolerance derived from the region's own median word height
(`_ROW_BAND_TOLERANCE_FRACTION`, `src/socr/tables/row_corroboration.py:129`). It never looks
at x except to order words inside a band (`src/socr/tables/row_corroboration.py:307`).

Three readers sit on it, and only one is GH-700's:

| reader | site | population | in GH-700's lane? |
| --- | --- | --- | --- |
| `partition_prose_bands` | `row_corroboration.py:364` | whole page, no bbox | **yes — this is the defect site** |
| `baseline_bands` | `row_corroboration.py:298` | region-scoped (table bbox) | no |
| `native_region_text` | `manifest.py:2270` | the prose words that ship | yes, indirectly (see §3.3) |

The shipping path is `native_prose_floor_text` (`src/socr/core/manifest.py:2504`) →
`_page_prose_partition` (`src/socr/core/manifest.py:2288`) → `partition_prose_bands`. The
withhold predicate is per-word `bears_printed_numeral`
(`src/socr/tables/row_corroboration.py:335`) counted per band against `row_shape_min`
(default `PROSE_BAND_MAX_NUMERIC_TOKENS + 1` = 1, `row_corroboration.py:362`). The marker is
stamped once per contiguous withheld run in the emission loop,
`src/socr/core/manifest.py:2612-2626`.

Measured on the ticket's own two-column fixture (`TestTwoColumnPagesFailSafe._page`,
`tests/test_gh649_scanned_prose_recovery.py:499`):

```
WITHHELD | The committee reviewed the swap arrangements at length Austrian National Bank 250.0
WITHHELD | and authorized their renewal for a further twelve months Bank of England 3000.0
WITHHELD | with no dissenting votes recorded in the minutes today Bank of France 2000.0
```

Three bands, all withheld, left-column prose lost. That is exactly the issue.

### 1.2 It is NOT `tables/locate.py`'s `row_bands*`

`locate.py`'s row banding runs over a *located table region*; the GH-700 lane is entered with
`detected_table_count == 0` and no bbox at all (`native_prose_floor_text`'s docstring,
`manifest.py:2506-2513`, and the fixture at `tests/test_gh649_scanned_prose_recovery.py:104`).
With no region there is nothing for `locate.py` to band. The band objects the issue's
behaviour depends on are the ones `partition_prose_bands` returns, and the tests the issue
points at import exactly that function
(`tests/test_gh652_witness_extent_abstention.py:67,94,101`).

### 1.3 What the ticket assumes that is no longer true

The issue says "the same band is also treated as table-attributed by the **corroboration
witness**". That witness was **deleted** in #652 round 10 — `_prose_corroboration_ok`,
`PROSE_CORROBORATION_MIN` and the helpers are gone (PR #695 body; the deletion is recorded in
the test module docstring at `tests/test_gh652_witness_extent_abstention.py:44-52`, which says
the tests now read "the SHIPPING partition ... because the witness these tests once observed
no longer exists"). No model prose ships from this branch at all.

So there is **no second reader to keep consistent** inside GH-700's lane. The remaining
band-reading "witness" is `_table_bbox_sane` (`manifest.py:2179-2192`) via `baseline_bands`,
and it returns `True` before touching bands when there are no bboxes (`manifest.py:2172`) —
which is always the case here. This materially shrinks the Q3 risk the ticket anticipated.

## 2. Q2 — is `_split_two_columns` reusable here? **No.**

`_split_two_columns` (`src/socr/core/born_digital.py:690`) over `_cluster_two_bands`
(`born_digital.py:654`) answers **"given that this is two columns, which column is this line
in"**. It does not answer **"is this page two columns"**, and GH-700 needs the second question
first. Measured, on per-line items:

| input | `_split_two_columns` returns |
| --- | --- |
| uniform single column (every `x0` equal) | `None` |
| single column with **indented paragraph openers** | a 2-way split (`[body lines], [indents]`) |
| single column with a **centred heading** | a 2-way split (`[body], [HEADING]`) |
| single column with a **bulleted list** | a 2-way split (`[paragraphs], [bullets]`) |
| two columns + a **full-width caption** | caption silently assigned to the left column |
| **three** columns | forced 2-way: col 0 left, cols 1+2 merged right |

Its `None` means only "fewer than two `x0` groups exist", not "this page is not two-column".
Every single-column page that indents a paragraph would be split. That is safe in its own
caller because `_try_aligned_run` applies four further guards on top of the partition
(`born_digital.py:959`, and `LABEL_COLUMN_WIDTH_SHARE` at `born_digital.py:474` is explicitly
"the discriminator that actually protects genuine two-column prose from a false merge; the gap
threshold alone is not sufficient"). Those guards are roster-specific (a label column is much
narrower than its value column) and do not transfer to prose-versus-table.

Second, structural mismatch: `_split_two_columns` takes **line** dicts (`x0`/`x1`/`text`). The
floor path has **words**, and lines only come into existence *after* banding. Feeding it words
gives nonsense — on the two-column fixture it returned left = the 3 words at `x0 == 0.0`, right
= the other 35; on a single-column page it returned 3/8 instead of `None`.

**Verdict: do not reuse it.** GH-700 needs a gutter detector over words, which is a different
primitive. Nothing stops both from existing; `_split_two_columns` should keep its roster job.

## 3. Q3 — what splitting does to the guarantee

### 3.1 The numeral guarantee survives, by construction

`bears_printed_numeral` is evaluated **per word** (`manifest` never re-tokenises; the count is
`sum(... for word in band)`, `row_corroboration.py:377`). If a split is a *partition of the same
word set* — no word dropped, none duplicated, none rewritten — then every digit-bearing word
lands in exactly one segment, that segment's count is ≥ 1, and that segment is withheld.
A split can only make a band smaller, and a smaller band cannot acquire a numeral it did not
have. **No printed numeral can reach the page as a consequence of splitting.** This is the
invariant to assert directly in the implementation (`set(words) == union of segments`), not to
argue from fixtures.

### 3.2 Marker placement is where the risk actually is

Today the marker means "content was elided *here*, in page y-order". Splitting forces a choice
of emission order, and this is the real fork:

* **y-major interleaved** (each band emits left segment then right segment, in place): a strict
  *refinement* of today's order — no content moves relative to anything it does not now follow.
  Cost: a right-column table row is separated from the next one by a left-column prose line, so
  each becomes its own contiguous withheld run and gets **its own marker**. A 40-row table
  beside prose yields 40 markers. Prose paragraphs are also broken into one-line blocks.
* **column-major** (all left bands, then all right): one clean left paragraph, one marker.
  Cost: it **reorders the page**. If the gutter detection is wrong, column-major moves content
  across the document; no numeral leaks, but the prose the lane exists to save is scrambled —
  a silent, content-preserving corruption that the numeral guarantee does not cover.

### 3.3 One consistency obligation that is easy to miss

`native_region_text` (`manifest.py:2270`) reconstructs the text handed to `text_layer_trusted`
(`manifest.py:2567`) and reuses `cluster_band_words` *explicitly* "so this reconstruction and
the prose/table partition can never disagree about where a line begins"
(`manifest.py:2275-2277`). On a two-column page today it joins the left prose and the right
table row into **one line**, and that mangled line is what the corruption detector scores. Any
column-aware change must feed `text_layer_trusted` the *same* segmentation, or the trusted-layer
verdict silently changes for a different reason than the one being fixed — a page can flip
between shipping and abstaining. Both must move together.

### 3.4 What must NOT be touched

`cluster_band_words` itself must stay y-only. Making *it* column-aware changes `baseline_bands`,
which is the row-corroboration witness (`row_corroboration.py:673`) and `_table_bbox_sane`'s
prose-vs-numeric band count (`manifest.py:2185-2192`) — i.e. the D3 floor's sanity verdict for
every page in the corpus that *does* have a bbox, a population that has nothing to do with
GH-700. Scope the change to `partition_prose_bands` (+ `native_region_text`, §3.3).

## 4. Q4 — blast radius (measured, not estimated)

Two test sites state the limitation:

* `tests/test_gh649_scanned_prose_recovery.py:475` — `class TestTwoColumnPagesFailSafe`, with
  `test_no_printed_value_reaches_the_page` (:513) and
  `test_a_shared_band_cannot_vouch_for_a_fabrication` (:519);
* `tests/test_gh652_witness_extent_abstention.py:235` — `test_two_column_shared_digits_withheld`,
  which imports #649's fixture class and re-ships it.

**They pin the CONSEQUENCE-guarantee, not the mechanism, and not the loss.** Their assertions
are: the three amounts are absent, `MARKER` is present, and the fabricated phrase is absent.
**No assertion anywhere asserts that the left-column prose is withheld.** The limitation lives
only in prose — the class docstring (`test_gh649_scanned_prose_recovery.py:476-487`) and the
one-line docstring at `test_gh652_witness_extent_abstention.py:236`.

Measured: with `manifest._page_prose_partition` monkeypatched to a column-aware partition
(gate of §5, option A), `tests/test_gh649_scanned_prose_recovery.py` +
`tests/test_gh652_witness_extent_abstention.py` run **68 passed, 0 failed, unchanged**, and the
two-column page then ships:

```
[page 1: unverified scan — the paragraphs below are this page's own text layer; every numeric row is withheld]

The committee reviewed the swap arrangements at length

[page 1 failed: unverifiable table — see image]

and authorized their renewal ... (etc., one marker between each)
```

So the ticket's "the current tests assert the opposite and should be updated in the same commit"
is **half right**: the docstrings must be rewritten, and a positive pin added that the left
prose ships. Nothing needs deleting, and no expectation needs flipping. That is a much smaller
and much less delicate change than the ticket implies.

(Unverified: `tests/pipeline/test_page_failed_marker_scope.py` pins the **real** Fed
1989-11-14 p3 and only runs on a machine holding the corpus. PR #695 claims that page ships
`PageOutput` byte-identical across its rounds. I could not run it here. Any implementation must
run it before merge — see §5, risk row for option B.)

## 5. Q5 + the options — what gates the split

The whole design reduces to one question: **what evidence says a page has a column gutter?**
`_split_two_columns` cannot answer it (§2). A gutter rule must be derived, not invented; this
repo already owns the relevant measurement.

`ALIGNED_RUN_GAP_MAX_WORD_SPACES = 2.0` (`src/socr/core/born_digital.py:471`) is documented at
`born_digital.py:455-470` as a **measured** boundary: on three real two-column papers
(Fama-French 1997, Morris-Shin 1998, Grossman-Stiglitz 1980) the narrowest column gutter is
**2.30 word spaces**, versus 0.92–1.76 for an intra-row label seam. Used in the opposite
direction — "a gap wider than this many word spaces is a column gutter, not a word space" — it
is a reuse of an existing measurement, not a new constant. The word-space yardstick itself is
the page's own (`_median_word_space_width`, `born_digital.py:573`; for band-local use compute
the median over the bands' own inter-word gaps, since `w[5]/w[6]` block/line ids are absent on
this population).

### Option A — strict gutter: **every** band must cross the same wide gap

Split only when one x-interval is (a) wider than `ALIGNED_RUN_GAP_MAX_WORD_SPACES` × the page's
own median word gap and (b) crossed by *no word in any band*. Any full-width line kills it.

Measured behaviour of a prototype of exactly this rule:

| page shape | gutter found |
| --- | --- |
| prose only (single column) | `None` → byte-identical to today |
| table + one full-width prose line | `None` → byte-identical |
| two columns + a spanning caption | `None` → byte-identical |
| **two columns, no spanning line** | found → left prose ships, every amount withheld |
| table only (labels left, amounts right) | **found** → row labels ship as prose |
| three columns | found → cols 1+2 merged into "right" |

* Determinism/replay: pure geometry on the page's own words. No model. Resume-safe (the input
  is `native_words`, already the lane's input).
* Silent-loss risk: none by §3.1; content is preserved, only grouping changes.
* Cost: **often inert**. A running header, a page number, a title or any full-width paragraph
  line disables it — which on real two-column documents is most pages. It buys the guarantee
  cheaply and may buy very little text.
* Note the "table only" row: even under the strict rule, a scanned page that is *nothing but* a
  two-column table now ships its row labels as prose beside the marker. `partition_prose_bands`'
  docstring already rules that acceptable for wrapped labels ("Shipping a bare label is the
  cheaper error", `row_corroboration.py:386-394`), but it is a widening of what ships.

### Option B — gutter runs: split within maximal runs of consecutive bands sharing a gutter

Bands that span the gutter act as separators and stay whole. Zero extra constants (a maximal
run is defined by construction).

* Recovers text on the realistic two-column page that has a title or a caption — i.e. it is
  the option that actually fixes GH-700 in the field.
* Cost: the "table only" result above proves a table's own label→amount seam *is* such a run,
  so on any page with a table, the table's stub column starts shipping as prose. That is the
  ruling from #652 round 8 walking back in: *band-gap geometry says where a block breaks and
  can never say what a block is* (`tests/test_gh652_witness_extent_abstention.py:28-33`).
* Highest risk of changing the real Fed fixture's bytes (§4 caveat).

### Option C — close GH-700 as won't-fix, pending #707

The loss is bounded, marked, and in the safe direction. **How often a real two-column scan
reaches this lane is unmeasured** — PR #695's only measured page (Fed 1989-11-14 p3) is single
column, and #707 is the open ticket that measures native-fallback fidelity across all scanned
Fed pages. Fixing an unmeasured loss with a geometric rule that #652 round 8 ruled against is
how the seven rejected admission rules happened.

## 6. Recommendation

**The gutter gate is settled by evidence: option A's rule (word-space-derived width + crossed by
no word in any band), scoped to `partition_prose_bands` and `native_region_text`, not to
`cluster_band_words`.** It is the only variant measured to leave single-column pages
byte-identical, it reuses an existing measurement rather than inventing a threshold, and it
passes all 68 existing assertions unchanged.

**What is a genuine fork, and what the panel should decide, is the emission order** (§3.2) —
because that is where the guarantee "every withheld run keeps its own marker at the point of
elision" either survives verbatim or gets traded for readability. I have a lean (y-major
interleaved: it cannot reorder content, and marker noise is honest about where elisions are)
but the cost — a 40-row table producing 40 markers and a paragraph shattered into one-line
blocks — is severe enough that I will not settle it alone.

Secondary question the panel can settle in the same breath if it wants: A versus B. I lean A
on the strength of #652 round 8; B is the only one that helps a real corpus page.

## 7. The consilium question (paste verbatim)

> On a scanned PDF page that reached a fail-closed floor, socr publishes the page's own native
> text layer as prose while withholding every printed numeral: words are clustered into
> horizontal baseline bands by y across the full page width, a band containing any digit-bearing
> word is withheld, and ONE marker ("[page N failed: unverifiable table — see image]") is stamped
> per contiguous run of withheld bands, at the point of elision. On a TWO-COLUMN page a left-column
> prose line shares a y-band with a right-column table row, so the prose is withheld with the
> digits — no leak, but real content loss. We will split bands at a detected column gutter. Since
> a split band yields a prose segment and a numeric segment at the same y, the emission order must
> be chosen. Which order should the publisher use?
>
> (A) **y-major interleaved** — for each band, emit its left segment then its right segment, in
> place. Strictly refines today's order, so no content can move relative to content it currently
> follows. Cost: each right-column table row is now separated from the next by a left-column prose
> line, so each becomes its own contiguous withheld run and gets its own marker (a 40-row table
> beside prose ⇒ 40 markers), and the left paragraph is emitted as one-line blocks between them.
>
> (B) **column-major** — emit every left-column band top-to-bottom, then every right-column band,
> with one marker for the right column's withheld run. Produces a clean paragraph and a single
> marker. Cost: it reorders the page, so if gutter detection is wrong (e.g. it fires on a table's
> own label→amount seam) content is moved across the document — no numeral leaks, but the prose
> this feature exists to save is silently scrambled.
>
> (C) **y-major interleaved, with markers coalesced per column lane** — keep (A)'s order but treat
> "contiguous withheld run" as per-column, so the right column's consecutive rows share one marker
> whose position in the stream is where that lane's run begins. Fewer markers, no reordering. Cost:
> the marker no longer sits at an unambiguous single point of elision in the linear output.
>
> The invariant that must not weaken: no band segment carrying a printed digit ships, and every
> withheld run stays visible where it was elided. Which option, and why?

## 8. Acceptance-criteria readiness

The ticket's "Done when" list:

1. *"Bands are separated by column before the prose/table split"* — implementable once §7 is
   decided. Tighten: name the site (`partition_prose_bands`, not `cluster_band_words`) and add
   the §3.3 obligation that `native_region_text` uses the same segmentation.
2. *"no band carrying a printed numeral ships, and every withheld run keeps its own marker at
   the point of elision"* — the first half is implementable and provable as a set invariant
   (§3.1). **The second half is exactly what §7 decides** and cannot be accepted as written
   until it is; under (B) or (C) "its own marker at the point of elision" changes meaning.
3. *"Pinned by a two-column fixture where the left prose ships and the right table stays
   withheld — the current tests assert the opposite and should be updated to the new expectation
   in the same commit"* — **needs correcting**: no existing assertion asserts the opposite (§4).
   The fixture already exists (`TestTwoColumnPagesFailSafe`); what is needed is a new positive
   assertion plus a docstring rewrite at two sites. Add two criteria the ticket is missing:
   * a **single-column byte-identity** pin — run the same page through the lane with the gutter
     gate on and off in one process and assert the bytes are identical (difference-pin, per
     CLAUDE.md, not a pinned tuple);
   * run `tests/pipeline/test_page_failed_marker_scope.py` on a corpus machine and confirm the
     **real** Fed 1989-11-14 p3 still ships byte-identical, since §5's "table only" result shows
     a real page's label→amount seam can be a gutter.
