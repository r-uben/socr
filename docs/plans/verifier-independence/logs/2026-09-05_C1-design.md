Everything is computed inside `region = witness.box.bbox` — the same `locate.TableBox`
that `orchestrator.py:4669` already hands `bind(words, markdown, region=…)`. Symbols used
from `locate.py`: `locate_tables` (`:61`), `TableBox` (`:45`), `_horizontal_rules` (`:169`),
`bands_from_rules` (`:122`) unchanged.

**Row bands.** A *row band* is a set of PDF text lines (`page.get_text("dict")` → block →
line) inside `region` whose baselines (`span["origin"][1]`) differ by less than the smaller
of their font sizes (`span["size"]`). One printed row = one band. The separator is derived
from the page's own type size, not tuned: every prediction in (d) is identical at 0.5 em and
1.0 em. Where per-row rules exist, `row_bands_from_rules` supplies the band edges instead.

**Column edge.** Sort each band's lines by `x0`. Let `R₀ = min` over all *non-leftmost*
lines of their `x0` — the leftmost point at which any row's second cell begins. Then shrink
to a whitespace edge: while some line has `x0 < R < x1`, set `R = min` of those `x0`. The
**label column** is `[region.x0, R]`. Fixed point in ≤2 passes on every corpus page.

**Ordinal origin.** Ordinals are counted from an origin neither lane supplies: the
**header rule**. Cluster the region's horizontal rules by y (rules closer than a rule
thickness are one drawn border, e.g. booktabs' `\toprule` pair); the origin is the y of the
**second** rule group. Measured: doc01 116.3, doc02 p3/p4 123.9, doc03 241.5, doc05/doc07
121.0; doc04 (scanned, no vector rules) has **no origin ⇒ every item on it abstains**.
Row band *k* is the (k+1)-th line band whose baseline is below the origin; native row *k* is
the (k+1)-th entry of `_native_rows`; model row *k* is the (k+1)-th data row of
`parse_grid`'s candidate grid (both already exclude their own headers).

**Cell correspondence (the ordinal chain).** A disputed item at native row *i*, bound by
`_bind_rows` to model row *j*, is *geometry-addressed* iff **all** hold:

1. an origin exists, `R` exists, and `R > region.x0`;
2. **native ↔ geometry, counted from the origin:** native rows `0…i` occupy bands `0…b`
   one-for-one, in order, with no band skipped and no band claimed twice — so *i = b*, and
   the disputed row is the *i*-th printed row on all counts. Every native row's band is
   taken from its own words (`label_bbox`, else its `lane_bboxes`), so a native row that
   dropped its label still contributes its ordinal;
3. **model ↔ geometry, counted from the same origin:** model rows `0…j` are each bound, and
   each one's native partner sits on the band of the same index — so *j = b* too, and
   `i = j = b`. Order-preservation alone is **not** enough: a mapping shifted by one whole
   row (`j → i = j+1`) is order-preserving, and would let the candidate be examined one row
   away from the row it actually claims;
4. **column:** band *b*'s leftmost line lies entirely left of `R`, and its second line, if
   any, starts at or after `R`.

The address is `(region.x0, band_b.y0, R, band_b.y1)`. The native `native_bbox` is **not**
used to locate anything; it stays on the item for audit only.

**Why this closes both holes.** *Native side:* bands are contiguous by construction, so a
printed row the native rowizer dropped shows up as a band with no native row and condition 2
fails there — the chain from the origin breaks and everything below abstains; a native row
that merged two printed rows makes two native rows claim one band and fails the same way.
*Model side:* a row the candidate inserts (or drops) above the disputed one leaves a model
row with no band of its own index, so condition 3 fails even though the mapping never
crosses. The item's band index is *counted from the header rule* on both sides; neither lane
can nominate it.

**Cost, stated plainly:** conditions 2–3 abstain wherever either lane's row segmentation
disagrees with the printed rows. Where that is the native rowizer, A2's repair usually removes
the contradiction outright rather than making it addressable (see (d)'s remaining-set count);
where it is the candidate — doc02 p4's model emits an **empty spacer row** for the visual gap
between the two blocks — nothing in stream A or C removes it, and any item below it abstains
permanently under this rule. **The dependency on A2 is a feature**: the verifier declines to
speak until the free lane can count the rows. The candidate-side cost is a genuine loss and is
called out in (f).

**What "one line = one cell" does and does not establish** (Astra's point). Conditions 2–4
establish that the addressed rectangle contains exactly one *reported* text-line box and no
part of any other line's box in that band, and that the whole disputed label is inside it by
construction. They do **not** establish that a PDF line is a logical cell. Both ways that can
fail are detected rather than silently over-captured: a line spanning several cells straddles
`R` (condition 4 abstains — this is doc03 and doc04), and a cell split across lines puts a
second line inside the column (condition 4 abstains). The residual, unclosed risk is glyph
ink drawn outside its reported box; the word "provably" from revision 1 is withdrawn.

**New helpers for C2a** (`locate.py`, pure, no binder/candidate input):

def row_bands_from_rules(rules, region) -> list[RowBand]

def ordinal_origin(page, region) -> float | None      # the header rule's y

The ordinal chain (conditions 2–3) is assembled at the orchestrator seam, which is the only
place that holds `native_rows`, the binding and the geometry at once.

**Crop padding.** `_render_adjudication_crop` (`:5634`) pads by `CROP_PADDING_PT = 6`;
clearance to the next cell is 0.2 pt on doc05. A geometry-addressed crop must be rendered
with x-padding clamped to the address and y-padding clamped to half the gap to the adjacent
band. Padding a geometry cell re-imports the over-capture hole.

## (b) Abstain rule

Nothing ever falls back to `native_bbox` or to the candidate's structure.

| table | ordinal chain (cond. 2–3) | column (cond. 4) | outcome |
|---|---|---|---|
| ruled (per-row rules) | intact to the item | `R` found | **geometry-addressed** (bands from rules) |
| ruled | intact | none / straddled | **abstained** |
| ruled | broken above the item (native dropped a row) | any | **abstained** |
| ruled | broken (two native rows on one band) | any | **abstained** |
| ruled | model row above the item unbound, or on a band of another index | any | **abstained** |
| ruled | binding not order-preserving | any | **abstained** |
| booktabs | intact to the item | `R` found | **geometry-addressed** (bands from lines) |
| booktabs | intact | none / straddled | **abstained** |
| booktabs | broken above the item | any | **abstained** |
| booktabs | broken (row merge / split) | any | **abstained** |
| booktabs | model chain broken (inserted/dropped candidate row above the item) | any | **abstained** |
| any | no header rule ⇒ no ordinal origin | any | **abstained** |
| any | native row's own words give no unique band | any | **abstained** |
| scanned / no text layer | none | none | **abstained** |

`_disprove_one` returns `None` with `disproof = "abstained"` — held, reason recorded, and the
transcriber is **not called**. `encoding_garbage` still short-circuits before any address.

**The origin-relative indexing an implementer must code.** All three ordinals are counted
from the header rule, and every element consumes an index — nothing is skipped:

- **band index `b`** — group the region's text lines into bands, drop the bands whose
  baseline is at or above the origin, index the rest from 0 downward. A band with no native
  row still consumes an index; that is how a dropped row becomes visible.
- **native index `i`** — `_native_rows` already excludes the bands it classified as header
  (`header_band_idxs`), so index 0 is `native_rows[0]`. Value-less parent/panel rows are
  retained by design and consume an index. Failure mode to watch: when native does *not*
  recognise a header band (doc01's rows 0–2 `Indicator and` / `` / `instruments`), those rows
  consume native indices 0–2 while sitting *above* the origin, so they have no band at all and
  the chain breaks immediately.
- **model index `j`** — `parse_grid(markdown).rows`; the markdown header row above the `---`
  separator is already excluded. Every remaining row consumes an index, **including
  value-less ones** — this is doc02 p4's spacer `M[14] = ('', '', '', '')`.

"Raw equality" means comparing those three list indices directly, with no prefix check.

| rule | addressed |
|---|---|
| raw index equality `i == j == b` (plus the column test) | 3/22 |
| native chain + order-preserving binding (rev 2) | 7/22 |
| **(a) as specified — native chain + model chain, both from the origin (rev 3)** | **3/22** |
| neighbour-only adjacency instead of the chain from the origin | 13/22 |

**Correction to rev 3:** that table previously read "literal raw-index equality → 0/22". That
was asserted, not measured, and it is wrong — doc05's three items satisfy raw equality
exactly, with triples `(i, j, b) = (4, 4, 4)`, `(6, 6, 6)`, `(8, 8, 8)`. On this corpus raw
equality and the origin-relative chain select **the same three items**; the counts do not
separate them.

The chain is still the rule to implement, because the guarantee differs where the count does
not. Raw equality is satisfied by any pair of compensating errors — native drops a row above
the item *and* the candidate inserts one — since both indices shift and re-align; the chain
checks every prefix element and catches either error alone and the pair. Rev 2's
order-preserving-only condition admits the shifted mapping outright and is rejected;
neighbour-only adjacency is rejected because a break further up the table leaves the local
neighbourhood consistent.
