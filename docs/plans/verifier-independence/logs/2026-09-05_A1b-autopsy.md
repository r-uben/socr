**Hypothesis answered:** yes. On every one of the 8 target items the native rowizer dropped

reading the native crop agrees with neither side, so `_disprove_one` returns `None`.

## The four disproofs are not the mechanism working — they are the failure's mirror image

- **doc01 `YR, GSS` → `2 YR, GSS`** (the corpus's *only* lifted table): the dropped `2`
  falls inside the 6 pt padding. Run 2's one lift is a padding accident.
- **doc05/doc07 `Sample …`, `Policy surprise …`**: the native label is *over-wide* (the
  row's non-numeric cells were absorbed into it), so the crop contains the model's token and
  the disproof fires.

Truncation never recovers; over-capture and padding luck sometimes do. That asymmetry is
the fact C1 has to design around: a crop addressed by the native box can only correct
native errors that made the box too big, never too small.
