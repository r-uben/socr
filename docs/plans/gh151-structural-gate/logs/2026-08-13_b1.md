# 2026-08-13 — GH-151 TICKET-B1 implementer note

Shipped the structural gate exactly as settled in the rewritten ticket block and
`docs/log/2026-08-13_gh151-b1-design.md`. Summary of what landed:

## Gate predicate

- `check_grid` fires `FINDING_DETACHED_LABEL` on a row-pair adjacency invariant only:
  body row `i` label-only + body row `i+1` values-only. The single exclusion is a
  pair-local canonical `(1)…(k)` column-number band on the follower (group heading
  above a numbered-column band is legitimate, not a split row). No numeric threshold,
  no third-row / modal signature.
- The page-level flag (`native_table_structure_defective`, on `PageAssessment` /
  `PageState`) is set iff any table block's `check_markdown` report has `ragged` OR
  `detached_label_rows`. `orphan_rows` alone is diagnostic-only and never gates —
  it fires on 27/29 real table blocks unnarrowed.
- `GridStructureReport.defective` (the OR of all three findings) is never consulted
  by the gate.

## Wiring

- Stamped once, at extraction time, in `born_digital._assess_page_signals`'s
  non-rotated `has_tables` branch only. Never re-derived downstream — `_phase_analyze`'s
  new `table_structure_failed` `AuditEvent` loop and every ship-site check key solely
  off the flag.
- A NEW `PageState` field, deliberately separate from `native_table_structure_failed`:
  that flag is cleared by `_score_per_page` on a passing heuristic score, which would
  silently erase this structural verdict if they shared a field.
- Deliberately **absent** from `PageState.needs_repair` (both the deficiency-entry
  condition and the audit-rejection clause) — adding it there would force an OCR
  repair pass and override `--native-only`, which is settled as forbidden.
- No `needs_ocr_enhancement`, no routing lever, no extra provider/OCR call anywhere.
- Attempt demotion (WARNING / `audit_passed=False` / `FailureMode.NATIVE_TABLE_STRUCTURE_FAILED`)
  at both ship sites: `_backbone_native_first`'s prose-pages loop and `_phase_agentic`'s
  native pin.
- `_score_per_page`'s native branch short-circuits BEFORE the heuristic scorer when the
  flag is set: forces the demotion, clears `best_output` if it was the demoted attempt,
  and `continue`s — the heuristic scorer (which is exactly what missed p26) never runs
  on a flagged attempt and cannot re-promote it.
- Persistence: sidecar write/restore, `_clear_fail_closed_flags` (only a measured
  improvement releases it), `_phase_assemble`'s `native_fallback_pages` OR (drives
  document `AUDIT_FAILED` + the existing yellow CLI line + the existing `native_fallback`
  event — no new surface needed there).
- `manifest._winning_page_output`: two locks — refuse to freeze a passing NATIVE
  `best_output` that carries the flag (a passing non-native winner is unaffected and
  still returns immediately); OR the flag into the `native_is_fallback` disjunction so
  a flagged native ships WARNING. This is the PP-7-R1 bug shape the ticket warned about:
  a flag the manifest doesn't read re-stamps `audit_passed=True` and makes the whole
  gate inert.

## Review round 2 (same day, PR #200)

Two BLOCKING findings on `2455279`, plus an investigate-and-report on a suspected
pre-existing double-count.

**BLOCKING 1 — the SE negative control did not pin the gate.** It asserted only
`report.detached_label_rows == ()`, which stays true even if the gate were widened to
include `orphan_rows` (the SE fixture's own blank-label-with-values row IS an orphan row).
Fixed by extracting the gate predicate itself into a new, shared function,
`structure_check.structural_gate_fires(reports)` (`ragged or detached_label_rows`, never
`orphan_rows`, never `.defective`), and switching `born_digital.py` to call it instead of
duplicating the boolean inline. Every negative control (SE-continuation, both group-heading
shapes) now asserts against this shared function, so the test and the production branch
provably share code rather than a hand-copied lookalike. Added
`test_se_control_is_load_bearing_against_a_widened_gate`, which shows the SE grid's
`orphan_rows` finding DOES fire, so a gate that included it would trip on this exact
fixture. **Load-bearing proof:** temporarily widened `structural_gate_fires` to
`ragged or orphan_rows or detached_label_rows` in the source tree and reran
`test_se_tstat_continuation_row_does_not_fire` — it failed
(`AssertionError: assert not True`) — then reverted (`git diff` showed zero residual change).

**BLOCKING 2 — `table_structure_failed` missing from `TABLE_DISTRUST_KINDS`.** Added it
with a comment explaining the omission and, following the same GH-96/`table_escalation_accepted`
pattern, explicitly recorded why no resolving kind is added alongside it: the event fires at
*analyze* time from the native attempt alone, before OCR routing is decided, and no measured
comparison exists at the point a later OCR read ships instead of the flagged native one. So in
agentic mode a page whose native attempt tripped this gate but whose final shipped output is a
passing OCR table still surfaces in `tables_trust.json` — over-flagging relative to the shipped
content, never under-flagging, consistent with the module's stated bias (a flag on a fine page
costs a look; a missing flag on a wrong number costs the corpus). Not fixed further: inventing a
new "resolved-by-OCR" audit-event kind was judged out of the finding's scope (it asks to add the
kind and report on `RESOLVING_KINDS`, not to design a new resolution mechanism), and no such
measured-comparison event exists anywhere in the pipeline to hook onto. Added
`test_structural_gate_failure_is_a_named_distrust_kind` in `tests/test_gh95_tables_trust.py`.
**Load-bearing proof:** removed the new member from `TABLE_DISTRUST_KINDS` and reran the test —
it failed (the event was silently dropped, `trust.untrusted_pages == []`) — then reverted.

**ALSO — the D3 double-count survives when `needs_ocr_enhancement` is set (confirmed real,
fixed).** Round 1's exclusion (`not (native_table_structure_failed and native_table_unverifiable)`)
lived *inside* the `native_table_structure_failed`/`native_table_structure_defective` disjunct of
`native_fallback_pages`'s OR. `needs_ocr_enhancement` is a separate, earlier disjunct in the same
OR — set independently (corrupt-math pages, rotated-table-refused pages) — so a page that is
BOTH a D3-floor page (`native_table_structure_failed` AND `native_table_unverifiable`) AND has
`needs_ocr_enhancement=True` (e.g. a corrupt-math page whose table region also hard-fails TR-3's
per-region geometry check) satisfied the `needs_ocr_enhancement` disjunct unconditionally and
bypassed the exclusion — double-counted in both `d3_floor_pages` and `native_fallback_pages`.
Fixed by moving the exclusion outside the whole OR so it applies uniformly to every reason a page
enters the list (mirrors `d3_floor_pages`'s own predicate exactly, per the round-1 comment's
stated intent). This bug predates B1 — `needs_ocr_enhancement` and the D3 floor both predate this
ticket — B1 only made it reachable via a new class of page (structurally-defective tables); it is
genuinely pre-existing, not introduced by B1, but was fixed in this commit rather than filed
separately since the change is a one-line reordering with full test coverage already at hand.
Added `test_three_flag_page_with_needs_ocr_enhancement_lands_only_in_d3_floor`.
**Load-bearing proof:** reverted the exclusion to its round-1 (inside-the-disjunct) placement —
the two pre-existing tests in the class still passed, but the new test failed
(`'native_fallback'` appeared alongside `'table_region_unverifiable'` in the event kinds) —
then restored the fix.
