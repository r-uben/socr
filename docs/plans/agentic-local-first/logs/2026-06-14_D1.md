# TICKET-D1 — Dense-table prompt: keep summary rows paired

Date: 2026-06-14
Status: DONE

## What changed

### `src/socr/prompts/table_extract.md`
Added one new bullet point immediately after the existing "Preserve the row and column
structure you see" rule. The new rule reads:

> When a table has paired columns (e.g. two consecutive year columns such as 2026
> and 2027 for each variable), ALL rows — including summary rows (Consensus, High,
> Low, Std Dev, Mean) — must use the same number of columns as the data rows. Do
> not flatten or merge columns for summary rows. If a summary row spans fewer
> visual columns than the header, insert blank cells to maintain alignment.

### `src/socr/prompts/judge_page.md`
Added one new bullet point immediately after the existing tables/figures line in the
comparison checklist:

> For tables with paired columns (e.g. two year columns per variable): summary rows
> (Consensus, High, Low, Std Dev, Mean) must have the same column count as data
> rows. Collapsed or merged summary rows are a transcription defect — mark as mangled.
