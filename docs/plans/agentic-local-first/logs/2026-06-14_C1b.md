# TICKET-C1b — Calibrate stall-guard soft-timeouts from bench data

**Date:** 2026-06-14
**Status:** DONE

## What changed

### `src/socr/pipeline/agentic.py`
Added module-level constant `DEFAULT_PROVIDER_TIMEOUTS: dict[EngineType, float]` with
calibrated values derived from `scratch/bench/out200/results.tsv` (2026-06-13):
- `EngineType.QWEN: 300.0` — local `qwen3-vl:30b-a3b-instruct` worst-case ~125s on
  dense tables; 300s sits comfortably above that but catches any runaway.
- `EngineType.GEMINI: 240.0` — `qwen3.5:cloud` worst-case ~127s; 240s buffer.

### `src/socr/pipeline/orchestrator.py`
`_phase_agentic` now falls back to `DEFAULT_PROVIDER_TIMEOUTS` when
`agentic_provider_timeout` is not set on config, replacing the previous `None` fallback.
The stall guard is now **active by default** with calibrated values.
Added `DEFAULT_PROVIDER_TIMEOUTS` to the local import of `socr.pipeline.agentic`.

### `docs/MODELS.md`
Added a paragraph under the local-tier model section citing the benchmark source
(`scratch/bench/out200/results.tsv`, 2026-06-13) and the derived timeout values.

### `tests/test_agentic.py`
Added import of `DEFAULT_PROVIDER_TIMEOUTS`.
Added `test_default_provider_timeouts_keys` — checks that QWEN and GEMINI keys are
present and have positive float values. Does not assert specific floats (they are tunable).

## Test result

762 passed, 0 failed (was 761 before this ticket; +1 for the new key-shape test).

## Deviations / notes

None. Values are all in the one named constant; orchestrator never has a magic number.
The `or DEFAULT_PROVIDER_TIMEOUTS` fallback correctly handles both the `None` case
(config attribute absent) and an empty dict `{}` case (falsy), which is a valid
conservative choice — an empty dict disables all timeouts, which the operator likely
intends if they set it explicitly.
