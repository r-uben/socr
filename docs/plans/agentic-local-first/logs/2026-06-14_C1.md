## What changed

### `src/socr/pipeline/agentic.py`
- Added `import concurrent.futures` at the top.
- Added `provider_timeout: dict[EngineType, float] | None = None` keyword-only parameter to `route_page`.
- When a provider's engine key is present in `provider_timeout`, the `run_provider` call is executed via `ThreadPoolExecutor(max_workers=1)` with `future.result(timeout=timeout_sec)`. On `TimeoutError`, the executor is shut down with `wait=False` (so we do not block waiting for the stalled thread), a WARNING is logged, an ERROR `ProviderAttempt` is recorded, and the loop `continue`s to the next rung.
- The successful path also calls `ex.shutdown(wait=False)` for symmetry (avoids brief join on the worker thread).
- Updated the docstring of `route_page` to document `provider_timeout`.

## Deviations / notes
- `future.cancel()` does not interrupt a running thread in Python's threading model.
  The workaround is `ex.shutdown(wait=False)`, which lets the stalled thread run to
  completion in the background (it's a daemon thread) while the calling code proceeds
  immediately. This is the standard Python approach and safe here since `run_provider`
  is a self-contained function that touches only its own page state.
- No new fields added to `ProviderAttempt` or `PipelineConfig` (both deferred to A1
  per the ticket).
